1. 개요 및 재구성 원칙
======================

1.1 재구성의 필요성
-------------------

현재 크리딜은 브로커 페이지 24개, 공개 페이지 18개, API 60여 개가 기능
단위로 병렬 나열된 구조다. 딜카드·IM·매거진·명함·캠페인이 각각 독립
메뉴로 존재해, 브로커는 하나의 딜을 진행하기 위해 여러 화면을 오가며
같은 매물을 반복 선택해야 한다. 기능은 많지만 \'내 딜이 지금 어디까지
왔는가\'를 한눈에 보여주는 화면이 없다. 재구성의 목표는 기능 추가가
아니라, 이미 만들어진 부품을 브로커의 실제 업무 단위인 \'딜\'을 중심으로
재조립하는 것이다.

1.2 재구성 4원칙
----------------

-   **딜이 중심 객체다.** 매물(건물)이 아니라 딜(매각 건)이 모든
    문서·활동·관계자를 묶는 단위다. 딜카드·IM·수임제안서는 딜의
    산출물이고, 열람·채팅·일정은 딜의 활동 기록이다.

-   **모든 화면은 3루프 중 하나에 속한다.** 루프 1(매일 앵커:
    홈·메모·고객), 루프 2(딜 자산화: 딜 워크스페이스·유통·추적), 루프
    3(네트워크: 공동중개·전문가). 어디에도 속하지 않는 기능은 통합하거나
    보류한다.

-   **입력은 한 번, 산출은 여러 번.** 메모·OCR·공공데이터로 채워진 딜
    데이터(표준 스키마)에서 딜카드·IM·수임제안서·카톡 문구·매거진 소재가
    파생된다. 같은 정보를 두 번 입력하게 하지 않는다.

-   **고객 대면 수치는 검증 없이는 표시하지 않는다.** NLG 마스크·정합성
    검증을 통과한 필드만 외부 문서·자동응답에 노출한다.

2.3 홈(코크핏) 재구성
---------------------

현재 대시보드는 KPI 카드·탭 4개·퀵액션 6개가 병렬된 \'계기판\'이다.
TO-BE 홈은 \'오늘 무엇을 해야 하는가\'에 답하는 실행 화면으로 바꾼다.

-   **① 오늘의 액션 큐(최상단).** Hot Lead 연락, Gate 요청 승인 대기,
    임장 일정, 만료 임박 딜 등 우선순위 정렬된 할 일 목록. 각 항목에서
    1탭으로 해당 딜·고객으로 이동.

-   **② 브리핑 카드.** 권역 시장 요약·전일 거래(모닝인텔 흡수) --- 접을
    수 있는 1개 카드.

-   **③ 파이프라인 스냅샷.** 단계별 딜 수와 정체 경고(장기 체류 딜
    하이라이트).

-   **④ 주간 성과.** 발행 IM·열람·리드 수 --- 상세는 리포트로 이동.

3.2 표준 스키마·검증 (온톨로지 1단계 적용)
------------------------------------------

-   자산군별 속성 마스터 리스트를 Asset 스키마로 적용. 도로접면
    12분류(가중치), 명도 상태·점유자 유형(리스크 등급), 물류
    스펙(층고·바닥하중·도크·램프·저온비율·수전용량),
    개발부지(지목·형상·토지거래허가·기부채납)를 enum으로 정의.

-   행정구역·권역 계층 테이블로 위치 추론(역삼동→강남구→서울) 구현 ---
    그래프 DB 없이.

-   정합성 검증 규칙: Cap Rate=NOI÷매각가 일치, NOI 공식 단일
    정의(관리비 처리 명문화), 용적률≤용도지역 상한, 이상값 경고. 위반 시
    발행 차단이 아닌 경고+수정 유도.

-   데이터 품질 등급(A\~D)을 이 스키마의 필드 충족률로 재정의. DCF·NPV는
    A등급에서만 옵션 표시.

4. 서비스별 상세 기획
=====================

4.1 S1. 메모·고객 CRM (루프 1 --- 매일 앵커)
--------------------------------------------

-   **목적:** 브로커가 매일 여는 이유 제공. 모든 정보의 진입점.

-   **핵심 기능:** 음성/텍스트 메모→AI
    분류(매물/매수/보강/일정/일반)→딜·고객·일정으로 1탭 전환(기존 유지),
    고객별 타임라인(보낸 문서·열람·채팅·통화 메모·미팅을 시간순 집계 ---
    신규), 고객 투자 프로파일(의향 조건+행동 데이터 결합).

-   **핵심 플로우:** 임장 중 음성 메모 → AI가 딜 초안+일정 생성 →
    사무실에서 딜 워크스페이스 이어서 작업. / 매수자 통화 후 메모 → 고객
    타임라인 자동 기록 → 다음 통화 전 타임라인 1분 리뷰.

-   **정책:** 고객 데이터는 브로커 소유·격리. 플랫폼은 익명 통계 외 접근
    불가(계약 명시).

4.2 S2. 딜 워크스페이스 (루프 2 --- 코어)
-----------------------------------------

-   **목적:** 딜 하나의 모든 것을 한 화면에서. 현재 딜카드 상세+IM
    승인+스튜디오에 분산된 기능의 통합.

-   **구성(탭):** ① 개요(파이프라인 단계, 핵심 지표, 액션 버튼) ②
    데이터(표준 스키마 편집, 충전 파이프라인, 품질 등급) ③
    문서(딜카드·IM B2B/B2C·수임 제안서·카톡 문구 --- 생성·버전·발행) ④
    관계자(매수 후보 매칭·공유 이력) ⑤ 활동(열람·Gate·채팅·일정
    타임라인).

-   **발행 단일 플로우:** 문서 편집→미리보기→발행 1버튼. 투자요약·OG
    저장 통합, OG 자동 동기화, 캐시 버스팅 서버 처리. 발행 전 정합성
    검증 경고 표시.

-   **수임 제안서(신규):** Asset 데이터+비교 실거래+마케팅
    계획(딜카드·IM 샘플+열람 추적 데모)을 묶은 매도인용 문서. \'전속으로
    맡기면 이렇게 팔고, 이렇게 보고합니다\'가 핵심 메시지.

-   **정책:** 블라인드 기본값. 재무 수치는 범위(±)·출처 표기. AI 초안
    편집 diff는 골든셋으로 자동 수집(브로커 동의 기반).

4.3 S3. 유통·추적·인박스 (루프 2)
---------------------------------

-   **목적:** 배포된 문서를 리드로 전환하고, 모든 반응을 한 곳에서 처리.

-   **핵심 기능:** 카톡/LINE 공유(기존), 열람 추적·리드 스코어링(기존),
    Hot Lead 알림톡(기존), 인박스 통합(Gate 요청 승인/거절/전화 + 열람
    피드 + 채팅 --- 알림의 단일 처리 지점).

-   **스마트톡-lite:** IM 뷰어 내 채팅 위젯. 고객은 가입 없이
    이름·연락처로 참여. FAQ 자동응답은 검증 필드 인용+출처 표기만, 부재
    모드는 정보 안내+방문 예약 접수+아침 요약 인계. 재무 계산(\@계산
    등)은 브로커 코파일럿 전용(브로커 확인 후 전송). chat\_rooms는 역할
    기반(sender\_type에 co\_broker·professional 예약)으로 설계해 딜룸
    확장에 대비.

-   **정책:** 자동응답이 답할 수 없는 질문은 즉시
    에스컬레이션(\"중개인이 확인 후 답변드립니다\"). 고객 대면 첫 자동
    메시지는 절제형(감시 인상 방지).

4.4 S4. 매칭 (루프 2→3 가교)
----------------------------

-   **목적:** 딜↔매수 의향 매칭의 신뢰도·활용률 제고.

-   **핵심 기능:** 규칙 기반 설명 가능 매칭(초안정 수익형·밸류애드
    후보·사옥 적합 등 규칙 10선 탑재), 매칭 사유 표시(\"공실률 3% 미만 ∧
    WALT 2.5년 이상\"), 명도 고위험 등 감점·제외 규칙, 브로커별 규칙
    토글.

-   **확장:** 2단계에서 매칭 대상을 \'내 고객\'에서 \'네트워크 참여
    브로커의 익명 의향\'으로 확장 --- 같은 규칙 엔진 재사용.

4.5 S5. 공동중개 네트워크 (루프 3 --- 2단계 개방)
-------------------------------------------------

-   **목적:** Gate 구조를 브로커 간 매물↔매수 유통망으로 개방. 한국형
    CRE MLS.

-   **핵심 기능:** 블라인드 딜카드의 네트워크 공개 옵트인, 크로스 매칭
    알림(상대 브로커에게 자산 익명 요약만), Gate 승인 시 단계적
    공개(권역→상세→주소), 공동중개 조건(수수료 배분율) 사전 합의 템플릿,
    평판 프로필(성사 이력·응답 속도·상호 평가).

-   **정책:** 매물 소유 브로커가 공개 범위·승인을 항상 통제. 무단 재유통
    방지(워터마크·열람자 기록). 초기에는 상호 신뢰 브로커 쌍의 수동
    파일럿으로 관행 학습 후 시스템화.

4.6 S6. 전문가 딜룸 (루프 3 --- 3단계)
--------------------------------------

-   **목적:** 세무사·건축사·법무사를 딜 단위 참여자로 초대해 IM을
    \'전문가 검증 문서\'로 격상.

-   **핵심 기능:** 딜별 전문가 초대(역할 권한: 담당 섹션만 열람·기고),
    기고 모듈(양도세 시뮬레이션·가설계 요약·권리분석)이 실명·자격 표시와
    함께 IM에 삽입, 협력 벤더 디렉토리(기존 벤더 리뷰 확장)와 성사 시
    정산.

-   **정책:** 전문가는 초대된 딜의 필요 정보만 접근. 기고 내용의 책임
    주체(전문가 실명) 명시 --- 플랫폼 법적 방어와 IM 신뢰를 동시에 확보.

7. 결론
=======

이 기획의 본질은 하나다: **흩어진 24개 화면을 \'딜\'이라는 업무 단위로
재조립하는 것.** 브로커는 메모로 딜을 시작하고, 딜 워크스페이스에서
데이터를 채워 문서를 발행하며, 인박스에서 반응을 처리하고, 매칭과
네트워크로 상대를 찾는다. 각 단계의 부품은 대부분 이미 존재한다 ---
재구성은 신규 개발이 아니라 연결과 정리의 프로젝트이며, 그래서 90일 안에
가능하다.
