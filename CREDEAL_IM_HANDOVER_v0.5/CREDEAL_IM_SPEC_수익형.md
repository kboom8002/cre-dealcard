### 0.3 D19의 입장

> **정직성은 하한이고, 소구력은 목표입니다.**

D18은 하한만 지켰습니다. 정본은 목표를 정했지만 하한을 강제할 수단이 없었습니다. **공공데이터 결합이 둘을 동시에 가능하게 합니다** — 지어내지 않고도 화면을 채울 수 있습니다.

**당산동 실증 — 같은 물건, 자료만 다릅니다.**

| | R1판 (원장만) | **R2판 (공공데이터 결합)** |
|---|---|---|
| 용도지역 | 확인 필요 | **준공업지역** |
| 용적률 | 확인 필요 | **221.80% / 상한 400% → 잔여 178.2%p** |
| 공시지가 | 확인 필요 | **평당 3,917만 · 매매가는 1.91배** |
| 시세 비교 | 산출하지 않음 | **토지 평당 7,492만 vs 인근 9,300만~1억 5,800만** |
| 역 거리 | 확인 필요 | **당산역 380m · 도보 5분** |

| 확인 필요 | **7건** | **2건** |

**R1판은 "믿을 수는 있지만 살 이유가 없는" IM이고, R2판은 "믿을 수 있고 살 이유가 보이는" IM입니다.**

## 1. 출처 등급 6단 — D19 신설

**모든 수치는 등급 하나를 답니다.** 등급 없는 수치는 렌더하지 않습니다.

| 등급 | 표기 | 출처 | 예 |
|:-:|---|---|---|
| **S1** | **공부** | 건축물대장·토지대장·등기부 | 대지 507.40㎡ · 용적률 221.80% |
| **S2a** | **공공 API 원시** | 그대로 쓸 수 있는 값 | 준공업지역 · 공시지가 11,850,000원/㎡ · 역 거리 |
| **S2b** | **공공 API + 중개인 보강** | **보강 없이는 쓸 수 없는 값** | **인근 실거래 비교** — §1.3 |
| **S3** | **원장** | 중개인 제출 임대 현황 | 월세 1,946만 · 보증금 2.90억 |
| **S4** | **파생** | 위 값의 계산 결과 (산식 노출) | 총취득원가 121.33억 |
| **S5** | **가정** | ◇ 표기 필수 | ◇ 대출금리 4.5% |
| **—** | **확인 필요** | 미확보 | 관리비 · 최초 계약일 |

### 1.1 등급 표시 규칙

| 위치 | 표시 |
|---|---|
| 표 | **출처 열 필수** — "건축물대장", "원장 8행 합계" 등 |
| Hero 숫자 | 값 아래 근거 한 줄 |
| 화면 상단 | **근거 칩** — 결합된 출처만 노출 |

**근거 칩은 실제로 결합된 것만 켭니다.** R1판은 `원장`만, R2판은 `건축물대장·토지이용계획·공시지가·실거래·POI·원장`.

### 1.2 우선순위

```
S1 공부  >  S2a 공공 API 원시  >  S3 원장
```

**충돌하면 상위가 이깁니다.** 다만 **충돌 사실을 숨기지 않고 함께 적습니다.**

> 당산동 연면적 — 원장 계 행 1,141.15㎡ · 층별 합 1,441.15㎡ · **공부 층별개요 1,441.15㎡**
> → 공부를 채택하고, 원장 계 행이 틀렸음을 확인사항에 남깁니다.

### 1.3 🔴 정정 — 인근 실거래는 공공데이터만으로 만들 수 없습니다

**v1.x는 comps를 S2(공공 API)로 분류했습니다. 틀렸습니다.**

국토부 **상업업무용 매매 실거래가 API**가 실제로 주는 필드를 확인했습니다.

| 주는 것 | 주지 않는 것 |
|---|---|
| 지역코드 · 시군구 · 법정동 | **지번 — 마스킹됩니다 (`1***`, `8**`)** |
| 유형(일반/집합) · **용도지역** · 건물주용도 | **어느 건물인지 특정 불가** |
| 건축년도 · 건물면적 · 거래금액 · 거래일 | **대로변 / 이면 구분** |
| 대지면적 — **일반건물만.** 집합건물은 공란 | 지상 층수(일반건물) · 상태 · 리모델링 이력 |

**결과 세 가지**

| # | 사실 | 영향 |
|:-:|---|---|
| 1 | **지번이 마스킹됩니다** | "당산동5가 대로변 근생"이라는 식별은 **중개인이 압니다** |
| 2 | **집합건물은 대지면적이 공란입니다** | **토지 평당가 비교가 불가능**합니다 |
| 3 | **대로변/이면 구분이 없습니다** | 같은 동이라도 평당가가 2배 차이납니다. 섞으면 비교가 무의미합니다 |

> **첨부 공공 API 보고서의 comps 표(토지 평당가 14,200만원 · "지상6층" · "대로변")는 API 단독으로 만들 수 없습니다.** 중개인 보강이 들어간 값이며, **S2b로 분류해야 합니다.**

**그래서 `comp_identify`·`comp_frontage`·`comp_land_sqm`·`comp_floors`·`comp_condition` 5개 필드를 바텀시트에 신설했습니다** (§7 · 부록 A).

## 2. 공부 교차검증 — D19 신설

**공공데이터도 틀립니다.** 받은 값을 그대로 쓰지 않고 **서로 검산합니다.**

### 2.1 필수 교차검증 4종

| # | 검증 | 산식 | 허용 오차 |
|:-:|---|---|:-:|
| **X1** | 건폐율 ↔ 건축면적 | 대지 × 건폐율 = 건축면적 | ±1% |
| **X2** | 용적률 ↔ 지상 연면적 | 대지 × 용적률 = 용적률산정 연면적 | ±2% |
| **X3** | 층별개요 합 ↔ 연면적 | Σ층별 = 연면적 | ±1% |
| **X4** | 공시지가 ↔ 총액 | 대지 × ㎡당 공시지가 = 총액 | ±1% |

### 2.2 실측 결과 — 당산동에서 오류를 하나 잡았습니다

**첨부된 공공 API 보고서 §2.2의 합계 기재가 자기 표와 맞지 않습니다.**

| | |
|---|---|
| 보고서 §2.2 층별 표 | B1 317.22 + 1F 183.99 + 2F 252.09 + 3F 252.09 + 4F 252.09 + 5F 183.67 |
| **실제 합** | **1,441.15㎡** |
| 보고서 기재 합계 | **1,141.15㎡** ← 원장 계 행과 같은 값 |

**X2 용적률 역산으로 판정했습니다.**

```
대지 507.40㎡ × 용적률 221.80% = 지상 연면적 1,125.41㎡
층별 합 1,441.15 − B1 317.22   = 지상 연면적 1,123.93㎡      차이 1.48㎡ (0.13%)  ✔
1,141.15 가정 시 지상            =            823.93㎡ → 용적률 162.38% (59.4%p 차이)  ✘
```

**X1도 일치합니다** — 507.40 × 49.68% = 252.08㎡ ≈ 건축면적 252.09㎡.

> **결론: 공부상 연면적은 1,441.15㎡입니다.** 원장 계 행 1,141.15와 보고서 합계 기재가 같은 오기입니다. **300.00㎡ 차이는 "자가/미등재 구획"이 아니라 계 행 오기입니다.**

**양평동은 X1·X2 모두 일치합니다** (302.92 = 302.92 · 2,068.58 ≈ 2,068.63).

### 2.3 교차검증이 게이트를 해소합니다

| 게이트 | R1판 | **R2판** |
|---|:-:|:-:|
| **C19** 면적 불일치 | **차단** | **해소** — 공부로 확정 |
| **G21** 첨부 공부 소재지 (양평) | **차단** | **해소** — 정본 필지 매칭 |

## 2A. 필지 · 제척 · 토지이용계획 표시 (v2.2 신설)

> 🔴 **이 절은 신설이 아니라 복원입니다.** CREDEAL 온톨로지 v0.3에 이미 있던
> 규격이 폐기 문서(`IM_PRECISION_SPEC.md`)에만 남아 승계에서 유실됐습니다.
> 경위는 D22-8 §2. 정본은 `CATALOG_SLOTS.md` §2.1·§5 와 `CATALOG_RULES.md`
> P01~P03·G12·L10~L12 이고, 기계 판독본은 `credeal/ssot/im.parcel.yaml` 입니다.

### 2A.1 필지는 배열입니다

물건 하나가 필지 하나라는 전제를 버립니다.

```ts
Parcel { pnu · jibun · jimok · area · ownership · share · exclusions[] }
Exclusion { kind(7종) · area · affectsFAR · provenance · note }
```

**필지가 없는 물건에 빈 배열을 넣지 않습니다.** 넣으면 단일 필지가 "1필지 물건"으로 표기되어 없던 면이 생깁니다.

### 2A.2 제척 — API가 주지 않는 값

| | |
|---|---|
| **사유 7종** | 계획도로 · 완충녹지 · 공원 · 하천 · 접도구역 · 법면 · 타인지분 |
| **취득 경로** | 🔴 **API 조회 불가** — 토지이용계획도의 도시계획시설 저촉선 판독 |
| **출처 등급** | S3 (중개인) · 화면에 `●중개인` 표기 |
| **확인** | 관할 구청 — 확인 전까지 확인사항에 남깁니다 |

`affectsFAR`에 기본값이 있지만 **기본값으로 계산하고 넘어가지 않습니다.** 필지마다 다르고, 틀린 값이 확신 있게 나갑니다.

### 2A.3 파생 — P01~P04

```
P04  대장 대지면적 = Σ 필지 면적
P01  유효 대지면적 = Σ(필지 면적 × 지분) − Σ(제척 where affectsFAR)
P02  유효 용적률   = 용적률산정 연면적 ÷ 유효 대지면적
P03  제척 영향도   = 제척 합 ÷ 대장 대지면적
```

🔴 **유효 대지가 작아지면 용적률은 올라갑니다.** 대장 면적으로 계산하면 증축 여유를 과대평가합니다.

### 2A.4 X05 — 필지 합 검산 (신설)

```
X05  필지 면적 합 = 공부 대지면적 · ±0.5% · 경고 · 필지 ≥ 2 일 때만
```

**X01·X02·X04는 대장 기준을 유지합니다.** 건폐율·용적률이 대장 대지 기준으로 고시되므로 유효 면적으로 바꾸면 공부끼리의 항등식이 깨집니다. 다필지의 위험은 합산 자체에 있으므로 합산을 따로 잽니다.

### 2A.5 한시 완화 임계 연동

한시적 용적률 완화가 "산정 용적률 N% 미만"을 조건으로 걸 때 **대장 기준으로는 충족인데 유효 기준으로는 이탈**할 수 있습니다.

실측 — 잠원동 두원빌딩 2필지, 제척 12.5㎡.

| | 대지면적 | 용적률 | 250% 조건 |
|---|--:|--:|:-:|
| 대장 | 616.1㎡ | 249.0% | 충족 |
| **유효** | **603.6㎡** | **254.1%** | **이탈** |

이탈이면 **완화를 전제한 규모 산출을 하지 않습니다.** 경고 + 확인사항으로 넘깁니다.

### 2A.6 토지이용계획 선택적 표시 (L12)

확인원에는 수십 항목이 찍힙니다. 다 보여주면 노이즈이고, **임의로 고르면 누락 책임이 생깁니다.**

```
매수 목적 5종 × 항목별 관련도 → high 본문 · medium 접기 · low 부록
🔴 관련도와 무관하게 전체 목록은 항상 부록에 싣습니다.
```

고르는 것은 **강조**이지 **감춤**이 아닙니다. 이 구분이 법적 책임을 가릅니다.

실측 — 잠원동 확인원 **7항목** 기준입니다 (레지스트리 관련도 표는 11항목).

| 목적 | 본문 | 접기 | 부록 |
|---|--:|--:|--:|
| 임대수익 | 2 | 3 | 7 |
| 가치 상승 여력 | 6 | 1 | 7 |
| 개발 | 7 | 0 | 7 |

**매핑에 없는 항목은 조용히 부록으로 내리지 않습니다.** 접기에 두고 `◇ 관련도 미등록`을 붙입니다. 모르는 것을 낮은 것으로 취급하면 그것이 누락입니다.

**매수 목적이 없으면** 전 항목을 같은 비중으로 냅니다 — 임의로 감추지 않습니다.

### 2A.8 다필지 탐색

## 3. R1판 / R2판

### 3.1 정의

| | **R1판 — 기본** | **R2판 — 공공데이터 결합** |
|---|---|---|
| 자료 | 중개인 원장만 | + 건축물대장 · 토지이용계획 · 공시지가 · 실거래 · POI |
| 만드는 시점 | 물건 접수 즉시 | 지번 확정 후 자동 |
| 용도 | 내부 검토 · 사전 타진 | **대외 발행** |
| 공부 항목 | 전부 "확인 필요" | 확정값 |
| 시세 비교 | 산출하지 않음 | **토지·연면적 기준 분리 제시** |

**R1판은 버리는 판이 아닙니다.** 자료가 오기 전에도 매수인에게 보낼 수 있어야 하고, **무엇이 없는지가 그 자체로 자료 요청서**가 됩니다.

### 3.2 임대차 해상도는 별개입니다

**공공데이터는 계약 정보를 주지 않습니다.** 관리비·최초계약일·대항력은 여전히 중개인이 받아야 합니다.

| 물건 | R1판 등급 | **R2판 등급** | 왜 |
|---|:-:|:-:|---|
| 당산동 | R1 | **R1** | 관리비·시작일 미확보 — 공공데이터로 못 채움 |
| 양평동 | R1 | **R2** | 층별개요가 임대면적을 채움 |

**R2판이어도 임대차 등급이 R1일 수 있습니다.** 두 축을 함께 표기합니다.

```
자료 근거   공부·공공 API 결합 (R2판)
임대 해상도 R1 — 관리비·시작일 미확보
```

### 3.3 이중 해상도 — L축 × P축 (v2.0 신설)

**한 축으로는 부족합니다.** 임대차 자료와 물건 자료는 출처도 다르고 채우는 사람도 다릅니다.

| 축 | 무엇 | 등급 | 누가 채우나 |
|:-:|---|---|---|
| **L** | 임대차 해상도 | R0~R3 | **중개인만** — 렌트롤 표준양식 |
| **P** | 물건자료 해상도 | P0~P3 | 지번 입력 → 공공 자동 + **중개인 보강** |

| 등급 | L축 요건 | P축 요건 |
|:-:|---|---|
| 1 | 호실·업종·금액·만료일·임대상태 | **지번** |
| 2 | + 면적·적용법령·관리비·시작일 | + 공부·용도지역·공시지가 (자동) |
| 3 | + 최초계약일·대항력 | + **비교사례 보강·사진** |

**P2는 지번만 넣으면 자동으로 올라갑니다. P3와 L2·L3는 사람이 넣어야 합니다.**

#### 현행 A~D 등급은 L×P에서 유도합니다 (v2.1)

**같은 물건이 세 개의 등급을 갖고 있었습니다** — 시퀀서 A~D · 정본 R0~R3 · D19 L×P.

| 등급 | 조건 | 덱 |
|:-:|---|---|
| **A** | L ≥ R2 **그리고** P ≥ P2 | 풀 기관투자 덱 |
| **B** | L ≥ R1 **그리고** P ≥ P2 | 공공 결합 표준 덱 |
| **C** | L ≥ R1 **그리고** P = P1 | 원장 기반 덱 |
| **D** | L = R0 **또는** P = P0 | 최소 덱 · 내부 검토용 |

**당산동 ② = L R1 · P P2 → B** · **당산동 ③ = L R2 · P P3 → A**

### 3.4 두 물건 실측 — `input_spec.py`

| 시나리오 | L | P | 열린 블록 |
|---|:-:|:-:|:-:|
| 당산 ① 원장만 | R1 | **P0** | **19 / 47** |
| 당산 ② + 지번(공공 자동) | R1 | **P2** | **31 / 47** |
| 당산 ③ + 중개인 보강 | **R2** | **P3** | **40 / 47** |
| 양평 ② + 지번 | R1 | P2 | 30 / 47 |

**지번 한 줄이 블록 12개를 엽니다.** 그다음 12개는 중개인이 손으로 넣어야 열립니다.

### 6A.1 앞 판이 어색했던 이유 4가지

| # | 문제 | 국내 관행 | 조치 |
|:-:|---|---|---|
| **1** | **사진이 없었다** | **표지·개요·갤러리에 외관 사진 전진배치** | 원본 IM에서 실물 사진 13매 추출·배치 |

## 7. 중개인 입력 표준 — 바텀시트 (v2.0 신설)

**앞선 판은 "중개인이 채워야 한다"고만 적고 무엇을 어떻게 받을지 정하지 않았습니다.**
그래서 물건마다 들어오는 항목이 달랐고, IM도 물건마다 달랐습니다.

### 7.1 3단 구조

| 단 | 개수 | 성격 | 미입력 시 |
|:-:|--:|---|---|
| **필수** | **9** | 없으면 IM을 만들지 않습니다 | **생성 중단** |
| **권장** | **17** | 없으면 해당 블록이 잠깁니다 | **"확인 필요"로 표기** |
| **선택** | **17** | 있으면 블록이 추가로 열립니다 | 블록 미노출 |

**총 43종.** 전체 사전은 **부록 A**입니다.

### 7.2 필수 9종

| 그룹 | 필드 |
|---|---|
| 물건 식별 | **소재지 지번** · **매매 희망가** |
| 임대차 원장 | **렌트롤 기준일** · 호실/층 · 업종 · 보증금 · 월세 · 계약 만료일 · 임대 상태 |

**지번이 필수인 이유** — 지번 한 줄이 공공 블록 12개를 엽니다 (§3.4). 지번 없이는 P축이 P0에 머뭅니다.

### 7.3 신설 필드 — 비교 사례 보강 5종

**§1.3에서 판정한 대로, 실거래 API 원시자료만으로는 비교표를 만들 수 없습니다.**

| 필드 | 왜 중개인만 채울 수 있나 |
|---|---|
| `comp_identify` 비교 물건 식별 | **API가 지번을 마스킹합니다** (`1***`) |
| `comp_frontage` 대로변/이면 | API에 없음 · 같은 동에서 평당가 2배 차이 |
| `comp_land_sqm` 비교 물건 대지면적 | **집합건물은 API가 공란**으로 줍니다 |
| `comp_floors` 비교 물건 규모 | API의 층 필드는 집합건물만 |
| `comp_condition` 비교 물건 상태 | 리모델링·공실·명도 여부 |

**5종을 넣으면 `comps_table`·`comps_land_unit`·`comps_reason` 3블록이 열립니다.**

### 7.4 그 밖의 신설 필드

| 그룹 | 필드 | 여는 블록 |
|---|---|---|
| 운영·금융 | 연간 운영비 · 관리비 부담 주체 · 대출 잔액·금리·승계 | NOI · 순수익률 · 월 총수입 · 실제 LTV |

## 8. 동적 생성 규칙 — 블록 게이팅 (v2.0 신설)

### 8.1 원칙

> **블록은 사람이 고르지 않습니다. 입력이 결정합니다.**

```
입력 집합 ──▶ resolve()  ──▶ (L등급, P등급, 부족 항목)
           └▶ evaluate() ──▶ 블록별 열림/잠김 + 잠김 사유
                          └▶ 렌더러가 그대로 따름
```

`credeal/input_spec.py`가 이 판정을 수행합니다. **렌더러는 판단하지 않습니다.**

### 8.2 잠긴 블록의 처리 — 3가지 중 하나

| 처리 | 언제 | 예 |
|---|---|---|
| **확인 필요로 표기** | 그 자리가 IM에 필요할 때 | 용도지역 · 대지면적 · 접면 도로 |
| **산출하지 않음을 명시** | 계산 결과가 없을 때 | "운영비 미제출 — 순수익률을 산출하지 않았습니다" |
| **면을 유지하고 안내** | 면 단위로 비었을 때 | 사진 면 "사진 미제출" |

**세 경우 모두 블록을 삭제하지 않습니다.** 없다는 사실이 자료 요청서입니다 (정본 §4.2 ⑦).

### 8.4 실측 — 입력이 늘면 블록이 열립니다

| 시나리오 | L | P | 열린 블록 | 늘어난 면 |
|---|:-:|:-:|:-:|---|
| ① 원장만 | R1 | P0 | **19** | — |
| ② + 지번 | R1 | P2 | **31** | 물건 개요 · 입지 · 공시지가 |
| ③ + 중개인 보강 | **R2** | **P3** | **40** | 비교 사례 3 · 개선 여력 · 사진 · 견해 |

**①→② 는 지번 한 줄로 12블록이 열립니다.** ②→③ 은 중개인이 12개 필드를 더 넣어야 9블록이 열립니다.

### 9.1 F9가 가장 시급합니다

**실거래 API는 이미 붙어 있는데 비교표를 만들 수 없습니다.** 지번이 마스킹되고 집합건물 대지면적이 공란이기 때문입니다.

**화면 설계** — 조회된 실거래 목록을 왼쪽에 띄우고, 중개인이 각 건에 5필드를 채워 오른쪽 비교표로 승격시킵니다.

```
[조회된 실거래]                    [비교표로 승격]
당산동5가 1*** · 145억 · 1,280㎡  →  식별 [대로변 근생    ]
2024-11 · 제2종근생 · 2019년         접면 [대로변 ▾]  규모 [지상6층]
                                    대지 [340.4 ㎡]  상태 [정상]
```

**5필드가 채워진 건만 비교표에 올립니다.** 나머지는 "원시 자료 n건 조회됨 — 보강 필요"로 남깁니다.
