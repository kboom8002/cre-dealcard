## 0. 개정 요약

### 0.1 v2.0 원안에 대한 판정

v2.0 기획안은 **딜 객체 중심 전환**이라는 정확한 처방을 담고 있으며, 설계 품질은 우수합니다(루브릭 83.3/100). 그러나 실행 계획에 세 가지가 빠져 있습니다.

| 누락 | 영향 |
|:---|:---|
| **팀 규모 미명시** | 13주 실현 가능성을 판단할 수 없음 |
| **리스크 섹션 부재** | 경영진 승인 문서로서 결함 |
| **후행지표 부재** | 활동 지표만으로는 유료화 근거를 만들 수 없음 |

본 문서는 이 세 가지를 채우고, P0/P1을 결합합니다.

### 0.2 결합 원칙

```
① v2.0 원안 항목은 스코프를 바꾸지 않는다 — 공수만 재산정
② P0/P1은 별도 트랙이 아니라 기존 스프린트에 흡수한다
③ 이미 v2.0에 대응 항목이 있으면 중복 개발하지 않는다
④ 각 항목의 출처(v2.0 / 세션 도출 / 결합)를 명시한다
```

### 0.3 항목별 결합 판정

| 이번 세션 도출 | v2.0 대응 | 판정 | 조치 |

### 1.2 결정적 발견 — 13주는 6명 팀이어야 가능합니다

```
268 man-day ÷ 13주(65 영업일) = 4.1 FTE   ← 가동률 100% 가정 (비현실적)
268 man-day ÷ 65일 ÷ 0.70 가동률        = 5.9 FTE ≈ 6명
```

> **v2.0의 "13주"는 개발자 6명을 전제한 숫자입니다.** 문서에 명시되지 않았으므로, 승인 전 팀 규모를 반드시 확정하십시오. 4명 팀이면 동일 스코프에 **19~20주**가 소요됩니다.

#### 토허 스크리너를 M3에 넣는 이유

서울 25개 자치구 전역이 토지거래허가구역이며(2025.10.20~2026.12.31, 상업용 대지지분 15㎡ 초과), 사실상 모든 딜에 절차가 부과된 상태입니다. v2.0은 이를 `개발부지` 속성의 enum 값으로만 다루고 있어 **판정 엔진이 없습니다.**

M3에 배치하는 이유는 두 가지입니다.

1. LURIS 토지이용규제 API가 M2의 공공데이터 자동 파생에서 이미 연결됨 — **선행 의존 충족**
2. 지정 효력이 2026년 12월 31일까지 — **늦게 만들수록 수명이 짧아짐**

> **법령 수치는 코드가 아니라 데이터로 관리하십시오.** 관리자 화면에서 임계면적·강화계수·유효기간을 배포 없이 수정할 수 있어야 합니다. 상세는 P0 명세 P0-2절 참조.

#### 확산 루프 (6 md)

```
전속계약 서명 성립 (M2 산출물)
    ↓
사례 카드 자동 생성 (블라인드 처리, 초기 draft)
    ↓
브로커 승인
    ↓
조직 공지 + 매거진 소재 + 브로커 프로필 실적
```

400명 조직에서 확산은 제품 성능이 아니라 옆자리 동료의 증언이 만듭니다. **"김 부장이 크리딜 제안서로 성수동 전속을 땄다"가 공지에 뜨는 것**이 확산 엔진의 핵심입니다.

### 7.2 신규 후행지표 (필수 추가)

원안 지표는 전부 **활동 지표**로, "쓰고 있다"는 말해도 "돈을 더 벌었다"는 말하지 않습니다. 90일 내에 성사(6~10개월 소요)가 나오지 않으므로 **수임을 프록시**로 씁니다.

| 지표 | 정의 | 90일 목표 | 왜 필요한가 |
|:---|:---|:---|:---|
| **브로커당 신규 수임 건수** | 전속·일반 수임 확정 건수 (도입 전후 비교) | +1건/분기 | 유료화의 유일한 근거 |
| **제안서 → 수임 전환율** | 전속계약 서명 / 제안서 발송 | 20%+ | 제안서의 실효성 검증 |
| **딜 단계 이동 속도** | 발굴 → 제안 소요일 중앙값 | −20% | 속도가 성사보다 먼저 나타남 |
| **정체 딜 비율** | 30일 이상 무활동 딜 / 전체 | 30% → 15% | 정체 탐지의 효과 |

> **M5 유료 플랜 단계에서 "왜 돈을 내야 하는가"에 답하려면 이 4개가 필요합니다.** 활동 지표만으로는 구독 전환 20% 목표를 설득할 근거가 없습니다.
