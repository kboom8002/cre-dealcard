# PART 0. 이 개정의 배경

### 현장에서 온 한 문장이 무엇을 뒤집었는가

## 0.1 현장에서 온 한 문장

> **제이에스부동산중개 파워중개인 의견**
>
> ### "수임서는 중요하지 않다. IM을 잘 디자인된 파워포인트로 만들어 주는 것이 중요하다."

짧은 문장이지만 v3.0 설계의 중심축을 건드립니다. v3.0은 수임 루프를 P0에 놓고, 보수약정 서명을 관측 레이어의 진입점으로 삼았습니다. 그 전제가 무너집니다.

이 개정은 우선순위를 한 칸 옮기는 작업이 아니라, 제품의 무게중심을 이동시키는 작업입니다.

## 0.2 이 피드백을 어떻게 읽어야 하는가

문장을 그대로 받으면 오독합니다. 세 겹으로 읽어야 합니다.

### 첫째 — "수임서가 무가치하다"가 아니라 "파워중개인에게 무가치하다"

수임 제안서는 수임을 두고 경쟁할 때 쓰는 도구입니다. 파워중개인은 이미 관계와 평판으로 수임합니다. 경쟁 도구가 필요한 쪽은 중하위 중개인입니다.

문제는 우리의 초기 100인 확보 전략이 **파워중개인을 앵커로 삼는** 전략이었다는 점입니다. 앵커가 쓰지 않는 기능을 P0에 배치한 것은 명백한 설계 오류입니다.

### 둘째 — "파워포인트"라는 형식 지정이 결정적이다

이것은 취향이 아니라 유통 구조의 반영입니다.

- **이메일 첨부로 돈다** — 자산운용사 심사역이 내부 투자심의에 올릴 때 첨부하는 것은 링크가 아니라 파일입니다.
- **중개인이 자기 손으로 고친다** — 협상 국면마다 숫자가 바뀌고, 특정 매수자용으로 한 장을 덧붙입니다.
- **인쇄한다** — 현장 미팅과 매도인 보고에서는 종이가 여전히 기본 단위입니다.

즉 링크는 CREDEAL의 관측 편의이고, **파일은 시장의 실제 유통 단위**입니다. 우리는 이 사실을 v3.0 설계에 반영하지 않았습니다.

### 셋째 — "잘 디자인된"이 진짜 요구다

시간 절약보다 앞서는 것은 체면입니다.

> 소형 중개인의 IM이 대형 운용사 수준의 IM 옆에 놓이면 초라합니다. 그 격차가 딜을 잃게 만듭니다.
>
> 파워중개인일수록 대형 매수자를 상대하므로 이 격차를 매일 체감합니다. "4시간을 20분으로"보다 "내 자료가 대형사 것처럼 보인다"가 더 강한 구매 동기입니다.

## 0.3 v3.0에서 무엇이 틀렸는가

### 설계 오류 ① — 앵커 사용자가 쓰지 않는 기능을 P0에 두었다

| 구분 | v3.0 전제 | 현장 확인 결과 |
|---|---|---|
| 수임 루프 | 수임 경쟁이 중개인의 최대 페인포인트 | 파워중개인은 관계로 수임 — 경쟁 도구 불필요 |
| 사용 빈도 | 딜당 1회 | 파워중개인 기준 사실상 0회 |
| 관측 진입점 | 보수약정 서명 시점에 딜 레코드 생성 | 수임 성공 건에만 발생 — 관측 표본이 희소 |

### 설계 오류 ② — 산출물의 유통 단위를 잘못 잡았다

v3.0은 모바일 링크를 1차 산출물로, PDF를 보조 산출물로 두었습니다. 실제 시장은 반대입니다. 파일이 1차이고, 링크는 심화 열람 채널입니다.

> **이 오류가 만든 2차 문제**
>
> 파일을 내주면 열람 추적이 끊깁니다. 그래서 v3.0은 파일 배포를 억제하는 방향으로 설계되었습니다.
> 결과적으로 중개인이 가장 원하는 것(잘 만들어진 파일)을 제품이 방해하는 구조가 되었습니다.

## 0.4 v3.1의 한 줄 명제

```
  v1.0   기능의 집합
  v2.0   딜 중심 재조립
  v3.0   딜 생애주기 완결 - 성사·무산이 기록되어 학습이 시작된다

  v3.1   산출물이 곧 관측 진입점 - IM을 축으로 한 재정렬
```

> **v3.1 명제**
>
> ### 중개인이 가장 자주 만들고, 가장 자주 남에게 보내는 물건을 우리가 만든다. 그 물건이 돌아다니는 경로가 곧 우리의 관측 레이어가 된다.

# PART 1. 전략 재정렬

### IM을 중심축으로 옮긴다

## 1.1 IM이 왜 수임서보다 강한 쐐기인가

| 기준 | 수임 제안서 | IM (투자설명서) |
|---|---|---|
| 제작 빈도 | 딜당 1회 · 파워중개인은 거의 0 | **딜당 3~5회 (초안 → 가격조정 → 매수자별)** |
| 수신자 | 매도인 1인 | **매수 후보 다수 + 매수자 내부 의사결정자** |
| 품질 비교 | 비교 대상이 없음 | **대형 운용사 IM과 즉시 비교됨** |
| 시간 소요 | 1~2시간 | **4~8시간, 길면 이틀** |
| 도입 효과 체감 | 수임 성공 여부로만 확인 — 지연 피드백 | **완성본을 본 즉시 확인 — 즉시 피드백** |
| 습관 형성 | 어려움 (빈도 낮음) | **용이 (매 딜마다 반복)** |

> **핵심**
>
> 쐐기 제품의 조건은 "가장 아픈 문제"가 아니라 "가장 자주 아픈 문제"입니다. 수임은 가끔 아프고, IM은 매번 아픕니다.
> 그리고 IM은 결과물의 품질 차이가 눈으로 즉시 보입니다. 데모에서 감탄이 나오는 제품이 도입 전환율이 높습니다.

## 1.2 4루프 재편

### v3.0 구조

```
   매일 앵커 루프  →  수임 루프  →  딜 자산화 루프  →  네트워크 루프
                               [ 관측 레이어 ]
                     진입점 = 보수약정 서명 (딜당 1회)
```

### v3.1 구조

```
   제작 루프          배포 루프          자산화 루프        네트워크 루프
   (IM Studio)   →   (발송·추적)   →   (결과 기록)   →   (조직 지식)

                        [ 관측 레이어 ]
              진입점 = IM 발행 (딜당 3~5회) + 결과 기록
```

| 루프 | 무엇을 하는가 | 산출물 | 관측되는 것 |
|---|---|---|---|
| 제작 | 온톨로지 슬롯 입력 → 자동 조판 | PPTX / PDF / 링크 | 발행 시각 · 버전 · 자료등급 |
| 배포 | 매수 후보에게 발송 · QR 유입 | 단축링크 · grant | 열람 · 체류 · 상세 요청 |
| 자산화 | 딜 종료 시 결과 1클릭 기록 | 성사 / 무산 / 보류 + 사유 | 가격 · 기간 · 무산 사유 |
| 네트워크 | 조직 단위 익명 집계 | 권역 통계 (N≥5) | 성사율이 높은 IM 구성 |

## 1.3 수임서의 재배치 — 삭제가 아니라 파생물로

수임 제안서를 없애지 않습니다. 비용 구조를 바꿉니다.

1. 중개인이 IM을 만들면, 그 데이터로 수임 제안서가 자동 생성됩니다. 추가 입력은 0입니다.
2. 파워중개인은 쓰지 않으면 그만입니다. 중하위 중개인은 공짜로 얻습니다.
3. 개발비는 거의 발생하지 않습니다. 같은 슬롯을 쓰는 다른 템플릿 1종일 뿐입니다.

> **전속중개 정기보고는 유지**
>
> 수임 루프에서 유일하게 지켜야 할 것은 전속중개의 법정 정기보고 의무 자동화입니다.
> 이것은 수임 경쟁 도구가 아니라, 이미 수임한 딜에서 2주마다 강제로 발생하는 접점입니다. 의무를 제품 가치로 전환하는 장치이므로 P1에 남깁니다.

## 1.4 파일 배포 ↔ 관측 레이어 딜레마

이번 개정에서 가장 중요한 설계 결정입니다. 파일을 내주면 추적이 끊기고, 추적이 끊기면 v3.0의 학습 구조 전체가 무너집니다. 세 가지로 풉니다.

### 해법 ① — 파일을 막지 말고, 파일에 관측을 심는다

- 모든 PPTX·PDF 페이지 하단에 딜 단축링크와 QR을 자동 삽입합니다.
- "최신 임대차 현황 확인", "호실별 상세" 같은 실질 유인을 링크 뒤에 배치합니다. 파일은 발행 시점 스냅샷이고, 링크는 현재 상태입니다.
- 결과적으로 파일이 3차·4차로 전달될수록 링크 유입이 늘어납니다. **파일 확산이 관측 축소가 아니라 관측 확대가 되도록 부호를 뒤집습니다.**

### 해법 ② — 관측 진입점을 서명에서 발행으로 옮긴다

| 구분 | v3.0 | v3.1 |
|---|---|---|
| 진입 이벤트 | 보수약정 서명 | IM 발행 (publish) |
| 발생 빈도 | 딜당 1회 | **딜당 3~5회 (버전마다)** |
| 발생 조건 | 수임 성공 건에만 | **모든 딜 (수임 실패 건 포함)** |
| 결과 기록 | 별도 입력 화면 | **IM 아카이브 시 1클릭 — "결과는?"** |

IM v1(초안) → v2(가격 조정) → v3(특정 매수자용)의 이력이 그대로 딜 진행 로그가 됩니다. 별도의 CRM 입력을 요구하지 않고 관측이 쌓입니다.

### 해법 ③ — Basic은 파일 자유, Pro는 링크 우선

| 구분 | Basic | Pro |
|---|---|---|
| 성격 | 1차 배포용 티저 | NDA 후 지정 열람 |
| 정보 수준 | 밴딩 적용 · 재식별 게이트 통과 | 정밀값 · 렌트롤 전체 · 권리관계 |
| 파일 배포 | **자유 — 제한 없음** | 링크 우선, grant 승인 시 워터마크본만 |
| 유출 시 피해 | 제한적 (애초에 밴딩됨) | 워터마크로 출처 특정 · 억제 |

> **왜 이 배분이 요구를 100% 수용하는가**
>
> 파워중개인이 "파일로 달라"고 하는 대부분의 상황은 1차 배포 단계입니다. 그 단계가 Basic입니다.
> Pro는 애초에 소수의 신원 확인된 매수자에게만 가므로, 링크 우선 정책이 실무를 불편하게 하지 않습니다.
> 즉 통제를 포기하지 않으면서 요구를 전부 들어줄 수 있습니다.

## 1.5 방어 가능성 — PPT 생성기는 누구나 만든다

정직하게 말해, 슬라이드에 데이터를 채워 넣는 도구 자체는 해자가 아닙니다. 해자는 다섯 겹입니다.

| # | 요소 | 왜 모방이 어려운가 |
|---|---|---|
| 1 | 온톨로지 70슬롯 + 공부 자동수집 | 입력 부담이 경쟁 대비 크게 낮습니다. 건축물대장·토지이음·공시지가를 자동 인출하므로 중개인이 채울 칸이 적습니다. |
| 2 | provenance 4-tier 표기 | 대형 운용사 IM에도 수치 출처를 항목별로 명시하는 사례는 드뭅니다. 신뢰 장치이자 우리의 시각적 서명입니다. |
| 3 | 아키타입 규칙 엔진 | 단순히 칸을 채우는 것이 아니라 "이 물건은 밸류애드형"이라는 서사를 자동 생성합니다. 판정 근거까지 문장화합니다. |
| 4 | JS 400명 딜 데이터 | N=23 같은 권역 집합 통계는 개인 중개인이 만들 수 없습니다. 조직 규모가 있어야 성립합니다. |
| 5 | **성사·무산 관측 축적** | **어떤 IM 구성이 성사율이 높은지 학습합니다. 시간이 지날수록 강해지는 유일한 항목이며, 진짜 해자입니다.** |

> **순서가 중요합니다**
>
> 1~3은 6개월 내 만들 수 있고, 6~12개월이면 모방 가능합니다.
> 4~5는 시간과 조직 규모가 필요합니다. 그래서 초기 100인 확보가 기술 개발보다 중요합니다.
> IM Studio는 4~5로 가는 입장권입니다. 그 자체가 목적이 아닙니다.

# PART 2. IM Studio

### "잘 디자인된"을 공학적으로 정의한다

## 2.1 품질을 결정하는 6요소

"예쁘게 만들어 달라"는 요구를 개발 스코프로 바꾸려면, 무엇이 품질을 만드는지 분해해야 합니다. 슬라이드에 데이터를 밀어 넣는 코드는 반나절이면 짜지만, 그 결과물은 쓸 수 없습니다.

| # | 요소 | 없으면 무슨 일이 벌어지는가 |
|---|---|---|
| 1 | 레이아웃 자동 선택 | 호실 4개짜리 물건과 20개짜리 물건에 같은 표를 쓰면, 한쪽은 텅 비고 한쪽은 넘칩니다. |
| 2 | 오버플로 제어 | 한글은 물건마다 글자 수 편차가 큽니다. 제어가 없으면 제목이 잘리거나 상자를 뚫고 나갑니다. |
| 3 | 차트 렌더링 원칙 | 차트를 이미지로 구우면 중개인이 숫자 하나를 못 고칩니다. 그 순간 도구를 신뢰하지 않습니다. |
| 4 | 이미지 파이프라인 | 지도와 사진이 없으면 아무리 조판이 좋아도 초라해 보입니다. 반대로 아무 사진이나 넣으면 아마추어처럼 보입니다. |
| 5 | 편집 가능성 | 협상 국면마다 숫자가 바뀝니다. 고칠 수 없는 파일은 한 번 쓰고 버려집니다. |
| 6 | 품질 게이트 | 한 건이라도 깨진 자료가 매수자에게 나가면, 그 중개인은 다시 쓰지 않습니다. |

## 2.2 레이아웃 선택 엔진

데이터의 형태에 따라 슬라이드 구성을 규칙으로 선택합니다. 첨부 샘플에 실제로 적용된 규칙들입니다.

| 코드 | 조건 | 동작 |
|---|---|---|
| L01 | 호실 수 ≤ 6 | 렌트롤 단일 표 1페이지 |
| L01 | 호실 수 7~12 | 렌트롤 표 + 만기 구조 차트 2페이지 분할 |
| L02 | 아키타입 = VALUE_ADD | 밸류애드 실행 계획 슬라이드 편성 |
| L02 | 아키타입 = CORE_STABLE | 밸류애드 슬라이드를 임대 안정성 슬라이드로 교체 |
| L03 | 사진 0장 | 위치 개념도 · 층별 다이어그램 · 차트 중심 레이아웃 |
| L03 | 사진 3장 이상 | 하프블리드 표지 + 갤러리 슬라이드 추가 |
| L04 | 자료등급 B 이하 | **DCF · 민감도 슬라이드 억제 + 사유 문구 삽입 (제약 C11)** |
| L05 | 공실 = 0 | 임대 안정성 · WALT 강조 프레이밍 |
| L05 | 공실 > 0 | 개선 여지 프레이밍 + Cap Rate 개선 시뮬레이션 |
| L06 | Cap Rate < 조달금리 | **역레버리지 경고 블록 강제 삽입 — 중개인이 제거할 수 없음** |
| L07 | 티어 = Basic | 전 수치 밴딩 · 재식별 게이트 검사 |
| L07 | 티어 = Pro | 정밀값 + 워터마크 + grant 헤더 |

> **L06이 핵심입니다**
>
> 중개인이 불리한 사실을 빼고 싶어도 뺄 수 없게 만드는 규칙입니다.
> 매수자가 나중에 발견하면 딜이 깨지지만, 먼저 밝히면 협상 조건이 됩니다. 이 규칙은 중개인을 제약하는 것이 아니라 보호합니다.

## 2.3 오버플로 제어 — 한글 특유의 문제

같은 슬롯이라도 "역삼동 근린생활시설"(11자)과 "강남구 논현동 업무시설 및 근린생활시설"(21자)은 폭이 두 배 가까이 차이 납니다. 영문 템플릿을 그대로 쓰면 여기서 무너집니다.

### 4단계 대응

1. 슬롯별 최대 글자수를 정의합니다. (제목 24자 / 부제 40자 / 콜아웃 본문 120자 등)
2. 초과 시 폰트를 3단계로 축소합니다. (100% → 92% → 85%)
3. 그래도 초과하면 레이아웃을 분기합니다. (2단 → 1단, 또는 다음 슬라이드로 분할)
4. 최후 수단으로 말줄임 처리하고 "상세는 링크 참조"를 붙입니다. 이 경우는 품질 게이트에서 경고로 표시됩니다.

> **폰트 정책**
>
> 본문·수치 모두 맑은 고딕으로 고정합니다. Windows·macOS 양쪽 Office에서 안전하게 표시되고, 폭 예측이 가능해 오버플로 계산이 신뢰할 만합니다.
> 멋을 위해 특수 폰트를 쓰면 중개인의 PC에서 대체 폰트로 바뀌며 레이아웃이 깨집니다. 이 위험을 감수할 이유가 없습니다.

## 2.4 차트 렌더링 원칙

원칙은 하나입니다. — **이미지로 굽지 않는다.**

| 구분 | 방식 | 해당 차트 |
|---|---|---|
| PowerPoint 네이티브 차트 | OOXML 차트 객체로 삽입 | 만기 구조 막대 · 업종 믹스 도넛 · 층별 단가 막대 · Cap Rate 벤치마크 · LTV별 CoC 선 · 10년 현금흐름 막대 |
| 도형 조합 | 네이티브 도형으로 직접 조판 | NOI 워터폴 · 층별 스택 다이어그램 · 위치 개념도 · 민감도 히트맵 · 용적률 여유 게이지 |
| ~~이미지~~ | **사용하지 않음** | 사진 · 실제 지도 타일에 한정 |

워터폴과 히트맵은 PowerPoint에 네이티브 형태가 없습니다. 이미지로 굽는 대신 도형을 계산해 배치하면, 중개인이 색상과 위치를 직접 조정할 수 있습니다. 첨부 샘플의 NOI 워터폴이 그 방식으로 만들어졌습니다.

## 2.5 이미지 파이프라인 — 가장 큰 격차 요인

> **먼저 밝혀 둘 것**
>
> 첨부한 샘플 2종에는 건물 사진이 한 장도 없습니다. 이것은 누락이 아니라 의도된 설계입니다.
> 사진이 없어도 성립하는 레이아웃을 먼저 만들어야, 사진을 못 구한 물건에서도 품질이 유지됩니다. 사진에 의존하는 템플릿은 절반의 딜에서 초라해집니다.

| 대상 | 처리 | 단계별 정책 |
|---|---|---|
| 지도 | 정적 지도 API + 커스텀 스타일 + 반경 오버레이 | Basic — 반경 개념도만 (재식별 게이트) / Pro — 실제 지도 + 주변 시설 |
| 건물 사진 | 업로드 → 자동 크롭(16:9) → 톤 보정 → 간판·차량번호 마스킹(선택) | 0장 / 1~2장 / 3장 이상 세 가지 레이아웃 분기 (L03) |
| 도면 | 건축물 현황도 PDF → 벡터 추출 → 층별 다이어그램 생성 | M3 이후 · 초기에는 층별 스택 다이어그램으로 대체 |
| 로고 · 서명 | 조직 브랜드 마스터에서 인출 | 전 페이지 자동 적용 |

## 2.6 편집 가능성 — 우리가 만든 파일을 중개인이 고칠 수 있어야 한다

중개인은 협상 국면마다 숫자를 바꾸고, 특정 매수자를 위해 한 장을 덧붙입니다. 고칠 수 없는 파일은 한 번 쓰고 버려집니다.

- 텍스트박스 · 표 · 도형 · 차트를 전부 네이티브 OOXML로 출력합니다.
- 슬라이드 삭제 · 순서 변경 · 텍스트 수정이 PowerPoint에서 그대로 됩니다.
- 단, 규칙 L06으로 삽입된 경고 블록 등 일부 필수 요소는 재발행 시 자동 복원됩니다. 파일에서 지우는 것은 막지 않되, 시스템 기록에는 원본이 남습니다.

> **수정률은 제품 지표입니다**
>
> 중개인이 export 후 얼마나 고치는지를 추적합니다.
> 수정률이 30%를 넘으면 그것은 사용자 취향의 문제가 아니라 우리 템플릿이 현장과 맞지 않는다는 신호입니다. 재설계 트리거로 삼습니다.

## 2.7 발행 전 품질 게이트

아홉 가지 자동 검사를 통과해야 발행됩니다. 하나라도 실패하면 발행이 차단되고, 실패 사유와 수정 위치가 제시됩니다.

| 코드 | 검사 | 실패 시 |
|---|---|---|
| G1 | 텍스트 오버플로 0건 | 해당 슬라이드·슬롯 지목 + 축약 제안 |
| G2 | 빈 플레이스홀더 0건 | 미입력 슬롯 목록 제시 |
| G3 | 필수 면책 문구 존재 (티어별) | 누락 문구 자동 삽입 후 확인 요청 |
| G4 | provenance 배지 누락 0건 | 출처 미지정 수치 슬롯 지목 |
| G5 | 밴딩 정책 준수 | Basic에 정밀값이 노출된 위치 지목 |
| G6 | 재식별 게이트 통과 (Basic) | 후보 필지 수가 임계 미만이면 발행 차단 |
| G7 | 제약 C01~C12 검증 | Cap Rate 정합 · 자본구조 역전 등 위반 항목 표시 |
| G8 | 워터마크 적용 (Pro) | grant 미지정 시 Pro 발행 불가 |
| G9 | QR · 단축링크 삽입 | 딜 링크 미생성 시 자동 생성 |

> **이 게이트가 제품의 진짜 차별점입니다**
>
> 경쟁 도구는 "빨리 만들어 준다"까지입니다. 잘못된 자료도 빨리 만들어 줍니다.
> CREDEAL은 "틀린 자료는 못 나가게 한다"까지 갑니다. 중개인이 실수로 매수자에게 잘못된 수치를 보내는 사고를 구조적으로 막습니다.

# PART 5. 사업 모델 조정

### IM을 중심에 두면 과금도 달라진다

## 5.1 과금 구조

| 플랜 | 월 요금 | 포함 | 대상 |
|---|---|---|---|
| Standard | 70,000원 | Basic IM 무제한 · Pro IM 월 2건 · PDF · 링크 · 발행 이력 | 일반 중개인 |
| **Pro** | **120,000원** | Pro IM 무제한 · 조직 브랜드 템플릿 · 배포 추적 상세 · 우선 지원 | 파워중개인 |
| 초과분 | 건당 30,000원 | Standard의 Pro IM 3건째부터 | — |

### 100인 도달 시 월 매출

```
   Standard  70명 x 70,000원   =  4,900,000원
   Pro       30명 x 120,000원  =  3,600,000원
   ─────────────────────────────────────────
   월 매출                        8,500,000원
   연 환산                      102,000,000원

   v3.0 가정 (100명 x 70,000원)  84,000,000원
   증가                          +21%
```

> **Basic을 무제한으로 두는 이유**
>
> 건당 과금은 사용을 억제합니다. 우리에게 필요한 것은 매출이 아니라 습관과 관측 데이터입니다.
> Basic IM을 많이 만들수록 발행 이력이 쌓이고, 그 데이터가 해자를 만듭니다. 초기에는 사용량을 사는 것이 옳습니다.

## 5.2 도입 훅 — "첫 딜 IM 무료 제작"

중개인에게 도구를 쓰라고 설득하는 대신, 완성품을 먼저 보여줍니다.

1. 중개인이 등기부 · 건축물대장 · 임대차 내역만 전달합니다.
2. 우리가 IM Basic 또는 Pro를 완성해 돌려드립니다.
3. 중개인은 그 자료를 실제 매수자에게 발송합니다.
4. 두 번째 딜부터 직접 만들도록 안내합니다.

| 구분 | 초기 (도구 미완성) | 도구 완성 후 |
|---|---|---|
| 건당 소요 | 약 1시간 (수동 개입) | 약 15분 |
| 베타 10인 | 10시간 | 2.5시간 |
| 확산 100인 | 100시간 (5개월 분산 시 월 20시간) | 25시간 |

> **왜 이 훅이 강한가**
>
> "쓰면 좋아집니다"는 설득이지만, 완성된 자료를 손에 쥐여 주는 것은 증명입니다.
> 자기가 만든 IM보다 나은 결과물을 본 중개인은, 다음 딜에서 스스로 도구를 엽니다. 이 순간이 도입의 실제 전환점입니다.

## 5.3 프리미엄 애드온

IM Studio가 자리 잡으면 전문가 마켓플레이스(P1-3)와 자연스럽게 연결됩니다.

| 서비스 | 가격 (참고) | 구조 |
|---|---|---|
| 전문 디자이너 리터치 1건 | 150,000원 | 외부 디자이너 연결 · 플랫폼은 중개 수수료 15~20%만 취득 |
| 실측 도면화 | 300,000원 | 건축사 연결 |
| 건물 · 드론 촬영 | 250,000원 | 촬영업체 연결 |

> **수수료 구조를 유지하는 이유**
>
> 변호사 · 세무사 등 자격사 소개료 규제를 피하기 위해, 플랫폼은 자격 업무의 알선 대가를 받지 않는 구조를 유지합니다.
> 디자이너 · 촬영업체는 자격사가 아니므로 중개 수수료 취득에 제약이 적으나, 자격사가 관여하는 항목(도면화 등)은 별도 검토가 필요합니다.

# 부록 A. 이번 개정에서 정정한 수치

샘플 제작 과정에서 기존 시연 자료의 오류 3건을 발견해 정정했습니다. 첨부 PPTX에는 정정된 값이 반영되어 있습니다.

## A-1 근저당 표기 모순 (중요)

| 항목 | 기존 (오류) | 정정 |
|---|---|---|
| 선순위 근저당 채권최고액 | ~~80억대~~ | **96억원** |
| 매도인 실 대출잔액 | ~~104.5억 (매도인 고지)~~ | **약 80억원 (잔금 시 상환·말소)** |
| 매수자 신규 대출 | (구분 없음) | **104.5억 (LTV 55% 가정)** |

두 가지 오류가 겹쳐 있었습니다. 첫째, 채권최고액이 실 대출잔액보다 작은 것은 성립하지 않습니다(통상 원금의 120% 설정). 둘째, 104.5억은 매수자의 신규 대출 가정치이지 매도인의 기존 대출이 아닙니다. 두 주체의 부채를 하나의 표에 섞어 놓은 것이 원인이었습니다.

> **정정 후 검증**
>
> - 채권최고액 96억 = 실 잔액 80억 × 1.2 — 성립
> - 자본구조 검증 C04 : 매수자 대출 104.5억 + 승계 보증금 10.5억 = 115억 < 매입가 190억 × 1.1 = 209억 — 통과

## A-2 비교사례 평당가 계산 오차

논현동 C 사례의 평당가를 1억 415만원으로 표기했으나, 182억 ÷ 174.8평 = **1억 412만원**이 정확합니다. 첨부 자료에 반영했습니다.

## A-3 자료등급 표기 일관화

Basic은 B등급(충족률 71%), Pro는 A등급(89%)으로 문서 간 표기를 통일했습니다. Basic에서 DCF·민감도 분석을 억제하는 근거(제약 C11 — A등급 확정 자료에서만 제공)를 슬라이드에 명시했습니다.
