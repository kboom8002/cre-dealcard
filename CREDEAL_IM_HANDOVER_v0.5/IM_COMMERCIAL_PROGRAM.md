## §1 목표

**중개인이 충분한 입력을 제공했을 때, 사람이 손댈 필요 없이 상용 품질 IM이 나오는 것.**

네 가지를 동시에 만족해야 합니다.

| 축 | 뜻 | 이 프로그램에서 |
|---|---|---|
| **오류 없음** | 틀린 숫자가 나가지 않는다 | 수치 동일성 시험 · 게이트 · 교차검증 |
| **정합성** | 같은 규칙이 어디서나 같게 판정된다 | SSoT 레지스트리 11종 · 코드 네임스페이스 정리 |
| **적응성** | 입력 수준에 따라 유연하게 낸다 | L×P 이중 해상도 · 블록 게이팅 · 프리셋 |
| **문체·디자인** | 사람이 만든 것처럼 보인다 | A/B등급 플레이북 · 렌더 회귀 · 사람 심사 |

세 번째와 네 번째가 서로 당깁니다. 유연하게 만들수록 밋밋해지기 쉽습니다. **그래서 상용 기준선을 A/B등급으로 올려 잡았습니다** — 값이 다 있는 상태를 기본으로 놓고 잘 쓰는 데 집중합니다.

## §2 전제 — 어디까지가 범위인가

### 2.1 입력 수준

```
상용 기준선   L ≥ R2 · P ≥ P2   (등급 A/B)
내부 검토용   그 미만            (등급 C/D · 워터마크)
```

| 축 | 단계 | 필요 입력 | 누가 |
|---|---|---|---|
| L | R1 | 호실·업종·보증금·월세·만료일·상태 | 중개인 |
| L | **R2** | + 임대면적·적용 법령·**관리비**·**계약 시작일** | 중개인 |
| P | P1 | 지번 | 중개인 |
| P | **P2** | + 대지면적·연면적·용도지역·공시지가 | **공공 자동** |

**실질 관문은 L축 R2입니다.** P2는 지번 하나로 자동으로 채워집니다. 관리비와 계약 시작일 두 필드가 B와 A를 가릅니다.

### 2.2 범위

| 안 | 밖 |
|---|---|
| 수익형 포스처 | 개발형·운영형·사옥형·Trading (D23 예정) |
| 단일 필지 | 다필지 (차단 후 수기) |
| 일반 건물 | 구분등기 (대지 평당가 미산출) |
| 모바일·PPTX·PDF | 인쇄 제본 · 이메일 템플릿 |
| 30억~500억 주력 대역 | 20억 미만 |

**다필지·구분등기를 반쯤 지원하지 않는 이유**는 합산값으로 교차검증이 통과해 버려서 틀린 값이 조용히 나가기 때문입니다. 차단이 조용한 오답보다 낫습니다.

## §10 이 프로그램이 하지 않는 것

솔직하게 적어 둡니다.

- **비수익형 포스처** — 개발형·운영형은 별도 프로그램입니다. 다만 레지스트리·계약·이미지·품질 게이트는 포스처 중립으로 설계했으므로 두 번째 시스템을 만들지는 않습니다.
- **LLM 카피 품질의 자동 판정** — 규칙으로 "어색함"을 잡을 수 없습니다. 사람 심사 5항이 유일한 장치입니다.
- **자동 검출 모델의 정확도 보증** — FR22는 편의 기능입니다. 방어선은 중개인 확인(FR20)입니다.
- **기발행 IM의 소급 정정** — 가정값이 바뀌어도 이미 나간 IM은 그대로 둡니다. 90일 이내 건만 재발행 대상으로 표시합니다.
