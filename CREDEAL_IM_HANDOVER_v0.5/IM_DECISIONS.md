## D1. PDF 출력 경로

**맥락** — PPTX를 LibreOffice로 변환할지, 같은 계획에서 PDF를 직접 뽑을지.

**결정** — **직접 렌더**. `renderPdf(plan, core)`가 `renderPptx`와 같은 `RenderPlan`을 받아 독립적으로 그립니다. 변환 경로는 쓰지 않습니다.

**근거** — 변환은 서버 폰트·자간·줄바꿈 엔진이 클라이언트와 달라 텍스트 위치가 어긋납니다. 이 세션에서 렌더 검증에 LibreOffice를 썼을 때도 원본 PPTX와 줄바꿈이 달라졌습니다. **v4 PDF의 결함 중 일부가 변환 단계에서 생겼을 가능성**이 있는데, 변환을 쓰는 한 이것을 배제할 수 없습니다. 무엇보다 G01(텍스트 오버플로 0건)을 PPTX에서 통과시켜도 PDF에서 다시 깨지면 게이트가 무의미해집니다.

**되돌림 조건** — 직접 렌더 구현이 4주를 넘거나, PDF 전용 요구(전자서명·PDF/A)가 생기는 경우.

**영향** — `im-render.d.ts` `renderPdf` 구현 · G01을 산출물별로 각각 실행 · 스프린트 2.

## D2. 폰트 임베딩·대체

**맥락** — 수신자 PC에 폰트가 없으면 줄바꿈이 무너집니다. 정본은 PPTX 45자·모바일 40자를 규정하는데, 이 기준은 특정 폰트의 자폭을 전제합니다.

**결정** — **PPTX에 서브셋 임베딩**. 폴백 체인은 `Pretendard → Noto Sans KR → Malgun Gothic → sans-serif`. 임베딩 불가 시 **발행을 막지 않고 경고**하되, 자폭이 가장 넓은 폴백(Malgun Gothic) 기준으로 줄바꿈을 계산합니다.

**근거** — 가장 넓은 폰트로 재면 어떤 폴백에서도 넘치지 않습니다. 반대로 가장 좁은 폰트로 재면 폴백 시 반드시 넘칩니다. 안전한 쪽으로 틀리게 만드는 것이 규칙의 일입니다.

**되돌림 조건** — 라이선스 확인 결과 임베딩이 불가하거나, Malgun 기준 계산으로 지면 낭비가 15%를 넘는 경우.

**영향** — `fitText()`가 폴백 자폭표를 참조 · 폰트 라이선스 확인 필요(§확인 필요 1) · 스프린트 2.

## D3. 이미지 최소 해상도

**맥락** — 규격이 없었습니다.

**결정** — 슬롯별 하한을 `im.image.yaml`에 못박습니다. 표지 **장변 2000px · 단변 1400px**, 일반 슬롯 **장변 1600px · 단변 1150px**, 캡처(지도·지적도) **장변 1400px**. 미달 시 **경고**(IMGQ01)로 처리하고 대체 슬롯을 찾습니다. 차단하지 않습니다.

**근거** — 표지 상자는 8.20 × 7.50인치입니다. 단변 1400px이면 **1400 ÷ 7.5 = 187dpi**로 인쇄 배포에 견딥니다.
**실측** — 양평동 `hero.jpg`는 964×894px입니다. 표지에 넣으면 **964 ÷ 8.20 = 118dpi**로 흐립니다. 당산동 `hero.jpg`는 1800×1350px로 크롭 후 180dpi입니다 — 통과선 근처입니다.
차단하지 않는 이유는 사진이 없는 IM보다 흐린 사진이 있는 IM이 낫기 때문입니다. 다만 중개인에게는 재촬영을 안내합니다.

**되돌림 조건** — 인쇄 배포를 하지 않기로 하면 하한을 낮출 수 있습니다(화면 전용이면 150dpi로 충분).

**영향** — `im.image.yaml` slots · `resolvePhotos()` · 바텀시트 업로드 안내 · 스프린트 3.

## D4. EXIF 처리 시점

**맥락** — 업로드 시 제거할지 발행 시 제거할지.

**결정** — **업로드 직후**. 회전(Orientation) 정보를 픽셀에 적용한 **다음** 전 태그를 삭제합니다. 순서를 바꾸면 사진이 눕습니다.

**근거** — 발행 시 제거하면 그 사이 어떤 경로로든 원본이 나가면 좌표가 함께 나갑니다. public 단계는 주소를 동까지만 노출하는데 EXIF에 좌표가 남아 있으면 마스킹이 무의미합니다.
**실측** — 현재 `credeal/assets/` 17매는 PPTX에서 추출된 것이라 EXIF가 이미 없습니다(GPS 0건). 실제 중개인 업로드 경로에서는 확인된 바 없습니다.

**되돌림 조건** — 없음. 이 결정은 되돌리지 않습니다.

**영향** — `im.image.yaml` pipeline 2·3단계 · 스프린트 3.

## D5. 다필지 물건  ⛔ **철회 — D22-8 §3 참조**

> **2026-08-24 철회.** 아래 결정은 "다필지 처리가 설계돼 있지 않다"는 **틀린 전제**에서 나왔습니다.
> `CATALOG_SLOTS.md` §2.1(Parcel[]·exclusions) · `CATALOG_RULES.md` P01~P03·G12·L10~L12에
> 이미 설계돼 있었습니다. **차단이 아니라 정식 지원**으로 바꿉니다 (D5′).
> G25(다필지 차단)는 폐기합니다.

### D5′ (대체 결정) — 다필지 정식 지원

필지 배열을 1급 입력으로 받고 **유효 대지면적**으로 용적률을 계산합니다(P01·P02).

원래 우려는 *"합산값으로 돌리면 오차가 허용범위 안에 들어와 틀린 것이 통과한다"*였습니다. 답은 **X01~X04를 유효 면적으로 바꾸는 것이 아닙니다** — 건폐율·용적률은 대장 대지 기준으로 고시되므로 그렇게 하면 공부끼리의 항등식이 깨집니다. 답은 **X05(필지 면적 합 = 공부 대지면적)를 신설**해 합산 자체를 따로 재는 것입니다.

```
X01·X02·X04   대장 대지 기준 — 공부끼리의 검산
X05 (신설)     필지 합 = 공부 대지면적 · ±0.5%
P01·P02       유효 면적·유효 용적률 — 검산이 아니라 파생
G12           제척 합계 ≤ 대지 합계
```

구현: `credeal/parcel.py` · `credeal/ssot/im.parcel.yaml`.

<details><summary>철회된 원 결정 (기록 보존)</summary>



**맥락** — 교차검증 X01~X04가 단일 필지를 전제합니다. 다필지가 들어오면 지금 시스템은 **조용히 틀린 값**을 냅니다.

**결정** — **필지 배열을 1급 입력으로 받되, 1차 상용화 범위에서는 다필지를 차단**합니다. `parcels.length > 1`이면 G25(신설)가 발행을 막고 "다필지 물건은 수기 검토 후 발행" 안내를 냅니다.

**근거** — 반쯤 지원하는 것이 가장 나쁩니다. 대지면적은 단순 합산이 되지만 용적률은 필지별 용도지역이 다르면 합산할 수 없고, 공시지가는 필지별로 다르며, 제척(도로 편입)이 있으면 유효 대지면적이 또 달라집니다. **X01~X04를 합산값으로 돌리면 오차가 허용범위 안에 들어와 버려서 틀린 것이 통과합니다.** 차단이 조용한 오답보다 낫습니다.

**되돌림 조건** — 다필지 물건이 파이프라인의 10%를 넘으면 정식 지원으로 승격합니다.

**영향** — `IMInput.parcels: Parcel[]` 스키마 · G25 신설 · 스프린트 1. **빈도 확인 필요**(§확인 필요 3).

## D6. 구분등기 물건

**맥락** — RTMS가 집합건물의 대지면적을 주지 않습니다. 평당가를 무엇으로 낼지.

**결정** — 구분등기 물건은 **전유면적 기준 평당가만** 냅니다. 대지 평당가는 산출하지 않고 "구분등기 — 대지권 비율 기준 별도 확인" 문구로 대체합니다. 대지권 비율이 중개인 입력으로 들어오면 그때 대지 평당가를 엽니다.

**근거** — 한국 시장에서 "평당가"는 통상 대지 기준인데, 집합건물에서 대지면적을 모르는 채로 연면적 평당가를 "평당가"라고 쓰면 매수인이 오해합니다. 불변조건 2(basis 없는 수익률 금지)와 같은 논리입니다 — **분모를 모르면 비율을 쓰지 않습니다.**

**되돌림 조건** — 등기부 대지권 비율을 자동 조회할 수 있게 되면 자동 산출로 승격.

**영향** — `landPyeongPrice()`가 Absent를 반환 · 바텀시트에 `ownership_share` 필드 추가 · 스프린트 1.

## D7. 버전·재발행 diff

**맥락** — 가격 조정·임차 변동 시 어느 수치가 바뀌었는지 수신자에게 보일 것인가.

**결정** — **보입니다.** 재발행 IM 표지에 "제2판 · 2026-09-15 · 변경 3건" 배지를 넣고, 확인사항 면에 변경 요약표를 붙입니다. 이전 판은 **발행일로부터 3년** 보관합니다.

**근거** — 숨기면 신뢰를 잃습니다. 매수인이 두 판을 나란히 놓고 볼 수 있는데 시스템이 침묵하면 의도적 은폐로 보입니다. 반대로 먼저 밝히면 성실해 보입니다. 보관 3년은 원본 사진 보관 기간과 맞춘 것입니다.

**되돌림 조건** — 중개 현장에서 "가격 인하 이력이 협상력을 떨어뜨린다"는 반발이 다수면 **변경 항목만 표시하고 이전 값은 숨기는** 절충안으로 조정.

**영향** — `PublishRecord` · diff 산출기 · 확인사항 면 블록 추가 · 스프린트 5.

## D8. 공공 API 실패 시 동작

**맥락** — 차단할지 R1으로 강등할지.

**결정** — **강등 + 확인사항 이동**. P축을 조회 성공한 항목까지만 올리고, 실패한 항목은 결손으로 확인사항 면에 표시합니다. 발행은 막지 않습니다. **단, 용도지역 조회 실패는 예외** — 개발 규모를 산출하지 않습니다(불변조건 4).

**근거** — 차단하면 중개인이 손을 놓습니다. API 장애는 중개인 잘못이 아닌데 그 사람의 작업이 멈춥니다. 반면 없는 값을 기본값으로 채우면 틀린 결과가 확신 있게 나갑니다 — 잠원동 용적률 400% 일괄 적용이 그 사례이고 **분양수입이 1.6배 과대**했습니다. 강등은 이 둘 사이의 유일한 정답입니다.

**되돌림 조건** — 없음.

**영향** — `resolve()`가 부분 실패를 다룸 · `deficiencies()`에 API 실패 항목 추가 · 스프린트 1.

## D9. 캐시 TTL

**맥락** — 공부·공시지가·실거래를 같은 TTL로 둘 수 없습니다.

**결정**

| 자료 | TTL | 근거 |
|---|--:|---|
| 건축물대장·토지대장 | 30일 | 변동이 드물지만 증축·용도변경이 있습니다 |
| 토지이용계획 | 90일 | 도시계획 변경 주기 |
| 개별공시지가 | 다음 공시일까지 | 연 1회(5월 말) 고시 — 날짜 기준 만료 |
| 실거래(RTMS) | 7일 | 월 단위 등록이지만 소급 등록이 있습니다 |
| POI·교통 | 180일 | 역·정류장은 잘 바뀌지 않습니다 |
| 등기부 | **캐시하지 않음** | 권리 변동은 당일 반영되어야 합니다 |

**근거** — 등기부만 캐시 금지인 이유는 근저당 설정·말소가 IM의 결론을 바꾸기 때문입니다. F01(등기부 권리 변동)이 `critical`로 분류되어 grant를 자동 무효화하는 것과 같은 이유입니다.

**되돌림 조건** — API 호출 비용이 예산을 넘으면 실거래를 14일로 늘립니다.

**영향** — 캐시 계층 · `PublishRecord.registryVersions`에 조회일 포함 · 스프린트 1.

## D11. 모바일 Pro 단계 인증

**맥락** — 마스킹 3단계가 인증에 걸려 있는데 인증 방식이 미정이었습니다.

**결정** — **링크 + 휴대폰 본인확인 + NDA 전자동의** 3단입니다. `public`은 링크만으로 열립니다. `nda`는 휴대폰 인증 후 NDA 동의 화면을 통과해야 합니다. `pro`는 중개인이 개별 승인한 계정만 접근합니다.

**근거** — 이메일 인증은 대리 열람을 막지 못합니다. 휴대폰 본인확인은 국내에서 이미 표준이고 매수인이 거부감을 덜 느낍니다. pro를 자동화하지 않는 것은 실사 자료 접근이 중개 판단의 영역이기 때문입니다.

**되돌림 조건** — 휴대폰 인증 이탈률이 40%를 넘으면 `nda` 단계를 이메일 + NDA 동의로 완화.

**영향** — 인증 연동 · `Stage` 판정을 서버에서 강제(클라이언트 신뢰 금지) · 스프린트 4.

## D12. 비수익형 포스처

**맥락** — D19는 수익형 전용입니다. 픽스처는 이미 개발 2·운영 1이 있습니다.

**영향** — `im.pages.yaml`에 `scope: posture=income` 명시 · 스키마에 posture 분기 여지 확보 · 전 스프린트.

**맥락** — `CATALOG_RULES.md`가 "코드 신설·폐기는 반드시 이 문서에 먼저 등록" · "코드 재사용 금지"를 규정합니다. **그 규정이 네 번 지켜지지 않았습니다.**

C1이 가장 위험합니다. **같은 코드가 한쪽에서는 경고이고 한쪽에서는 차단입니다.** 어느 구현을 쓰느냐로 발행 가부가 갈립니다. C3의 네 번째는 이번 세션에 제가 만든 것이므로 제 잘못입니다.


### D14. 가정값을 코드에서 뺍니다

**맥락** — `ASSUMPTION_REGISTRY.md`(D4)가 21종을 잘 정리했으나 **표는 코드가 읽지 못합니다.** `core.py`의 `ASSUMED_LOAN_RATE`가 문서와 두 벌입니다.

**결정** — `im.assumptions.yaml`이 값의 정본입니다. D4는 근거 서술을 소유합니다. 코드는 `assumption('loanRateDefault')`로만 접근하고, **폐기된 키를 호출하면 예외를 던집니다.**

```python
ValueError: 폐기된 가정입니다: noiEstimateCoefficient — 근거 없음 · 문서·주석 전무
          · 대체 gross 계열만 산출
```

**근거** — 폐기 상수는 조용히 사라지면 누군가 다시 씁니다. **호출하면 왜 폐기됐는지와 무엇을 쓰라는지를 말해 주는 편**이 주석보다 강합니다.

## 확인 필요 — 제가 정할 수 없는 것

1. **폰트 라이선스** — Pretendard·Noto Sans KR의 PPTX 임베딩 및 상업 배포 허용 여부. D2가 여기 걸려 있습니다.
2. **지도 이용약관** — 지도·지적도 캡처의 상업적 재배포 범위. 확인 전까지 출처 표기를 반드시 넣습니다.
3. **구분등기 빈도** — 파이프라인에서 차지하는 비율. 10% 미만이면 D6의 차단 방침이 맞고, 그 이상이면 정식 지원으로 올려야 합니다. **다필지는 D5′로 이미 정식 지원이므로 이 지표의 대상이 아닙니다.**
4. **번호판·얼굴 검출을 자체 모델로 할지 외부 API로 할지** — 외부 API는 **마스킹 전 원본**이 밖으로 나갑니다. 그 사진에는 임차인 상호가 찍혀 있습니다.
5. **호텔 GOP 2배 산출 의혹** — `financials.ts:132` Opex 35%와 `financials.ts:421` GOP 마진 35%가 같습니다. Opex 35%면 GOP 마진이 65%가 되는데 업계 통상은 30~40%입니다. 운영형 착수 전에 확인이 필요합니다.
6. **comps 상한 300억의 근거** — `price-prediction.ts:77`에 주석이 없습니다. 주력 상단(B4 300~500억)이 통째로 막혀 있는데, 근거를 모른 채 풀면 다른 것이 깨질 수 있습니다.
