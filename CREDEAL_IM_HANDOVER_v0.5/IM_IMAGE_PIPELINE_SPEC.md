**문서번호** D22-2 · **버전** 1.0 · **작성일** 2026-08-24
**소유** 이 문서가 이미지 취득·품질·처리·발행의 정본입니다
**기계 판독** `credeal/ssot/im.image.yaml` · 마스킹 **대상**은 `im.masking.yaml` §images
**참조구현** `credeal/image_pipeline.py`

## §0 왜 이 문서가 생겼는가

불변조건 14는 *"물건명·법인명·임차인명은 대외 문서에 표기하지 않는다"*입니다.

지금까지 이 규칙은 **텍스트에만** 걸려 있었습니다. 검사기 `output_qa.py`도 텍스트만 읽습니다. 그래서 이런 일이 벌어졌습니다.

| | 텍스트 | 같은 장의 사진 |
|---|---|---|
| 당산동 1층 A호 | "약국" | 간판에 상호가 그대로 |
| 당산동 4층 | "주류판매" | 간판에 상호가 그대로 |

**가린 의미가 없습니다.** 그리고 차량 번호판과 보행자 얼굴은 층이 다른 문제입니다 — 임차인 동의로도 해소되지 않고, 개인정보 보호법이 걸립니다.

이 문서는 이미지를 **문서로 취급**합니다.

## §1 노출 단계별 규칙

`im.masking.yaml`의 3단계를 이미지에 적용합니다.

| 대상 | public | nda | pro | 조치 | 심각도 |
|---|:-:|:-:|:-:|---|:-:|
| 임차인 상호 간판 | 가림 | 가림 | 노출 | 블러 또는 크롭 | **차단** |
| 차량 번호판 | 가림 | 가림 | **가림** | 블러 | **차단** |
| 보행자 얼굴 | 가림 | 가림 | **가림** | 블러 | **차단** |
| EXIF 위치정보 | 제거 | 제거 | **제거** | 태그 삭제 | **차단** |
| 인접 건물 상호 | 판단 보류 | 노출 | 노출 | — | 경고 |

번호판·얼굴·EXIF가 pro 단계에서도 가려지는 이유는 **개인정보이지 거래정보가 아니기 때문**입니다. NDA를 맺어도 제3자의 개인정보를 넘길 근거는 되지 않습니다.

인접 건물 상호는 판단을 보류합니다. 본건 임차인이 아니므로 불변조건 14 대상은 아니지만, 상권 사진에서 경쟁 점포가 식별되는 것이 적절한지는 별개 문제입니다. **지금은 경고만 띄우고 중개인이 정합니다.**

## §2 해상도

### 2.1 판정은 화소가 아니라 실효 dpi로 합니다

같은 2000px 사진도 표지(8.20인치)에 넣으면 244dpi이고 갤러리(4.79인치)에 넣으면 417dpi입니다. **화소만 보면 판정이 어긋납니다.**

```
실효 dpi = cover-fit 크롭 후 상자를 채우는 픽셀 ÷ 상자 인치
```

| 종류 | 하한 | 근거 |
|---|--:|---|
| 사진 | **180dpi** | 슬라이드 인쇄 배포에 견디는 하한 |
| 캡처(지도·지적도) | **150dpi** | 선 위주라 낮은 값에서도 읽힙니다 |

`min_px`는 중개인에게 보여 줄 알기 쉬운 목표치일 뿐이고, **구속력은 실효 dpi에 있습니다.**

### 2.2 실측 — 현 에셋 17매

`python3 credeal/image_pipeline.py --audit`

```
17매 · 통과 14 · 미달 3

🔴 양평동 hero      964×894   → 표지 상자에서 118dpi  (하한 180)
🔴 양평동 map      1158×728   →           132dpi  (하한 150)
🔴 양평동 cadastre  984×820   →           139dpi  (하한 150)

⚠  당산동 hero     1800×1350  →           180dpi  ← 하한에 정확히 붙어 있습니다
⚠  당산동 map      1614×836   →           152dpi  ← 여유 2dpi
```

**미달 3매가 전부 양평동입니다.** 당산동은 통과하되 표지와 지도가 하한에 붙어 있어 여유가 없습니다 — 상자를 조금만 키우면 바로 미달로 떨어집니다.

### 2.3 미달 시 동작 — 차단하지 않습니다

```
① 같은 성격의 대체 슬롯을 찾습니다 (hero 미달 → front 사용)
② 대체가 없으면 그 슬롯을 비우고 "사진 미제출" 안내 상자를 넣습니다
③ 중개인 화면에는 "재촬영 권장 — 현재 118dpi, 권장 180dpi 이상" 을 띄웁니다
```

**차단하지 않는 이유** — 사진이 없는 IM보다 흐린 사진이 있는 IM이 낫습니다. 다만 조용히 넘어가지도 않습니다.

### 2.4 최소 장수

**외부 3장 + 내부 3장 = 6장**입니다. 미달이면 사진 갤러리 면을 렌더하지 않고 "촬영 후 보완" 안내로 대체합니다.

실측 — 당산동 13매(충족) · **양평동 4매(미달)**.

## §3 파이프라인 9단계

**순서를 바꾸지 않습니다.** 특히 2단계와 8단계 — EXIF 회전을 픽셀에 적용하기 전에 크롭하면 사진이 눕습니다.

| # | 단계 | 하는 일 | 실패 시 |
|--:|---|---|---|
| 1 | 수신 | 업로드 원본을 private 버킷에 보관 (3년) | 업로드 실패 |
| 2 | 회전 정규화 | EXIF Orientation을 픽셀에 적용 | — |
| 3 | **EXIF 제거** | 전 태그 삭제 (GPS 포함) | 처리 중단 |
| 4 | 자동 검출 | 번호판·얼굴 → 후보 영역 목록 | 5단계로 진행 |
| 5 | 상호 검출 | OCR → 임대 현황의 업종·상호와 대조 | 6단계로 진행 |
| 6 | **중개인 확인** | 검출 결과를 겹쳐 보여주고 추가·삭제·승인 | 발행 불가 |
| 7 | 마스킹 적용 | 가우시안 블러를 픽셀에 굽습니다 | 처리 중단 |
| 8 | 파생본 생성 | 슬롯별 cover-fit 크롭 + JPEG q88 | — |
| 9 | **발행 전 검사** | G20 — 미승인 이미지가 있으면 차단 | 발행 4xx |

### 3.1 4단계 — 재현율을 우선합니다

검출 모델의 목표는 **재현율 0.95**입니다. 정밀도가 아닙니다.

과검출은 중개인이 6단계에서 지우면 됩니다. **미검출은 그대로 새어 나갑니다.** 비대칭이 큰 문제에서는 시끄러운 쪽으로 틀리게 만듭니다.

### 3.2 6단계가 실질 방어선입니다

자동 검출 정확도는 100%가 아닙니다. OCR은 기울어진 간판, 손글씨, 로고형 상호를 자주 놓칩니다.

**사람이 마지막에 봅니다.** 6단계 승인 없이는 9단계에서 발행이 막힙니다.

### 3.3 7단계 — 되돌릴 수 없게 굽습니다

```python
patch = im.crop(box)
radius = max(4, int(min(r.w, r.h) * 0.08))       # 영역 단변의 8%
im.paste(patch.filter(ImageFilter.GaussianBlur(radius)), box)
```

**금지** — CSS 필터·오버레이 도형·SVG 마스크. 전부 원본이 파일에 남습니다. 받는 쪽에서 개발자 도구를 열거나 도형을 지우면 그대로 보입니다.

반경이 작으면 글자가 읽힙니다. 단변의 8%가 하한입니다.

### 3.4 8단계 — 크롭 기준점

세로로 자를 때 **상단 30% 지점**을 기준으로 삼습니다. 정중앙을 쓰면 건물 몸통이 아니라 하늘과 바닥이 반씩 남습니다.

> 표지를 풀블리드로 깔았다가 4:3 원본이 위아래로 잘려 건물 아랫부분이 사라진 적이 있습니다. 지금 표지가 좌우 분할인 것은 그 때문입니다.

## §4 저장

| 버킷 | 접근 | 노출 단계 |
|---|---|---|
| `original` | private | **없음** — pro 단계에서도 노출하지 않습니다 |
| `masked` | 서명 URL | nda · pro |
| `derived` | 서명 URL | public · nda · pro |

**파일명 규칙** — `{dealId}/{slot}/{sha256[:12]}.{ext}`

파일명에 물건명·주소·임차인명을 넣지 않습니다. URL은 로그·리퍼러·공유 링크를 타고 여기저기 남습니다.

### 4.1 감사 레코드

```json
{
  "dealId": "...",
  "slot": "hero",
  "sha256": "...",
  "maskedRegions": 3,
  "approvedBy": "broker:1024",
  "approvedAt": "2026-08-24T05:12:33Z",
  "pipelineVersion": "v1"
}
```

`approvedBy`는 사람 식별자입니다. **G20이 이것을 봅니다.** `pipelineVersion`이 바뀌면 재처리 대상이 됩니다 — 마스킹 규칙이 강화됐는데 옛 처리본이 그대로 나가면 안 됩니다.

## §5 게이트 G20 — 신설

```
G20  발행 이미지 전량에 마스킹 처리 이력 존재
     심각도: 차단
     불변조건: 14
     해소: 6단계 중개인 승인
```

```python
def gate_g20(used, approvals):
    fails = []
    for u in used:
        a = approvals.get(u['sha256'])
        if a is None:
            fails.append(f'G20 차단 slot={u["slot"]} resolve=마스킹 승인 필요')
        elif a.get('pipelineVersion') != PIPELINE_VERSION:
            fails.append(f'G20 차단 slot={u["slot"]} resolve=파이프라인 재처리 필요')
    return fails
```

**로그에 파일명·좌표·검출 내용을 담지 않습니다.** 슬롯 키와 해소 경로만 남깁니다.

G20은 `CATALOG_RULES.md`에 아직 등록되지 않았습니다(D22-1 §D13). 등록 PR이 선행되어야 합니다.

## §7 구현 순서

**스프린트 3**입니다. 앞선 두 스프린트에 의존하지 않으므로 **병렬 진행 가능**합니다.

```
1. 업로드 경로에 2·3단계 삽입 (EXIF)          ← 가장 싸고 즉시 효과
2. 저장 버킷 3분할 + 감사 레코드 스키마
3. 8단계 슬롯별 크롭 (기존 photo() 이식)
4. 6단계 중개인 확인 UI
5. G20 발행 게이트
6. 4·5단계 자동 검출 모델                     ← 가장 비쌈. 마지막
```

**6번 없이도 5번까지로 상용화가 가능합니다.** 중개인이 수동으로 영역을 지정하는 방식입니다. 자동 검출은 편의 기능이지 방어선이 아닙니다 — 방어선은 6단계입니다.
