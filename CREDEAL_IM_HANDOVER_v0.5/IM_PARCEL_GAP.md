## §2 왜 놓쳤는가 — 거버넌스 실패

이건 제 부주의만이 아니라 **문서 체계의 구조적 실패**이기도 합니다.

### 2.1 승계 문서가 승계하지 않았습니다

`IM_PRECISION_SPEC.md`가 계산식을 소유했습니다. 이 문서는 2026-08-23에 폐기됐습니다.

```
⛔ SUPERSEDED — 이 문서는 IM_SYSTEM_SSOT.md §5 + API_TYPE_CONTRACT.md 로
   대체되었습니다 (2026-08-23).
```

그런데 승계 문서 두 개에서 검색한 결과입니다.

```
IM_SYSTEM_SSOT.md     "제척" 0건 · "다필지" 0건 · "parcels" 0건
API_TYPE_CONTRACT.md  "제척" 0건 · "다필지" 0건 · "Exclusion" 0건
```

**대체한다고 선언만 하고 내용을 옮기지 않았습니다.** 폐기 문서에만 남은 규격은 아무도 읽지 않습니다.

### 2.2 소유 참조가 폐기 문서를 가리킵니다

`CATALOG_SLOTS.md`는 살아 있는 정본인데 이렇게 적혀 있습니다.

> 구조·원칙은 `ONTOLOGY_V0.3_SPEC.md`, **계산식은 `IM_PRECISION_SPEC.md`가 소유**합니다.

**폐기된 문서를 소유자로 가리키고 있습니다.** 슬롯 정의(`exclusions`)는 살아 있는데 그 값으로 무엇을 계산하는지는 폐기 문서에만 있습니다.

### 2.3 제 잘못 — 읽고도 지나쳤습니다

코드 네임스페이스를 정리하면서 `CATALOG_RULES.md`를 열었습니다. G 게이트 16종을 세고 C·L·M·F·S 코드군 표까지 봤습니다. **그러면서 P01~P03과 L10~L12를 지나쳤습니다.** 게이트만 찾고 있었기 때문입니다.

D22-0 §5에서 제가 직접 "소유표에 없는 정본은 정본이 아닙니다"라고 썼는데, 정작 소유표를 역방향으로 읽지 않았습니다 — **"이 규칙은 어디에 있나"만 보고 "이 문서의 규칙 중 내가 안 쓴 것은 무엇인가"를 보지 않았습니다.**

## §3 D22-1 §D5 철회

### 철회하는 결정

> **D5. 다필지 물건** — 필지 배열을 1급 입력으로 받되, 1차 상용화 범위에서는 다필지를 **차단**합니다. `parcels.length > 1`이면 G25가 발행을 막습니다.

### 철회 사유

그 결정의 근거는 *"반쯤 지원하는 것이 가장 나쁩니다. X01~X04를 합산값으로 돌리면 오차가 허용범위 안에 들어와 버려서 틀린 것이 통과합니다"*였습니다.

**논리 자체는 맞습니다.** 틀린 것은 전제입니다 — 저는 다필지 처리가 **설계돼 있지 않다**고 전제했습니다. 실제로는 필지 배열·제척·유효 면적·게이트·레이아웃까지 다 있었고, 없는 것은 구현뿐이었습니다.

### 새 결정 — D5′

**다필지를 정식 지원합니다.** 차단하지 않습니다.

```
필지 배열을 1급 입력으로 받습니다 (CATALOG_SLOTS §2.1).
유효 대지면적으로 용적률을 계산합니다 (P01·P02).
G12 로 제척 합계를 검증합니다.
X05 를 신설해 **필지 합 = 공부 대지면적**을 검산합니다 — 이것이 원래 우려의 답입니다.
X01·X02·X04 는 대장 기준을 유지합니다 (건폐율·용적률이 대장 기준으로 고시되므로).
필지가 2개 이상이면 필지 명세 면을 넣습니다 (L10).
```

G25(다필지 차단)는 **폐기**합니다. 대신 다필지 탐색에서 후보가 10개를 넘으면 자동 중단하고 사람이 고릅니다.

## §4 실측 — 12.5㎡가 사업 구조를 바꿉니다

`python3 credeal/parcel.py`

실제 CREDEAL 물건입니다. 잠원동 두원빌딩, 2필지.

```
필지                대장(㎡)   지분반영     제척      유효
잠원동 26-14         511.7    511.7     0.0    511.7
잠원동 26-16         104.4    104.4    12.5     91.9
                    └ 도시계획도로 저촉 12.5㎡ (용적률 산정 제외) · ●중개인
──────────────────────────────────────────────────────
P04 대장 합          616.1
P01 유효 대지         603.6
P03 제척 영향도        2.03%
```

용적률 산정 연면적 1,534㎡ 기준입니다.

| | 용적률 |
|---|--:|
| 대장 기준 | 249.0% |
| **P02 유효 기준** | **254.1%** |
| 차이 | **+5.2%p** |

**여기가 핵심입니다.**

```
🔴 한시 완화 임계 250% — 대장 기준 충족 · 유효 기준 이탈
```

"서울시 소규모 건축물 한시적 용적률 완화"는 **산정 용적률 250% 미만**을 조건으로 겁니다. 대장 면적으로 계산하면 249.0%로 충족인데, 제척 12.5㎡를 반영하면 254.1%로 **조건에서 벗어납니다.**

제척을 모르고 IM을 쓰면 **받을 수 없는 완화를 전제로 신축 규모와 분양수입을 제시**하게 됩니다. 원장 어디에도 틀린 숫자가 없는데 결론이 틀립니다.

> 제척 면적은 **API로 나오지 않습니다.** 토지이용계획도의 도시계획시설 저촉선을 읽어야 하고, 초기에는 중개인 입력(●중개인)으로 받아 관할 구청 확인 전까지 확인사항에 남깁니다.

## §5 토지이용계획 선택적 표시 (L12)

확인원에는 수십 항목이 찍힙니다. 다 보여주면 노이즈이고, **임의로 고르면 누락 책임이 생깁니다.**

### 5.1 규칙

```
매수 목적 5종 × 항목별 관련도 → high 본문 · medium 접기 · low 부록
🔴 relevance 와 무관하게 전체 목록은 항상 부록에 싣습니다.
```

고르는 것은 **강조**이지 **감춤**이 아닙니다. 이 구분이 법적 책임을 가릅니다.

### 5.2 실측 — 같은 물건, 다른 매수자

같은 7개 항목을 매수 목적만 바꿔 배치한 결과입니다.

| 목적 | 본문 | 접기 | 부록 |
|---|--:|--:|--:|
| 임대수익 | 2 | 3 | 7 |
| 개발 | 7 | 0 | 7 |

```
[임대수익] 본문 — 용도지역 · 토지거래허가구역
[개발]     본문 — 용도지역 · 정비구역 · 지구단위계획구역 ·
                도시계획시설 저촉 · 과밀억제권역 ·
                가로구역별 최고높이 제한구역 · 토지거래허가구역
```

임대수익 매수자에게 고도지구·정비구역은 접어 두고, 개발 매수자에게는 전부 앞에 냅니다. **토지거래허가구역만 목적과 무관하게 본문**입니다 — 거래 자체의 조건이기 때문입니다.

### 5.3 신설한 항목 3종

정본 매핑에 없던 것을 추가했습니다. 중개 현장에서 실제로 묻는 것들입니다.

| 항목 | 왜 |
|---|---|
| **정비구역** | 정비사업 진행 단계에 따라 처분 제한이 걸립니다 |
| **지구단위계획구역** | 획지·용도·높이 지침이 개별 필지에 직접 걸립니다 |
| **도시계획시설 저촉** | 제척의 원인입니다. 저촉이 있으면 L11이 함께 켜집니다 |

### 5.4 매핑에 없는 항목

**조용히 부록으로 내리지 않습니다.** 접기에 두고 `◇ 관련도 미등록`을 붙입니다. 모르는 것을 낮은 것으로 취급하면 그것이 누락입니다.

## §7A 새 규격이 곧바로 잡아낸 것 — 양평동은 3필지였습니다

§2A를 만들고 나서 알았습니다. **양평동은 단일 필지가 아닙니다.**

```
public_data.py:94   landSqm 518.70㎡  '3필지 합산'
덱 3면 카피          '3필지 합지 518.70㎡'
fixtures/yangpyeong.json   parcels 키 없음
```

지금까지 세 번의 검수를 통과했는데 아무도 못 봤습니다. **필지 개념이 없었기 때문에 물어볼 질문이 없었습니다.**

그대로 두면 L10이 꺼진 채 "단일 필지처럼" 나갑니다. 조용히 틀립니다. 그래서 픽스처에 이렇게 넣었습니다.

```json
"land": { "parcelCount": 3, "parcelsKnown": false, "ledgerAreaSqm": 518.70,
          "parcels": [] }
```

코어는 **필지 수만 알고 내역이 없으면 단일 필지로 오인하지 않고 결손으로 넘깁니다.**

```
확인사항 8건 (7건 → 8건)
· 필지 3개 합지 — 필지별 면적·제척 미확보
```

빈 배열을 그대로 두되 "모른다"를 말합니다. 불변조건 13입니다 — 결손은 사라지지 않고 확인사항으로 이동합니다.

> **규격이 생기면 없던 질문이 생깁니다.** 이 한 건은 §2A를 쓰지 않았으면 영영 안 보였을 것입니다.

---

## §8 배운 것 — 소유표를 역방향으로 읽습니다

지금까지 저는 소유표를 이렇게 썼습니다.

```
"금지어는 어느 문서가 소유하지?"  →  IM_STANDARD §6
```

이 방향으로만 읽으면 **내가 모르는 규칙은 영영 못 찾습니다.** 반대로도 읽어야 합니다.

```
"CATALOG_RULES 가 소유한 규칙 중 내 스펙이 안 쓰는 것은?"
  →  P01~P03 · L10~L15 · M 24종 · T-R 7종 …
```

D22-6에 티켓을 추가합니다.

> **FR34 · 정본 역방향 대조** — 살아 있는 정본 문서의 모든 규칙 코드를 열거하고, D19·D22가 쓰지 않는 것을 목록으로 냅니다. 안 쓰는 것마다 "의도적 범위 밖" 또는 "누락" 중 하나를 명시합니다. 그리고 **폐기 문서의 규격이 승계 문서에 실제로 옮겨졌는지** 대조합니다.

이 검사를 CI에 넣으면 이번 같은 일이 다시 생기지 않습니다.
