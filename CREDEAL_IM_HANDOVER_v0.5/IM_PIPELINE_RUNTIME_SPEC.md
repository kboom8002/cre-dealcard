> 규격은 "이런 IM이 나와야 한다"를 말하고, 이 문서는 **"120초 안에 7섹션 중 3개가

## 0. 왜 이 문서가 필요한가

레포에 **"시스템이 어떻게 도는가"를 적은 문서가 없었습니다.**

| 있던 것 | 없던 것 |
|---|---|
| 어떤 IM이 나와야 하는가 (D19 · D22) | 실패하면 무엇이 나오는가 |
| 무엇을 검사하는가 (`CATALOG_RULES` G·C) | 검사가 언제 도는가 |
| 무엇이 갭인가 (D23) | 정상 동작이 무엇인가 |
| 어떤 단계가 있는가 (현행 명세) | 단계 사이의 **계약** |

🔴 **계약이 없으면 각 단계가 앞 단계를 신뢰하는 방식이 제각각이 됩니다.**
어떤 단계는 `null` 을 받으면 기본값을 쓰고, 어떤 단계는 던지고, 어떤 단계는
빈 문자열을 렌더합니다. 평당가가 두 값으로 나온 사고도 결국 **어느 단계가
그 값을 확정하는지가 정해져 있지 않았기** 때문입니다.

## 1. 단계와 계약

```
① 메모 입력 ──▶ ② 슬롯 추출 ──▶ ③ 딜카드 ──▶ ④ 바텀시트 ──▶ ⑤ 등급
                                                                  │
                              ⑧ 발행 ◀── ⑦ 렌더 ◀── ⑥ 콘텐츠 생성 ◀┘
```

### 1.1 단계별 입출력 계약

| 단계 | 입력 | 출력 | 실패 시 |
|:-:|---|---|---|
| ① 메모 | 원문 텍스트 · 음성 · 저장 메모 | `RawMemo` (PII 마스킹 후) | 사용자에게 반환 |
| ② 추출 | `RawMemo` | `SlotDraft` + `ambiguous[]` | **부분 성공 허용** |
| ③ 딜카드 | `SlotDraft` + 지번 | `BuildingSSoT` (P축 확정) | 지번 실패 → ④로 진행 불가 |
| ④ 바텀시트 | `BuildingSSoT` | `IMInput` (L축 확정) | 중개인이 저장 못 함 |
| ⑤ 등급 | `IMInput` | `Grade` + `LxP` + 결손 목록 | **실패 없음** — 항상 등급이 나옵니다 |
| ⑥ 생성 | `IMInput` + `Grade` | `IMDoc` (섹션 배열) | §5 부분 복구 |
| ⑦ 렌더 | `IMDoc` + `RenderPlan` | pptx · html | §5 부분 복구 |
| ⑧ 발행 | 산출물 + `GateResult[]` | `PublishRecord` | 4xx + 사유 |

### 1.2 🔴 값이 확정되는 단계는 하나입니다

**같은 지표가 여러 단계에서 계산되면 반드시 갈립니다.**

| 값 | 확정 단계 | 이후 단계의 의무 |
|---|:-:|---|
| P축 슬롯 (필지·건축물·용도지역·접면·권리) | ③ | **읽기만** |
| L축 슬롯 (포스처별) | ④ | 읽기만 |
| 파생값 (유효 대지·유효 용적률·환산보증금·수익률·평당가) | **⑤** | 읽기만 |
| 등급 · 잠금 블록 | ⑤ | 읽기만 |
| 문장 | ⑥ | 수치를 **생성하지 않습니다** — 주입만 |
| 배치 · 자릿수 표기 | ⑦ | 값을 바꾸지 않습니다 |

> **⑥과 ⑦은 계산을 하지 않습니다.** 렌더러가 "이 값을 평으로 바꿔서 보여주자"
> 하는 순간 같은 지표가 두 값이 됩니다. 단위 변환도 ⑤에서 미리 계산해
> `IMDoc` 에 담습니다.
>
> 평당가가 한 면 15,933만원 · 다른 면 1억 5,923만원이었던 사고가 이 규칙의
> 근거입니다. 게이트 `G28`이 사후에 잡지만, **애초에 계산 지점을 하나로 두면
> 발생하지 않습니다.**

### 1.3 계약 위반 검출

```ts
// ⑥ 이후 단계에서 파생 계산을 금지합니다
export function assertNoDerivation(stage: Stage, op: string): void {
  if (stage >= Stage.Generate && DERIVING_OPS.has(op)) {
    throw new PipelineViolation('RT01',
      `${stage} 단계에서 파생 계산 금지 — ⑤ 등급 단계로 옮기십시오 (${op})`);
  }
}
```

## 2. 실패 분류 — 3종

불변조건 21 — **"실패"를 시스템오류·입력누락·의도된차단으로 나눠 집계한다.**

세 가지를 한 통에 넣으면 **"실패율 12%"가 아무것도 말해 주지 않습니다.**
차단이 잘 도는 것도 실패로 세면 게이트를 끄고 싶어집니다.

| 분류 | 뜻 | 사용자에게 | 재시도 | 알림 |
|---|---|---|:-:|:-:|
| **`system_error`** | 우리 잘못 — 타임아웃·API 장애·버그 | "잠시 후 다시" | ○ | ○ |
| **`input_missing`** | 자료가 부족 — 결손 | **무엇을 채우면 되는지** | ✗ | ✗ |
| **`intended_block`** | 규칙이 막음 — 게이트·제약 | **어느 규칙이 왜** | ✗ | ✗ |

### 2.1 판별

```ts
export function classify(e: unknown): FailureKind {
  if (e instanceof GateFailure)        return 'intended_block';
  if (e instanceof OntologyViolation)  return 'intended_block';
  if (e instanceof MissingSlot)        return 'input_missing';
  if (e instanceof TimeoutError)       return 'system_error';
  if (e instanceof UpstreamApiError)   return e.status >= 500
                                         ? 'system_error' : 'input_missing';
  return 'system_error';   // 🔴 모르면 우리 잘못으로 셉니다
}
```

**모르는 것을 `system_error` 로 두는 것이 안전한 방향입니다.** 반대로 두면
버그가 "자료 부족"으로 집계되어 영원히 안 고쳐집니다.

### 2.2 사용자 문구

| 분류 | 문구 예 |
|---|---|
| `system_error` | "생성에 실패했습니다. 잠시 후 다시 시도해 주세요." |
| `input_missing` | "운영비를 입력하면 순수익률을 산출할 수 있습니다." |
| `intended_block` | "사진에 임차인 상호가 보입니다. 가린 뒤 발행할 수 있습니다. (G20)" |

🔴 **`intended_block` 에 게이트 코드를 노출합니다.** 중개인이 같은 문제를 반복해서
겪을 때 코드로 검색할 수 있어야 합니다.

### 2.3 로그에 입력값을 담지 않습니다

```ts
log.warn({ code: 'G21', stage: 'publish', field: 'opexAnnual' });   // ○
log.warn({ code: 'G21', value: 32_400_000, tenant: '○○의원' });      // ✗ 금지
```

**필드명만 남깁니다.** 로그는 보존 기간이 길고 접근 권한이 넓습니다.

## 3. 재시도

| 단계 | 재시도 | 횟수 | 백오프 | 왜 |
|:-:|:-:|:-:|---|---|
| ① 메모 | ✗ | — | — | 사용자 앞 |
| ② 추출 | ○ | 2 | 1s · 3s | LLM 일시 실패 |
| ③ 딜카드 (공공 API) | ○ | **3** | 1s · 2s · 5s | 공공 API가 자주 흔들립니다 |
| ④ 바텀시트 | ✗ | — | — | 사용자 앞 |
| ⑤ 등급 | ✗ | — | — | 순수 계산 — 재시도해도 같습니다 |
| ⑥ 생성 (섹션별) | ○ | 1 | 2s | §5 참조 |
| ⑦ 렌더 | ○ | 1 | 즉시 | 폰트·이미지 I/O |
| ⑧ 발행 | ✗ | — | — | 게이트는 결정론입니다 |

### 3.1 재시도하면 안 되는 것

**게이트 실패와 제약 위반은 절대 재시도하지 않습니다.** 결정론이므로 결과가
같고, 재시도하면 시간 예산만 소모합니다. `intended_block` 은 재시도 대상이
아니라는 것이 §2 분류의 실용적 이유입니다.

**⑤ 등급도 재시도하지 않습니다.** 같은 입력에 같은 등급이 나오지 않으면
그것 자체가 버그입니다 (§4).

### 3.2 공공 API 3회인 이유

세움터·V-World는 점검·과부하로 5xx를 자주 냅니다. 3회 실패하면 **차단하지 않고
P축 결손으로 처리**합니다 — 등급이 내려가고 중개인에게 "잠시 후 다시 조회"
버튼이 뜹니다. 딜 생성 자체를 막으면 중개인이 시스템을 안 씁니다.

## 4. 멱등 — 같은 입력에 같은 산출

### 4.1 멱등키

```
idempotencyKey = sha256(
  dealId + inputHash + ontologyVersion + lexiconVersion +
  promptVersion + rendererVersion + posture
)
```

`inputHash` 는 `IMInput` 을 **키 정렬 후** 직렬화해 해싱합니다.
키 순서가 바뀌면 다른 해시가 나오므로 정렬이 필수입니다.

### 4.2 무엇이 결정론이어야 하는가

| 대상 | 결정론 | 근거 |
|---|:-:|---|
| ③ 공공 데이터 수집 | △ | 원천이 바뀔 수 있음 — 조회 시각을 기록 |
| ⑤ 등급·파생값 | **◎ 필수** | 순수 계산 |
| ⑥ 문장 | ✗ | LLM — §4.3 |
| ⑦ 배치·기하 | **◎ 필수** | 같은 `IMDoc` → 같은 픽셀 |
| ⑧ 게이트 판정 | **◎ 필수** | 같은 산출물 → 같은 결과 |

### 4.3 문장은 결정론이 아닙니다 — 그래서 Pin 합니다

LLM 출력은 재현되지 않습니다. **재현이 필요한 것은 문장이 아니라 발행된 문서**이므로,
`PublishRecord` 가 산출물 자체와 버전 조합을 Pin 합니다.

```
PublishRecord {
  idempotencyKey, artifactHash,
  ontologyVersion, lexiconVersion, promptVersion, rendererVersion,
  gateResults, publishedAt
}
```

**재렌더 요청이 오면 문장을 다시 만들지 않고 Pin된 산출물을 돌려줍니다.**
`FAST_MODE` 에서도 결정론 게이트는 실행합니다 (불변조건 11).

### 4.4 중복 요청

같은 `idempotencyKey` 로 생성 요청이 들어오면 **새로 만들지 않고 진행 중인
작업에 붙입니다.** 중개인이 버튼을 두 번 눌러서 IM 두 개가 생기고 서로 다른
문장을 갖는 것이 실제로 있는 사고입니다.

## 5. 부분 실패 복구 — 7섹션 중 3개가 실패하면

### 5.1 원칙 — 빈 면을 내보내지 않습니다

| 상황 | 동작 |
|---|---|
| **필수 섹션** 실패 | 재시도 1회 → 실패 시 **전체 차단** |
| **권장 섹션** 실패 | 재시도 1회 → 실패 시 **면 자체를 빼고** 확인사항에 사유 기재 |
| 선택 섹션 실패 | 조용히 제외 |

필수/권장/선택은 포스처 표준의 섹션 표(`IM_STANDARD_<posture>` §2)가 정합니다.

🔴 **"생성 실패"라고 적힌 면을 매수자에게 보내지 않습니다.** 결손은 사라지지 않고
**확인사항으로 이동**합니다 (불변조건 13). 확인사항은 공개 단계에서도
마스킹하지 않습니다 (불변조건 9).

### 5.2 부분 실패 시 등급

**등급을 사후에 내리지 않습니다.** 등급은 ⑤에서 입력 기준으로 확정되었고,
⑥의 실패는 자료 문제가 아니라 우리 문제입니다. 대신 **발행 기록에 남기고
알림을 보냅니다** (`system_error`).

### 5.3 렌더 실패

| 실패 | 동작 |
|---|---|
| 폰트 없음 | **차단** — 대체 폰트로 렌더하면 기하가 달라집니다 |
| 이미지 로드 실패 | 해당 슬롯만 제외 · `G26`(사진 장수) 경고 |
| 표 오버플로 | **차단** (`G01`) — 잘린 표는 틀린 정보입니다 |
| pptx 저장 실패 | 재시도 1 → `system_error` |

## 6. 시간 예산 — 120초

불변조건 15. `maxDuration` 한계이자 중개인의 인내 한계입니다.

### 6.1 실측과 배분

```
현행 122초  ← 이미 2초 초과
  섹션 순차 생성  112.5초 (92.2%)  ← 섹션당 16.1초 × 7
  나머지            9.5초
```

**섹션을 늘리면 확실히 실패합니다.** 포스처 5종 × 섹션 8~10개면 순차로는 불가능합니다.

| 구간 | 예산 |
|---|--:|
| ③ 공공 API (병렬) | 8s |
| ⑤ 등급·파생 | 1s |
| ⑥ 섹션 생성 (**병렬**) | 55s |
| ⑦ 렌더 | 12s |
| ⑧ 게이트 | 4s |
| 여유 | 40s |

### 6.2 병렬화 없이는 포스처 확장이 막힙니다

```
병렬화 후   55초  →  섹션 +2  →  87초  ✓
병렬화 없이 122초  →  섹션 +2  → 154초  ✗
```

**`GENERATION_PERF_SPEC.md`(D13)가 `PPTX_ARCHETYPE_SPEC.md`(D7)의 선행 문서인
이유**가 이것입니다. 섹션을 늘리기 전에 시간을 재야 합니다 (불변조건 15).

### 6.3 예산 초과 시

| 시점 | 동작 |
|---|---|
| 90초 경과 | 남은 선택 섹션 생성 중단 |
| 105초 경과 | 렌더로 넘어감 — 미완 섹션은 확인사항으로 |
| 120초 | 타임아웃 → `system_error` · 부분 산출물 폐기 |

**부분 산출물을 저장하지 않습니다.** 반쪽 IM이 DB에 남으면 다음 요청이
그것을 캐시로 씁니다.

## 7. 게이트 발동 지점

| 코드군 | 언제 | 실패 시 |
|---|---|---|
| **`QG`** 운영 | ②~⑦ 각 단계 진입·종료 | 재시도 또는 알림 |
| **`C`** 제약 | ⑤ 등급 직후 | 차단 · 자동 정정 · 억제 · 경고 |
| **`X`** 교차검증 | ③ 딜카드 직후 | X05 차단 · 나머지 경고 |
| **`G`** 발행 | ⑧ 발행 직전 | 4xx |

### 7.1 왜 C가 ⑤ 직후인가

**파생값이 확정된 직후, 문장이 만들어지기 전**입니다. 여기서 막으면 LLM 호출
비용과 55초를 아낍니다. 문장을 다 만든 뒤에 "수익률에 basis가 없다"고 차단하면
낭비입니다.

### 7.2 왜 X가 ③ 직후인가

공부 수치끼리의 정합이므로 L축 입력을 기다릴 필요가 없습니다.
**`X05`(필지 합)가 차단이므로 여기서 걸러야** 중개인이 바텀시트를 채우기 전에
필지 목록을 고칠 수 있습니다.

### 7.3 `G`와 `QG`는 지금 코드가 겹칩니다 🔴

```
CATALOG_RULES §4       G01~G30   발행 게이트
quality-gates-v02.ts   G01~G16   운영 게이트
```

개명 전까지 로그에 **출처 접두**를 붙입니다.

```
publish:G07   runtime:G07
```

절차는 `IM_QUALITY_GATES.md` §7.

## 8. 관측

### 8.1 단계별 지표

| 지표 | 태그 |
|---|---|
| `stage.duration_ms` | stage · posture · grade |
| `stage.failure` | stage · **kind**(3종) · code |
| `section.duration_ms` | section · posture |
| `gate.result` | code · pass/warn/fail · posture |
| `grade.distribution` | **L** · **P** · grade · posture |
| `idempotency.hit` | — |

### 8.2 등급을 L·P로 나눠 봅니다 🔴

"C등급 비율 40%"는 조치로 이어지지 않습니다.

```
C등급  P가 낮아서   →  공공 API 수집 문제 · 우리 일
C등급  L이 낮아서   →  중개인 입력 부족 · 교육·UI 일
```

**두 축을 나눠 보면 누구의 일인지가 갈립니다.**

### 8.3 알림 기준

| 조건 | 알림 |
|---|---|
| `system_error` 비율 > 3% (15분) | 즉시 |
| p95 생성 시간 > 100초 | 즉시 |
| 공공 API 3회 실패 비율 > 10% | 15분 |
| `intended_block` 비율 상승 | **알리지 않음** — 정상 동작입니다 |
