## §0 총평

현행 파이프라인은 **잘 만들어져 있습니다.** 3-Tier 슬롯 추출, 4단계 위상 병렬 Writer, LLM-as-Judge, 할루시네이션 가드, 17 아키타입, 텍스트 예산 — 이만한 얼개를 갖춘 시스템은 드뭅니다.

문제는 얼개가 아니라 **두 세계가 이름으로 이어져 있지 않다는 것**입니다.

```
운영   메모 슬롯 40+ · layers JSONB · 등급 100점 · 섹션 7 · 아키타입 A01~A17 · 게이트 G01~G16
규격   필드 49 · 블록 51 · 등급 L×P · 페이지 16 · 게이트 G01~G26 · 불변조건 21
```

이름이 다르면 "같은 것인가"를 아무도 확신하지 못하고, 결국 **양쪽에 비슷한 로직이 하나씩** 생깁니다. 실제로 그렇게 됐습니다 — 텍스트 예산이 두 곳, 수치 검증이 두 곳, 편성 결정이 두 곳에 있습니다.

`im.bindings.yaml`을 만들어 대응표를 못박고, 대응이 없는 것은 **버리지 않고 목록으로 남겼습니다.**

```
$ python3 credeal/ssot/loader.py
  🔴 운영 파이프라인 미대응 28건
     메모 슬롯 누락    4건 — rr_as_of · buyer_purpose · parcel_list · mgmt_bearer
     layers 누락      3건 — layers.land · layers.zoning.items · layers.lease_as_of
     출처 등급 누락    3건 — S2a · S2b · S4
     섹션 누락        5건 — parcels · land · evidence · landvalue · photos_ext
     운영에 없는 게이트 9건 — G01 · G10 · G12 · G17 · G18 · G19 · G20 · G22~24 · G26
     표기 규칙 위반    4건
  🔴 코드 충돌 (운영) G01~G16 — 차단 · 3중
```

## §1 🔴 차단급 6건

발행 품질에 직접 영향을 주고, 지금 상태로는 **조용히 틀리는** 것들입니다.

### 1.1 G 코드가 세 곳에서 다른 뜻입니다

| 소스 | G07의 의미 |
|---|---|
| `CATALOG_RULES.md` §4 (정본) | 제약 C01~C33 검증 |
| **`quality-gates-v02.ts` (운영 중)** | 데이터 무결성 계열 중 하나 |
| `im.errors.yaml` | CATALOG 승계 |

`"G07 실패"`라는 로그 한 줄이 세 가지를 뜻할 수 있습니다. **발행 API가 4xx를 내도 어느 규칙이 막았는지 특정되지 않습니다.**

> **보완** — 운영 게이트를 `QG01~QG16`(Quality Gate)으로 개명합니다. `G`는 CATALOG 발행 게이트 전용으로 남깁니다. 대응은 `im.bindings.yaml` `gate_map`이 소유합니다. 스프린트 1, FR02와 함께.

### 1.2 텍스트 예산이 자르면 안 되는 것을 자릅니다

```
TEXT_LIMITS   statValue: 10 · tableHeader: 16 · statLabel: 18
enforceTextBudget()  초과 시 "…" 로 절단
```

**이 셋은 절대 자르면 안 되는 것들입니다.** D17 E01 사고가 정확히 이 경로입니다 — `"현재 연 순수익률 (Cap R"`에서 문장이 끊겼습니다.

> **보완** — `enforceTextBudget(text, maxLen, kind)`로 요소 종류를 받습니다. `im.budget.yaml` `truncation.never`(라벨·표 헤더·단위·출처·제목·수치)에 해당하면 **절단 대신 예외를 던지고**, 호출부가 폰트를 줄이거나 다음 면으로 흘립니다. 그래도 안 되면 빌드를 멈춥니다.

### 1.3 렌트롤이 12행에서 잘립니다

`a03-large-table.ts` — **셀 45자 절단 · 최대 12행 트림**.

13행짜리 렌트롤은 조용히 12행이 됩니다. **불변조건 18(렌트롤 전량 표기) 위반**이고, 사라진 행을 아무도 모릅니다.

> **보완** — `L.table`에 이미 `autoPage: true`가 있습니다. 12행 상한을 없애고 자동 분할에 맡깁니다. 셀 45자 절단도 `kind='tableCell'`이면 줄바꿈으로 바꿉니다.

### 1.4 `--`가 "확인 필요"를 덮습니다

`sanitizePersona()` — `NaN/null/undefined + 단위 → "--"`.

`im.format.yaml`의 `missing.forbidden_tokens`에 `-`와 `—`가 들어 있습니다. **매수인은 `--`를 "해당 없음"으로 읽습니다.** 실제로는 "아직 모른다"입니다. 두 상태를 같은 기호로 쓰면 **확인 요청이 사라집니다.**

> **보완** — `"확인 필요"`로 바꿉니다. 계산이 불가한 경우는 `"{이유} {대상}을 산출하지 않았습니다"` 형식을 씁니다. 예: `"운영비 미입력 — 연 순수입을 산출하지 않습니다"`.

### 1.5 임차인 마스킹이 업종까지 지웁니다

```
"㈜스타벅스" → [TENANT_A]
```

불변조건 14는 **상호를 가리라** 하고, 불변조건 6은 **업종을 원문 그대로 쓰라**고 합니다. 한 토큰으로 뭉개면 두 규칙을 동시에 지킬 수 없습니다.

> **보완** — `[TENANT_NAME_A]`(상호 — 어느 단계에서도 복원 금지)와 업종(원문 유지, 마스킹 대상 아님)으로 나눕니다. 파서가 `"㈜스타벅스 카페"`에서 둘을 분리하지 못하면 **업종을 비우고 확인사항으로 넘깁니다.** 추론하지 않습니다(G17).

### 1.6 `capRatePct` 슬롯이 불변조건 셋을 어깁니다

슬롯 정의가 `"Regex + 역산 · 연 순수익률"`입니다.

```
① 운영비 없이 "순수익률"을 만들 수 없습니다        불변조건 1·3
② 메모에서 뽑거나 역산한 값에는 basis 가 없습니다   불변조건 2
```

> **보완** — 슬롯을 폐기하고 `claimed_yield`로 바꿉니다. 출처는 S3이고 화면에 **"중개인 제시"**를 병기해 산출값과 나란히 놓습니다. 두 값이 다르면 그 자체가 확인사항입니다.

## §2 스테이지별 갭과 보완

### 2.1 Stage 1 — 메모 · 슬롯 추출

| 갭 | 영향 | 보완 |
|---|---|---|
| `rr_as_of` 없음 | **기준일 없이 만료를 판정하면 전부 틀립니다.** 원장이 1년 전이면 전 호실이 만료로 나옵니다 | 필수 슬롯으로 승격 · 없으면 G18 경고 |
| `buyer_purpose` 없음 | L12 목적별 토지이용계획 표시가 못 돕니다 | 딜카드 생성 시 5지선다 · 미선택이면 전 항목 동일 비중 |
| `parcel_list` 없음 | 다필지가 단일 필지로 처리됩니다 | 대표 지번 → 인접 탐색 → 후보 ≤10 → 사람 선택 |
| `mgmt_bearer` 없음 | 관리비 금액만 있고 부담 주체가 없어 실질 수입을 못 냅니다 | 바텀시트 권장 필드 |
| 슬롯에 provenance·기준일 없음 | 값이 어디서 왔는지 뒤에서 알 수 없습니다 | 슬롯을 `{value, provenance, asOf}` 삼중항으로 |

**추가 보완 — 추출률을 신뢰도로 쓰지 마십시오.** `extractionRate`는 "몇 개를 뽑았나"이지 "얼마나 맞나"가 아닙니다. 등급에 반영하면 **틀린 값을 많이 뽑은 메모가 높은 점수**를 받습니다.

### 2.2 Stage 2 — 딜카드 · SSoT

**`layers`가 자유 JSONB입니다.** 스키마 검증이 없으면 필드명이 조용히 흘러갑니다.

> **보완** — `im.gating.yaml`의 필드 49개에서 **JSON Schema를 생성**해 쓰기 시점에 검증합니다. 스키마에 없는 키는 거부하지 말고 `layers._unmapped`로 격리한 뒤 로그에 남깁니다 — 버리면 나중에 못 찾습니다.

**신설할 layers 3종**

```
layers.land          parcels[] · exclusions[] · effectiveArea · parcelCount · parcelsKnown
layers.zoning.items  토지이용계획 확인원 전 항목 (지금은 문자열 하나로 뭉쳐 있습니다)
layers.lease_as_of   임대 현황 기준일
```

`parcelsKnown: false`가 중요합니다. **필지 수만 알고 내역을 모르면 단일 필지로 오인하지 않고 결손으로 넘깁니다.** 양평동이 실제로 3필지 합지인데 그렇게 처리되고 있었습니다(D22-8 §7A).

### 2.3 Stage 3 — 바텀시트

**렌트롤 임포터 열 매핑에 만료일이 없습니다.** 현행은 `층/업종/보증금/월세/관리비/공실/면적/계약일` — `계약일`이 시작인지 만료인지 모호합니다. **만료일이 없으면 G22~G24가 돌지 않습니다.**

> **보완** — 열을 `계약 시작일`·`계약 만료일`로 분리합니다. 헤더 자동 감지에 `만기·만료·종료·expiry·end`를 추가합니다.

**신설 필드 11종** (D19 §2A.9 · D22-8)

```
임대차   rr_as_of · rr_legal · rr_first · rr_opposing · mgmt_bearer
필지     parcel_list · parcel_share · exclusion_kind · exclusion_area · exclusion_affects_far
목적     buyer_purpose
```

**잠금 사유 안내가 없습니다.** 지금 바텀시트는 빈칸만 보여줍니다. 중개인은 무엇을 채우면 무엇이 열리는지 모릅니다.

> **보완** — `im.gating.yaml`의 `opens`를 읽어 필드마다 안내를 붙입니다. `"관리비 부담 주체를 넣으면 실질 수입이 열립니다"`. 그리고 `evaluate()`가 **실제로 빠진 것만** 말하도록 합니다 — 고정 문구를 쓰면 이미 받은 것까지 다시 달라고 하게 됩니다.

**사진 카테고리 8종 ↔ 슬롯 14종 매핑이 없습니다.** 카테고리만으로는 표지·위치도·지적도 슬롯을 특정할 수 없습니다.

> **보완** — 카테고리에 슬롯 키를 부여하고, 업로드 시 **실효 dpi**를 계산해 즉시 안내합니다. `"표지용으로는 118dpi입니다. 1500px 이상으로 재촬영을 권합니다"`. 지금은 1920px 리사이즈만 하고 슬롯별 판정이 없습니다.

### 2.4 Stage 4 — 등급

**단일 100점은 무엇이 부족한지 말하지 못합니다.** 68점이 나왔을 때 임대차가 얇은 것인지 공부가 없는 것인지 구분되지 않습니다.

> **보완** — 점수는 유지하되 **표시를 L×P로** 바꿉니다. 점수는 정렬용, 축은 안내용입니다.

```
L축  lease_roll
P축  building_basic · land_parcel · zoning · road_access · market_comp
축 무관  financial_input · title_encumbrance
```

**출처 등급에 S2a/S2b가 없습니다.** 현행은 `public_data` 계수 1.00이 실거래 comps에도 붙습니다. RTMS는 지번을 `1***`로 마스킹하므로 **어느 건물인지 모르는 채로 1.00을 받습니다.** 중개인이 식별·대로변/이면·규모를 얹어야 쓸 수 있고, 그때 비로소 S2b입니다.

**"income은 구조화 렌트롤 필수 · 미충족 시 B 캡"은 좋은 규칙입니다.** 다만 렌트롤이 "있는지"만 보고 **원장 행수와 대조하지 않습니다.** 전량 조건을 더하십시오.

### 2.5 Stage 5 — 모바일 IM 생성

여기가 가장 크게 바뀌어야 합니다.

**지금** — LLM이 본문과 수치를 함께 쓰고, 사후에 검증합니다(할루시네이션 20×/10×, cross-validator ±15%, 렌트롤만 결정적 주입).

**바꿀 것** — **수치는 코어가, 서사는 LLM이.**

```
IMCore 가 Val{value, basis, source} 를 냅니다
LLM 은 그 값을 **자리표시자로** 받아 문장을 씁니다
치환은 렌더 직전에 결정적으로 일어납니다
```

이유는 하나입니다. **사후 검증으로는 오타를 못 잡습니다.**

> 실측 — 평당가가 한 면은 `15,933만원`, 다른 면은 `1억 5,923만원`이었습니다. 차이 0.06%로 ±15% 검사를 그대로 통과합니다. 검사기 다섯 층이 전부 통과시켰습니다.

**cross-validator를 두 층으로 나눕니다.** (현행은 가격 20× 초과 또는 0.05× 미만 · 면적 10× 이탈을 극단값으로 잡고, 앵커 대비 ±15%를 경고합니다.)

| 층 | 대상 | 허용 |
|---|---|--:|
| ① 앵커 대비 괴리 | LLM 환각 탐지 | ±15% (유지) |
| ② **면 간 동일성** | 같은 지표가 면마다 같은 값인가 | **0%** |

②는 `qa/consistency_check.py`가 이미 합니다. 억·만 혼용을 정규화해 비교하고, 오타를 되돌려 넣으면 잡습니다.

**basis 강제를 생성 단계로 올립니다.** `basis-enforcer.ts`가 지금은 PPTX 쪽에만 있습니다. 모바일 생성에도 걸어야 G10(모든 수익률에 basis)이 실제로 집행됩니다.

**LLM-as-Judge 폴백을 드러냅니다.** `< 3.0 → 템플릿 폴백`이 조용히 일어나면 품질이 떨어진 것을 아무도 모릅니다. 폴백 횟수를 문서 메타에 남기고, 검수 화면에 표시하십시오.

**골든 자동 승격을 막습니다.** `≥ 4.5 → 골든 후보`는 좋습니다. 다만 **승격은 사람이 눌러야 합니다**(불변조건 10). 자동이면 LLM이 자기 출력을 학습 예시로 삼는 폐순환이 생깁니다 — `GOLDEN_REBUILD_SPEC`이 이미 경고한 것입니다.

**섹션 7개로는 담을 곳이 없습니다.** 필지 명세·토지·교차검증·토지가치가 들어갈 자리가 없어 `property_overview`에 섞입니다.

> **보완** — 섹션을 늘리지 말고 **블록 게이팅**을 도입합니다. 섹션은 서사 단위로 두고, 그 안의 블록 51개가 입력에 따라 열리고 닫힙니다. 조건부 절(`parcels_sec`·`zoning_sec`)은 데이터가 없으면 아예 생성되지 않습니다 — 빈 절이 늘어나지 않습니다.

### 2.6 Stage 6 — 모바일 뷰어

**노출 3단계가 없습니다.** 공개 URL 하나(`/im-lite/[buildingId]`)에 전부 나갑니다. 지번·호실별 금액·만료일의 노출 경계가 없습니다.

> **보완** — `public`(링크) · `nda`(휴대폰 본인확인 + 전자동의) · `pro`(중개인 개별 승인). **`Stage` 판정은 서버에서 강제**합니다 — 클라이언트를 신뢰하지 않습니다.

| 항목 | public | nda | pro |
|---|:-:|:-:|:-:|
| 주소 | 동까지 | 동까지 | 지번 |
| 호실별 금액 | 합계만 | 호실별 | 호실별 |
| 만료일 | 미표기 | 호실별 | 호실별 |
| **확인사항** | **전부** | **전부** | **전부** |

확인사항은 어느 단계에서도 가리지 않습니다(불변조건 9).

**편성 결정이 두 곳에 있습니다.** `deck-sequencer.ts`가 Posture×Grade로 A01~A17 순서를 정하고, `im.pages.yaml`이 프리셋별 면 순서를 정합니다. 둘 다 살아 있으면 프리셋을 바꿔도 순서가 안 바뀌거나 두 번 바뀝니다.

## §3 파이프라인 보완 — 구조 4가지

개별 수정을 넘어 얼개를 바꿔야 하는 것들입니다.

### 3.1 레지스트리를 런타임에 읽습니다

지금은 규칙이 코드 안에 있습니다 — 금지어, 텍스트 예산, 취득세율, 페이지 순서, 색 토큰. **같은 규칙이 두 곳에 있으면 반드시 어긋납니다.**

> 실측 — 검사기 두 개의 금지어 교집합이 **8/26(31%)**이었습니다. `"안전 보장"`은 한쪽만, `"희소성"`은 다른 쪽만 잡았습니다.

```
빌드   credeal/ssot/*.yaml (12종) → registry.json → 번들
런타임 loadRegistry() · 버전 불일치면 부팅 실패
```

조용히 낡은 규칙으로 도는 것이 더 위험합니다.

### 3.2 `layers`에 스키마를 겁니다

`im.gating.yaml`의 필드 49개에서 JSON Schema를 생성해 쓰기 시점에 검증합니다. 스키마에 없는 키는 **거부하지 말고 `layers._unmapped`로 격리**한 뒤 로그에 남깁니다 — 버리면 나중에 못 찾습니다.

### 3.3 수치와 서사를 분리합니다

```
코어    Val{value, basis, source}  ← 모든 수치
LLM     자리표시자를 포함한 문장    ← 서사만
렌더    결정적 치환                ← 마지막에
```

카피에 숫자를 손으로 적으면 반드시 어긋납니다. 자리표시자를 쓰십시오.

```python
'토지 평당 {land_pyeong} — 인근 1.38억~1.85억 범위 내'   # 좋음
'토지 평당 1억 5,923만원 — 인근 1.38억~1.85억 범위 내'    # 실제로 틀렸습니다
```

### 3.4 검증을 5층으로 세웁니다

| 층 | 무엇을 보는가 | 도구 |
|---|---|---|
| 1 | **수치** — 산식·반올림·단위 | 코어 자기검사 · parity |
| 2 | **결함** — 43종 카탈로그 | `output_qa` (26검사) |
| 3 | **표준** — 정본 준수 · 불변조건 | `standard_check` · `invariant_check` |
| 3.5 | **면 간 일관성** — 같은 지표가 같은 값인가 | `consistency_check` |
| 4 | **보이는 것** — 렌더 픽셀 | `render_snapshot` |
| 5 | **사람** — 지면 감각 | 심사 5항 체크박스 |

**각 검사기는 양방향 보정을 통과해야 합니다.**

```
① 오탐 0 — 정상 산출물을 차단하지 않는다
② 미탐 0 — 결함 산출물을 반드시 차단한다   ← 결함은 주입해서 만듭니다
```

한쪽만 보면 "아무것도 안 잡는 검사기"가 만점을 받습니다. 실제로 그런 경로가 하나 있습니다 — `qa/consistency_check.py`는 인자 0개로 호출되면 검사할 것이 없습니다. 지금은 `return 2`로 CI를 실패시키지만(`consistency_check.py:96~101`), **인자 누락을 CI가 잡지 못하면 게이트가 조용히 무력화됩니다.**

## §5 작성 방법론 보완

### 5.1 프롬프트에 수치를 넣지 않습니다

`buildNarrativeUserPrompt`가 "사전 계산 재무 테이블"을 프롬프트에 넣습니다. LLM이 그 표를 보고 **문장 안에 숫자를 다시 씁니다.** 옮겨 적는 순간 틀릴 수 있습니다.

> **보완** — 프롬프트에는 **자리표시자 목록**을 줍니다. `{land_pyeong}`·`{gross_price}`·`{effective_far}`. LLM은 어느 값을 어디에 놓을지만 정하고, 값 자체는 만지지 않습니다.

### 5.2 문형을 태그로 남깁니다

지금 카피는 평문입니다. 문형(F3 사실 / F4 비교 / F5 조건부 / OPINION 견해)을 태그로 남기면 두 가지가 가능해집니다.

```
① 물건 간 중복 판별 — 사실 주장은 같으면 안 되고 정책은 같아도 됩니다
② 문체 일관성 — 경고와 견해만 완결문장, 나머지는 개조식
```

지금 `cross_property`는 **"숫자가 없으면 정책"**으로 판별합니다. 그래서 `"잔금 일정 확정 전에 대출 승인을 받으시길 권합니다"`가 두 물건에 똑같이 들어가도 통과합니다. 이건 정책이 아니라 견해입니다.

### 5.3 잠금 사유는 빠진 것만 말합니다

```
고치기 전  "관리비·부담 주체 미입력"    ← 관리비 금액은 이미 받았습니다
고친 뒤    "관리비 부담 주체 미입력"
```

고정 문구를 쓰면 이미 준 것을 또 달라고 하게 되고, 중개인이 두 번 찾습니다.

### 5.4 게이트가 풀리면 문구도 사라집니다

손으로 쓴 확인사항·리스크 목록은 게이트가 해소돼도 그대로 남습니다. 실측 — G19·G21을 해소한 뒤에도 `"표지 요약과 원장 합계 불일치"`가 리스크 칸에 남아 있었습니다.

> **보완** — 게이트별 문구 패턴을 두고 해소 시 함께 지웁니다. 더 근본적으로는 **손으로 쓴 목록을 게이트에서 생성**합니다.

### 5.5 다음 한 단계만 말합니다

```
고치기 전  "임대면적·적용법령·관리비·시작일이 채워지면 평당 단가가 열립니다"
           ← 이미 R2 인데 R1→R2 안내를 하고 있었습니다
고친 뒤    "최초 계약일·대항력이 채워지면 갱신요구권이 열립니다"
```

### 5.6 사람 심사 5항

규칙 검사가 통과해도 봅니다. 서술형 기준은 지켜지지 않으니 체크박스로 고정합니다.

```
□ 1. 첫 장에서 건물이 보이는가
□ 2. 3초 안에 가격과 수익률의 기준을 찾을 수 있는가
□ 3. 표만 있는 면이 3연속으로 오지 않는가
□ 4. 명사형과 완결문장이 자리별로 일관된가
□ 5. 이 면을 지우면 아쉬운 면만 남았는가
```
