## §1 원칙 — 검사기를 믿을 수 있는 조건

검사기가 통과했다는 말이 IM이 옳다는 뜻은 아닙니다. 통과가 의미를 가지려면 **양쪽을 다 재야** 합니다.

```
① 오탐 0 — 정상 산출물을 차단하지 않는다
② 미탐 0 — 결함 산출물을 반드시 차단한다
```

한쪽만 보면 쓸모없는 검사기가 통과합니다. ①만 보면 "아무것도 안 잡는 검사기"가, ②만 보면 "전부 잡는 검사기"가 만점을 받습니다.

**②의 결함은 주입해서 만듭니다.** 실제 결함 산출물이 나오기를 기다리면 검사기가 만들어지지 않습니다.

이 원칙은 이미 `qa/calibrate.py`에 적용돼 있고, 이번에 `calibrate_invariant.py`로 확장했습니다.

## §3 미검사 불변조건 — 3건 중 2건 해소

`loader.py`가 매 실행 경고하던 항목입니다. 이번에 둘을 채웠습니다.

```
이전:  🔴 자동 검사 없는 불변조건 3건 — 6 · 14 · 18
현재:  🔴 자동 검사 없는 불변조건 1건 — 14 (이미지 경로 · D22-2 소관)
```

### 3.1 QA-SRC-01 — 불변조건 6 (업종 원문)

*"업종·상호는 원문 그대로 쓰고 추론하지 않는다"*

**원장을 함께 받습니다.** 산출물만 봐서는 원문인지 알 수 없습니다. 이것이 지금까지 이 검사가 없었던 이유입니다 — 검사기가 산출물만 읽었습니다.

```python
data, biz = find_rentroll(rows)          # 업종 열을 특정합니다
known = [r['tenantBusiness'] for r in ledger]
shown = [r[biz] for r in data]
# 자가·공실·확인 필요는 업종이 아니므로 제외합니다
```

**문서 전체가 아니라 업종 열만 봅니다.** 처음에 전체를 훑었더니 "제이에스부동산중개(주)"의 '부동산'과 거래 절차의 '은행'이 업종으로 잡혔습니다. 검사 범위를 좁히는 것이 정규식을 정교하게 만드는 것보다 낫습니다.

**로그에 값을 담지 않습니다.** `"업종이 원문과 다름 1건: 5행"` — 행 번호만 냅니다.

### 3.2 QA-RR-01 — 불변조건 18 (렌트롤 전량)

*"렌트롤은 전량 표기한다"*

원장 행수와 산출물 표 행수를 셉니다. 계 행은 세지 않습니다.

표를 찾는 방법이 중요합니다. 처음에 문서 전체에서 호실 패턴(`1F`·`B1`)을 찾았더니 다른 표의 행까지 걸렸고, `1F (A)` 같은 그룹 표기를 놓쳤습니다. **헤더로 표를 특정**하는 쪽으로 바꿨습니다 — `업종`이 있고 `호실`·`층별` 중 하나가 있는 행이 헤더입니다.

PPTX는 `층별 … 임차 업종`, 모바일은 `호실 … 업종`으로 헤더가 다릅니다. 둘 다 잡습니다.

### 3.3 QA-MASK-02 — 불변조건 14 (텍스트 경로)

임차인명이 텍스트에 새지 않았는지 봅니다. **이미지 경로는 G20 소관**입니다(D22-2).

### 3.4 보정 결과 — 실측

`python3 qa/calibrate_invariant.py`

```
① 오탐 검사 — 산출물 11종         차단 0     통과
② 미탐 검사 — 주입 결함 4종
     렌트롤 1행 삭제              QA-RR-01  검출
     업종을 다른 말로 바꿈           QA-SRC-01 검출
     업종을 상위 개념으로 일반화        QA-SRC-01 검출
     하위 행을 잘라 요약            QA-RR-01  검출

보정 정상
```

"업종을 상위 개념으로 일반화"(주류판매 → 근린생활)를 넣은 이유는 **LLM이 가장 자주 하는 추론**이기 때문입니다. 틀린 말이 아니어서 사람 눈에 잘 안 띕니다.

## §4 렌더 스냅샷 회귀

### 4.1 왜 필요한가

텍스트 검사로는 **보이는 문제**를 잡지 못합니다. 이번 세션에서 실제로 겪은 것들입니다.

| 결함 | 텍스트 검사 | 사람 눈 |
|---|:-:|:-:|
| 표 라벨 칸이 붉게 칠해져 흰 글씨가 안 보임 | 통과 | 즉시 |
| 줄바꿈된 본문의 `space_after` 누적으로 상자 넘침 | 통과 | 즉시 |
| 제목만 남고 표가 다음 장으로 넘어감 | 통과 | 즉시 |
| 표지 전면 사진이 건물 하단을 잘라먹음 | 통과 | 즉시 |

**전부 텍스트 추출로는 통과합니다.** 글자는 다 있고 순서도 맞습니다. 그려 봐야 압니다.

### 4.2 파이프라인

```
PPTX → soffice --convert-to pdf → pdftoppm -r 72 → PNG → 기준본과 픽셀 비교
```

72dpi로 충분합니다. 회귀 판정에 인쇄 해상도가 필요하지 않고, 낮을수록 빠릅니다.

**힌팅 차이 필터** — 픽셀 밝기 차이 8 이하는 같은 것으로 봅니다. 폰트 렌더링은 환경에 따라 미세하게 흔들립니다.

**임계 0.30%** — 이보다 크게 바뀌면 사람이 봅니다.

### 4.3 실측

```
$ python3 qa/render_snapshot.py
  통과  당산동_PPTX_IM_KR_R2.pptx        13면 · 최대 차이 0.00%
  통과  양평동_PPTX_IM_KR_R1.pptx        13면 · 최대 차이 0.00%
  통과  데모_당산동_evidence_first.pptx    14면 · 최대 차이 0.00%
  통과  데모_당산동_land_value_first.pptx  14면 · 최대 차이 0.00%
```

같은 입력에서 **0.00%**입니다. 렌더가 결정적이라는 뜻이고, 임계 0.30%가 지나치게 헐겁지 않다는 뜻이기도 합니다.

### 4.4 민감도 자기검사

```
$ python3 qa/render_snapshot.py --selftest
  통과  6%×10% 사각형 주입 → 차이 0.62% (임계 0.3%)
```

**이것이 없으면 "아무것도 안 잡는 검사기"가 늘 통과합니다.** 화면 면적의 0.6%짜리 변화를 잡습니다 — 표 한 칸이 잘못 칠해지는 정도입니다.

### 4.5 기준본 관리

| 항목 | 규칙 |
|---|---|
| 갱신 | `--update` 후 **사람이 눈으로 본 뒤** 커밋 |
| 위험 | 깨진 렌더를 기준으로 삼으면 그 뒤로 영영 통과합니다 |
| 크기 | 54면에 13MB. Git LFS 또는 CI 아티팩트 보관을 권합니다 |
| 면수 변경 | 픽셀 비교 이전에 실패시킵니다 — 면이 늘거나 줄면 반드시 사람이 봅니다 |

## §5 골든 세트 확장

### 5.1 현재 — 얇습니다

수익형 픽스처 **2건**(당산·양평)이고, L×P 16쌍 중 **3쌍**만 덮습니다.

```
덮은 것    (R1,P0)=D ×2 · (R1,P3)=B · (R2,P3)=A
못 덮은 것  R0 전 구간 · R3 전 구간 · P1·P2 전 구간 · 등급 C
```

**P2 조합도 실행된 적이 없습니다.** 두 픽스처의 R2판이 전부 P3까지 올라가 버려서, 공공 결합은 됐지만 비교사례 보강이 없는 흔한 상태를 밟지 않습니다.

**등급 C(L≥R1 & P=P1) 경로는 한 번도 실행된 적이 없습니다.** 지번은 있으나 공부 조회가 부분 실패한 흔한 상황입니다.

### 5.2 목표 — 6건

| # | 픽스처 | L×P | 등급 | 왜 |
|---|---|---|:-:|---|
| 1 | 당산동 (기존) | R1×P0 → **R1×P3** | D → **B** | 8행 · 통합계약 · 자가사용 |
| 2 | 양평동 (기존) | R1×P0 → R2×P3 | D → A | 12행 · 계약면적 층별표 |
| 3 | **신규** 공부 부분 실패 | R2×**P1** | **C** | **미실행 경로** |
| 4 | **신규** 렌트롤 최소 | **R0**×P2 | D | 원장이 거의 비었을 때 |
| 5 | **신규** 완전 입력 | **R3**×P3 | A | 최초계약일·대항력까지 |
| 6 | **신규** B4 대역 (300억 초과) | R2×P2 | A | **comps 자동조회 공백 구간** |

6번이 특히 중요합니다. 주력 상단(300~500억)이 자동 comps에서 잘려 있는데(`price-prediction.ts:77`), 이 경로가 시험된 적이 없습니다.

### 5.3 픽스처 요건

각 픽스처는 `expect` 블록을 갖습니다. 코어가 낸 값과 대조하는 기대치입니다.

```json
"expect": {
  "equity": { "acquisitionTax": …, "brokerFee": …, "totalAcquisitionCost": … },
  "yields": { "gross_price": …, "gross_price_deposit": … },
  "resolution": { "L": "R2", "P": "P1", "grade": "C" },
  "blocks": { "open": […], "locked": { … } }
}
```

**기대치를 코어가 낸 값으로 채우지 않습니다.** 그러면 시험이 아니라 기록입니다. 손으로 계산하거나 실제 IM에서 가져옵니다.

## §6 수치 동일성 시험

### 6.1 왜 값이 아니라 문자열인가

```
2.2449%  와  2.24%  는 값으로는 같지만 화면에서는 다릅니다
```

반올림 자리·단위 전환 임계·소수 자릿수가 어긋나면 **IM 두 벌이 서로 다른 숫자를 말합니다.** Python 참조구현과 TypeScript 운영 구현이 나란히 도는 동안 이것을 막아야 합니다.

### 6.2 기준표

`credeal/make_parity.py`가 `contracts/parity.golden.json`을 생성합니다.

```
parity.golden.json  4건 · 41.2 KB
  dangsan     R1  R1×P0  지표 7/14 · 블록 19열림
  dangsan     R2  R1×P3  지표 14/14 · 블록 34열림
  yangpyeong  R1  R1×P0  지표 11/14 · 블록 14열림
  yangpyeong  R2  R2×P3  지표 14/14 · 블록 31열림
```

담기는 것 — 해상도 · 원장 합계 · 지표 14종(값 + **basis 문자열**) · LTV 3안 · 게이트 · 결손 · Hero 3지표 · 한 줄 정의 · 출처 칩 · **열린 블록 집합** · **잠긴 블록의 사유 문장** · 교차검증 4종.

### 6.3 잠긴 블록의 사유까지 대조하는 이유

```json
"noi": "운영비 미입력 — 연 순수입을 산출하지 않습니다"
```

이 문장은 **화면에 그대로 나갑니다.** 문구가 달라지면 사용자 경험이 달라지고, 문구가 사라지면 결손이 조용히 묻힙니다(불변조건 13 위반).

### 6.4 불변조건 시험

픽스처와 무관하게 항상 참이어야 하는 것들입니다.

| 시험 | 불변조건 |
|---|---|
| 운영비 없이 NOI를 만들지 않는다 | 1 |
| basis 없는 수치를 만들 수 없다 | 2 |
| 실투자금 = 총취득원가 − 보증금 − 대출 | 재무 단언 |
| 역레버리지 구간에서 ROE ≤ 무차입 ROE | 재무 단언 |
| 자가사용을 공실로 세지 않는다 | 8 |
| 렌트롤을 전량 표기한다 | 18 |

## §7 사람 심사 5항

### 7.1 왜 규칙으로 안 되는가

`standard_check`가 "위반 0"을 낸 초기 PPTX를 보고 **"너무 후지고 어색하다"**는 평가가 나왔습니다.

검사기는 규격을 봤고 규격은 지켜졌습니다. 문제는 **지면 문법**이었습니다 — 사진 없음, 전부 완결문장, 강조 없음, 여백 낭비. 이것을 규칙으로 잡을 수 없습니다.

### 7.2 체크박스

서술형 판정 기준은 지켜지지 않습니다. 체크박스로 고정합니다.

```
□ 1. 첫 장에서 건물이 보이는가
□ 2. 3초 안에 가격과 수익률의 기준을 찾을 수 있는가
□ 3. 표만 있는 면이 3연속으로 오지 않는가
□ 4. 명사형과 완결문장이 자리별로 일관된가
□ 5. 이 면을 지우면 아쉬운 면만 남았는가
```

**5번이 가장 어렵고 가장 중요합니다.** 15면 중 지워도 아쉽지 않은 면이 있으면 그 면은 자리를 차지하고 있을 뿐입니다.

### 7.3 기록

심사 결과를 `PublishRecord`에 남깁니다. 누가 언제 무엇을 통과시켰는지가 남아야 심사가 형식이 되지 않습니다.

## §8 물건 간 문장 재사용

### 8.1 현재 판별의 허점

`cross_property.py`는 **"숫자가 들어 있으면 사실 주장"**으로 판별합니다.

```
"역세권 상권으로 배후 수요가 두텁습니다"     ← 숫자 없음 → 통과
```

두 물건에 똑같이 들어가도 걸리지 않습니다. **이것이 IM이 템플릿처럼 보이는 주된 경로입니다.**

**실측** — 당산동·양평동 R2 덱 대조 결과입니다.

```
문장 26 vs 26 · 공통 7 (사실 주장 0 · 정책·방법론 7)
```

사실 주장 공통은 0으로 깨끗합니다. 그런데 "정책·방법론 7"에 이런 문장이 섞여 있습니다.

```
잔금 일정 확정 전에 대출 승인을 받으시길 권합니다
```

**이것은 정책이 아니라 견해(OPINION)입니다.** 두 물건에 똑같이 들어가 있고, 지금 규칙은 숫자가 없다는 이유로 통과시킵니다. 문형으로 판별하면 걸립니다.

> 참고 — `cross_property.py`가 `.pptx`를 바이너리로 읽어 깨진 문장을 내던 버그를 이번에 고쳤습니다. zip에서 슬라이드 XML을 꺼내 `<a:t>`만 봅니다. 고치기 전에는 253건의 "사실 주장 공통"이 잡혔는데 전부 압축 바이트였습니다.

### 8.2 개선 — 문형으로 판별합니다

숫자 유무가 아니라 **문형 태그**로 봅니다.

| 문형 | 물건 간 동일 | 판정 |
|---|:-:|---|
| F3 사실 진술 | 금지 | 차단 |
| F4 비교 | 금지 | 차단 |
| F5 조건부 | 금지 | 차단 |
| OPINION 견해 | 금지 | 차단 |
| 정책·면책·방법론 | 허용 | — |

카피 엔진이 문장을 낼 때 문형 태그를 함께 남기면 판별이 정확해집니다. **F3 문형으로 쓰면 저절로 해결되기도 합니다** — "당산역 380m · 배후 아파트 5,000세대"는 물건마다 다를 수밖에 없습니다.

## §9 CI 파이프라인

```yaml
# 매 PR
- ssot-selfcheck        python3 credeal/ssot/loader.py
                        └ 미검사 불변조건·미등록 코드·충돌을 매번 출력
- ssot-build            python3 credeal/ssot/build_ssot.py
                        └ 생성본이 코드와 어긋나면 diff 로 실패
- core-selfcheck        python3 credeal/core.py
- parity                npm run test:parity
- output-qa             python3 qa/calibrate.py
- invariant             python3 qa/calibrate_invariant.py
- standard              python3 qa/standard_check.py <산출물 11종>
- consistency           python3 qa/consistency_check.py <산출물>
                        └ 같은 지표가 면마다 같은 값인가
- cross-property        python3 qa/cross_property.py
- render-snapshot       python3 qa/render_snapshot.py
- render-sensitivity    python3 qa/render_snapshot.py --selftest

# 야간
- 골든 6건 전량 재생성 + 전 검사
- 생성 시간 p95 측정 (한계 120초 · 불변조건 15)

# 발행 시 (런타임)
- 게이트 전량 (등록되고 폐기되지 않은 전 G·C 코드 · X01~X05)
- 사람 심사 5항
```

**`loader.py`를 CI에 넣는 이유**는 갭이 조용히 묻히지 않게 하기 위함입니다. 미검사 불변조건이 다시 늘면 매 PR 로그에 뜹니다.

**`build_ssot.py`를 넣는 이유**는 생성본을 손으로 고친 것을 잡기 위함입니다. 코드에서 다시 생성했을 때 diff가 나면 실패시킵니다.

## §7 `QG` 네임스페이스 — 운영 게이트 (v0.5 예약) 🆕

### 7.1 왜 나누는가

🔴 **`G01~G16` 이 세 곳에서 서로 다른 뜻으로 쓰이고 있었습니다.**

```
CATALOG_RULES §4          G01~G16   발행 게이트 — 문서를 내보내도 되는가
quality-gates-v02.ts      G01~G16   운영 게이트 — 파이프라인이 정상인가
credeal/ssot/im.errors    G01~G30   발행 게이트 (확장판)
```

`G07 실패` 라는 로그 한 줄이 세 가지를 뜻할 수 있습니다. 발행 API가 4xx를 내도
**어느 규칙이 막았는지 특정되지 않습니다.**

| | 발행 게이트 `G` | 운영 게이트 `QG` |
|---|---|---|
| 묻는 것 | 이 문서를 내보내도 되는가 | 이 실행이 정상인가 |
| 시점 | 발행 직전 | 생성 중 |
| 대상 | IM 산출물 | 파이프라인 |
| 실패 시 | 4xx + 중개인에게 사유 | 재시도 또는 알림 |
| 소유 | `CATALOG_RULES.md` §4 | **이 문서 §7** |

### 7.2 현재 상태 — 예약만 되어 있습니다

**운영 게이트 16종의 실제 의미가 이 레포에서 확인되지 않았습니다.**
`credeal/ssot/im.bindings.yaml` 의 `namespace_collision` 이 "운영 G07 = 미확인"으로
남겨 둔 그대로입니다. 알려진 것은 계열뿐입니다 — 데이터 무결성 · PII 누출 ·
규제 준수 · 수치 교차.

🔴 **개수를 채워 적지 않습니다.** "QG01~QG16 정의됨"이라고 써 두면 확인한 것처럼
보이고, 그 문서를 근거로 다음 사람이 코드를 짭니다. **포인터만 있고 가리키는 곳이
비어 있는 것이 D22-8 사고의 형태였습니다** — 같은 실수를 여기서 반복하지 않습니다.

### 7.3 개명 절차

| 순서 | 작업 | 산출 |
|:-:|---|---|
| 1 | `quality-gates-v02.ts` 를 읽고 16종의 실제 검사 내용을 표로 옮긴다 | 이 절의 표 |
| 2 | 각 항목에 `QG01~QG16` 을 배정하고 `applies_to` 를 단다 | 코드 배정 |
| 3 | `im.errors.yaml` 에 `QG` 네임스페이스를 등록한다 | 레지스트리 |
| 4 | 운영 코드의 `G0x` 문자열을 `QG0x` 로 치환한다 | 코드 변경 |
| 5 | 로그 파서·대시보드에 구코드 → 신코드 **읽기 전용** 매핑을 남긴다 | 과거 로그 보존 |
| 6 | `qa/ontology_check.py` `GROUPS` 에 `QG` 를 추가한다 | 자동 대조 |

**5번을 빠뜨리면 개명 이전 로그의 해석이 사후에 바뀝니다.** 구코드는 지우지 않고
"이 시점 이전의 G07은 운영 게이트"라는 기록으로 남깁니다.

### 7.4 개명 전까지의 임시 규칙

로그에 게이트 코드를 남길 때 **출처를 접두로 붙입니다.**

```
publish:G07   발행 게이트
runtime:G07   운영 게이트
```

개명이 끝나면 접두는 뗍니다. 코드가 다르면 접두가 필요 없습니다.
