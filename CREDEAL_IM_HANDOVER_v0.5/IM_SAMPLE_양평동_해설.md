## §0 이 물건을 고른 이유

양평동은 **잘 되는 것과 안 되는 것이 한 물건에 다 들어 있습니다.**

| 잘 되는 쪽 | 안 되는 쪽 |
|---|---|
| L=R2 · P=P3 → **등급 A** (상용 기준선) | 사진 4매 — 최소 6매 미달 |
| 공부 4종·실거래·POI 전부 결합 | 사진 3매가 해상도 하한 미달 |
| 교차검증 X01~X04 전부 충족 | 만료 경과 계약 11건 (임대중 전 호실) |
| 관리비·계약시작일 확보 | 최초계약일·대항력 미확보 (R3 미달) |

깨끗한 물건으로 샘플을 만들면 시스템이 무엇을 못 하는지 보이지 않습니다.

## §1 생성 흐름 9단계

### 1단계 · 원장 적재

### 2단계 · 공공데이터 결합 (P축)

지번 하나로 자동 조회됩니다.

```

```

**여기서 L축이 함께 올라갑니다.** 원장 12행 중 11행에 임대면적이 비어 있었는데, 공부 층별개요가 그것을 채웁니다.

```

```

🔴 **다만 출처가 바뀝니다.** 채워진 면적의 출처는 S3(원장)이 아니라 **S1(공부)**이고, 이 건물의 층별개요는 바닥면적이 아니라 **계약면적**입니다. 표에 출처를 병기해야 합니다 — §3.1 참고.

## §2 산출물이 실제로 말하는 것

### 2.1 표지 3지표 — 검산 가능한 것만

| 라벨 | 값 | 근거 |
|---|---|---|
| 매매 희망가 | 250억 | 중개인 제공 |
| 평당가 (토지) | 15,933만원/평 | 건축물대장 대지면적 |
| 월 임대료 합계 | 4,657만원 | 임대 현황 12행 합계 |

250억 ÷ 156.9평 = 15,933만원. 표의 월세 열을 더하면 4,657만원. **매수인이 종이에 적어 확인할 수 있습니다.**

한 줄 정의는 `선유도역 95m · 대지 157평` — 18자입니다 (상한 25자).

### 2.2 투자 구조 — 역레버리지를 먼저 밝힙니다

```
총취득원가 = 250억 + 취득세 11.50억(4.6%) + 중개보수 2.25억(0.9%) = 263.75억
실투자금(무차입) = 263.75억 − 보증금 4.95억 = 258.80억
```

| LTV | 대출 | 실투자금 | 월 순현금 | ROE |
|--:|--:|--:|--:|--:|
| 0% | — | 258.80억 | +4,657만 | 2.16% |
| 40% | 100.00억 | 158.80억 | +907만 | 0.69% |
| 50% | 125.00억 | 133.80억 | **−30만** | **−0.03%** |

대출 금리(4.5%) > 무차입 수익률(2.16%)이므로 **대출을 늘릴수록 수익률이 낮아지고, 50%에서 월 현금흐름이 음수로 뒤집힙니다.** 표 바로 아래에 씁니다.

수익률은 기준을 병기합니다 — `2.24% (÷ 매매가)` · `2.28% (÷ 매매가 − 보증금)`. 운영비가 없으므로 **"순수익률"이라는 말을 쓰지 않습니다.**

### 2.3 토지 가치 — 이 물건의 실제 논지

임대 수익률 2.24%만 보면 살 이유가 없습니다. 이 물건은 다른 축이 있습니다.

```
공시지가 총액 49.19억  ·  매매가 250억  →  5.08배
현행 용적률 398.8%  /  법정 상한 400%  →  잔여 1.2%p
```

**용적률 여력이 사실상 없습니다.** 그래서 `land_value_first` 프리셋을 써도 개발 논리가 서지 않고, 소구점은 "선유도역 95m · 2018년 준공 · 용적률 소진 완료"라는 **완성형 자산**입니다. 시스템은 이것을 자동으로 판단하지 못합니다 — §4.6.

### 2.4 확인사항 7건

```
· 임대차계약 11건의 최초 계약일
· 임차인 대항력 요건 (사업자등록 여부)
· 운영비 내역
· 등기부등본 — 근저당·권리 제한
· 만료 경과 11건 · 임대중 전 호실 — 묵시적 갱신 확인
· 건물 사진 4매 — 표준 최소 6매(외부3·내부3) 미달
· 사진 화질 미달 3매 — cadastre · hero · map
```

보강 전에는 9건이었습니다. **중개인이 표지 정본과 첨부 공부를 확정하자 두 건이 사라졌습니다** — 그렇게 사라져야 정상입니다(§3.8).

**이 면이 길다고 부끄러워할 일이 아닙니다.** 확인사항이 비어 있는 IM이 오히려 의심스럽습니다.

## §3 이번에 고친 것 9건

샘플을 만들다 발견한 것들입니다. 전부 실제 결함이었습니다.

### 3.1 X03 판정 문구 — "일치 (11.13%)"

```
고치기 전   X03  계약면적 합 ≤ 연면적   2,213.68  2,490.88   일치 (11.13%)
고친 뒤     X03  계약면적 합 ≤ 연면적   2,213.68  2,490.88   충족
```

**부등식 검사에 등식 판정 문구를 쓰고 있었습니다.** 11.13%는 공용·기계실 비율이지 오차가 아닌데, "일치" 옆에 11.13%가 붙으면 읽는 사람이 어긋난 것으로 봅니다. 검사 성격(등식/부등식)에 맞는 말을 쓰도록 고쳤습니다.

### 3.2 잠금 사유가 이미 받은 것까지 요구

```
고치기 전   gross_income  "관리비·부담 주체 미입력"
고친 뒤     gross_income  "관리비 부담 주체 미입력"
```

관리비 **금액**은 12행 전부 받았습니다. 없는 것은 **부담 주체**뿐입니다. 고정 문구를 쓰면 이미 준 것을 또 달라고 하게 되고, 중개인이 두 번 찾습니다. `evaluate()`가 **실제로 빠진 필드만** 이름으로 말하도록 바꿨습니다.

### 3.3 다음 단계가 물건 이름으로 분기

```python
# 고치기 전 — 원인 A · 하드코딩
if c.fixture_id == 'dangsan':
    steps.append('연면적 확정 …')
else:
    steps.append('정본 확정 …')
    steps.append('서류 교체 …')
```

게이트가 풀려도 문구가 남습니다. 실제로 보강 후 G19·G21이 해소됐는데 모바일 IM에는 여전히 "표지 요약과 각 행의 합 중 어느 쪽이 맞는지 확인"이 떠 있었습니다. **열려 있는 게이트에서 생성**하도록 바꿨습니다.

같은 이유로 "공부 조회"·"비교사례 확보"도 이미 확보됐으면 내지 않습니다.

### 3.4 "무엇이 열리나" 안내가 이미 채운 것을 요구

```
고치기 전   "임대면적·적용법령·관리비·시작일이 채워지면 평당 단가가 열립니다"
            ← R2 인데 R1→R2 안내를 하고 있었습니다
고친 뒤     "최초 계약일·대항력이 채워지면 갱신요구권이 열립니다"
```

**다음 한 단계만 말합니다.** 조사도 받침에 맞춰 고릅니다 — "계약 경과이" → "계약 경과가".

### 3.5 필드 라벨에 금지어

`rr_as_of`의 라벨이 **"렌트롤 기준일"**이었습니다. 정본 §6.1이 `렌트롤 → 임대 현황`을 규정하는데, 이 라벨이 잠금 사유로 산출물에 나가면서 §6.1 위반이 잡혔습니다. "임대 현황 기준일"로 고쳤습니다.

> 규칙을 SSoT로 모아 두면 **규칙 자신에게도 규칙을 적용**할 수 있습니다. 필드 43개·블록 47개의 라벨을 금지어 26종·치환 14쌍에 대조해 이 한 건을 찾았습니다.

### 3.6 렌더 기준본 삭제 실패가 면수 판정을 속임

기준본을 갱신할 때 마운트 환경에서 `unlink`가 막혀 파일 내용만 비웠습니다. 그랬더니 15면 → 14면으로 줄었는데 기준본 파일은 15개가 남아 **면수 비교가 계속 틀렸습니다.** 지우지 못하면 예외를 던지도록 바꿨습니다.

### 3.7 같은 IM 안에서 평당가가 두 값이었습니다 🔴

```
표지 · 개요 · 토지가치 면    15,933만원/평   ← 코어 산출
한 장 요약 면              1억 5,923만원   ← 손으로 쓴 카피
```

**10만원 차이의 오타가 IM 안에 살아 있었습니다.** 요약 면의 문장이 `build_pptx_kr.COPY`에 손으로 적혀 있었기 때문입니다. 검사기 다섯 층이 전부 통과했습니다 — 어느 검사도 "같은 지표가 면마다 같은 값인가"를 보지 않습니다.

자리표시자로 바꿔 코어 값이 채우게 했습니다.

```python
'토지 평당 {land_pyeong} — 인근 1.38억~1.85억 범위 내'
```

> **손으로 쓴 카피에 숫자를 적으면 반드시 어긋납니다.** 강조할 내용은 사람이 고르되 수치는 코어에서 받으십시오.

### 3.8 해소된 게이트의 문구가 남았습니다

보강으로 G19·G21을 해소했는데 리스크 칸에는 여전히 이렇게 적혀 있었습니다.

```
· 표지 요약과 원장 합계 월 360만원 불일치 (연 4,320만원)
· 첨부 공부 오첨부 (R1판) — 정본 필지 교체 필요
```

확인사항 목록(`core.DEFICIENCIES`)과 리스크 목록(`COPY[fid]['risk']`)이 **물건별 고정 배열**이라 게이트가 풀려도 그대로 남습니다. 게이트별 문구 패턴을 두고 **해소되면 함께 지우도록** 했습니다.

### 3.9 확인사항이 8건에서 잘려 사라졌습니다 🔴

리스크 면 배지에는 "확인 필요 11건"이라 쓰고 본문은 `items[:8]`로 **8건만 그렸습니다.** 3건이 조용히 사라졌습니다 — **불변조건 13(결손은 사라지지 않고 확인사항으로 이동한다) 위반**입니다.

8건을 넘으면 마지막 칸에 `외 N건 — 모바일 IM 에 전량 표기`를 씁니다. 사진 화질 3줄은 한 줄로 묶었습니다.

## §4 한계 9건

### 4.1 만료 게이트가 계산된 적이 없었습니다 🔴

픽스처에 이렇게 적혀 있었습니다.

```json
"gatesNotEvaluable": ["F12", "F13"]
```

**"평가 불가"로 적혀 있을 뿐 아무도 계산하지 않았습니다.** 양평동은 11건 전부가 만료일을 지났는데 게이트가 조용했습니다.

이번에 `expiry_gates()`를 구현했습니다. 그러면서 **규격도 한 건 고쳤습니다.**

> 🔴 **만료 경과 = 공실이 아닙니다.**
> 상가건물임대차보호법 제10조 갱신요구권과 민법 제639조 묵시의 갱신이 있어, 만료일이 지나도 임차인이 계속 점유하면 계약이 유지됩니다. 그래서 G23(만료 비율 50% 초과)을 **차단에서 경고로 내렸습니다.** 만료와 함께 상태가 '공실'로 뒤집힌 경우에만 차단입니다.

원래 규격대로 차단했다면 이 물건은 발행 자체가 막혔을 텐데, 실무적으로는 **묵시적 갱신 확인이 필요한 정상 물건**입니다. 규격이 실무를 몰랐던 것입니다.

**남은 한계** — 묵시적 갱신인지 실제 공실인지는 시스템이 알 수 없습니다. 확인사항으로 넘깁니다.

### 4.2 임대면적의 출처가 원장이 아닙니다

12행 중 11행의 면적이 **공부 층별개요**에서 왔고, 그것도 바닥면적이 아니라 **계약면적**입니다.

```
계약면적 합 2,213.68㎡  vs  연면적 2,490.88㎡
차이 277.20㎡ = 공용·기계실  →  임대면적 비율 88.9%
```

임대차계약서상의 면적과 다를 수 있습니다. 표에 출처를 병기하지만, **평당 임대료를 이 면적으로 계산하면 계약서 기준과 어긋날 수 있습니다.**

### 4.3 사진이 상용 기준에 미달합니다

```
제출 4매 (최소 6매)  ·  그중 3매가 해상도 하한 미달
내부 사진 0매  →  갤러리 내부 면 생략
```

등급은 A인데 **사진 때문에 상용 품질이 아닙니다.** 데이터 해상도와 자산 품질은 별개 축이라는 것이 이 사례의 교훈입니다.

그리고 표지 사진에 **건물 외벽 간판이 찍혀 있습니다.** 마스킹 파이프라인이 미구현이므로 지금 이 파일은 **대외 발행할 수 없습니다** — 불변조건 14.

### 4.4 검사기가 사진 장수를 셀 수 없습니다

정본 §9.1의 "사진 6장 이상"을 `standard_check`가 **문자열 `사진`이 있는지로만** 보고 있었습니다. 사진이 2매여도 통과합니다.

산출물에서 셀 수도 없습니다 — 같은 원본을 여러 면에 배치하면 `ppt/media` 항목이 늘어나 과다 계상됩니다(양평 4매 → media 9개).

**항목명을 "사진 면 존재"로 바로잡고, 장수 판정은 생성 시점 게이트 G26으로 옮겼습니다.**

### 4.5 표지 합계 불일치의 정본을 시스템이 정할 수 없습니다

원장 표지에는 월세 5,017만원, 각 행의 합은 4,657만원 — **360만원 차이**입니다. 연 4,320만원이고 매매가 250억 기준 수익률 0.17%p입니다.

시스템은 "각 행의 합을 쓴다"고만 정할 수 있습니다. **어느 쪽이 맞는지는 중개인이 원장으로 확정해야 합니다.** 공공데이터로 풀리지 않습니다.

### 4.6 소구점 판단은 자동화되지 않습니다

양평동은 용적률 잔여가 1.2%p뿐이라 개발 논리가 서지 않습니다. 그런데 `land_value_first` 프리셋을 고르면 시스템은 토지 가치를 앞으로 끌어옵니다 — **여력이 없다는 사실과 무관하게.**

프리셋 선택은 사람이 합니다. 자동 추천 규칙(`아키타입 ↔ 프리셋` 매핑)은 아직 SSoT가 아닙니다(S1 잔여).

### 4.7 카피의 절반은 아직 사람이 씁니다

`build_pptx_kr.COPY`에 물건별 문구가 들어 있습니다.

```python
'tags_R2': ['선유도역 95m', '2018년 준공', '용적률 398.8%'],
'points_R1': [...], 'upside': [...], 'risk': [...]
```

수치는 코어에서 오지만 **무엇을 강조할지는 사람이 정합니다.** 이 부분이 LLM으로 넘어가면 §4.8의 문제가 생깁니다.

### 4.8 같은 지표가 면마다 같은 값인지 아무도 안 봅니다 🔴

§3.7의 평당가 오타를 **검사기 다섯 층이 전부 통과시켰습니다.**

```
정본 준수    통과   — 금지어·문장길이·필수요소만 봅니다
결함 26종    통과   — basis 누락·중복·환각 패턴만 봅니다
불변조건     통과   — 원장 대조만 봅니다
렌더 스냅샷  통과   — 기준본과 같으면 통과입니다
수치 동일성  해당없음 — Python↔TS 대조이지 면↔면 대조가 아닙니다
```

**면 간 일관성(cross-page consistency) 검사가 없었습니다.** 자리표시자로 원인은 막았지만, 누가 다시 손으로 숫자를 적으면 똑같이 통과합니다. 그래서 `qa/consistency_check.py`를 만들었습니다.

```
$ python3 qa/consistency_check.py <산출물 4종>
  통과  양평동_IM_D22_A등급.pptx
  통과  당산동_PPTX_IM_KR_R2.pptx
  통과  양평동_IM_D22_A등급_모바일.html
  통과  당산동_모바일IM_R2.html
```

미탐 검사 — 요약 면의 평당가를 오타로 되돌려 넣으니 잡습니다.

```
🔴 토지 평당가 — 면마다 값이 다릅니다:
     159,330,000 (slide1,3,9,12) / 159,230,000 (slide2)
```

억·만 혼용을 정규화해 비교합니다. `1억 5,923만원`과 `15,923만원`은 같은 값입니다.

**만드는 과정에서 오탐도 한 번 겪었습니다** — `평당`만 보면 연면적 평당가·공시지가 평당가까지 같은 지표로 묶여 3건이 잘못 잡혔습니다. 같은 지표끼리만 비교하도록 좁혔습니다.

**남은 한계** — 지표 6종만 봅니다. 표 안의 값과 본문 문장의 값을 대조하지는 못합니다.

### 4.9 물건 간 문장 중복을 지금 규칙으로는 다 못 잡습니다

당산동 R2와 대조하면 **사실 주장 공통 0건**으로 깨끗합니다. 그런데 "정책·방법론"으로 분류된 7건 중에 이런 문장이 있습니다.

```
잔금 일정 확정 전에 대출 승인을 받으시길 권합니다
```

이것은 정책이 아니라 **견해(OPINION)**이고 두 물건에 똑같이 들어가 있습니다. 지금 판별은 "숫자가 없으면 정책"이라 통과시킵니다. 문형 태그 기반 판별(FR26)이 들어와야 잡힙니다.

## §5 주의 포인트 11

개발팀·중개인이 실제로 걸려 넘어질 자리입니다.

### 5.1 등급 A가 "발행 가능"을 뜻하지 않습니다

```
등급 A     = 데이터 해상도가 충분하다
발행 가능  = 차단 게이트가 0이다
상용 품질  = 그 위에 사진·마스킹·사람 심사까지 통과했다
```

양평동은 A이고 차단 0이지만 **사진 마스킹 미구현으로 대외 발행 불가**입니다. 세 가지를 같은 말로 쓰지 마십시오.

### 5.2 보강 입력은 원장을 덮어쓰지 않습니다

`broker_inputs/`는 원장 **위에** 얹힙니다. 원장 파일을 직접 고치면 나중에 "누가 무엇을 바꿨는지"를 추적할 수 없습니다. 재현 감사(FR29)가 성립하지 않습니다.

### 5.3 공공데이터가 L축을 올릴 수 있습니다

L축은 임대차, P축은 물건자료 — 독립처럼 보이지만 아닙니다. **공부 층별개요가 임대면적을 채우면 L축이 R1→R2로 올라갑니다.** 이때 출처 등급이 S3에서 S1으로 바뀌므로 표에 반드시 병기하십시오.

### 5.4 기준일 없이 만료를 판정하지 마십시오

기준일이 없으면 시스템은 "오늘"을 씁니다. 원장이 1년 전 것이면 **전부 만료로 나옵니다.** 양평동이 정확히 그 상태였습니다. G18(기준일 부재)이 경고인 이유가 이것입니다 — 경고를 무시하면 그 아래 모든 만료 판정이 틀립니다.

### 5.5 필수 슬롯 사진은 화질이 나빠도 씁니다

표지 사진이 없는 IM은 한국 시장에서 성립하지 않습니다. 흐려도 넣고 재촬영을 안내합니다. **선택 슬롯은 반대** — 흐린 사진으로 갤러리를 채우지 않습니다.

### 5.6 빈 면을 만들지 마십시오

내부 사진 0매일 때 "사진 미제출"만 적힌 면을 낼지 고민했고, **내지 않기로** 했습니다. 확인사항이 이미 말하고 있고, 빈 면은 심사 5항("이 면을 지우면 아쉬운가")을 통과하지 못합니다.

1매 이상 있는데 부족한 경우에는 **있는 것을 보여주고 안내를 병기**합니다. 그래서 정책이 `placeholder_if_partial`입니다.

### 5.7 페이지 순서를 코드에 두지 마십시오

`im.pages.yaml`을 고치면 코드 수정 없이 순서가 바뀝니다. 이 샘플에서 프리셋 3종이 같은 코어로 다른 순서를 냅니다. **순서를 코드에 두면 프리셋이 존재할 이유가 없습니다.**

### 5.8 스위치 이름을 두 곳에 두지 마십시오

`crosscheckPage`·`farGaugePage`가 `presets.py`와 `im.pages.yaml` 양쪽에 있어서 실제로 어긋났습니다 — 처음 빌드에서 두 면이 통째로 빠졌습니다. **페이지 편성 스위치는 `im.pages.yaml`이, 스타일 스위치는 `presets.py`가 소유**하도록 나눴습니다.

### 5.9 확인사항 한 줄도 45자를 넘지 않습니다

만료 게이트 문구를 넣었더니 §4.7 위반이 났습니다. 그리고 "월세 비중 100%"라고 썼더니 §6.3 금지어(`100%`)에 걸렸습니다. **비중이 전부일 때는 숫자가 아니라 말로 씁니다** — "임대중 전 호실".

### 5.10 카피에 숫자를 손으로 적지 마십시오

강조할 **내용**은 사람이 고르고 **수치**는 코어에서 받습니다. 자리표시자를 쓰십시오.

```python
'토지 평당 {land_pyeong} — 인근 1.38억~1.85억 범위 내'   # 좋음
'토지 평당 1억 5,923만원 — 인근 1.38억~1.85억 범위 내'    # 나쁨 · 실제로 틀렸습니다
```

### 5.11 로그와 확인사항에 값을 담지 마십시오

`"업종이 원문과 다름 1건: 5행"` — 행 번호만 냅니다. 값을 담으면 로그가 임차인명·금액이 새는 경로가 됩니다.
