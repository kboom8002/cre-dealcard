## 2. 🔴 치명적 결함 6건

### 2.1 Cap Rate에 근거 없는 0.85

```
Cap Rate (Base) = (월임대료 × 12 × 0.85) ÷ 매매가 × 100
NOI = 월임대료 × 12 × (1 − 공실률/100) × 0.85
```

**0.85가 어디서 왔는지 8개 문서 어디에도 없습니다.** 운영비 15%를 하드코딩한 것으로 보입니다.

| 물건 | 시스템 산출 | `gross_price` | 오차 |
|---|--:|--:|--:|
| 당산동 | **1.73%** | 2.03% | −0.30%p |
| 양평동 | **1.90%** | 2.24% | −0.34%p |

문제는 세 겹입니다.

| # | 문제 |
|:-:|---|
| 1 | **물건별 실제 운영비와 무관한 고정 계수** — 관리비 별도 징수 물건과 포함 물건이 같은 값 |
| 2 | **가정치를 NOI(실측 개념)로 명명** — 매수인은 실제 순영업수익으로 읽습니다 |
| 3 | **`basis-enforcer`가 "(현행 임대료 기준)"을 붙여도 0.85 적용 사실은 안 밝혀짐** |

> 당산동 원본 IM은 3.1%(정상화·보증금차감), 표준은 2.03%(gross). **시스템은 1.73% — 어느 것도 아닌 제4의 숫자**를 냅니다.

**조치** — 0.85를 제거하고 `CapRateBasis` 7종으로 명시 산출. 운영비를 아는 물건만 `noi_price`를 냅니다.

### 2.2 실투자금에 취득비용 누락

```
실투자금 = 매매가 − 대출금 − 보증금 합계
```

**취득세 4.6%와 중개보수가 빠졌습니다.**

| 물건 (LTV 50%) | 시스템 | 실제 | 누락 | 오차율 |
|---|--:|--:|--:|--:|
| 당산동 | 54.6억 | 60.9억 | **6.33억** | **11.6%** |
| 양평동 | 120.0억 | 133.8억 | **13.75억** | **11.5%** |

**"실투자금(내 돈)"이라고 부르는데 실제로는 6억이 더 듭니다.** 50~60대 매수인이 자금 계획을 세우는 바로 그 숫자입니다.

### 2.3 자기자본수익률이 모듈마다 다름

| 모듈 | 산식 | 당산동 산출 |
|---|---|--:|
| `financials.ts` | NOI ÷ 실투자금 | **+3.64%** |
| `net-cash-flow-calculator.ts` | 연 순수익 ÷ 실투자금 | **−0.46%** |
| 실제 (취득비용 반영) | 연 순수익 ÷ 실투자금 | **−0.41%** |

**같은 지표에 세 값이 존재합니다.** 첫 번째는 이자를 안 뺐고, 두 번째는 운영비를 안 뺐습니다. 부호가 반대라 결론이 뒤집힙니다.

같은 문서 안에서 Cap Rate는 0.85를 곱하고 월 순수익은 안 곱하는 **기준 혼재**도 있습니다.

### 2.4 역레버리지를 "강점"으로 고정 편성

`investment_thesis` income 오버레이의 3대 포인트 중 하나입니다.

```
• 레버리지 효과: 대출 활용 시 자기자본수익률 및 향후 자산가치 상승 여력
```

| 물건 | 수익률 | 대출금리 4.5% | 판정 |
|---|--:|:-:|---|
| 당산동 | 2.03% | > | **역레버리지** |
| 양평동 | 2.24% | > | **역레버리지** |

**두 물건 모두 대출할수록 손해인데 "레버리지 효과"가 무조건 편성됩니다.** 구조적 오도입니다.

**조치** — 3대 포인트를 고정 목록이 아니라 **조건부 선택**으로. `수익률 < 대출금리`면 레버리지 포인트를 빼고 **역레버리지 경고**로 대체합니다.

### 2.5 자가사용 개념 부재

| | 당산동 |
|---|---|
| 시스템 `vacancy_signal` | **"만실" → 공실률 0%** |
| 실제 자가사용 | 400.25㎡ / 1,441.15㎡ = **27.8%** |

**임대 안 되는 면적이 27.8%인데 "만실"로 표기됩니다.** `leaseState` 3값(임대중/공실/자가사용) 개념이 없어 공실로 넣어도 만실로 넣어도 틀립니다.

자가사용은 **공실 손실이 아니라 임대 전환 여력**이므로 별도 분류가 필요합니다.

### 2.6 할루시네이션 탐지 임계값이 무의미

```
가격: 매매가 × 20배 초과 or 1/20 미만
면적: 연면적 × 50배 초과 or 1/50 미만
```

매매가 115억이면 임계는 **2,300억 / 5.75억**입니다.

| 실제 발생 오류 | 크기 | 20배 임계 탐지 |
|---|--:|:-:|
| 양평동 월세 4,657만 → 5,017만 | +7.7% | **✗ 불가** |
| 당산동 계 행 1,441 → 1,141㎡ | −20.8% | **✗ 불가** |
| 업종 11개 전건 조작 | — | **✗ 불가** |

**실무에서 실제로 발생한 오류는 하나도 못 잡습니다.** 정작 필요한 건 **합계 일치 검증**인데 파이프라인에 없습니다.

### 4.2 효과성 (2/5)

**가드레일 6단계가 실제 오류를 못 잡습니다.**

| 가드레일 | 어제 발견 오류 탐지 여부 |
|---|:-:|
| ① 할루시네이션 (20배) | ✗ |
| ② LLM-as-Judge | **✗ 문체가 유창하면 통과** |
| ③ 결정론적 렌트롤 | **○ 유일하게 유효** |
| ④ 용어 정규화 | △ 방향이 반대 (§4.4) |
| ⑤ Risk Boundary | ○ "적극 추천" 등 광고 문구는 잡음 |
| ⑥ Disclosure Guard | ○ PII·면책 |

**②가 위험합니다.** Judge는 LLM이고, 어제 평가한 생성물은 **업종 11개가 전부 허구인데도 문장은 유창**했습니다. Judge 4.5 이상이면 **자동 Golden 승격**되므로 **오류가 자기강화**됩니다.

> **Golden 승격에 사람 승인을 강제해야 합니다.** 문서에 "브로커 수정본 우선"이 있지만 자동 승격 경로가 별도로 살아 있습니다.

**교차검증도 범위가 좁습니다.**

| 검증 대상 | 있음 | 없음 |
|---|:-:|---|
| 공실률·연면적·매매가·Cap Rate | ○ | |

| **표지 요약 = 렌트롤 합계** | | **✗** |
| **첨부 공부 소재지 = 본건** | | **✗** |

**세 가지 모두 실매물에서 실제로 발생한 오류**입니다.

**"불안감 해소"가 목표가 되면 리스크를 축소 서술하게 됩니다.** 그리고 **"자료를 못 받았다"는 항목 자체가 미션에 없습니다.**

```

```

매수인 CTA(전화·자료요청·현장방문)가 없습니다.

### 5.2 P0-1 · CapRateBasis 도입

```ts
// ❌ 현행 — financials.ts
const capRate = (monthlyRent * 12 * 0.85) / price * 100;

// ✅ 개선
export function computeYields(i: FinancialInput): YieldSet {
  const annual = i.monthlyRentKrw * 12;
  const out: YieldSet = {
    gross_price:         { value: annual / i.priceKrw * 100, basis: 'gross_price' },
    gross_price_deposit: { value: annual / (i.priceKrw - i.depositKrw) * 100,
                           basis: 'gross_price_deposit' },
  };
  // 운영비를 아는 물건만 NOI 계열 산출 — 추정 금지
  if (i.opexKrw != null) {
    out.noi_price = { value: (annual - i.opexKrw) / i.priceKrw * 100, basis: 'noi_price' };
  }
  return out;
}
```

**운영비를 모르면 NOI를 내지 않습니다.** 0.85로 만들어내지 않습니다.

### 5.3 P0-2 · 총취득원가

```ts
export const ACQ_TAX_RATE = 0.046;   // 취득세 4.0 + 지방교육세 0.4 + 농특세 0.2

export function computeEquity(i: FinancialInput): EquityBreakdown {
  const tax  = i.priceKrw * ACQ_TAX_RATE;
  const fee  = i.brokerFeeKrw ?? i.priceKrw * 0.009;
  const total = i.priceKrw + tax + fee + (i.otherCostKrw ?? 0);
  return {
    totalAcquisitionCost: total,
    equity: total - i.depositKrw - (i.loanKrw ?? 0),
    breakdown: { price: i.priceKrw, tax, fee },   // 화면에 반드시 표시
  };
}
```

**내역을 반드시 노출합니다.** 매수인이 검산할 수 있어야 합니다.

### 5.4 P0-3 · 합계 일치 검증

```ts
export function validateTotals(ctx: IMContext): Violation[] {
  const v: Violation[] = [];
  const rollRent = sum(ctx.floorLeases.map(l => l.monthlyRentKrw ?? 0));
  if (ctx.monthlyRentTotalKrw && rollRent !== ctx.monthlyRentTotalKrw) {
    v.push({ code: 'G19', block: true,
      msg: `표지 월세 합계(${fmt(ctx.monthlyRentTotalKrw)})와 렌트롤 합계(${fmt(rollRent)})가 다릅니다. 어느 쪽이 정본입니까?` });
  }
  const rollArea = sum(ctx.floorLeases.map(l => l.leaseAreaSqm ?? 0));
  if (ctx.statedTotalAreaSqm && Math.abs(rollArea - ctx.statedTotalAreaSqm) / rollArea > 0.02) {
    v.push({ code: 'C19', block: true,
      msg: `임대면적 합계(${rollArea.toFixed(2)}㎡)와 표기 연면적(${ctx.statedTotalAreaSqm}㎡)이 다릅니다.` });
  }
  for (const d of ctx.attachedDocs) {
    if (d.address && !samePnu(d.address, ctx.address)) {
      v.push({ code: 'G21', block: true, msg: `첨부 ${d.kind}의 소재지가 본건과 다릅니다: ${d.address}` });
    }
  }
  return v;
}
```

**세 검증 모두 실매물에서 실제 발생한 오류**를 겨냥합니다. 20배 임계보다 이쪽이 훨씬 유효합니다.
