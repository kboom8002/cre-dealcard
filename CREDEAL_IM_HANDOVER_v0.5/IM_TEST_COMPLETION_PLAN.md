## 1. MECE 분할 — 무엇을 고정하고 무엇을 변화시키는가

계층을 "단위/통합/E2E"로 나누면 경계가 흐려집니다. **고정과 변화**로 나눕니다.

| 층 | 고정 | 변화 | 실행기 | 결정론 | 케이스 |
|:-:|---|---|---|:-:|--:|
| **L1** | 입력 | 계산 하나 | pytest · vitest | 완전 | 14 |
| **L2** | 슬롯 상태 | 판정 코드 하나 | pytest | 완전 | 38 |
| **L3** | 픽스처 | 편성 (L·M·섹션) | pytest | 완전\* | 29 |
| **L4** | 픽스처 + 렌더러 | 파일 산출물 | `qa/*.py` | 완전\* | 18 |
| **L5** | 메모 원문 | 4단계 전체 | playwright · 실 LLM | 🔴 **불완전** | 24 |

\* 문장 제외

### 1.1 겹치지 않는 이유

각 층은 **위 층이 고정한 것을 변화시킵니다.** L2는 L1의 계산을 참으로 두고
판정만 봅니다. L3는 판정을 참으로 두고 편성만 봅니다.

**같은 것을 두 층에서 보면 하나가 거짓 안심입니다.** 실제로 그랬습니다 —
렌트롤 전량(불변조건 18)이 **4곳**에서 시험되고 있습니다
(`TEST_PLAN` RG-A03-01 · `invariant_check.py` · `parity.spec.ts` · grep 검사).

### 1.2 🔴 L5에서 문장을 단언하지 않습니다

LLM 출력은 재현되지 않습니다. **구조·수치·게이트만** 단언합니다.
문장을 단언하면 프롬프트를 고칠 때마다 테스트가 깨지고, 곧 테스트를 끕니다.

문장 품질은 **골든 심사(사람)** 와 `golden/verify_golden.py`(금지어·페르소나·
지번 노출)가 봅니다.

## 3.4 🔴 테스트가 스스로를 의심합니다 — 대조군

V3 를 처음 채점했을 때 **8건 해소**로 나왔습니다. 틀렸습니다. 실제로는 6건입니다.

| 검사 | 무엇이 잘못됐는가 |
|---|---|
| `_v2_fail_open` | 식이 `A or B` 인데 **`B` 가 항상 참** — 조건 전체가 무조건 참. Fail-Open 이 글자 그대로 남아 있는데 통과했습니다 |
| `_v2_partial_output` | V2 리터럴만 봤습니다. V3 가 말을 바꾸자 빗나갔고, **결함은 오히려 커졌는데** 통과했습니다 |

**무력화된 검사는 "통과"라고 말하기 때문에 없는 것보다 나쁩니다.**

### 3.4.1 규칙

`tests/control_v2/` 에 **V2 3종 사본**을 두었습니다. 수정하지 않습니다.

```
V2 는 그 결함을 가지고 있던 판입니다.
따라서 그 결함을 잡는 검사는 V2 에서 반드시 실패해야 합니다.
V2 에서 통과하면 그 검사는 아무것도 보고 있지 않습니다.
```

`test_v3_checks_are_falsifiable()` 이 매 실행마다 전 적합성 검사를 대조군에
돌리고, 하나라도 통과하면 **공허하다고 보고 차단**합니다.

이것은 §3.1 negative 짝 규칙을 **명세 검사에 적용한 것**입니다.

```
positive  현행에서 통과하는가   →  오탐 0
negative  V2 에서 잡아내는가    →  미탐 0   ← 새로 생긴 쪽
```

|---|---|
| `_v2_qg_not_blocking` | 차단 여부는 **상위 제목**에 적히는데 행 안에서만 찾았습니다 |

생성 경로가 없습니다. 모든 결손이 모여야 하는 자리인데 채울 사람이 없습니다.

🔴 **면제는 예외이지 기본값이 아닙니다.** `test_falsifiable_exemptions_are_justified()`
가 사유 없는 면제와 죽은 항목을 막습니다.

## 6. 실행 — Antigravity 페어 코딩

### 6.1 케이스는 레지스트리에, 구현은 골격에

```
credeal/ssot/im.tests.yaml   무엇을 시험하는가 (88건)
       ↓
tests/test_registry.py       어떻게 시험하는가 (IMPL 딕셔너리)
       ↓
qa/test_coverage.py          몇 개가 실제로 도는가
```

**케이스를 코드에 적지 않습니다.** 레지스트리에 적고 `IMPL`에 함수를 등록하면
자동으로 실행됩니다. 등록 전까지는 `xfail`로 뜹니다 — **skip이 아닙니다.**
skip은 목록에서 사라지지만 xfail은 "아직 안 됨"으로 남아 세어집니다.

### 6.2 한 케이스를 구현하는 절차

```
1  im.tests.yaml 에서 케이스를 고릅니다 (status: 미구현)
2  target 코드가 CATALOG_RULES 에 등록돼 있는지 확인합니다
3  tests/test_registry.py 의 IMPL 에 함수를 등록합니다
4  status: 구현됨 · impl: 경로 로 레지스트리를 갱신합니다
5  게이트·제약이면 **negative 짝**을 함께 만듭니다
6  python3 qa/test_coverage.py --set-baseline
```

4번을 빠뜨리면 `test_impl_registered_cases_marked_done`이 잡습니다.

### 6.3 실행

```bash
pytest tests/ -q                  # 전체
pytest tests/ -q -k G28           # 코드별
pytest tests/ --collect-only -q   # 케이스 목록만

python3 qa/test_coverage.py       # 커버리지 · 스테일 · negative 짝
```

**현재 123 케이스 · 통과 12 · xfail 111(알려진 결함 11 포함) · 실패 0**
(pytest 미설치 환경에서는 골격을 직접 구동해 검증했습니다.)
