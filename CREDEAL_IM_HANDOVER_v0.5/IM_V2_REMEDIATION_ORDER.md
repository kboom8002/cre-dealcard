### M-10 상세 — 왜 이것이 중대한가

**계산 지점이 여러 개면 같은 지표가 반드시 갈립니다.** BL-8의 근본 원인입니다.

다른 면은 "1억 5,923만원"이 됩니다. **애초에 ⑤에서 둘 다 만들어 담아야 합니다.**

## 5. 그 밖에 짚어야 할 것 4건

### 5.1 `QG`에 차단 권한을 주었습니다

```
02:202~214   QG01~QG08 · QG10 = 차단(Block)
```

**개명은 했는데 역할 분리는 안 했습니다.** `IM_QUALITY_GATES` §7.1 —
`QG` 실패는 **재시도 또는 알림**이고, 4xx 차단은 `G` 전용입니다.
발행 게이트와 운영 게이트를 나눈 이유가 사라집니다.

### 5.2 `QG17·18·19` 결번

```
02:200   "17개(QG01~QG20)"
```

`ONTOLOGY_V0.5_SPEC` §4.5 — **결번으로 두는 것은 금지**입니다.
채우거나 명시적으로 폐기하십시오. 더하여 `applies_to` 미부착,
`im.errors.yaml` 미등록 — **3중 위반**입니다.

### 5.3 Fail-Open

```
02:241   LLM 호출 실패 시 passed:true 로 안전 통과
```

검사기가 죽으면 통과시킵니다. **안전한 방향이 반대입니다** —
검사하지 못했으면 `system_error`로 올리고 사람이 봐야 합니다.

### 5.4 A07 빈 데이터 시 리스크 날조

```
03:290   빈 데이터 → 3개 표준 CRE 리스크 필러 자동 생성
```

🔴 **없는 리스크를 렌더러가 지어냅니다.** 불변조건 13 · `G02`(빈 플레이스홀더) 위반.
비어 있으면 확인사항으로 보내야지 채워 넣으면 안 됩니다.

## 6. 착수 순서

```
0  promptVersion 도입           ← BL-7 멱등의 선행
   │
1  BL-5 아키타입 재배정 + 재판정  ← 다른 편성 작업의 선행
   │
2  BL-1 · BL-3 · BL-6 · BL-8    ← 발행 안전 4건 (병렬 가능)
   │
3  BL-2 · BL-4                  ← 렌더 유실 2건
   │
4  BL-9 + M-1~M-3               ← 계약·등급 (MIGRATION_RUNBOOK V5-4 와 동시)
   │
5  M-5 · M-6 · M-7 · M-8        ← 출처·게이트
   │
6  M-10 파생 계산 ⑤로 이동       ← BL-8 의 근본 해소
   │
7  M-4 · M-11 · 경미 8건
```

**0번이 먼저인 이유** — `promptVersion` 없이 멱등키를 만들면 프롬프트를 고쳐도
같은 키가 나와 캐시가 낡은 문장을 돌려줍니다. 멱등이 있으나 마나 합니다.

**1번이 먼저인 이유** — 아키타입이 틀린 채로 `L02` 편성을 고치면,
**틀린 분기 위에서 테스트가 통과합니다.**
