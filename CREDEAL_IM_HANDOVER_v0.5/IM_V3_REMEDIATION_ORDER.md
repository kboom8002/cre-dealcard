## 7. 이번에 바뀐 것 — 테스트가 스스로를 의심합니다

§0.1 에서 적었듯 검사 2건이 거짓 통과했습니다. 원인은 같습니다 —
**검사가 결함을 보는지 아무도 확인하지 않았습니다.**

### 7.1 대조군

`tests/control_v2/` 에 **V2 3종 사본**을 두었습니다. 수정하지 않습니다.

```
V2 는 그 결함을 가지고 있던 판입니다.
따라서 그 결함을 잡는 검사는 V2 에서 **반드시 실패해야 합니다.**
V2 에서 통과하면 그 검사는 아무것도 보고 있지 않습니다.
```

`test_v3_checks_are_falsifiable()` 이 매 실행마다 전 적합성 검사를 대조군에
돌립니다. 하나라도 통과하면 **그 검사를 공허하다고 보고 차단**합니다.

이것이 `qa/test_coverage.py ③` 의 negative 짝 규칙을, 명세 검사에 적용한 것입니다.

```
positive  현행에서 통과하는가   →  오탐 0
negative  V2 에서 잡아내는가    →  미탐 0   ← 새로 생긴 쪽
```

### 7.2 붙이자마자 6건이 더 걸렸습니다

| 검사 | 왜 공허했는가 | 조치 |
|---|---|---|
| `_v2_qg_not_blocking` | 차단 여부는 보통 **상위 제목**에 적히는데 **행 안에서만** 찾았습니다 | 직전 제목을 문맥으로 들고 판정 |
| `_v2_writer_section_count` | 정규식이 0을 내면 `stage == 0` 면제 조건으로 **조용히 통과**했습니다 — 🔴 **0을 정상으로 취급한 것이 결함**입니다 | 숫자가 아니라 **섹션 키 등장 여부**로 전환 → BL-10 을 새로 잡았습니다 |
| `_v3_grade_single_definition` | V2 는 점수가 **별도 칸**, V3 는 등급 칸 안 — 한쪽 형식만 봤습니다 | 두 형식 모두 판정 |
| `_v3_dead_archetype_reuse` | 아키타입 정의는 표가 아니라 **제목**인데 표 행만 훑었습니다 | 제목까지 포함 |
| `L2-INV14-02` · `L3-LEX-03` · `L5-GATE-03` | V2 에 없던 **V3 신설 결함**이라 대조군에서 잡힐 수 없습니다 | `FALSIFIABLE_EXEMPT` 에 **사유와 함께** 등재 |
