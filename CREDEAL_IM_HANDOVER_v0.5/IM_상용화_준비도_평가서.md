## §0 판정

**개발 착수는 가능합니다. 다만 지금 전달하면 상용 IM은 나오지 않습니다.**

세 가지가 서로 다른 이야기입니다.

| 물음 | 답 | 근거 |
|---|---|---|
| 개발팀이 착수할 수 있는가 | **예** | 필드 43·블록 47·게이팅 판정·프리셋 계약·기하 상수까지 기계 판독 가능한 형태로 있습니다 |
| 착수하면 오류 없는 IM이 나오는가 | **아니오** | 불변조건 21 중 3건에 자동 검사가 없고, 그중 1건은 이미 산출물에서 위반이 실측되었습니다 |
| 상용화까지 결정이 남았는가 | **예 — 12건** | §4. 제가 임의로 정하면 나중에 되돌리는 비용이 더 큽니다 |

이 문서는 **"무엇이 준비되었는가"보다 "무엇이 아직 아무 문서에도 없는가"**에 지면을 씁니다. 전자는 이미 D19·D20에 있습니다.

## §2 🔴 상용화 차단 3건

### B1. 이미지 마스킹 미구현 — 불변조건 14 위반 (실측 확인)

불변조건 14는 *"물건명·법인명·임차인명은 대외 문서에 표기하지 않는다"*입니다. 지금까지 이 규칙은 **텍스트에만** 적용되었습니다. 사진은 검사 대상이 아니었습니다.

당산동 산출물에 실제로 들어간 사진을 눈으로 확인한 결과입니다.

| 파일 | 노출 항목 | 근거 |
|---|---|---|
| `hero.jpg` | 임차인 상호 간판 · 보행자 4~5인 얼굴 | 1층 점포 간판 판독 가능 |
| `front.jpg` | 임차인 상호 간판 · 차량 번호판 | 정면 촬영 — 간판이 화면 중앙 |
| `ext1.jpg` | 임차인 상호 간판 · 차량 번호판 | |
| `in_shop.jpg` | 임차인 상호 | 내부 촬영 |

텍스트에서는 "약국"으로 가려 놓고 같은 장의 사진에는 상호가 그대로 찍혀 있습니다. **가린 의미가 없습니다.** 번호판과 얼굴은 개인정보 보호법 문제로 층이 다릅니다 — 임차인 동의로도 해소되지 않습니다.

`credeal/ssot/im.masking.yaml` §images 에 대상 5종·파이프라인 5단계·수용 기준을 적어 두었으나 **`status: 미구현` · `blocking: true`** 입니다. 구현 없이는 대외 발행을 열 수 없습니다.

> **결정 요청** — 자동 검출(번호판·얼굴 검출 모델) + 중개인 확인 2단으로 갈지, 중개인 수동 마스킹만으로 시작할지. 자동 검출은 정확도가 100%가 아니므로 **어느 쪽이든 발행 전 "미처리 이미지 0" 게이트는 필요합니다.**

### B2. 참조구현(Python) ↔ 운영(TypeScript) 포팅 계약 부재

`credeal/`은 Python입니다. 운영 시스템은 Next.js/TypeScript입니다. 지금 전달하면 개발팀이 **손으로 옮깁니다.** 손으로 옮긴 순간 두 벌이 되고, 두 벌은 어긋납니다 — 이 세션에서만 세 번 겪은 일입니다(§B3).

옮기지 말아야 할 것과 옮겨야 할 것을 나눕니다.

| 자산 | 처리 | 이유 |
|---|---|---|
| `input_spec.py` FIELDS/BLOCKS | **옮기지 않음** — `im.gating.yaml`을 런타임에 읽습니다 | 43×47 표를 두 언어로 유지할 수 없습니다 |
| `presets.py` 토큰 | **옮기지 않음** — `im.tokens.yaml` | 색 하나 바꿀 때마다 두 곳 수정은 실패합니다 |
| 어휘·표기·불변조건 | **옮기지 않음** — YAML 4종 | §B3 |
| `core.py` 산식 | **포팅 + 골든 대조** | 언어별 반올림 차이가 있어 수치 동일성 시험이 필요합니다 |
| `copy_im.py` 문형·조사 | **포팅** | 한국어 조사 규칙은 언어 무관 |
| `build_pptx_kr.py` | **재작성** (pptxgenjs) | python-pptx ↔ pptxgenjs 기하 모델이 다릅니다 |

**수치 동일성 시험이 필수입니다.** 같은 픽스처를 Python 참조구현과 TS 운영 코드에 넣어 Hero 3지표·평당가·실투자금·ROE 4종이 **표기 문자열까지** 일치해야 합니다. 반올림 자리에서 갈리면 IM 두 벌이 서로 다른 수익률을 말하게 됩니다.

### B3. 규칙 이중화 — 금지어 교집합 31% (실측)

두 검사기가 각자 금지어 목록을 갖고 있었습니다. 같은 정본을 근거로 삼았는데도 이렇습니다. (아래는 **SSoT 통합 직전**의 인라인 목록입니다. 현재 코드에는 남아 있지 않습니다.)

```
standard_check.py   21종
output_qa.py        13종
교집합               8종   (31%)
─────────────────────────────
standard_check 에만  13종  100% · Zero · 강력 추천 · 놓치면 후회 · 리스크 없음 ·
                          불패 · 서두르 · 안전 보장 · 영구적 · 적극 추천 ·
                          전혀 없음 · 초안정 · 확실한 수익
output_qa 에만        5종  급행 · 보장 · 초역세권 · 확정적 · 희소성
```

**"안전 보장"이라 쓴 IM은 `standard_check`만 통과하지 못하고, "희소성"이라 쓴 IM은 `output_qa`만 통과하지 못했습니다.** 어느 검사를 먼저 돌리느냐로 결과가 달라집니다.

문서 쪽도 같습니다 — `.md` 89개 중 **금지어를 언급한 문서 15개 · 불변조건을 언급한 문서 26개 · 해상도를 언급한 문서 22개**. 사람이 동기화할 수 있는 규모가 아닙니다.

이번에 SSoT 레지스트리로 합쳐 두 검사기를 여기에 물렸습니다(§3). 합집합 26종으로 통일한 뒤에도 **보정은 그대로 통과**했습니다 — 오탐 0 / 미탐 14. 목록을 넓혀도 정본 산출물이 걸리지 않았다는 뜻입니다.

## §4 미정 규격 12건 — 결정 요청

제가 임의로 정하지 않았습니다. 되돌리는 비용이 큰 것들입니다.

| # | 항목 | 쟁점 | 제 의견 |
|---|---|---|---|
| D1 | **PDF 출력 경로** | PPTX→PDF 변환인가, 별도 렌더러인가 | LibreOffice 변환은 서버 폰트·자간이 달라 줄바꿈이 어긋납니다. v4 PDF 결함 일부가 여기서 왔을 가능성이 있습니다. **PPTX와 PDF를 같은 렌더러에서 뽑는 편**을 권합니다 |
| D2 | **폰트 임베딩·대체** | 수신자 PC에 폰트가 없을 때 | 임베딩 없으면 45자 기준 줄바꿈이 무너집니다. 라이선스 확인 필요 |
| D3 | **이미지 최소 해상도** | 규격 없음 | **실측 — 양평동 사진 964×894px.** 13.3in 슬라이드에서 7.5in 폭을 차지하면 128dpi입니다. 인쇄 배포 시 흐립니다. 최소 1500px 장변을 제안합니다 |
| D4 | **EXIF 처리 시점** | 업로드 시인가 발행 시인가 | 업로드 시 제거를 권합니다. 회전 정보는 적용 후 제거 |
| D5 | **다필지 물건** | 대지면적·공시지가·용적률을 어떻게 합산하는가 | 교차검증 X1~X4가 단일 필지 전제입니다. **다필지가 들어오면 지금 시스템은 조용히 틀린 값을 냅니다** |
| D6 | **구분등기 물건** | 대지권 비율 · 집합건물 실거래 대지면적 부재 | RTMS가 집합건물 대지면적을 주지 않습니다. 평당가 산출 기준을 정해야 합니다 |
| D7 | **버전·재발행 diff** | 가격 조정·임차 변동 시 | 어느 수치가 바뀌었는지 수신자에게 보일 것인가. 보인다면 이전 판 보관 기간은 |
| D8 | **공공 API 실패 시 동작** | 차단인가 R1 강등인가 | **R1 강등 + 확인사항 이동**을 권합니다. 차단하면 중개인이 손을 놓습니다 |
| D9 | **캐시 TTL** | 공부·공시지가·실거래 | 공시지가는 연 1회, 실거래는 월 단위. 같은 TTL을 쓸 수 없습니다 |
| D10 | **덱 상한 초과 시** | `Overflow` 예외를 던지는데 그 다음은 | 지금은 빌드가 멈춥니다. 중개인에게 무엇을 보여줄지 미정 |
| D11 | **모바일 Pro 단계 인증** | NDA 확인을 무엇으로 하는가 | 마스킹 3단계가 인증에 걸려 있는데 인증 방식이 미정입니다 |
| D12 | **비수익형 포스처** | 개발형·운영형 IM 규격 | D19는 수익형 전용입니다. 픽스처는 이미 5종(개발 2·운영 1)이 있습니다 |

## §5 품질 게이트의 빈 곳 5건

검사기가 통과했다는 말이 IM이 옳다는 뜻이 아닌 이유입니다.

### 5.1 불변조건 3건에 자동 검사가 없습니다

`loader.py`가 매 실행마다 출력합니다.

| # | 불변조건 | 없는 것 |
|---|---|---|
| 6 | 업종·상호는 원문 그대로 쓰고 추론하지 않는다 | 원문 대조 장치. LLM이 "고은약국"에서 "의약 업종"을 지어내도 검사기는 모릅니다 |
| 14 | 물건명·법인명·임차인명 대외 미표기 | **이미지 경로** — §B1 |
| 18 | 렌트롤은 전량 표기한다 | 행수 대조. 원장 12행인데 IM에 9행만 나와도 통과합니다 |

### 5.2 골든 세트가 얇습니다

수익형 픽스처 **2건**(당산·양평)입니다. 해상도 조합은 L×P 16쌍 중 **3쌍**만 덮습니다.

```
덮은 것    (R1,P0)=D · (R1,P2)=B ×2 · (R2,P3)=A
못 덮은 것  R0 전 구간 · R3 전 구간 · P1 전 구간 · 등급 C
```

**등급 C(L≥R1 & P=P1) 경로는 한 번도 실행된 적이 없습니다.** 지번은 있으나 공부 조회가 부분 실패한 흔한 상황입니다. 최소 6건까지 늘리기를 권합니다 — R0 1건 · P1 2건 · R3 1건 추가.

### 5.3 렌더 스냅샷 회귀가 없습니다

지금 검사는 **텍스트만** 봅니다. 이 세션에서 실제로 겪은 결함 중 텍스트 검사로는 잡히지 않는 것들입니다.

- 표 라벨 칸이 붉게 칠해져 흰 글씨가 보이지 않음
- 줄바꿈된 본문의 `space_after`가 누적되어 상자를 넘침
- 제목만 남고 표가 다음 장으로 넘어감(고아 제목)
- 표지 전면 사진이 건물 하단을 잘라먹음

**해결책은 렌더 후 이미지 비교입니다.** LibreOffice → `pdftoppm` → 기준 이미지와 픽셀 차이. 임계값을 넘으면 사람이 봅니다. 이 파이프라인은 이미 이 세션에서 검증에 썼으므로 CI로 옮기면 됩니다.

### 5.4 규칙 기반 검사는 어색함을 잡지 못합니다

`standard_check`가 "위반 0"을 냈던 초기 PPTX를 보시고 **"너무 후지고 어색하다"**고 하셨습니다. 검사기는 규격을 봤고 규격은 지켜졌습니다. 문제는 **지면 문법**이었습니다 — 사진 없음, 전부 완결문장, 강조 없음, 여백 낭비.

규칙으로 이것을 잡을 수 없습니다. 필요한 것은 **사람 심사**입니다.

> 발행 전 심사 5항 (사람) — ① 첫 장에서 건물이 보이는가 ② 3초 안에 가격과 수익률을 찾을 수 있는가 ③ 표가 두 개 이상 연달아 나오지 않는가 ④ 문장이 명사형과 완결문장 사이에서 흔들리지 않는가 ⑤ 이 장을 지우면 아쉬운가

D19 §10에 검증 4층을 두었으나 4층(사람)의 판정 기준이 서술형입니다. 위 5항을 체크박스로 고정하시기 바랍니다.

### 5.5 물건 간 문장 재사용을 막는 기준이 애매합니다

`cross_property.py`가 두 물건의 공통 문장을 찾습니다. 정책·방법론 문장은 같아도 되고 사실 주장은 같으면 안 됩니다. 지금 판별은 **"숫자가 들어 있으면 사실 주장"**입니다.

"역세권 상권으로 배후 수요가 두텁습니다" — 숫자가 없어 통과합니다. 두 물건에 똑같이 들어가도 걸리지 않습니다. **이것이 IM이 템플릿처럼 보이는 주된 경로입니다.** 사실 주장 판별을 숫자 유무가 아니라 문형(F3/F4/F5 vs OPINION)으로 바꾸기를 권합니다.

## §7 착수 순서

의존 관계를 지킨 순서입니다. 앞을 건너뛰면 뒤에서 되돌아옵니다.

**1차 — 기반 (선행)**
`im.gating.yaml`·`im.tokens.yaml` 런타임 로딩 → 오류 코드 사전(S4) → 가정·세율 레지스트리(S2·S3) → D1·D2·D8 결정

**2차 — 산출 경로**
`core.py` 포팅 + 수치 동일성 시험 → 카피 엔진 포팅 → pptxgenjs 재작성 → 프리셋 3종

**3차 — 차단 해소**
이미지 마스킹 파이프라인(B1) → 발행 전 "미처리 0" 게이트 → EXIF 제거(D4)

**4차 — 품질 게이트**
렌더 스냅샷 회귀(5.3) → 골든 6건 확장(5.2) → 미검사 불변조건 3건(5.1) → 사람 심사 5항 체크박스(5.4)

**5차 — 운영**
감사 로그(O3) → 생성 시간 측정(O6) → 정본 소유표 갱신(O4) → 변경 절차 문서화(O5)

**1차와 3차는 병렬 가능합니다.** 2차는 1차에 의존합니다.

## §9 확인 필요

제가 판단할 수 없어 남겨 둔 것들입니다.

1. **이미지 마스킹을 자동 검출로 갈지, 중개인 수동으로 시작할지** — 자동 검출 모델 도입 비용과 오검출 감수 범위는 사업 판단입니다
2. **폰트 라이선스** — 임베딩 가능 여부를 확인해야 D2가 정해집니다
3. **다필지·구분등기 물건이 실제 파이프라인에 얼마나 들어오는지** — 빈도가 낮으면 D5·D6은 "차단 후 수기"로 두어도 됩니다
4. **비수익형 포스처(개발·운영) 착수 시점** — D19를 수익형 전용으로 둘지, 공통 골격을 먼저 뽑을지
5. **운영 시스템의 현재 상태** — 이 평가는 전달 문서와 참조구현만 보고 했습니다. 운영 코드베이스를 보지 않았으므로 §B2의 포팅 범위는 추정입니다
