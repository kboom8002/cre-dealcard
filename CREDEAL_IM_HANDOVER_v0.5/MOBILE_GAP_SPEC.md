## 0. 🔴 먼저 정정합니다 — 타이포는 이미 잘 돼 있습니다

SSoT v1.1에서 **"본문 최소 16px 필요 · 현행 `text-[10px]` 금지"** 라고 썼습니다. **사실과 다릅니다.**

`globals.css`에 **7단계 토큰 체계가 있고 CJK 상향까지 적용**돼 있습니다.

| 클래스 | px | 용도 |
|---|--:|---|
| `text-2xs` | 11 | 캡션·법적 문구 |
| `text-xs` | 13 | 보조·뱃지 |
| `text-sm` | 14 | 섹션 본문 |
| **`text-base`** | **17** | **기본 본문 — 16→17 CJK 상향** |
| `text-lg` | 19 | 소제목 |
| `text-xl` | 22 | 섹션 타이틀 |
| `text-3xl` | 32 | Hero 가격 |

**`text-[10px]`는 면책 조항 전용입니다.** T1-2 답변의 "인라인 사용"을 본문 전반으로 오독한 것이 원인입니다.

> **이 정정이 D8의 범위를 절반으로 줄였습니다.** 타이포 전면 재설계가 아니라 갭 5건 + 응급 1건입니다.

## 2. 🔴 응급 E0 — 입력 폼 사전 검증

### 2.1 왜 응급인가

30일간 44건 시도 중 **16건이 필수값 없이 서버까지 도달**했습니다.

| | 건수 | |
|---|--:|---|
| 완료 | 26 | |
| 의도된 차단 (Grade D) | 2 | **정상** |
| **입력 누락** | **16** | **개선 대상** |
| 시스템 오류 | **0** | |

서버 게이트가 **0.6초에 막아 252회 LLM 호출을 아꼈습니다.** 게이트는 잘 작동했습니다.

> **문제는 "왜 필수값 없이 제출 버튼을 누를 수 있었나"입니다.**

### 2.2 구현

```ts
export const REQUIRED_BY_POSTURE: InputRequirement[] = [
  { field: 'priceKrw',       label: '매각 희망가', requiredFor: ['income','owner_occupied','development','operating','trading'] },
  { field: 'monthlyRentKrw', label: '월 임대료',   requiredFor: ['income'] },
  { field: 'targetFar',      label: '용도지역',     requiredFor: ['development'] },
  { field: 'gopMarginPct',   label: 'GOP 마진',    requiredFor: ['operating'] },
  { field: 'manualComps',    label: '비교사례',     requiredFor: ['trading'] },
];

export function missingFields(input: RawInput): InputRequirement[] {
  if (!input.posture) return [{ field: 'posture', label: '투자 자세', requiredFor: [] }];
  return REQUIRED_BY_POSTURE
    .filter(r => r.requiredFor.includes(input.posture!))
    .filter(r => input[r.field] == null || input[r.field] === '');
}
```

### 2.3 화면 규칙

| 상태 | 제출 버튼 | 표시 |
|---|---|---|
| 결손 있음 | **비활성** | **"매각 희망가 · 월 임대료 입력이 필요합니다"** |
| 결손 없음 | 활성 | — |

```

```

### 2.4 포스처 선택 시 필수 칸이 바뀝니다


## 3. Hero 지표 교체

### 3.1 현행의 문제

| 현행 | 문제 |
|---|---|
| **Cap Rate** | `basis` 미표기 + **0.85 계수 적용값** |
| 예상 매각가 | **comps 없이 창작** (매입가 × 1.2) |
| 대지 지분 비중 | 유지 가능하나 우선순위 낮음 |
| **WALE** | **중개인도 쓰지 않는 용어** |

**넷 중 둘이 근거 없는 숫자입니다.**

### 3.2 교체안 — 2×2 유지

| 위치 | 지표 | 양평동 | 당산동 |
|:-:|---|--:|--:|
| 1 | **매매가** | 250억 | 115억 |
| 2 | **평당가 (대지)** | 15,923만원 | 7,500만원 |
| 3 | **월 임대료** | 4,657만원 | 1,946만원 |
| 4 | **확인 필요** | n건 | n건 |

**전부 매수인이 검산할 수 있는 숫자입니다.** (불변조건 19)

### 3.3 그리드는 줄이지 않습니다

SSoT v1.1의 **"숫자 3개로 축소"** 권고를 정정합니다. **문제는 개수가 아니라 지표 선택**이었습니다. 2×2를 유지하고 내용만 바꿉니다.

### 3.4 D7 A02와 동일해야 합니다

| | 모바일 Hero | PPTX A02 |
|:-:|---|---|
| 1 | 매매가 | 매매가 |
| 2 | 평당가 | 평당가 |
| 3 | 월 임대료 | 월 임대료 |
| 4 | 확인 필요 n건 | 확인 필요 n건 |

**같은 물건의 두 매체가 다른 숫자를 보이면 신뢰를 잃습니다.** 둘 다 `IMCore`에서 직접 렌더합니다.

### 3.5 확인 필요 0건일 때

```
"확인 필요 0건"  ❌
"제출 자료 전량 확보"  ✅
```

**결손이 없다는 사실 자체가 강점입니다.**

## 4. 하단 고정 바 — 전화 편입

### 4.1 현행

```
[공유] [PDF] [PPTX] [모드전환] [신청]
```

**5개 중 3개(PDF·PPTX·모드전환)가 중개인용 기능입니다.** 매수인이 보는 화면에 있습니다.

### 4.2 개선

```
[📞 전화] [신청] [공유] [···]
```

| 순위 | 버튼 | 대상 |
|:-:|---|---|
| **1** | **전화** | **매수인** |
| 2 | 자료 신청 | 매수인 |
| 3 | 공유 | 양쪽 |
| 4 | ··· (PDF·PPTX·모드전환) | **중개인** |

```tsx
<a href={`tel:${broker.phone}`} aria-label={`${broker.name}에게 전화 걸기`}
   className="flex-1 min-h-[44px] rounded-xl bg-primary text-white text-base font-semibold">
  전화 문의
</a>
```

**`tel:` 링크는 모바일에서 즉시 통화 화면을 엽니다.** 번호를 복사해 옮겨 적는 단계가 사라집니다.

### 4.3 중개인 기능은 `···`로 접습니다

**공개 링크를 받은 매수인에게 PPTX 다운로드 버튼은 혼란만 줍니다.** 마스크 레벨이 `public`이면 4번 그룹을 아예 렌더하지 않습니다.

```ts
const showBrokerTools = maskLevel === 'full';
```

## 5. 접근성 (단계 11)

| 컴포넌트 | 추가 |
|---|---|
| 아코디언 | `aria-expanded={isOpen}` · `aria-controls` |
| 갤러리 | `aria-label="사진 N / 전체 M"` |
| 라이트박스 | `role="dialog"` · `aria-modal="true"` · **Esc 닫기** |
| 지도 | `alt=""` → **`alt="○○동 위치 지도"`** |
| Progress Dots | `aria-hidden="true"` (장식) |
| 하단 바 | 각 버튼 `aria-label` |

### 5.1 터치 영역은 이미 확보돼 있습니다

`w-10 h-10`(40px) + 패딩으로 ~44px입니다. **선언만 명시하면 됩니다.**

```css
.tap-target { min-width: 44px; min-height: 44px; }
```

## 6. 이미지 폴백

```tsx
<Image src={item.url} alt={item.label}
  onError={(e) => { e.currentTarget.src = '/fallback-property.svg'; }} />
```

**외부 이미지 URL이 깨지면 현재는 빈 칸이 남습니다.** 매수인 눈에는 "자료가 부실한 매물"로 보입니다.

## 7. 유지할 것 — 건드리지 않습니다

| 항목 | 평가 |
|---|---|
| `text-base` 17px CJK 상향 | **좋은 판단** |
| `max-w-2xl` (672px) | 데스크톱에서도 모바일 폭 — **의도적 설계** |
| 아코디언 다중 오픈 (`Set`) | 적절 |
| OSM 3×3 타일 지도 폴백 | 카카오 API 실패 대비 |
| Intersection Observer 계측 | **이미 구현됨** (D6 §0.1) |
| `beforeunload` 체류 시간 | 동일 |
| 라이트박스 스와이프 | 적절 |

**잘 되어 있는 것을 재설계하지 않습니다.** 이번 진단에서 "계측 전무"·"타이포 미흡" 두 판단이 모두 틀렸던 이유입니다.

## 8. 렌더 경로 — PPTX와 공유

```
IMCore ──┬─→ 모바일 렌더  ← 이 문서
         ├─→ PPTX 렌더    ← D7
         └─→ 마크다운
```

**마크다운을 경유하지 않습니다.** 현행 모바일은 섹션 마크다운을 렌더하는데, 이는 **텍스트 섹션에만** 적용하고 Hero·수치 카드는 `IMCore`에서 직접 뽑습니다.

```ts
// ✅ Hero — IMCore 직결
const hero = [
  { label: '매매가',      value: fmtEok(core.price.askingKrw) },
  { label: '평당가',      value: fmtMan(core.price.perPyeongLand) },
  { label: '월 임대료',   value: fmtMan(sumRent(core.leases)) },
  { label: '확인 필요',   value: `${core.deficiencies.length}건` },
];

// ✅ 본문 — 마크다운 유지
<Markdown>{section.body}</Markdown>
```
