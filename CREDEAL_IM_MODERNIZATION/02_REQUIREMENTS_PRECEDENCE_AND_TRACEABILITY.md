# 요구사항 우선순위와 상위 문서 추적

## 1. 목적

이 문서는 D54·D54-A·D55, D58, 제작 파이프라인, IM CORE, 게이트 하네스 사양이 충돌할 때 무엇을 우선하고 어떻게 변경할지를 정한다.

## 2. 우선순위

| 순위 | 정본 | 담당 결정 |
|---:|---|---|
| 1 | 승인된 통합 결정·JSON Schema | 상태·필수필드·식별자·단계종료 |
| 2 | D54·D54-A·D55 | 한국 소형 상업용 부동산 문서·용어·산출항목·중개인 업무 |
| 3 | D58 | IM CORE·모바일·PPTX 경계와 채널관계 |
| 4 | 이 통합 SDD | 실행순서·통합 계약·릴리스 차단선 |
| 5 | 파이프라인·CORE·게이트 상세 SDD | 구성요소별 구현 상세 |
| 6 | 기존 코드·생성본·운영설정 | 현행 증거, 목표 정본 아님 |

상위 문서가 절차까지 상세히 규정하지 않은 경우 하위 SDD가 구체화할 수 있다. 상위 의미를 바꾸는 확장은 불가하다.

## 3. 문서별 채택범위

### D54

- 현실적 중개인형 최소 구현
- L1/L1.5/L2 산출항목 묶음
- 원자료·불일치·정정·유효값
- 다필지·렌트롤·단순 임대수익률
- 중개인 입력 보존과 외부 카피
- 사진·사람 편집승인·P0 차단

### D54-A

- 수집경로와 정보영역의 분리
- Claim 기반 영역상태
- 자산형태·거래범위·검토관점 차원
- 데이터 계보·정정원장·필드별 근거
- 자료해상도와 산출항목 허용의 분리
- 단계별 HITL·시험·RACI·정본 최소화

### D55

- 한국 중개실무 용어와 외부 문장규칙
- L1.5를 실무 기본 골디락스 문서로 정의
- 중개인 의견·사진·자료요청·보완과제
- 실제 페이지 블루프린트와 독자품질
- 개발팀 발행검사·변조시험·완료조건

### D58

- 공통 발행묶음 기반 모바일·PPTX 형제채널
- IM CORE의 근거·판정·발행 CORE 분리
- 모바일 기본 L1/L1.5
- PPTX Studio의 독립 편집·렌더링 책임
- 승인·버전·해시·무효화

### 파이프라인 SDD

- 재개 가능한 장시간 실행
- 단계 체크포인트와 불변 산출물
- 멱등성·작업임대·재시도·사건보관함
- 채널 독립 실행과 최소 재생성

### IM CORE SDD

- 도메인·저장·API·서비스 계약
- `EffectiveSnapshot`, `ClaimEvaluationSet`, `PublicationPackage`
- 채널 조립기와 호환 어댑터
- 데이터 이전·RLS·LLM 경계

### 게이트 하네스 SDD

- 7상태 결과와 적용성
- 산출물별 검사 프로필
- 실제 관측값·반대조건·변조시험
- 승인사건·무효화·하네스 자기감사

## 5. 충돌 처리

다음 중 하나면 구현을 멈추고 결정요청을 만든다.

- 같은 ID·열거값·산식을 두 정본이 다르게 정의
- 문서등급이 페이지 수나 데이터량으로 다시 계산됨
- 외부 카피에 내부 개발용어가 필요하다고 주장함
- 채널이 CORE 허용범위를 넘어 새 사실을 생성하려 함
- 기존 코드 호환 때문에 허위 통과를 유지하려 함
- 성능을 이유로 승인 재검사나 파일해시 결속을 생략하려 함

결정요청은 대안, 사용자 영향, 안전위험, 이전비용, 권고안, 만료일을 포함한다.

## 6. 버전관리

- 상위 방법론 변경은 `methodologyPolicyVersion`을 올린다.
- 산출항목·산식 변경은 `claimPolicyVersion` 또는 `formulaVersion`을 올린다.
- 외부 카피 용어 변경은 `terminologyPolicyVersion`을 올린다.
- 공개·가림 정책 변경은 `disclosurePolicyVersion`을 올린다.
- 채널 편성·레이아웃 정책 변경은 채널 정책버전을 올린다.
- 기존 승인을 유지할 수 있는지는 `13_PHASE_7_INVALIDATION_AND_REGENERATION.md`의 영향표로 판정한다.
