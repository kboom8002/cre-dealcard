# CREDEAL 통합 IM 고도화 마스터 작업지시서

> 작업군 코드: `CIM`  
> 실행방식: 사양주도개발  
> 태스크 정본: 이 문서, `20_IMPLEMENTATION_BACKLOG.md`, `knowledge/work_item_catalog.yaml`

## 0. 실행명령

CREDEAL의 딜카드→바텀시트→모바일 IM→PPTX IM 제작흐름을 다음 구조로 개편한다.

1. D54·D54-A·D55의 문서·용어·산출항목·렌트롤·다필지·중개인 의견 요구를 제품 기준선으로 동결한다.
2. 생성검사 영속화, 승인 재수화, 대상해시 비교, 7상태 판정으로 현행 허위 통과를 먼저 제거한다.
3. 장시간 요청을 단계별 체크포인트와 불변 산출물을 가진 재개 가능한 실행으로 바꾼다.
4. 메모 파싱 딜카드를 IM과 분리된 블라인드 발행물로 만든다.
5. IM CORE에 원자료·정정·유효기준본·산출항목·공통 발행묶음을 구현한다.
6. 모바일을 L1/L1.5 기본 채널로 전환한다.
7. PPTX를 모바일 변환기가 아닌 독립 `PPTX IM Studio`로 전환한다.
8. 사실·문구·사진·정책·파일 변경의 영향승인과 최소 재생성을 자동화한다.
9. 산출물별 하네스·사람승인·변조시험을 각 단계와 함께 완성한다.
10. 그림자·카나리·복구훈련 후 구형 신규생성 경로를 폐기한다.

## 1. 공통 착수규약

모든 작업카드는 다음을 지킨다.

- 작업 ID와 선행조건을 명시한다.
- 상위 사양·스키마·지식소스를 먼저 읽는다.
- 실제 소유 파일·호출자·생성경로를 검색해 문서 경로를 검증한다.
- 실패재현 또는 기대 실패시험을 먼저 고정한다.
- 데이터계약·DB·UI·전환을 한 PR에 과도하게 묶지 않는다.
- 정책·상태·열거값을 코드에서 임의 추가하지 않는다.
- 기능깃발, 롤백, 운영관측, 이전 증적을 포함한다.
- 기존 사용자 데이터와 발행파일을 삭제하지 않는다.
- 완료 시 변경계약·시험·기능깃발·미해결 위험을 보고한다.

## 2. 단계별 작업지시

### CIM-M0 — 기준선·정본 동결

목표: 구현 전에 제품과 기술의 의미를 하나로 맞춘다.

필수 작업:

1. DEC-001~005 승인, DEC-006~018의 책임자·기한 확정
2. 사람 관리 정본과 생성 정본의 소유권 목록 작성
3. 현행 딜카드·모바일·PPTX·승인 호출지도 저장
4. 당산동·상도동·양평동 기준자료와 오류사례 동결
5. 현행 제작시간·실패율·수정량·품질평점 기준선 측정

종료: `MG-0` 승인.

### CIM-M1 — 안전봉합

목표: 구조개편 중에도 현재 잘못된 외부발행을 줄인다.

필수 작업:

1. 생성 당시 주장·산출항목·검사·규칙버전 직렬화
2. 승인 API 저장객체 재수화와 `expectedHash` 비교
3. 7상태 결과 호환모델과 미실행 차단
4. 죽은 검사·고정 관측값·환경변수 심각도 전환 제거
5. 운영비·관리비·채권최고·공란·다필지 오표현 차단
6. 기계검사와 사람승인 사건 분리
7. 기능깃발·감사로그·되돌리기

종료: `MG-1` 승인.

### CIM-M2 — 실행·하네스 공통기반

목표: 후속 CORE와 채널이 동일한 재개·산출물·검사 기반을 사용한다.

필수 작업:

1. 실행·단계·산출물·사건보관함·승인사건 저장
2. 멱등 명령·작업임대·심장박동·재시도·격리
3. `ArtifactEnvelope`와 스키마·해시·계보
4. 프로필 선택·적용성·관측·판정·보고서 실행기
5. 사용자 진행상태와 운영자 재개·취소 도구
6. 전구간 `runId`·`artifactId` 관측성

종료: `MG-2` 승인.

### CIM-M3 — 블라인드 딜카드

목표: 메모에서 빠르게 만들되 사실확정과 공개범위를 통제한다.

필수 작업:

1. `MemoObservationSet`과 원문 위치·신뢰도·모호성
2. 블라인드 공개 최소묶음과 밴딩 변환
3. 정확주소·직접식별·간접 재식별·과장·무단보완 검사
4. 중개인 공개확인과 발행버전
5. 메모·바텀시트 변경 후 `STALE` 전환

종료: `MG-3` 승인.

### CIM-M4 — IM CORE v1

목표: 채널이 다시 판단하지 않는 공통 사실·판정·발행계약을 완성한다.

필수 작업:

1. 접수·근거·불일치·정정·매각범위
2. 다필지·네 면적 분모·렌트롤 행상태
3. 불변 `EffectiveSnapshot`
4. `ClaimDefinition`, `FormulaRegistry`, `ClaimEvaluationSet`
5. `ProposalUnit`, 사진·위험·실사·보완과제
6. L1/L1.5/L2 가능범위와 CORE 검사
7. 채널중립 `ContentUnit`과 `PublicationPackage`
8. 구형 `ReleaseTier`·body 호환 어댑터와 그림자 이중실행

종료: `MG-4` 승인.

### CIM-M5 — 모바일 L1/L1.5

목표: 중개인 일상 사용이 가능한 첫 완전한 IM 채널.

필수 작업:

1. 모바일 내용계획과 구조화 카드 조립
2. 한국어 숫자마스크·외부 카피·내부어 제거
3. L1 기본, L1.5 자동 적격과 사람 편집승인
4. 의견 반영표와 사진 0/1/3/8/10+ 적응형 배치
5. 모바일 검사·승인·발행·철회·버전
6. 기존 공개 URL 호환
7. 중개실무 품질평가

종료: `MG-5` 승인.

### CIM-M6 — PPTX IM Studio

목표: 같은 CORE를 사용하는 독립 편집·조립·렌더링 제품.

필수 작업:

1. 프로젝트·버전·낙관잠금·문서개요
2. 페이지 구성·문안·사진계획·부록 편집
3. 구조화 숫자토큰과 근거패널
4. 미리보기와 최종렌더의 동일 버전 결속
5. 텍스트 넘침·겹침·잘림·지면이탈·사진·수치 교차검사
6. 편집승인·최종파일승인·배포
7. 구형 렌더러 호환과 신규 직접변환 차이로그

종료: `MG-6` 승인.

### CIM-M7 — 무효화·최소 재생성

목표: 변경된 범위만 정확히 재실행하고 관련 승인만 무효화한다.

필수 작업:

1. 변경유형 13종과 의존그래프
2. 승인 결속해시와 자동 무효화
3. 재사용·재실행·영향 발행본을 보여주는 계획 API
4. `STALE`, `SUPERSEDED`, `WITHDRAWN` 전이
5. 그림자 예상결과와 실제 사용자 수정 비교

종료: `MG-7` 승인.

### CIM-M8 — 병행전환·폐기

목표: 실물표본과 복구훈련으로 검증한 뒤 신규 경로를 기본으로 전환한다.

필수 작업:

1. 구/신 이중실행과 중대 차이 대시보드
2. 교차채널 일관성·오류주입·변조시험
3. 카나리 1/10/50/100%
4. 장애·철회·롤백 훈련
5. 구형 신규 모바일→PPTX 변환과 직접 원자료 바인딩 차단
6. 두 릴리스 사용량 0 확인 후 폐기

종료: `MG-8` 승인.

## 3. 통합 병합 차단조건

- 스키마 검증 없이 JSONB를 새 정본으로 저장
- 상태·열거·산식을 코드에 중복 정의
- `not_evaluated`·`NOT_RUN`을 통과나 조용한 생략으로 처리
- 채널이 원시 enrichment·공공 API·다른 채널 body에서 사실을 재판정
- 승인 API가 저장객체·대상해시·선행승인을 확인하지 않음
- 차단 실패를 면책문구로 우회
- 실제 관측기 없는 차단급 검사를 PASS로 고정
- 최종 PPTX 파일을 보지 않고 파일승인
- 기능깃발·되돌리기·이전·관측 없는 외부발행 변경
- 기존 사용자 자료·발행파일·공개 URL을 파괴

- 이전 오류 재현 또는 기준선
- 양성·음성·변조·복구시험 ID와 결과
- 실행 전후 검사보고서·해시
- 기능깃발과 되돌리기
- 운영 계기판·경보 변화
- 남은 위험과 승인자
