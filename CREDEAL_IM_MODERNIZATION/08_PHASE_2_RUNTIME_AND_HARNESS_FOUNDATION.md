# M2 — 재개 가능한 실행기와 공통 검사틀

> 단계 ID: `CIM-M2` · 선행: M1 · 종료게이트: `MG-2`

## 1. 목적

딜카드·IM CORE·모바일·PPTX가 공유하는 실행기, 검사보고서, 승인·해시·발행원장을 먼저 만든다. 이후 각 산출물이 이 공통 기반 위에서 독립적으로 실행되게 한다.

## 2. 실행단위

- `deal_run`: 한 거래건의 전체 실행
- `artifact_run`: 딜카드·모바일·PPTX 중 한 산출물 실행
- `stage_run`: 수집·정규화·판정·조립·렌더·검사·승인·발행 단계
- `attempt`: 같은 단계의 재시도

각 단계는 입력해시, 규칙버전, 코드버전, 출력해시, 상태, 오류, 시작·종료시각을 저장한다.

## 3. 재개와 멱등성

멱등키는 최소 `deal_id + artifact_type + stage + input_hash + rule_version`을 포함한다. 이미 성공한 동일 입력 단계는 재사용하고 실패 또는 변경영향 단계부터 재개한다. 외부 API 호출·파일발행·메시지 발송은 중복방지키를 별도로 둔다.

## 4. 공통 검사보고서

각 검사는 다음을 반환한다.

- 검사 ID·버전·심각도·차단여부
- 실제 상태와 측정값
- 판정식·기대값
- 근거참조와 대상해시
- 실행기·시각·오류정보
- 예외승인 ID와 만료

검사를 실행하지 않았으면 보고서 행 자체가 사라지지 않고 `NOT_RUN`으로 남는다.

## 5. 관리 API 최소계약

- 실행 생성·조회·재개·취소
- 단계별 결과와 오류 조회
- 검사보고서 생성·조회
- 승인 생성·무효화·조회
- 발행요청·철회·발행본 조회
- 변경영향 미리보기

## 6. 저장 원칙

- DB: 상태·계보·참조·판정·승인·발행원장
- 객체저장소: 원파일·렌더파일·검사증적·발행파일
- 로그: 개인식별정보를 가린 운영사건
- 원파일과 발행파일은 같은 키로 덮어쓰지 않는다.

## 7. MG-2 통과조건

- 단계 중단 후 성공단계를 재수행하지 않고 재개한다.
- 중복요청이 중복발행을 만들지 않는다.
- 입력·규칙 변경이 새 실행묶음과 계보를 만든다.
- 차단검사 누락을 자동 발견한다.
- 모든 승인·발행을 대상해시까지 추적할 수 있다.
