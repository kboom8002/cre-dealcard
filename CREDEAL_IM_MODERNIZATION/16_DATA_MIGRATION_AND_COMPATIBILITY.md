# 데이터 이전·호환성 사양

## 1. 이전 원칙

- 과거 발행본은 바이트와 URL을 가능한 한 그대로 보존한다.
- 구형 레코드는 읽을 수 있어야 하나, 근거가 부족한 값을 신형 사실로 승격하지 않는다.
- 이전은 재실행 가능하고 중간중단 후 재개 가능해야 한다.
- 원본·변환본·오류·보류를 분리하고 건수와 해시를 대조한다.

## 2. 이전 분류

| 분류 | 처리 |
|---|---|
| 신형으로 완전변환 가능 | 새 ID·계보·변환버전 저장 |
| 일부 근거 부족 | 읽기전용 구형값 + `legacy_unverified` 표시 |
| 구조 불명확 | 보류목록과 사람검토 |
| 과거 발행파일 | 불변보관, 신형 발행본으로 간주하지 않음 |
| 구형 승인 | 감사기록 보존, 신형 승인권한으로 사용 금지 |

## 3. 겸용 운영

신형이 구형을 읽는 어댑터와 구형 클라이언트가 신형 응답을 읽는 호환계층을 분리한다. 이중쓰기는 최소화하며, 필요한 경우 어느 저장소가 정본인지 필드별로 명시한다. 영구 양방향 동기화는 금지한다.

## 4. 검증

- 건수·식별자·참조무결성 대조
- 대표 표본과 무작위 표본의 의미 대조
- 금액·면적·날짜·단위 변환 대조
- 파일 존재·해시·접근권한 대조
- 승인·발행·철회 이력 대조
- 개인정보 보유·삭제정책 대조

## 5. 완료조건

이전결과 보고서, 미변환 목록, 되돌리기 절차, 호환종료일, 책임자가 승인되어야 한다. 구형 신규쓰기는 신형 안정화 전에는 제거하지 않는다.
