# 팀 역할·변경·병합 통제

## 1. 책임 역할

| 역할 | 최종 책임 |
|---|---|
| 제품책임자 | 범위·단계승격·사용자 가치 |
| 부동산 도메인책임자 | D54~D55 해석, 공부·렌트롤·문구·등급 |
| 아키텍처책임자 | 서비스경계·정본·호환·기술예외 |
| 파이프라인팀 | 실행기·재개·멱등·이벤트·발행원장 |
| IM CORE팀 | 증거·상충·정정·산식·주장·발행자격 |
| 채널팀 | 모바일·PPTX Studio 조립·렌더·편집 |
| 품질/게이트팀 | 검사틀·독립시험·증적·변조시험 |
| 운영/보안 | 관측·권한·개인정보·사고·되돌리기 |
| 중개인 자문그룹 | 실제 입력가능성·문장·사진·편집성 |

## 2. 저장소 소유권

정본 스키마·공식·게이트 목록·외부용 어휘는 책임자를 명시한 변경승인을 요구한다. 채널팀이 CORE 스키마를 편의상 바꾸거나, CORE팀이 채널 배치정책을 정본화하지 않는다.

## 3. 변경요청 필수항목

- 상위 요구 ID와 작업 ID
- 사용자·도메인 영향
- 변경 전후 계약과 이전방안
- 검사·승인·발행·되돌리기 영향
- 양성·음성·변조·복구시험
- 관측항목과 기능깃발
- 미해결 위험·결정 필요사항

## 4. 병합 규칙

- 한 변경요청은 가능한 한 한 작업카드의 완료정의에 대응한다.
- 스키마 변경과 소비자 변경은 호환순서에 따라 분할한다.
- 기능깃발 기본값은 외부발행에 안전한 값이다.
- 증적 없는 `BLOCKER` 규칙 변경은 병합하지 않는다.
- 사람승인을 자동시험으로 대체하지 않는다.

## 5. 관리게이트 승인

각 MG는 제품·도메인·기술·품질의 최소 네 역할을 필요로 한다. M8은 운영·중개실무를 추가한다. 승인자는 실행증적 링크와 남은 위험을 확인하고 대상 종료보고서 해시에 서명한다.
