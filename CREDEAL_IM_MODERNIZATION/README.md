# CREDEAL 통합 IM 고도화 SDD 문서 세트

> 패키지: `CREDEAL_INTEGRATED_IM_MODERNIZATION_SDD`  
> 버전: `1.0.0`  
> 기준일: `2026-08-31`  
> 상태: 개발팀 채택 제안  
> 대상: 제품·부동산 도메인·백엔드·데이터·모바일·PPTX Studio·품질·운영팀

## 1. 이 문서 세트가 해결하는 문제

D54·D54-A·D55는 **무엇을 만들고 어떤 문서를 허용할지**를 정한다. D58과 IM 제작 파이프라인·IM CORE·게이트 고도화 문서는 **그 요구를 어떤 시스템 경계와 실행구조로 구현할지**를 정한다. 각 문서를 따로 적용하면 다음 문제가 생긴다.

- 같은 P0 작업을 세 팀이 다른 이름과 상태값으로 중복 구현한다.
- 실행기반이 없는 상태에서 CORE를 먼저 바꾸어 장시간 요청과 재시도 문제가 남는다.
- 게이트를 마지막에 붙여 이미 만들어진 데이터계약과 승인흐름을 다시 뜯는다.
- 모바일과 PPTX가 서로의 산출물을 사실정본으로 사용한다.
- 방법론의 L1·L1.5·렌트롤·다필지·중개인 의견 요구가 화면과 시험에서 빠진다.

이 패키지는 위 문서를 하나의 의존그래프로 재배열한 **통합 실행 정본**이다.

## 2. 한 줄 적용 순서

```text
방법론·용어·상태 정본 동결
→ 현행 허위 통과와 승인 오류 봉합
→ 재개 가능한 실행·산출물·게이트 공통기반
→ 블라인드 딜카드 독립 발행
→ IM CORE 유효기준본·산출항목·공통 발행묶음
→ 모바일 L1/L1.5
→ PPTX IM Studio
→ 전 채널 무효화·최소 재생성
→ 그림자·카나리 전환과 구형 신규생성 폐기
```

게이트 시스템은 마지막 단계가 아니다. 공통 판정모델은 1~2단계에서 만들고, 딜카드·모바일·PPTX의 산출물별 검사묶음은 각 산출물과 같은 단계에서 완성한다.

## 7. 절대 불변조건

1. 한 발행본은 하나의 유효기준본과 하나의 공통 발행묶음만 사용한다.
2. 메모 파싱값은 사실이 아니라 관측값이다.
3. 블라인드 딜카드는 IM의 낮은 등급이 아니라 독립 제한공개 산출물이다.
4. 모바일과 PPTX는 같은 CORE의 형제 채널이며 서로를 정본으로 삼지 않는다.
5. 렌더러와 LLM은 사실판정·재무계산·발행허가를 새로 수행하지 않는다.
6. `NOT_RUN`, `INDETERMINATE`, `SYSTEM_ERROR`는 차단급 검사에서 통과가 아니다.
7. 기계검사와 사람승인은 별도 사건이며 모두 대상 해시에 결속된다.
8. 중개인 의견은 원문·근거·매수자 의미·최종문구·반영위치로 역추적한다.
9. 사실·문구·사진·정책·파일이 바뀌면 영향을 받는 승인만 자동 무효화한다.
10. 구형 데이터와 발행파일은 삭제하지 않고 읽기 호환을 유지한다.
