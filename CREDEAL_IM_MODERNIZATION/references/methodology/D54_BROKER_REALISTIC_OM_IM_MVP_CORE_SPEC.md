## 0. 결정

### 0.1 이번 버전에서 구현한다

1. 빈칸·관리비·채권최고액 오표현 방화벽
2. 매도인 제시·계약·실제수납 임대료 분리

4. 원자료값 → 불일치 → 승인정정 → 유효기준본
5. 다필지 매각대상 필지묶음과 면적분모 분리
6. 산출항목 단위 허가와 산출항목 묶음 기반 L1/L1.5/L2 판정
7. 중개인 의견 → 분석가정 제안 → 사람승인의 단방향 구조
8. `일반건물·나대지`와 `수익현황·가치개선·개발검토`의 최소 처리조건
9. 발행검사의 조치·위험등급·관측유형 분리
10. 근거자료 목록·시험실행기록·임계값 검증상태

### 0.3 판정 언어

| 판정 | 내부코드 | 의미 |
|---|---|---|
| 채택 | `ADOPT` | 현재 근거자료로 구현 |
| 수정채택 | `MODIFY` | 범위·순서·표현을 고쳐 구현 |
| 보류 | `DEFER` | 유효한 가설이나 근거자료가 부족함 |
| 기각 | `REJECT` | 목적과 충돌하거나 기존 규칙과 중복됨 |

| 근거 | 요구 근거자료 |
|---|---|
| E0 | 아이디어만 있음 |
| E1 | 식별 가능한 실물 또는 개발 저장소 상태 1건 이상 |
| E2 | 정상·실패 짝과 실행결과가 있음 |
| E3 | 복수 실물에서 재현되고 오탐·미탐이 측정됨 |

E0·E1 규칙은 `잠정`이다. 외부 발행을 더 쉽게 만드는 방향으로는 사용할 수 없다.

### 0.4 한국어 표시 계약

D56의 권장어는 외부 문서와 중개인 입력화면의 정본이다. 데이터베이스·API·정책파일의 기존 영문 식별자는 호환성을 위해 유지할 수 있으나, 화면·문서·오류안내에는 다음 한국어 표시어를 사용한다.

| 내부 식별자·기존어 | 외부·화면 표준어 |
|---|---|
| OM / IM | 매각안내서 / 투자검토서 |
| Claim | 산출항목 |
| Evidence | 근거자료 |
| Conflict | 불일치 |
| CorrectionEvent | 정정기록 |
| EffectiveSnapshot | 유효기준본 |
| Assumption | 분석가정 |
| Gate | 발행검사 |
| AssetForm | 자산형태 |
| Lens | 검토관점 |
| ParcelSet | 매각대상 필지묶음 |
| Rent Roll | 임대차 현황표 |

표시어만 번역하고 의미를 합치지 않는다. 특히 `price`, `area`, `rent`, `yield` 같은 단일 내부 필드로 여러 경제적 의미를 함께 담는 것을 금지한다.

### 0.5 v1.1 개정사항

1. 외부 문서어·중개인 화면어·내부코드를 분리했다.
2. 발행단계를 사실확인형·표준 검토형·중개분석형·전문가 협업형으로 통일했다.
3. 가격·면적·임대료·수익률·거리의 필수 꼬리표를 발행계약에 추가했다.
4. 월세·보증금·관리비를 월 기본임대료·임대차보증금·월 관리비로 세분했다.
5. 사용가능·조건부 사용가능·사용차단·해당없음·현 단계 미제공·미판정의 화면 표시어를 확정했다.
6. 기술코드는 유지하되 사용자에게 영문 내부코드가 직접 노출되지 않도록 했다.

### 0.6 v1.2 품질개정 원칙

안전한 문서가 곧 좋은 문서는 아니다. L1·L1.5·L2 외부 문서는 사실관계를 지키면서도 매수자가 매물의 장점과 검토가치를 빠르게 이해하도록 작성해야 한다. 다음 네 가지를 동시에 만족하지 못하면 발행검사를 통과시키지 않는다.

1. **중개인 입력 보존**: 중개인이 제공한 매각 포인트·현장관찰·시장판단을 이유 없이 삭제하거나 일반적인 위험문구로 치환하지 않는다.
2. **한국형 매각문체**: 대한민국 소형 상업용 부동산 중개인이 실제로 말하고 쓰는 표현을 사용한다.
3. **매수자 소구 우선**: 장점·가격·임대현황·활용방안을 먼저 이해시키고, 한계와 확인사항은 해당 주장 가까이에 짧게 붙인다.
4. **내부어 비노출**: L등급·산출항목·발행검사·유효기준본·가상 보완 같은 제작·정책용 표현을 외부 표지와 본문 제목에 노출하지 않는다.

L0는 내부 점검문서이므로 검증·보완 중심으로 작성한다. L1·L1.5·L2는 외부 매수자용 문서이므로 내부 점검문체를 그대로 승계하지 않는다.

### 0.7 v1.3 제품개정 원칙

1. **L1.5를 독립 발행단계로 둔다.** L1 사실묶음에 근거 있는 중개인 의견·매수자 의미·자동 적격 PASS·사람 편집승인 APPROVED가 더해지면, 임대·시장 분석이 부족해도 `중개인 제안형 매각제안서`를 발행할 수 있다.
2. **L1.5는 축소된 L2가 아니다.** L1.5의 핵심은 계산량이 아니라 중개인의 현장지식과 매각논리를 근거와 함께 보존하는 것이다.
3. **실무 기본 골디락스는 L1.5다.** 임대·가격·시장 분석까지 허용되면 L2 분석 확장형으로 승급한다.
4. **사진은 고정 페이지가 아니라 근거자료다.** 대표 외관은 물건 개요에 우선 배치하고, 나머지는 해당 사실·의견·확인사항 가까이에 둔다.
5. **사진 부족을 가상 이미지로 보완하지 않는다.** 사진이 없으면 지도·공부·도식 중심으로 재조립하고 미제공 상태를 표시한다.

### 0.8 v1.4 운영개정 원칙

1. **L1.5의 자동 적격판정과 사람 편집승인을 분리한다.** 필드와 근거의 존재는 기계가 검사하고, 매수자 의미와 한국 중개문장의 자연스러움은 사람이 승인한다.
2. **사람승인은 승인 대상에 결속한다.** 유효기준본·외부문구·사진집합·적용 정책이 바뀌면 기존 승인을 자동 무효화한다.
3. **L1.5를 내부 숫자등급 하나로만 표현하지 않는다.** `L1 사실묶음 + 중개인 제안판 + 사람승인`을 각각 저장하고 외부 발행명을 파생한다.
4. **관측유형 자리표시자를 금지한다.** 게이트는 등록된 관측유형 ID를 참조하며, 미등록·미매핑 상태는 운영환경에서 통과로 취급하지 않는다.
5. **시험변종은 번호 목록이 아니라 안정 ID로 관리한다.** 활성 기능의 변종은 `active`, 보류 기능의 변종은 `dormant`로 두고 기능승격과 동시에 활성화한다.
6. **문서 간 중복규칙을 만들지 않는다.** D54-A는 근거·추적·시험등록부, D55는 실행설명과 예시를 소유한다.

## 1. 제품 경계

### 1.1 발행등급

| 등급 | 목적 | 일반 구성 | 계산 상한 |
|---|---|---|---|
| L0 내부검토본 | 식별·불일치·자료보완 | 내부화면 | 외부발행 금지 |
| L1 사실확인형 매각안내서 | 공부·가격·현장·현재상태 전달 | 7~9면 목표 | 합계·면적·분모가 표시된 3.3㎡당 가격 |
| L1.5 중개인 제안형 매각제안서 | 추천·적합성·활용방안 제시 | 9~13면 목표 | L1 상한 + 허용된 현재 임대합계 |
| L2 표준 검토형 매각안내서 | 문의·답사·자료요청·예비가격 검토 | 10~16면 목표 | 허용된 임대합계·명시형 단순 임대수익률 |
| L3 중개분석형 투자검토서 | 만기·비교·실행방안·승인 시나리오 | 모듈별 E2 이후 | 운영비가 확인될 때만 순영업소득·자본환원율 |
| L4 전문가 협업형 투자검토서 | 최종 투자심의·전문 쟁점 | 별도 사양 | 쟁점별 전문가 검토범위 |

면수는 설계 목표이며 발행검사 기준이 아니다. 자료가 없으면 빈 페이지를 만들지 않는다.

발행명을 내부에서 다음 네 상태로 분해한다.

| 내부 상태 | 값 | 역할 |
|---|---|---|
| 사실묶음 수준 | `L1/L2/L3` | 어떤 사실·계산·시장 산출항목을 사용할 수 있는가 |
| 문서판 | `fact_om/broker_proposal_om/broker_review_om/broker_analysis_im` | 사실을 어떤 매수자 질문과 매각논리로 조립하는가 |
| 자동 적격판정 | `PASS/FAIL/NOT_RUN` | 필수 필드·근거·연결·정책검사가 끝났는가 |
| 사람 편집승인 | `APPROVED/REVISE/REJECTED/NOT_RUN` | 실제 의미·문장·공개범위를 사람이 승인했는가 |

`L1.5/L1P`는 `사실묶음=L1`, `문서판=broker_proposal_om`, `자동 적격=PASS`, `사람 편집승인=APPROVED`일 때 파생하는 내부 발행상태다. 자동 적격만 통과한 상태를 L1.5 외부발행 허가로 보지 않는다.

## 2. 단계 H0 안전패치

구조개편 전에 기존 산출항목·의견·발행검사 정본을 확장해 먼저 적용한다.

### 2.1 운영환경 차단규칙

| ID | 규칙 | 기대효과 |
|---|---|---|
| H0-01 | 누락·공란을 0으로 변환 금지 | 허위 합계·순영업소득 차단 |
| H0-02 | 관리비 청구액을 순수익·순영업소득에 합산 금지 | 관리비 과대계상 차단 |
| H0-03 | 채권최고액을 대출잔액으로 표시 금지 | 권리·금융 오표현 차단 |
| H0-04 | 단순 임대수익률 산정기준이 없으면 외부 표시 차단 | 수익률 오독 차단 |

### 2.2 병행검증 규칙

- 기존 `rent_sum`과 `reportedRent/contractedRent/collectedRent`를 병렬 계산한다.
- 기존 발행단계와 산출항목 묶음 발행단계를 병렬 계산한다.
- 기존 만료규칙과 점유·수납·최대임차인을 결합한 규칙을 병렬 평가한다.
- 의견·분석가정 승인 이벤트를 저장하되 외부 시나리오 계산은 아직 열지 않는다.

병행검증 결과는 문서를 바꾸지 않고 차이·원인·예상효과만 기록한다.

## 3. 최소 실행 흐름

```text
거래자료 접수
→ 매각대상 범위·토지 고유번호 확인
→ 원자료값과 근거자료 위치 저장
→ 표기·단위 통일
→ 불일치 탐지
→ 정정 승인
→ 유효기준본 생성
→ 산출항목 평가
→ L1/L1.5/L2 필수 산출항목·의견 묶음 판정
→ 문서 장 조립
→ 발행검사·개인정보·출력물 검사
→ 중개인 최종발행 승인
→ 수정불가 발행본 저장
```

AI는 추출·요약·문장·전략 후보를 만든다. 다음은 수행하지 않는다.

- 원자료 불일치의 자동승인
- 수치 계산의 정본 생성
- 산출항목 허가·발행단계 결정
- 빈 운영비·공사비·금리·공실률 보충
- 매각범위·비교사례·가정·외부발행 승인

## 4. 1차 처리조건

### 4.1 실행값

| 차원 | 값 | 처리 |
|---|---|---|
| 자산형태 | `whole_building` | 일반건물 매각안내서 |
|  | `vacant_land` | 필지·규제 중심 매각안내서 |
|  | `requires_review` | L0, 사람 확인 |
| 검토관점 | `yield` | 현재 임대수입·지속성 강조 |
|  | `value_add` | 임대격차·공실·만기·개선행위 강조 |
|  | `redevelop` | 필지·도로·이론규모·명도 질문 강조 |

검토관점은 최대 2개다. 이는 최적값이 아니라 초기 검증범위를 제한하기 위한 운영규칙이다.

### 4.2 적용규칙

- 자산형태는 시스템이 후보를 만들고 중개인이 승인한다.
- 공부상 주용도는 `legalUseTags[]`로 저장하며 문서분기를 만들지 않는다.
- 검토관점은 섹션 우선순위를 바꾸지만 산출항목 전제를 완화하지 않는다.
- 핵심 사실·수익 산출항목은 검토관점과 무관하게 평가한다.
- 검토관점 전용 실행방안·시나리오만 검토관점을 적용여부 조건으로 쓴다.
- 부동산 외 사업·지분이 거래에 포함되면 L1.5/L2/L3 자동작성을 중단하고, 공개 가능한 L1 범위와 전문가 이관을 별도 결정한다.

내부코드 `whole_building`, `vacant_land`, `yield`, `value_add`, `redevelop`는 자료구조에서만 사용한다. 입력화면에는 각각 `일반건물`, `나대지`, `수익현황`, `가치개선`, `개발검토`로 표시한다.

### 4.3 검토관점 결정기록

```yaml
lensDecision:
  candidates:
    - { lens: yield, signals: [rentroll_present] }
    - { lens: value_add, signals: [expiry_concentration] }
  selected: [yield, value_add]
  rejected: []
  revisitIf: ["특정 실사용 매수자 요구 접수"]
  approvedBy: broker-017
  approvedAt: 2026-08-30T15:30:00+09:00
```

## 7. 임대차 현황표와 산출항목

### 7.1 행 상태

```text
occupancy   = leased | vacant | owner_occupied | free_use | unknown
leaseStatus = active | expired_holdover_verified | expired_unverified | terminated | unknown
payment     = collected_verified | seller_reported_current | delinquent | unknown
mgmtFee     = billed | collected | pass_through | net_income_verified | unknown
```

공란은 내부코드 `unknown`, 외부 표시어 `미확인`이다. 0원은 `zeroConfirmed=true`가 있어야 하며 외부에는 `0원 확인`으로 표시한다.

### 7.2 1차 산출항목

| ID | 산출항목 | 필수전제 |
|---|---|---|
| RR-C01 | 매도인 제시 월 기본임대료 합계 | 행, 확인범위율 정책, 기준일, 중대한 불일치 없음 |
| RR-C02 | 계약상 월 기본임대료 합계 | RR-C01 + 계약 근거자료 확인범위율 정책 |
| RR-C03 | 실제 수납 월 기본임대료 합계 | 기간이 표시된 수납 근거자료 확인범위율 정책 |
| RR-C04 | 임대차보증금 합계 | 확인범위율 정책, 불일치 없음 |
| RR-C05 | 공실률 | 사용상태 100%, 자가사용 분리, 분모 확인 |
| RR-C09 | 월 관리비 청구합계 | 청구 기준과 확인범위율 |
| RR-C10 | 관리비 순효과 | 청구·수납·관련지출 확인 |
| RR-C11 | 산식이 표시된 단순 임대수익률 | 사용가능한 기본임대료, 가격, 산정기준, 만료정책 |

RR-C02·03은 원자료가 없으면 오류가 아니라 `현 단계 미제공(not_available_at_stage)`이다. 유효총수입·순영업소득·자본환원율·가중평균 잔여 임대차기간·시나리오는 선행 산출항목이 E2가 된 뒤 모듈별로 추가한다.

### 7.3 단순 임대수익률

```text
매도 희망가 기준 단순 임대수익률
= 연 기본임대료(부가가치세·관리비 제외) / 매도 희망가

임대차보증금 차감 매도 희망가 기준 단순 임대수익률
= 연 기본임대료(부가가치세·관리비 제외)
  / (매도 희망가 - 승계 임대차보증금)
```

매도인 제시액만 있으면 제목에 `매도인 제시 현행 기본임대료 기준`을 쓴다. 임대차보증금·부가가치세·월 관리비·자가사용·공실·연체 처리방식을 각주에 표시한다.

### 7.4 경험적 임계값

확인범위율 80/90/95%, 미확인 만료계약 비중 10%, 자료 유효기간은 모두 `잠정` 기준이다. 각 값은 다음을 가진다.

```yaml
threshold:
  id: RR-RENT-COVERAGE-MIN
  value: 0.80
  status: provisional
  evidenceIds: []
  rationale: "초기 보수정책"
  falseAllowCost: critical
  falseBlockCost: material
  owner: product-owner
  reviewCondition: "labeled eligible cases accumulated"
```

검증 전에는 수치를 완화해 산출항목을 여는 변경을 금지한다.

## 8. 의견과 시나리오

### 8.1 분리

```text
중개인 의견
→ 분석가정 제안
→ 중개인 승인
→ 승인된 분석가정
→ 시나리오 계산기
→ 시나리오 산출항목(현재 사실 지표와 분리)
```

1차 구현은 승인된 분석가정까지 저장한다. 승인 누락·변조 실패시험이 E2가 되기 전에는 외부 시나리오 계산기 연결을 끈다.

### 8.2 중개인 의견

- 화자·소속
- 작성일·대상·기간
- 관찰·판단
- 식별 가능한 근거
- 값이면 범위
- 반증·철회조건
- 전문가 필요 여부
- 공개승인

의견은 사실 표에 넣지 않는다. 사실 핵심지표 계산에도 직접 넣지 않는다.

### 8.3 중개인 입력 보존 계약

중개인이 입력한 매각 논리마다 `중개인 의견 기록`을 만든다. 시스템은 의견을 조용히 누락할 수 없다.

```yaml
brokerNarrative:
  id: BN-001
  originalText: "병원·약국 장기임차로 공실위험이 낮음"
  normalizedText: "병원·약국이 장기간 영업 중인 임대구성"
  speaker: broker-017
  observedAt: 2026-08-30
  evidenceRefs: [RENT-ROLL-01, SITE-PHOTO-02]
  targetBuyerType: "현재 임대수입과 일부 직접사용을 함께 검토하는 매수자"
  buyerMeaning: "병원·약국 영업을 유지하면서 자가사용 공간을 직접 쓰거나 임대로 전환할 수 있음"
  condition: "계약 갱신상태와 자가사용 공간의 인도시점 확인"
  recommendedAction: "갱신합의서·최근 수납내역·인도조건 요청"
  targetMessage: "장기 영업 중인 의료·약국 임차구성"
  externalCopy: "병원·약국이 장기간 영업 중이며, 자가사용 공간은 직접 사용 또는 임대 전환을 검토할 수 있습니다."
  targetPages: [핵심매각포인트, 임대차현황]
  disposition: retained | softened | omitted
  reason: null
  approvedForRelease: true
```

필수규칙:

- 중요 중개인 의견의 `retained·softened·omitted` 상태를 100% 기록한다.
- `softened`이면 원문의 매각의도는 남기고 과장 부분만 제한한다.
- `omitted`이면 법적·사실적·개인정보 사유를 기록하고 중개인에게 보여 준다.
- 의견을 위험요인으로만 바꾸거나 실사목록에만 남기는 것을 금지한다.
- 사실근거가 부족한 의견은 삭제 대신 `중개인 의견`으로 표시하고 성립조건을 붙인다.
- 가상값은 중개인 의견으로 둔갑시킬 수 없다.
- L1.5 후보 의견은 `targetBuyerType·buyerMeaning·condition·externalCopy·targetPages`가 모두 있어야 자동 적격검사 대상으로 들어간다.
- `투자자에게 적합`, `미래가치가 높음`, `임대료 상승 가능`처럼 대상·근거·조건이 없는 일반론은 L1.5 제안단위로 인정하지 않는다.

## 9. 산출항목 허가와 발행등급

### 9.1 상태

```text
allowed
allowed_with_warning
blocked
not_applicable
not_available_at_stage
not_evaluated
```

`미판정(not_evaluated)`을 통과로 보지 않는다.

| 화면 표시어 | 내부코드 | 처리 |
|---|---|---|
| 사용가능 | `allowed` | 해당 산출항목을 외부 문서에 사용할 수 있음 |
| 조건부 사용가능 | `allowed_with_warning` | 지정된 주의문구와 함께 사용 |
| 사용차단 | `blocked` | 해당 산출항목을 외부 문서에 넣지 않음 |
| 해당없음 | `not_applicable` | 자산·거래에 적용되지 않음 |
| 현 단계 미제공 | `not_available_at_stage` | 현재 거래단계에는 자료가 없는 것이 정상 |
| 미판정 | `not_evaluated` | 검사 미실행이며 통과로 취급하지 않음 |

### 9.2 L1 묶음

- 매각범위·주소·가격
- 핵심 토지·건물 공부
- 현장·사진 상태
- 기준일·출처
- 열린 위험·미확인
- 개인정보·발행승인 검사

### 9.3 L1.5 묶음

L1에 다음을 더한다. 아래 항목은 **자동 적격조건**이다.

- 공개 승인된 중개인 추천의견 1건 이상, 권장 3~5건
- 각 의견의 사실·현장관찰·사진 중 하나 이상의 근거연결
- 매수자에게 갖는 의미와 적합한 매수자 또는 활용방향
- 의견의 성립조건 또는 짧은 추가 확인사항
- 중개인 원문·정규화문·외부문구·반영면·승인상태의 추적

자동검사는 필드와 연결의 존재·정합성만 판정한다. `매수자에게 갖는 의미가 실제로 구체적인가`, `제목과 본문이 한국 중개인의 설명처럼 자연스러운가`, `다음 행동으로 이어지는가`는 기계 통과값으로 대체하지 않고 §12.5의 사람 편집승인에서 판정한다.

| 자동 적격 | 사람 편집승인 | 결과 |
|---|---|---|
| PASS | APPROVED | L1.5 발행 가능 |
| PASS | REVISE/REJECTED/NOT_RUN | L1.5 발행 보류, 안전한 L1 가능 여부 별도 판정 |
| FAIL/NOT_RUN | 어떤 값이든 | L1.5 불가, 실패한 의견을 L1에 우회 노출 금지 |

단순 임대수익률·조정 비교사례·미래 시나리오는 L1.5 필수요건이 아니다. 의견이 공개 승인됐어도 근거·대상 매수자·매수자 의미·성립조건이 없으면 자동 적격을 통과시키지 않는다. LLM의 자연스러움 점수나 자체평가를 사람 편집승인으로 사용하지 않는다.

### 9.4 L2 묶음

외부 L2 문서는 L1.5의 추천·매수자 의미·활용 제안 모듈을 포함하고 다음 분석을 더한다. 다만 내부 사실묶음 판정은 `L1 사실묶음 + 아래 분석조건`으로 계산한다. 사람 편집승인이 계산·산출항목 허가를 대신하거나 막지 않도록 하기 위해서다.

- 현재 사용현황·임대차 현황 또는 해당없음
- 가격 산정기준
- 시장근거 또는 공개승인 중개인의견
- 핵심 검토요약
- 구체적 자료요청·현장·매입의향서 확인사항
- 수익현황 검토이면 RR-C01 또는 임대 해당없음
- `redevelop`이면 이론값 경고와 필지 확인범위율

L2 외부발행에는 해당 사실·분석을 사용한 최종문구에 대한 사람 편집승인이 별도로 필요하다. L2 사실묶음이 가능하다는 이유로 L1.5 제안문구를 자동 승인하지 않는다.

비필수 산출항목 하나가 막혔다는 이유로 전체 발행단계를 낮추지 않는다. 해당 묶음의 필수 산출항목만 판정한다.

## 10. 문서 조립

### 10.1 공통 페이지 계약

각 페이지는 다음을 가진다.

1. 매수자 질문 한 개
2. 허용 산출항목에 근거한 결론 또는 판단불가
3. 표·지도·사진·계산 한 개
4. 출처·기준일·산정기준
5. 다음 확인 또는 행동

### 10.2 L1 권장 구성순서

1. 표지
2. 대표 외관을 포함한 물건 개요·핵심 거래조건
3. 매각범위·공부 확인내용
4. 입지·접근
5. 현재 사용현황
6. 매수 전 확인사항·출처
7. 문의·자료 유의사항
8. 필요한 경우에만 추가 사진 부록

추천의견이 필수는 아니다. 사진은 별도 면에 몰지 않고 관련 사실 가까이에 둔다.

### 10.3 L1.5 권장 구성순서

1. 대표 외관 중심 표지
2. 매물 추천 포인트
3. 대표 외관을 포함한 물건 개요
4. 매각범위·토지·건물 현황
5. 입지·접근
6. 층별 사용·임대현황
7. 중개인 제안 또는 활용 포인트
8. 허용된 가격 참고정보
9. 매수자 유형별 적합성
10. 매수 전 확인사항
11. 문의·자료 유의사항
12. 필요한 경우에만 추가 사진 부록

자료가 적으면 9면까지 통합하고, 사진이 적으면 별도의 사진 페이지를 만들지 않는다.

### 10.4 L2 권장 구성순서

1. 표지 및 핵심조건
2. 핵심 검토요약
3. 자료 확인현황
4. 매각범위·필지·건물
5. 입지·시장 맥락
6. 층별 사용현황·임대차 현황표
7. 허용된 임대수입·명시형 단순 임대수익률
8. 가격 수준 검토
9. 검토관점별 중개인 판단
10. 위험요인·반대근거
11. 자료·현장·매입의향서 확인조건
12. 담당자·자료 유의사항과 필요한 경우 추가 사진 부록

검토관점은 선택 분석항목을 우선시하지만 필수 사실·위험·자료 유의사항을 삭제할 수 없다.

### 10.5 핵심 숫자 표시 계약

다음 숫자는 값만으로 발행할 수 없다. 표시명·산정기준·근거자료·기준일을 함께 가져야 한다.

| 숫자 | 필수 표시 |
|---|---|
| 가격 | 매도 희망가·계약금액·실거래 신고금액 중 성격, 부가가치세와 포함대상 |
| 면적 | 토지·대지·건축·연·전용·임대면적 중 종류, ㎡ 원값, 근거자료 |
| 임대료 | 월 기본임대료·월 관리비 분리, 부가가치세, 제시·계약·수납 여부 |
| 수익률 | 정확한 지표명, 분자, 분모, 임대차보증금·월 관리비·운영비 처리 |
| 거리·도로 | 출발점·도착점·경로 또는 도로명·너비·접면, 측정자료와 조회일 |

`매매가`, `평당가`, `임대료`, `수익률`, `역세권`을 위 꼬리표 없이 단독 표시하면 관련 산출항목을 차단한다.

### 10.6 외부 문서 카피 계약

외부 문서는 다음 순서로 쓴다.

```text
확인된 사실 → 중개인 추천 포인트 → 매수자에게 주는 의미 → 짧은 확인사항
```

외부 제목은 매수자가 3초 안에 이해할 수 있는 `명사형 제목` 또는 `핵심 숫자형 제목`을 우선한다.

권장 예:

- `당산역 도보 5분, 병원·약국 장기 영업 중인 수익형 빌딩`
- `매매가 115억원｜대지 153.3평｜연면적 435.9평`
- `인근 매물 대비 낮은 토지 평당가`
- `자가사용 공간 임대 전환 및 기존 임대료 조정 여지`

금지 예:

- `115억원에 매각 제안된 당산역 생활권 근린생활시설이다`
- `매각대상은 단일 필지와 그 위 단일 건물로 정리한다`
- `매수자 논거와 반대근거를 같은 무게로 검토한다`
- `검토의 핵심은 …이다`를 모든 페이지에서 반복

본문은 `~입니다·~할 수 있습니다·~로 확인됩니다`를 자연스럽게 사용하되, 한 문장에 사실·의견·주의를 모두 몰아넣지 않는다. `검토 논거`, `반대근거`, `현재본`, `사실문서`, `표시 제한`, `산출항목` 같은 내부 보고서 표현은 외부 본문에서 금지한다.

### 10.7 장점과 확인사항의 화면 위계

- 표지와 앞 30% 페이지에는 매물의 핵심조건과 추천 포인트를 우선 배치한다.
- 확인사항은 관련 숫자·의견 바로 아래 한두 줄 또는 별도 `매수 전 확인사항` 페이지에 둔다.
- 위험 전용 페이지를 제외하고 경고문 면적이 본문 면적의 30%를 넘지 않게 한다.
- 면책문구로 페이지를 끝내지 않는다. 매수자가 취할 다음 행동을 함께 제시한다.
- 오류가 있는 원본값은 바로잡되, 그 오류 때문에 원본의 정상적인 매각 논리까지 삭제하지 않는다.

### 10.8 사진 자료의 역할·배치 계약

- 사용할 수 있는 대표 외관사진이 있으면 표지와 물건 개요에 우선 사용한다. 같은 원본을 재사용할 때는 표지와 개요의 목적에 맞게 서로 다른 크롭을 쓴다.
- 사진은 그것이 설명하는 사실·의견·확인사항과 같은 페이지 또는 바로 다음 페이지에 우선 배치한다.
- `현장사진` 또는 `사진 및 부록`은 필수 페이지가 아니다. 본문에서 사용하지 않은 추가 확인용 사진이 있을 때만 생성한다.
- 입지주장에는 도로 전면·접근로, 임차주장에는 간판·출입구, 활용주장에는 해당 공간, 확인사항에는 주차·설비·보수대상 사진을 연결한다.
- 사진마다 대상·층 또는 공간·촬영일 또는 자료 기준일·제공자·공개승인상태를 기록한다.
- 동일 사진의 동일 크롭은 본문에서 한 번만 사용한다. 사용 가능한 사진이 1~2장뿐이면 대표 외관 원본의 목적별 재크롭을 허용한다.
- 가상 생성사진·다른 건물 사진·출처 불명 사진으로 부족한 현장자료를 보완하지 않는다.
- 얼굴·번호판·전화번호·출입정보·민감 상호는 외부공개 전 검사하고 필요한 경우 가림처리한다.

사진수에 따른 기본 조립은 다음과 같다.

| 사용가능 사진 | 기본 조립 |
|---:|---|
| 0장 | 지도·공부·도식 중심, 사진 미제공 표시 |
| 1~2장 | 표지와 물건 개요에 목적별 크롭 |
| 3~5장 | 물건 개요·입지·사용현황·확인사항에 분산 |
| 6~10장 | 각 주장 가까이에 근거사진 배치 |
| 10장 초과 | 본문 핵심사진 선별, 잔여사진만 부록화 |

### 10.9 외부 노출명

L1·L1.5·L2는 시스템 내부 등급이다. 외부 파일과 표지에는 다음 이름을 쓴다.

| 내부 | 외부 권장명 |
|---|---|
| L1 | 매각안내서 |
| L1.5 | 매각제안서 |
| L2 | 매각안내서 · 매수 검토자료 포함 |
| L3 | 투자검토서 |

`골든 예시`, `L1 사실확인형`, `L1.5 중개인 제안형`, `L2 표준 검토형`, `가상 보완값 포함`은 제작·시험용 워터마크나 마지막 부록에서만 사용할 수 있다.

## 11. 중개인 입력화면

1차 구현에서 중개인이 추가로 결정하는 것은 세 묶음뿐이다.

1. 매각범위와 자산형태 후보 확인
2. `수익현황·가치개선·개발검토` 중 최대 2개 검토관점 승인
3. 위험·미확인·공개범위를 포함한 최종발행 승인

거래대상 범위는 예외질문 하나만 한다.

> 부동산 외에 운영사업·영업권·주식·수익권도 거래대상에 포함됩니까?

`예`이면 L1.5/L2/L3를 자동 생성하지 않고, 공개 가능한 L1 범위와 전문가 이관을 별도 결정한다.

활성 사용시간, 수정횟수, 도움말 열람, 이탈을 측정한다. 측정 전에는 60분 같은 입력시간 목표를 합격기준으로 사용하지 않는다.

보완과제는 최대 3개를 보여 준다.

- 현재 막는 위험
- 열리는 산출항목·페이지
- 담당자
- 예상 노력
- 목표 발행단계 최소조합

### 11.1 매각 논리 입력

중개인에게 최소한 다음 여섯 질문을 받는다.

1. 이 매물을 한 문장으로 어떻게 소개하시겠습니까?
2. 매수자에게 가장 먼저 말할 장점 세 가지는 무엇입니까?
3. 가격 경쟁력의 근거는 무엇입니까?
4. 임대수입 또는 활용가치를 높일 방법은 무엇입니까?
5. 설명할 때 반드시 함께 알려야 할 약점·확인사항은 무엇입니까?
6. 어떤 매수자에게 가장 적합하며, 그 이유는 무엇입니까?

시스템은 각 답변의 반영 예정 페이지와 최종 문구를 보여 주고, 중개인이 `그대로 반영·완곡하게 반영·제외`를 승인하게 한다.

### 11.2 사진 입력

중개인은 사진별로 `대표사진 여부·촬영대상·층/공간·촬영일·제공자·공개 가능 여부`를 확인한다. 시스템은 사진의 권장 배치와 연결된 의견을 제시하되, 대표사진 지정과 외부공개는 중개인이 최종 승인한다.

## 12. 발행검사

### 12.1 직교 분류

| 구분 | 내부 필드 | 의미 |
|---|---|---|
| 조치 | `effect` | BLOCK_RELEASE/DOWNGRADE/BLOCK_CLAIM/WARN/PASS/NOT_RUN |
| 위험등급 | `riskClass` | RC0/RC1/RC2 |
| 관측유형 | `observationType` | 현행 발행검사 사양의 관측유형 ID |
| 적용범위 | `scope` | artifact/domain/claim/field |

| 위험등급 | 적용 | 필수기록 |
|---|---|---|
| RC0 | 형식·출력물·자료구조 | 기대결과·실제결과 |
| RC1 | 산출항목·발행단계 | 실패 판정조건·허용되기 위한 조건 |
| RC2 | 외부발행·개인정보·법적경계·핵심수치 | 반대상황·관리책임자·예외승인 정책 |

미분류는 RC2로 처리한다. RC0 하향은 관리책임자 승인과 실패 표준시험사례가 필요하다.

관측유형은 다음 여덟 안정 ID를 사용한다. 기존 발행검사 정본의 ID가 다르면 정본 목록에서 별칭을 일대일로 연결하고 원래 ID를 보존한다. 매핑이 확인되지 않은 값은 `UNMAPPED`로 기록하고 운영환경에서는 `NOT_RUN + RC2`로 차단한다.

| 관측유형 ID | 화면 표시어 | 주로 확인하는 것 |
|---|---|---|
| `OBS-SURFACE` | 지면·출력물 | 넘침·빈 페이지·사진반복·파일 정상성 |
| `OBS-VALUE-CONSISTENCY` | 값정합 | 숫자·단위·합계·공식·동일 핵심지표 |
| `OBS-CONFLICT` | 불일치 | 출처 간 값 차이·미해결 충돌 |
| `OBS-TEMPORAL` | 기준일·현재성 | 만료계약·자료 노후·현재 점유·수납 |
| `OBS-NARRATIVE` | 서술·화자 | 사실·진술·의견·가정·성립조건 |
| `OBS-LEXICON` | 어휘·의미 | 채권최고액·대출잔액, 단순수익률·자본환원율 구분 |
| `OBS-PRIVACY` | 개인정보·공개 | 개인정보·사진·계약정보의 공개 가능성 |
| `OBS-REGULATORY` | 규제·전문경계 | 이론값·법정사실·전문가 확정판단의 구분 |

한 게이트는 실패원인과 보정행동을 가장 잘 설명하는 관측유형 하나를 주유형으로 갖는다. 서로 다른 보정행동이 필요하면 복수태그를 붙이기보다 원자적 게이트로 분리한다.

### 12.3 즉시 외부발행 차단

- 매각대상·가격단위 불명
- 대표필지 사실의 전체 전파
- 중요 불일치를 사용한 핵심 숫자
- 단순 임대수익률을 순영업소득 기준 자본환원율로 표시
- 관리비 청구액을 순수익으로 합산
- 채권최고액을 대출잔액으로 표시
- 개발 이론값을 실제 건축가능규모로 표시
- 매도인 진술을 계약확인으로 표시
- AI 숫자를 계산입력으로 사용
- 개인정보·공개정책 위반
- 중개인 최종승인 또는 필수 발행검사 미실행

### 12.4 독자품질검사

숫자가 맞아도 다음 품질검사를 통과하지 못하면 외부발행을 차단한다.

| 검사 | 합격기준 |
|---|---|
| 중개인 의견 반영률 | 중요 의견 100%가 반영·완곡반영·제외 중 하나로 추적됨 |
| 핵심 매각논리 보존 | 중개인이 승인한 장점·가격근거·활용방안이 앞부분에 모두 보임 |
| 3초 이해검사 | 표지와 요약면에서 위치·종류·가격·핵심장점이 즉시 식별됨 |
| 낭독검사 | 제목과 본문을 소리 내 읽었을 때 한국 중개인의 설명처럼 자연스러움 |
| 내부어 검사 | 외부 표지·제목의 L등급·정책·개발 내부어 0건 |
| 경고문 과잉검사 | 위험 전용면 외 경고문이 화면을 지배하지 않음 |
| 문장반복 검사 | `~이다·~한다`형 결론제목의 기계적 반복 없음 |
| 매수자 행동검사 | 문의·답사·자료요청·가격검토 중 다음 행동이 명확함 |
| 의견근거 연결검사 | L1.5의 모든 외부 의견이 사실·현장관찰·사진 중 하나 이상과 연결됨 |
| 사진역할 검사 | 사진이 장식용 반복이 아니라 물건개요·입지·사용·확인사항의 근거로 배치됨 |
| 대표외관 검사 | 사용 가능한 대표 외관이 있으면 물건 개요에서 건물 식별과 핵심제원을 함께 이해할 수 있음 |
| 사진진실성 검사 | 가상사진·타 건물·출처불명 사진 0건, 개인정보 공개검사 완료 |

한국 중개실무자 1명 이상이 `매물 설명력·문장 자연스러움·정보 신뢰성·문의 유도력`을 각 5점으로 평가하고, 평균 4점 미만 또는 어느 항목이든 3점 미만이면 재작성한다.

점수는 편집개선 지표이며 필수 의미검사를 대체하지 않는다. `근거 없는 핵심장점·사실과 의견의 화자혼동·다음 행동 부재·내부어 노출` 중 하나라도 있으면 평균과 무관하게 재작성한다. 파일럿 첫 30건은 작성자 외 중개인 또는 편집검수자가 전수검수하고, 이후 표본검수 전환은 품질책임자가 승인한다.

### 12.5 L1.5 사람 편집승인

사람 편집승인은 체크박스가 아니라 승인 대상에 결속된 기록이다.

```yaml
humanEditorialApproval:
  status: APPROVED
  reviewerRole: broker_author
  reviewerId: broker-017
  snapshotId: SNAP-001-R2
  proposalUnitIds: [BPU-01, BPU-02, BPU-03]
  copyHash: sha256:...
  photoSetHash: sha256:...
  policyVersions:
    claims: claims-1.0.0
    gates: gates-1.0.0
    terminology: terms-1.0.0
  checks:
    buyerMeaningConcrete: true
    naturalKoreanBrokerCopy: true
    speakerAndBasisClear: true
    nextActionClear: true
  approvedAt: 2026-08-31T10:00:00+09:00
```

다음 중 하나가 바뀌면 승인을 자동으로 `NOT_RUN`으로 되돌리고 재검토한다.

- 유효기준본 또는 핵심 사실값
- 중개인 원문을 바탕으로 한 외부문구·제목·추천 매수자·활용 제안
- 의견 근거로 사용한 사진집합·크롭·가림처리
- 산출항목·발행검사·공개·용어 정책버전

LLM은 누락·어색함·과장 후보와 수정문을 제안할 수 있으나 `APPROVED`를 기록할 수 없다. 사람승인이 미실행된 L1.5 파일은 렌더에 성공했더라도 외부발행하지 않는다.

### 13.3 필수 변종

번호목록을 문서마다 복제하지 않는다. D54-A §18.2의 단일 시험변종 등록부가 안정 ID·활성상태·활성조건·대상규칙·기대조치·표준시험사례를 소유한다. D54는 다음 활성군을 필수로 요구한다.

| 활성군 | 필수 시험 |
|---|---|
| H0 경제·권리 | 공란→0, 관리비 청구→순영업소득, 채권최고액→대출잔액, 수익률 산정기준 제거 |
| 임대차·시간 | 월 기본임대료 불일치, 만료·기준일, 자가사용 공실화, 임대면적 오염, 통합계약 이중계상 |
| 자산·다필지 | 대표필지 전체전파, 매각제외 필지 포함, 표지·본문 주소 불일치, 기존건물 나대지 오분류 |
| 승인·파이프라인 | AI 숫자 계산입력, 필수 검사 `NOT_RUN`, 유효기준본 이후 원자료 변경, 승인 없는 의견 시나리오 |
| 공개·개인정보 | 개인정보·내부 거래정보의 외부노출 |
| 검토관점 | 복수 검토관점 중 하나를 덮어쓰기 |
| 사진 | 0·1·3·8·10장 초과 적응형 조립, 대표외관 누락, 동일 크롭 반복, 타건물·출처불명·가상사진, 의견-사진 대상 불일치, 사진 개인정보 승인누락 |

보류 기능의 시험은 삭제하지 않고 `dormant`로 유지한다. BuyerMandate·상세 InternalDealContext 등의 기능 플래그가 켜지면 연결 시험도 같은 변경묶음에서 `active`가 되어야 한다. 활성 기능인데 연결 시험이 `dormant`이면 배포를 차단한다.

### 13.4 조합검증

초기 처리조건은 `자산형태 2 × 검토관점 조합 7 = 14`다.

- 합성·변종으로 14개 처리조건을 모두 실행한다.
- 규칙별 판정조건의 참·거짓 경우를 모두 실행한다.
- 자산형태×검토관점, 검토관점×근거자료상태의 쌍 조합 결과를 보고한다.
- 금액·권리·개인정보에 영향을 주는 상호작용은 전수검증하거나 세 요소 조합검증으로 올린다.
- 합성 통과를 실물 E2/E3로 간주하지 않는다.

### 13.5 임계값 검증

임계값 후보별 오류행렬, 잘못된 허용·잘못된 차단의 손실, 표본분포, 윌슨 신뢰구간을 보고한다. 실패 0건일 때 95% 상한은 대략 `3/n`이다. 데이터가 부족하면 `잠정 + 확인 전 차단`을 유지한다.

### 14.1 단일 정본 목록이 먼저다

현재 정본마다 다음을 기록한다.

| 관리항목 | 내부 필드 예시 |
|---|---|
| 파일 경로 | `path` |
| 관리책임자 | `owner` |
| 이름범위 | `namespace` |
| 사용모듈 | `consumers` |
| 버전관리 방식 | `versioning` |
| 다른 정본과의 중복범위 | `overlaps` |
| 유지·병합·폐기예정 결정 | `disposition` |

D53이 기존 정본으로 식별한 `im.axes.yaml`과 `im.gatespec.yaml`의 역할을 inventory 없이 재정의하지 않는다.

실제 저장소에서 위 파일명이 확인되지 않거나 다른 이름의 생성본만 존재하면 추정으로 새 파일을 만들지 않는다. 현재 경로·생성원천·소유 namespace를 먼저 확인하고, D54가 사용하는 논리명과 실제 정본 사이의 별칭을 문서목록에 기록한다. `UNMAPPED`, 깨진 참조, 소유자 미정 상태는 규범 채택 완료로 보지 않는다.

규범 우선순위는 다음과 같다.

1. 실제 실행 정책파일과 그 생성원천
2. 사람이 읽는 규범 핵심계약 D54
3. 판단근거·추적·시험등록부 D54-A
4. 실행설명·예시 백서 D55
5. 외부·화면 표시어 D56

D54-A와 D55는 D54에 없는 운영규칙을 독립적으로 만들지 않는다. 실행 정책파일과 D54가 충돌하면 외부발행을 중단하고 제품책임자와 해당 정본 관리책임자가 차이를 해결한다.

### 14.2 신규 정본은 최대 2개

기존 정본이 수용하지 못하는 경우에만 다음을 후보로 한다.

- `im.corrections.yaml`
- `im.context.yaml`

임대차·필지·검토관점 산출항목은 inventory로 확인된 기존 Claim 정본, 의견·분석가정은 기존 의견 정본, 발행검사는 확인된 발행검사 정본을 우선 확장한다. `im.claims.yaml·im.opinion.yaml·im.gatespec.yaml`은 논리명이며 실제 경로와 생성원천을 문서목록에서 확정한다.

새 정본에는 관리책임자, 사용모듈, 자료이전 절차, 되돌리기 절차, 정상·실패 표준시험사례가 있어야 한다.

## 16. 완료기준

### 안전

- H0 오표현 오류주입시험이 모두 기대 조치를 낸다.
- 중대 불일치·개인정보·NOT_RUN을 사용한 외부발행이 없다.
- 핵심 숫자에 유효기준본·산출항목·근거자료의 출처이력이 있다.
- 활성 게이트의 관측유형 `UNMAPPED`가 0건이다.

### 데이터

- 원자료값은 불변이고 정정·현실변경·분석가정이 분리된다.
- 하나의 발행본은 하나의 유효기준본만 참조한다.
- 다필지는 PNU별 포함여부와 면적분모가 검증된다.

### 분석

- AI는 계산·산출항목·발행단계를 결정하지 않는다.
- 단순 임대수익률 산정기준이 재현된다.
- 의견과 승인된 분석가정이 분리된다.
- 막힌 산출항목은 원인·해제조건·담당자를 반환한다.

### 산출물

- L1/L1.5/L2가 산출항목 묶음과 의견 묶음에 따라 조립된다.
- 자동 적격 또는 사람 편집승인이 `NOT_RUN`인 L1.5 외부발행이 0건이다.
