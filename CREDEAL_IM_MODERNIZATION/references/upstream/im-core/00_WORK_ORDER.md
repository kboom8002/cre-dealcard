# IM CORE 개편 작업지시서

> 작업군 코드: `IC`  
> 실행방식: 사양주도개발(Spec-Driven Development)  
> 목표 릴리스: IM CORE v1 + 모바일 L1/L1.5 + PPTX IM Studio v1  
> 태스크 정본: 이 문서와 `08_IMPLEMENTATION_BACKLOG.md`

---

# 0. 실행명령

현재 시스템을 다음 구조로 개편한다.

1. 생성 시점의 원자료·불일치·정정·주장목록·발행검사를 저장하고 승인 시 같은 버전을 다시 검사한다.
2. 근거 검증상태와 외부 사용허가상태를 분리한다.
3. 등급 하나가 분석면을 개방하지 않도록 산출항목별 전제판정으로 바꾼다.
4. 공통 `PublicationPackage`를 도입하고 모바일과 PPTX가 같은 패키지를 참조하게 한다.
5. 모바일은 기본 L1, 조건 충족 시 L1.5로 조립한다.
6. PPTX를 모바일 변환기가 아닌 `PPTX IM Studio`로 분리한다.
7. 모바일과 PPTX의 최종승인·발행본·파일해시를 각각 저장한다.
8. 기존 API와 공개 URL은 호환 어댑터로 유지하고 병행검증 후 구형 연속생산 경로를 폐기한다.

# 1. 착수 규약

## 1.1 모든 작업에 적용

1. 작업 시작 전 해당 작업의 선행 문서·지식 소스·JSON Schema를 전부 읽는다.
2. 명세에 없는 상태·열거값·발행규칙을 코드에 임의 추가하지 않는다.
3. 신규 정책이 필요하면 `IC-OQ` 결정 또는 SDD 개정부터 한다.
4. 런타임 정본 생성파일을 직접 수정하지 않는다. 소유 코드 또는 사람이 관리하는 정본을 수정하고 생성·차이검사를 실행한다.
5. 모든 외부 수치는 산출항목 평가결과 또는 결정론적 표시계산에서만 온다.
6. LLM 출력은 사실정본이 아니며 숫자·상태·산정기준의 입력으로 사용하지 않는다.
7. 승인 API는 `expectedHash` 없는 승인요청을 거부한다.
8. 한 발행본은 하나의 `snapshotId`와 하나의 `packageId`만 사용한다.
9. 실패한 발행검사를 면책문구로 우회하지 않는다.
10. 기능깃발을 끄면 구형 안정경로로 되돌아가야 하며, 새 데이터는 삭제하지 않는다.

## 1.2 AI 코딩 에이전트 착수 프로토콜

1. 배정된 작업 ID와 범위를 응답 첫 줄에 명시한다.
2. 실제 소유 파일과 호출자를 검색해 작업지시서의 경로가 최신인지 확인한다.
3. 기존 사용자 변경을 보존한다.
4. 구현 전 실패시험을 먼저 추가하거나, 최소한 기대 실패사례를 고정한다.
5. 한 작업에서 데이터계약과 화면개편을 동시에 크게 바꾸지 않는다.
6. 작업 완료 시 변경파일·시험결과·미해결 위험·기능깃발 상태를 보고한다.

## 1.3 문서와 지식 소스 우선순위

```text
schemas/*.schema.json
→ knowledge/*.yaml의 ID·enum·전제
→ 상세 SDD의 절차·책임
→ 구현 코드
```

충돌 시 구현을 멈추고 `11_TRACEABILITY_AND_OPEN_DECISIONS.md`에 결정요청을 추가한다. 조용히 한쪽을 선택하지 않는다.

# 2. 작업범위

## 2.1 포함

- IM 근거·유효기준본·산출항목·발행묶음 도메인
- L1/L1.5 문서등급 판정
- L2/L3 선택 산출항목을 위한 확장점
- 모바일 조립기와 기존 `/im-lite` 호환
- PPTX IM Studio 프로젝트·편성·미리보기·렌더링·승인
- 발행검사·승인·버전·해시·무효화
- 데이터베이스·RLS·서비스·API·이벤트
- 기존 D37 경로의 병행검증과 단계적 폐기
- 당산동·상도동·양평동형 시험사례

## 2.2 제외

- 감정평가·법률·세무·건축·구조 전문가의 확정판단
- L4 전문가 협업형의 전체 업무흐름
- 자동 공사비·자동 대출승인·자동 적정가 확정
- 신규 공공 API 공급자 자체 개발
- 기존 PPTX 디자인 토큰 전면교체
- 기존 공개 URL 변경
- 과거 모든 문서의 일괄 재생성

# 3. 작업단계와 차단관계

```text
P0 신뢰봉합
  ├─ 승인 재수화·해시
  ├─ 발행검사 영속화
  └─ 정본 소유권 복구
       ↓
P1 CORE v1
  ├─ 유효기준본
  ├─ 산출항목 판정
  └─ 공통 발행묶음
       ↓
P2 모바일 L1/L1.5
       ↓
P3 PPTX IM Studio
       ↓
P4 병행검증·전환
       ↓
P5 구형 연속생산 폐기
```

P0 완료 전 P2·P3의 외부발행 기능을 켜지 않는다. UI 뼈대 병렬개발은 가능하지만 실데이터 발행은 금지한다.

# 6. 리뷰 반려 사유

```yaml
forbidden:
  - 생성 당시 주장목록을 저장하지 않고 승인 시 빈 목록으로 검사
  - 기계검사 passed를 사람의 approved로 저장
  - ReleaseTier 또는 자료등급 하나로 재무·시나리오 전체 개방
  - PPTX 렌더러가 enrichment 원시객체나 모바일 markdown을 사실값으로 재해석
  - 운영비 없이 NOI 또는 자본환원율 산출
  - 관리비 청구액을 순수입에 자동 합산
  - 채권최고액을 실제 대출잔액으로 표기
  - 공란·미제공·해당없음을 0으로 정규화
  - 대표필지 사실을 다른 필지에 복제
  - LLM 출력 수치를 산출항목 입력으로 사용
  - 공개승인 없는 중개인 의견 또는 사진을 외부발행
  - 모바일 승인으로 PPTX 최종승인을 갈음
  - expectedHash 없는 승인·발행 API
  - 한 발행본에서 snapshotId 혼용
  - not_evaluated를 통과로 처리
  - im.gating.yaml·im.tokens.yaml·im.budget.yaml 직접 수정
  - 기능깃발·롤백경로 없는 신규 외부발행
  - 기존 공개 URL 변경
```

# 7. 전 작업 완료정의

- 요구 ID와 구현·시험이 추적표에서 연결됨
- TypeScript·Zod·JSON Schema의 enum과 필수필드가 일치함
- 단위·통합·가드레일·E2E 시험 통과
- 차단사례가 실제 발행 API에서 4xx로 거부됨
- 기능깃발 off 회귀 통과
- 신규 이벤트와 실패사유가 관측 가능함
- 문서·정본·코드 생성차이 CI 통과
- 모바일과 PPTX의 공통 핵심값 불일치 0건
- 중개인 의견 원문→근거→외부문구→반영위치 추적률 100%
- 최종발행본에 snapshot/package/copy/photo/layout/artifact 해시가 기록됨
