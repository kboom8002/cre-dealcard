## 0. 이 화면의 유일한 목적

**매수자가 [상세 요청]을 누르게 하는 것.**

정보를 다 주는 화면이 아닙니다. 정보를 다 주면 누를 이유가 없어집니다. 그렇다고 너무 감추면 관심이 안 생깁니다. **딜카드의 모든 설계 판단은 이 균형점 하나로 수렴합니다.**

```
너무 감춤  →  "뭔지 모르겠다" → 이탈
적정       →  "이건 봐야겠다" → 상세 요청     ← 여기
너무 공개  →  "다 봤다"       → 이탈
```

## 1. 노출 경계 — 무엇을 넣고 무엇을 빼는가

### 1.1 원칙

> **매수자가 이해할 수 없거나, 판단에 쓰지 않거나, 우리 내부 사정인 것은 넣지 않습니다.**

### 1.2 넣는 것 (대고객)

| 항목 | 이유 |
|---|---|
| 물건 유형 — **B2C 어휘** | "상가주택" ○ / "mixed_shop_house" ✗ |
| 투자 관점의 **결과** | 화면 구성이 달라질 뿐, 관점 이름을 적지 않습니다 |
| 아키타입의 **의미와 근거** | "밸류애드형 — 용적률 여유 113%p" |
| 가격·수익률·면적 **밴드** | 정밀값은 상세 요청 후 |
| 물건 특징 칩 | 각지·용도지역·주차·위반건축물 |
| curiosity slot | 상세 요청을 유도하는 한 문장 |
| 조건 슬라이더 | 개인화 · 전부 가정 배지 |
| 규제 스크리닝 | 토허 등 — 매수자에게 실질 영향 |
| 공개 정책 고지 | **신뢰 신호**. 감춘 이유를 밝힘 |
| 중개인 프로필 | 응답 보장·성사 건수·자격 |

### 1.3 빼는 것 (내부 독백)

| 항목 | 왜 빼는가 |
|---|---|
| ~~자료등급 "B등급"~~ | **매수자는 등급 체계를 모릅니다.** B·C면 오히려 불신을 부릅니다 |
| ~~아키타입 코드 "R02"~~ | 내부 코드. 의미만 남기고 코드는 제거 |
| ~~딜 준비도 7축~~ | 우리가 이 딜을 어떻게 보는지는 매수자와 무관 |

| ~~슬롯 결손·"확인 중"~~ | 부족함을 광고할 이유 없음 (IM에서는 밝힘) |

> **💥 기준판 대비 변경.** `시연자료_정적판.html`에는 **`B등급` 배지와 `R02 판정`** 이 노출되어 있습니다. 둘 다 제거합니다.
> 자료등급은 발행 게이트용 내부 지표이고, 아키타입 코드는 우리 규칙 식별자입니다. **근거 문장("건물연령 26년 ∧ 용적률 여유 113.9%p")은 유지**합니다 — 이건 매수자가 판단에 씁니다.

### 1.4 판정 규칙

```ts
// 슬롯 하나를 딜카드에 노출할지 결정하는 유일한 기준
export function isTeaserVisible(slot: SlotDef): boolean {
  if (slot.visibility !== 'public') return false;      // 공개 정책
  if (slot.audience === 'broker_internal') return false; // 내부 지표
  if (!slot.b2cLabel) return false;                     // B2C 어휘 없으면 노출 불가
  return true;
}
```

**`b2cLabel`이 없는 슬롯은 딜카드에 나올 수 없습니다.** 내부 용어가 새어 나가는 경로를 타입 수준에서 막습니다.

## 4. 관점이 티저를 결정한다 — v0.4 핵심

기준판은 밸류애드형 하나만 있었습니다. v0.4에서는 **`investmentPosture`가 ⑥ 히어로 항목과 ⑧ curiosity를 통째로 바꿉니다.**

### 4.1 관점별 히어로 4칸

| posture | 1칸 | 2칸 | 3칸 | 4칸 |
|---|---|---|---|---|
| `income` | 매각가 밴드 | **임대수익률 밴드** | 대지/연면적 | 공실 |
| `owner_occupied` | 매각가 밴드 | **사용 가능 면적** | 대지/연면적 | 입주 가능 시기 |
| `development` | 매각가 밴드 | **개발 가능 규모** | 대지 | 명도 조건 |
| `operating` | 매각가 밴드 | **객실 수 · 객실당** | 연면적 | 운영 형태 |
| `trading` | 매각가 밴드 | **권역 평단가 대비** | 대지 | 거래 회전 |

**`income`에만 수익률이 나옵니다.** 개발형 물건에 Cap Rate를 띄우면 매수자가 잘못된 기준으로 판단합니다.

## 5. 밴딩 정책

### 5.1 밴드 규칙

| 항목 | 밴드 |
|---|---|
| 매각가 | 십억 단위 — "190억대" |
| 수익률 | 1%p 구간 — "2%대 중반" |
| 대지·연면적 | ±10% 범위 — "170~190평" |
| 공실 | 개수만 — "1개층" |
| 주소 | **권역까지** — "역삼권" |

### 5.2 수익률에는 기준을 답니다

밴드로 뭉개도 **어느 기준인지는 밝힙니다** (G10).

```
Cap Rate         2%대 중반
                 만실 시 3%대
        ↓ v0.4
임대수익률        2%대 중반          ← 실투자금 기준
                 만실 시 3%대
```

`CapRateBasis` → B2C 라벨 매핑은 `PPTX_TEMPLATE_SPEC.md` §16.2와 동일합니다. **딜카드에서는 실투자금 기준 하나만** 씁니다 — 여러 기준을 나열하면 티저의 목적을 잃습니다.

### 5.3 밴드가 거짓이 되지 않게

```ts
// 밴드는 실제 값을 포함해야 합니다
export function assertBandContains(band: Band, actual: number): void {
  if (actual < band.lo || actual > band.hi)
    throw new Error(`밴드 위반 — ${band.label}에 실제값 ${actual} 없음`);
}
```

"190억대"라고 해놓고 실제가 205억이면 상세 열람 시점에 신뢰를 잃습니다.

## 10. 물건 유형별 변형

v0.4에서 새로 다루는 유형입니다.

### 10.1 상가주택 · 주택 혼합

```
특징 칩    🔹 1·2층 상가 + 3·4층 주택
           🔹 임대차 승계 조건
```

**임대차 법령 구분(상임법/주임법)은 딜카드에 넣지 않습니다.** 매수자가 티저 단계에서 판단할 사항이 아니고, 잘못 읽히면 오히려 해롭습니다. IM에서 다룹니다.

### 10.2 집합건물 · 구분등기

```
특징 칩    🔹 층별 구분등기
           🔹 소유자 2인 (전원 동의 필요)
```

**동의 요건은 반드시 노출합니다.** 매수 진행 자체를 좌우하는 조건이라 나중에 알면 분쟁이 됩니다. 소유자 이름·지분은 넣지 않습니다.

### 10.3 숙박 · 운영 자산

```
히어로     매각가 300억대 | 94실 · 객실당 3억대 | 연면적 1,100평대 | 위탁 운영
curiosity  "객실당 3억대입니다. 신촌·이대 권역 평균과 비교해 보십시오."
```

**ADR·OCC·GOP는 딜카드에 넣지 않습니다.** 운영 지표는 밴드로 뭉개도 오독 위험이 크고, GOP 기준임을 설명할 지면이 없습니다 (C31).

### 10.4 나대지 · 개발부지

```
히어로     매각가 89억대 | 개발 가능 2,400평대 | 대지 190평대 | 나대지
```

**개발 규모에는 전제를 답니다** — "지구단위계획 수립 시" 같은 조건이 빠지면 확정으로 읽힙니다 (C22·§5.3의 밴드 규칙과 동일한 이유).

| 스크립트 | 슬라이더·추적 최소 (§11.1) |

### 11.1 스크립트 최소 원칙

기준판이 **완전 정적**인 이유는 Safari에서 깨졌기 때문입니다. 원인은 `innerHTML` 주입이었지 스크립트 자체가 아니었습니다.

```
콘텐츠 렌더    서버 사이드 · 스크립트 없음      ← 유지
슬라이더       최소 스크립트 (DOM 조작 없음)
추적 비콘      view.section · view.slider · view.completed
```

**추적 없이는 S 신호(반응)가 성립하지 않습니다** (`PRD_발행후관리.md` §8.1). 콘텐츠는 정적으로, 계측은 비콘으로 분리합니다.
