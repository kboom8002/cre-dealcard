## 0. 이 문서를 읽는 LLM에게

새 슬라이드를 만들 때 순서는 다음과 같습니다.

0. **`investmentPosture`를 먼저 확인한다.** §15에서 덱 시퀀스가 결정됩니다. 관점을 모르면 어떤 슬라이드를 만들지 알 수 없습니다.
1. **§7에서 아키타입을 고른다.** 새 레이아웃을 발명하지 마십시오. 13종이면 대부분 덮입니다.
2. **§9로 텍스트 길이를 먼저 맞춘다.** 글을 쓰고 상자를 키우는 게 아니라, 상자에 맞게 글을 씁니다.
3. **§8 컴포넌트만 조합한다.** 좌표를 직접 계산하지 말고 §6 컬럼 패턴을 씁니다.
4. **§16 표기 강제를 적용한다.** 기준 없는 수치는 발행 게이트에서 차단됩니다.
5. **§12 금지 사항을 확인한다.** 여기 있는 것 중 하나라도 하면 템플릿이 깨집니다.

> **가장 흔한 실패는 텍스트 과다입니다.**
> 이 템플릿은 여백이 많아 보이지만 그건 의도입니다. 빈 공간을 채우려고 문장을 늘리는 순간 institutional한 인상이 사라집니다. 상자가 비어 보이면 글을 늘리지 말고 상자를 줄이십시오.
>
> **두 번째로 흔한 실패는 관점을 무시하는 것입니다.** 개발형 물건에 렌트롤 3장을 넣으면 매수자가 안 봅니다. §15를 건너뛰지 마십시오.

## 1. 템플릿 정체성

### 왜 이렇게 생겼는가

강남 상업용 부동산 IM입니다. 참조한 물성은 **석재 · 유리 · 황동**입니다.

- **무채색이 지배한다 (60~70%)** — 잉크 차콜과 오프화이트가 화면 대부분을 차지합니다.
- **액센트는 황동 하나뿐** — `B98A2E`. 다른 강조색은 의미(양호·위험·주의·정보·출처)에만 씁니다. 장식용 색은 없습니다.
- **다크 슬라이드는 세 자리에만** — 표지 / 핵심 강조 1~2장 / 마감. 샌드위치 구조입니다.
- **장식이 없다** — 제목 밑줄, 색 바, 사이드 스트라이프, 그라디언트 전부 없습니다. 구분은 여백과 배경 톤으로만 합니다.
- **모든 수치에 출처가 붙는다** — provenance 배지가 이 템플릿의 시각적 서명입니다.

### 이 템플릿이 아닌 것

컨설팅 덱도, 스타트업 피치덱도 아닙니다. **읽고 판단하는 문서**입니다. 슬라이드당 정보 밀도가 높고, 애니메이션·전환·아이콘 일러스트가 없습니다.

## 2. 기하

```js
const W = 13.333;   // LAYOUT_WIDE 캔버스 폭
const H = 7.5;      // 높이
const M = 0.62;     // 좌우 마진 (실측 236회 사용 — 절대 기준선)
const CW = 12.093;  // 콘텐츠 폭 = W - M*2
```

**`pres.layout = 'LAYOUT_WIDE'`를 슬라이드 추가 전에 반드시 설정하십시오.** 기본 캔버스는 10×5.625in이며, 나중에 설정하면 좌표가 캔버스 밖으로 나가고 **경고 없이 사라집니다.**

### 수직 영역

| 영역 | y 범위 | 용도 |
|---|---:|---|
| 제목 블록 | 0.50 ~ 1.36 | §8.1 `head()` |
| **콘텐츠** | **1.62 ~ 6.85** | 사용 가능 5.23" |
| 푸터 | 6.98 ~ 7.22 | §8.2 `foot()` |

### 콘텐츠 시작 y — 실측 클러스터

| 값 | 상황 |
|---:|---|
| **1.62** | 제목만 (부제 없음) · `sub()` 소제목으로 시작 |
| **1.66** | 제목만 · 차트로 시작 |
| **1.72** | 부제 있음 · 카드/스탯으로 시작 |
| **1.78 ~ 1.86** | 부제 있음 · 표로 시작 |
| **1.96** | `sub()` 소제목 바로 아래 `rows()` |

부제(`sub` 인자)가 있으면 콘텐츠를 **0.10~0.24" 아래로** 내리십시오.

## 5. 제목 블록과 푸터

### `head(s, num, kicker, title, sub)` — 밝은 슬라이드

```
황동 원  x=M      y=0.50  0.42 × 0.42   ← 번호 (Arial 13pt bold white, 중앙)
kicker  x=M+0.62  y=0.50  h=0.20        ← 9.5pt bold brass, charSpacing 2
title   x=M+0.62  y=0.70  h=0.40        ← 23pt bold ink
sub     x=M+0.62  y=1.10  h=0.26        ← 11pt mute (선택)
```

`headD()`는 동일 좌표에 제목만 흰색입니다.

번호는 `String(num).padStart(2,'0')` — `01`, `02`. 표지·마감 슬라이드는 `num=''`을 넘기고 원 안에 `!` 또는 `⌘`를 직접 그립니다.

### `foot(s, page, docno, onDark)`

```
좌  x=M       y=6.98  h=0.24   8pt mute   'CREDEAL · 제이에스부동산중개(주)   |   {docno}'
우  x=W-M-1.0 y=6.98  h=0.24   9pt bold brass, 우측 정렬, 페이지 번호
```

## 6. 컬럼 패턴 — 직접 계산하지 마십시오

```js
const col = (n, gap) => (CW - gap * (n - 1)) / n;
const x   = (i, w, gap) => M + i * (w + gap);
```

실측 사용 빈도 순입니다.

| 패턴 | gap | 폭 | 용도 |
|---|---:|---:|---|
| **2열 균등** | 0.28 | **5.91** | 콜아웃 쌍 — 가장 많이 씁니다 |
| **비대칭 7:5** | 0.36 | 7.10 / 4.63 | 좌 표·rows / 우 스탯·콜아웃 |
| **비대칭 7.3:4.2** | 0.60 | 7.30 / 4.19 | 좌 차트 / 우 콜아웃 스택 (`rx = 8.20`) |
| 3열 균등 | 0.30 | 3.83 | 카드 3장 |
| 3열 균등 | 0.34 | 3.80 | 다크 슬라이드 3블록 |
| 4열 균등 | 0.26 | 2.83 | 스탯 그리드 |
| 단일 | — | 12.09 | 대형 표 |

**비대칭 패턴에서 우측 시작점은 `rx`를 명시**하십시오. `M + 좌폭 + gap`을 매번 계산하면 어긋납니다.

```js
// 7:5
const lw = 7.10, rx = M + lw + 0.36, rw = CW - lw - 0.36;   // rx=8.08, rw=4.633
// 7.3:4.2
const rx = 8.20, rw = CW - (rx - M);                        // rw=4.513
```

### A3 — 대형 표 (light)

```

### A11 — 호실 구성 (light) 🆕 `residential_spec`

다가구·상가주택·오피스텔. 호실이 12개를 넘으면 개별 나열이 무의미하므로 **유형별 집계**로 보여줍니다.

    콜아웃 (rx, 4.30) rw×1.20   위반건축물 고지 또는 개별계량 여부
```

> **위반건축물 항목은 값이 있든 없든 자리를 만듭니다.** "확인 중"이라도 적습니다 — 없으면 매수자가 안 물어본 것으로 오해합니다 (G16).

### A12 — 소유자 · 권리 구성 (light) 🆕 `sectional_spec`

층별구분등기·집합건물. 당산동(형제 2인 공동담보)에서 필요성이 확인되었습니다.

```
좌  rw=7.10
    sub    (M,1.66)
    표     (M,1.98)  7.10  rh=0.35
           열: 호실 / 소유자 / 대지권지분 / 채권최고액 / 공동담보그룹
    note   (M, 표끝 + 0.07)
           '공동담보 그룹 A는 1회만 합산 — 중복 계상 아님'   ← 필수
우  rx=8.08 rw=4.63
    콜아웃 3개 (각 1.24, gap 0.14)  y=1.98   → 하단 5.98
           소유자 수 / 전원동의 필요 여부 / 일부 매각 가능성
```

> 우측 마지막 콜아웃 하단이 **5.98**입니다. `note`가 y=6.20에 오므로 간격 0.22"로 규칙(0.20" 이상)을 만족합니다. 콜아웃을 1.32로 키우면 하단이 6.26이 되어 **주석과 겹칩니다** — 실제로 골든 덱 제작 중 여러 슬라이드에서 났던 결함입니다.

> **공동담보 각주는 생략 불가입니다.** 없으면 매수자가 채권최고액을 단순 합산해 실제의 두 배로 읽습니다 (C32).

### A13 — 운영 지표 (light) 🆕 `hospitality_spec` · `posture=operating`

호텔·생활형숙박시설·요양시설. 렌트롤 자리를 대체합니다.

```
좌  rw=7.30
    sub①   (M,1.66)   객실 구성
    표①    (M,1.98)  7.30  rh=0.34   타입/객실수/면적
    sub②   (M, 표①끝 + 0.13)   운영 지표
    표②    (M, sub② + 0.32)  7.30  rh=0.34   ADR/OCC/RevPAR/GOP마진
우  rx=8.20 rw=4.51
    스탯 (rx,1.98) rw×1.12   객실당 단가
    콜아웃 (rx,3.22) rw×1.44  Cap Rate — **GOP 기준 명시 필수**
    콜아웃 (rx,4.80) rw×1.18  계절성 · 운영사 계약 잔여   → 하단 5.98
```

> **GOP 기준 표기가 없으면 발행이 차단됩니다** (C31). 임대차 NOI 기준 Cap Rate와 나란히 놓는 것도 금지입니다 — 매수자가 같은 지표로 오독합니다.

| 7.30 | 45자 |
| 5.91 (2열) | **36자** |
| 4.51 | 27자 |
| 3.83 (3열) | 22자 |

### 콜아웃 높이 — 실측 대응표 (w = 5.91)

| 본문 글자수 | 줄 | 권장 h |
|---:|---:|---:|
| ~36 | 1 | 0.85 |
| ~72 | 2 | **1.12** |
| ~108 | 3 | **1.34** |
| ~145 | 4 | **1.72** |

`\n\n`(빈 줄)이 들어가면 **1줄을 추가로** 계산하십시오.

다른 폭에서는 `h = 0.55 + 줄수 × 0.29` 로 근사하고, 렌더 확인 후 조정합니다.

| 형태 | 코드 | 쓰는 곳 |

미래 시나리오(총수익률·NPV·IRR)는 입력이 전부 공부여도 **항상 ◇**입니다.

## 11. 다크 슬라이드 사용 규칙

24p 덱에서 다크는 **4장뿐**입니다 — 표지 / 문서 통제 / 밸류애드 강조 / 마감.

| 쓸 때 | 쓰지 말 때 |
|---|---|
| 표지·마감 | 표가 있는 슬라이드 |
| 덱 전체의 핵심 주장 1~2장 | 데이터 밀도가 높은 슬라이드 |
| 문서 통제·법적 고지 | 연속 2장 이상 |

**다크가 5장을 넘으면 리듬이 깨집니다.** 강조가 흔해지면 강조가 아닙니다.

## 12. 금지 사항

### 템플릿을 깨는 것

- [ ] 제목 아래 밑줄·액센트 선을 긋지 않았는가 — AI 생성 슬라이드의 전형
- [ ] 색 바·사이드 스트라이프·카드 한쪽 테두리 강조가 없는가
- [ ] 그라디언트를 쓰지 않았는가 (pptxgenjs 미지원이기도 함)
- [ ] 본문을 가운데 정렬하지 않았는가 (제목만 중앙)
- [ ] 아이콘 일러스트·이모지를 본문에 넣지 않았는가 (섹션 머리의 ①②③ 정도만)
- [ ] 폰트를 맑은 고딕·Arial 외로 바꾸지 않았는가
- [ ] brass를 슬라이드당 3회 이상 쓰지 않았는가
- [ ] 좌표 리터럴 대신 `M`·`CW`·`col()`을 썼는가

### 내용을 틀리게 하는 것 🆕

- [ ] 표 합계를 문자열 리터럴로 넣지 않았는가 (**배열에서 계산**, §17.1)
- [ ] 수익률에 기준 라벨을 붙였는가 (§16.2 — 없으면 G10 차단)
- [ ] 용적률이 두 기준으로 다르면 둘 다 적었는가 (§16.1)
- [ ] GOP 기준 Cap Rate를 임대차 기준과 나란히 놓지 않았는가 (§16.3 — C31)
- [ ] 임대차 표에 적용 법령(상임법/주임법)을 표기했는가 (§16.4 — G15)
- [ ] 주택 갱신권 잔여를 경과년수로 추정해 적지 않았는가 (§16.4)
- [ ] 임대료 인상 계획 옆에 법정 상한을 병기했는가 (§17.3)
- [ ] 시나리오 수치에 `◇` 배지와 전제 각주를 달았는가 (§16.5 — C22)
- [ ] 결손 항목의 열을 지우지 않고 "확인 중"으로 남겼는가 (§17.2)
- [ ] 공동담보 표에 그룹 중복 합산 각주를 달았는가 (A12 — C32)
- [ ] 관점에 맞지 않는 슬라이드를 넣지 않았는가 (§15.4)

### pptxgenjs 치명적 오류 (파일이 열리지 않음)

- [ ] 색상에 `#`을 붙이지 않았는가 — `'FF0000'` ○ / `'#FF0000'` ✗
- [ ] 8자리 알파 헥사를 쓰지 않았는가 — 투명도는 `transparency: 0-100`
- [ ] shadow `offset`이 0 이상인가
- [ ] 누적 막대 `dataLabelPosition`이 `ctr`/`inEnd`/`inBase`인가
- [ ] 보조축 사용 시 `valAxes`·`catAxes`를 각 2개씩 선언했는가

### 조용한 오류 (열리지만 잘못됨)

- [ ] `pres.layout`을 슬라이드 추가 **전에** 설정했는가
- [ ] 옵션 객체를 두 `add*` 호출에서 재사용하지 않았는가 (EMU 변환 오염)
- [ ] `charSpacing`을 썼는가 (`letterSpacing`은 존재하지 않음)
- [ ] `rectRadius`를 `roundRect`에만 썼는가
- [ ] 차트에 `dataLabelFormatCode`를 지정했는가
- [ ] 표 `colW` 합계가 `w` 이하인가
- [ ] 텍스트박스에 `margin: 0`을 줬는가

## 13. 생성 체크리스트

| # | 확인 |
|---:|---|

| 3 | 좌우 컬럼이 서로 침범하지 않았는가 |
| 4 | 요소 간 간격이 0.20" 이상인가 |

| 6 | 다크 슬라이드가 5장을 넘지 않았는가 |
| 7 | 모든 수치에 provenance 배지가 있는가 |
| 8 | **표의 합계 행이 위 행들의 합과 일치하는가** 🆕 |
| 9 | **모든 수익률·용적률에 기준이 표기되었는가** 🆕 |
| 10 | **덱 구성이 `investmentPosture`와 맞는가** 🆕 (§15) |

### 자동 검사 — 육안 확인 전에 돌립니다 🆕

```python
# 표 합계 정합성 · 기준 라벨 누락 스캔
python3 - <<'EOF'
import zipfile, re
z = zipfile.ZipFile('out.pptx')
BASIS = ('기준', 'Cap Rate (', '실투자금', '매매가 기준', '총취득원가', 'GOP')
for n in sorted(x for x in z.namelist() if re.match(r'ppt/slides/slide\d+\.xml', x)):
    txt = ' '.join(re.findall(r'<a:t>([^<]*)</a:t>', z.read(n).decode()))
    for m in re.finditer(r'(\d+\.\d+)\s*%', txt):
        seg = txt[max(0, m.start()-60):m.end()+60]
        if ('수익률' in seg or 'Cap' in seg) and not any(b in seg for b in BASIS):
            print(f'{n}: 기준 미표기 의심 — {m.group(0)}')
EOF
```

이 스캔은 **의심만 표시**합니다. 오탐이 있으므로 차단하지 않고 사람이 확인합니다. 최종 판정은 발행 게이트 G10이 합니다.

## 15. 관점별 덱 시퀀스 🆕

**`investmentPosture`가 슬라이드 구성과 순서를 결정합니다.** 아키타입을 고르기 전에 이 절을 봅니다.

### 15.1 공통 골격

관점과 무관하게 고정되는 자리입니다.

```
p1   A1  표지 (dark)
p2   A2  핵심 요약 — 스탯 그리드
p3   A6  입지 — 3관점 (공법적 · 감정평가적 · 접근성)
p4   A4  토지 · 필지
p5   A4  건물 개요
     ────────── 관점별 본문 (§15.2) ──────────
p-2  A7  리스크
p-1  A9  진행 절차
p    A10 마감 · 표기 기준 (dark)
```

### 15.2 관점별 본문

| posture | 본문 시퀀스 | 슬라이드 수 |
|---|---|---:|
| **`income`** | 렌트롤 → 임대 안정성 → 수익 구조 → 자본 구조 → 비교사례 | 8~11 |
| **`owner_occupied`** | 층별 사용계획 → **자가vs임차 비교** → 통근 분석 → 자산가치 | 6~8 |
| **`development`** | 토지 상세 → 신축 규모 → **명도 계획** → 투입비용 → 스태킹 → 사업수지 | 9~12 |
| **`operating`** | **A13 운영지표** → 매출 구조 → 계절성 → 운영사 계약 → 시장 포지션 | 7~9 |
| **`trading`** | 비교사례 → 권역 거래동향 → 회전율 → 가격 포지션 | 5~7 |

### 15.3 `income` 안의 아키타입 분기

**같은 수익형이라도 덱이 정반대입니다.** 역설계에서 확인된 두 극단입니다.

| 아키타입 | 중심 슬라이드 | 억제할 슬라이드 | 실증 |
|---|---|---|---|
| `R-INC-01` 초안정형 | 임차인 분산 · 계약 잔여 타임라인 · 공실 해소 | 임대료 인상 시나리오 | 양평동 |
| `R-INC-02` 임대료 정상화형 | **임대료 갭 비교표** · 인상 경로 · 법적 상한 | 안정성 강조 | 당산동 |
| `R-INC-03` 공실 해소형 | 공실 원인 · 유치 전략 · 회복 시나리오 | — | — |
| `R-INC-04` 리모델링형 | 투입 대비 개선 · 전후 비교 | — | — |

```
R-INC-01 덱      "손댈 것이 없다" 를 강점으로 구성
                 → 예측 가능성 · 임차인 신용 · 계약 잔여가 중심

R-INC-02 덱      "지금 싸게 받고 있다" 를 기회로 구성
                 → 시세 갭 · 인상 여력 · 갱신 시점이 중심
                 → 단, 법적 상한을 반드시 병기 (§16.4)
```

**두 아키타입에 같은 덱을 쓰면 둘 다 설득력이 없습니다.**

### 15.4 관점별 억제 규칙

| posture | 억제 | 이유 |
|---|---|---|
| `development` | 임차인 업종 · 관리비 · 임대료 인상 | 어차피 명도 |
| `owner_occupied` | 렌트롤 상세 · Cap Rate | 임대 목적이 아님 |
| `operating` | **렌트롤 전체** | 임대차가 존재하지 않음 |
| `trading` | NOI · 운영경비 | 보유 기간이 짧음 |
| `bare_land` | **건물 슬라이드 전체** | 건물이 없음 |

> 억제는 **슬라이드를 비우는 것이 아니라 만들지 않는 것**입니다. "해당 없음"으로 채운 슬라이드는 덱의 신뢰를 떨어뜨립니다.

### 15.5 티어별 분량

| tier | 분량 | 밴딩 |
|---|---:|---|
| Basic | 10p | 금액 구간 표기 · 정밀 좌표 제외 |
| Pro | 20~24p | 전체 노출 · **grant 워터마크 필수** |

## 16. 기준 표기 강제 🆕

**값만 적고 기준을 안 적는 것이 실전 IM 5건 전부에서 나온 결함입니다.** 템플릿이 구조적으로 막습니다.

### 16.1 용적률 — 2기준 병기

```js
L.rows(s, M, y, w, [
  ['용적률 (지상 연면적 기준)', '398.8%', '✓공부'],
  ['용적률 (전체 연면적 기준)', '480.2%', '✓공부'],
]);
L.note(s, M, y2, w, '※ 실무 관행상 지상 연면적 기준을 병용합니다. 건축법상 용적률은 전체 기준입니다.');
```

| 규칙 | |
|---|---|
| 두 값이 다르면 **둘 다 적습니다** | 하나만 적으면 매수자가 다른 쪽으로 읽습니다 |
| 각주 생략 불가 | 왜 두 개인지 모르면 오류로 보입니다 |
| 지하가 없으면 1개만 | 같은 값을 두 번 적지 않습니다 |

세 개 중개법인이 독립적으로 지상 기준을 씁니다 — 잠원동 247.0% · 당산동 221.8% · 양평동 398.8%.

### 16.2 Cap Rate — 코드와 표기 라벨 매핑

내부 코드는 산식 기반, **화면 표기는 실무 언어**입니다.

| `CapRateBasis` | 슬라이드 표기 |
|---|---|
| `gross_price_deposit` | 임대수익률 (실투자금 기준) |
| `gross_price` | 임대수익률 (매매가 기준) |
| `noi_price` | Cap Rate (표준) |
| `noi_price_deposit` | Cap Rate (실투자금 기준) |
| `noi_equity` | Cap Rate (자기자본 기준) |
| `noi_total_cost` | Cap Rate (총취득원가 기준) |
| `gop_price` | **Cap Rate (GOP 기준)** |

```js
// 라벨 없는 수익률은 G10이 발행을 차단합니다
L.stat(s, x, y, w, h, '2.46%', '임대수익률 (실투자금 기준)', 'brk');
```

**여러 기준을 한 슬라이드에 놓을 때는 표로만** 놓습니다. 스탯 카드 4개를 나란히 두면 매수자가 가장 높은 것만 봅니다.

### 16.3 GOP 기준 — 병렬 배치 금지

```
✓   Cap Rate (GOP 기준)  3.57%
    ※ 운영 인건비·마케팅비 차감 후 기준으로, 임대차 NOI 기준과 성격이 다릅니다.

✗   Cap Rate 3.57%  |  Cap Rate 2.46%      ← 같은 지표로 오독됨
```

`posture=operating` 덱에 임대차 기준 Cap Rate를 함께 넣지 않습니다 (C31).

### 16.4 임대차 — 적용 법령 명시

주택과 상가는 갱신요구권이 **10년 대 4년**으로 다릅니다. 표기하지 않으면 매수자가 상가로 읽습니다.

```js
L.table(s, M, y, 7.30, {
  head: ['호실', '용도', '적용 법령', '갱신권 잔여', '인상 상한'],
  rows: [
    ['1층', '근린생활', '상임법', '7년',  '5%'],
    ['2층', '주택',     '주임법', '2년',  '5%'],
  ],
});
L.note(s, M, y2, CW,
  '※ 주택임대차보호법은 갱신요구권 1회·2년(최장 4년)이며 권리금 보호 규정이 없습니다.');
```

| 표기 | 조건 |
|---|---|
| 갱신권 잔여 | 상가만 자동 산출. **주택은 행사 이력 확인 시에만** |
| "확인 필요" | 미확정 시 숫자 대신 이 문구 (G15) |
| 권리금 | 주택 행에는 "해당 없음" |

> **묵시적 갱신은 갱신요구권을 소진하지 않습니다.** 경과년수로 추정한 값을 슬라이드에 적지 마십시오.

### 16.5 가정·계획의 표기

```
✗   1,260% 용적률 허가 필, 2,500평 개발 가능

✓   지구단위계획 수립 시 최대 1,260% 검토 가능 — 약 2,500평   ◇ AI추정·가정
    ※ 지구단위계획 약 18개월 예상 · 기부채납 조건 발생 가능 · 확정 아님
    현행 800% 적용 시 약 1,552평
```

| 규칙 | |
|---|---|
| 시나리오 수치는 **항상 `◇`** | 입력이 전부 공부여도 (C22) |
| 전제 조건과 소요 기간 병기 | 없으면 확정으로 읽힘 |
| 보수적 대안값 병기 | 하나만 적으면 그것이 기준이 됨 |

## 17. 오류 층위별 조판 대응 🆕

실전 IM 5건에서 나온 오류를 **조판 단계에서** 막습니다. 상세 분류는 `IM_QUALITY_TRAINING_PLAN.md` §1.

| 층위 | 조판에서 하는 일 |
|---|---|
| **L1 산술** | 표 합계 행은 **하드코딩 금지** — 배열에서 계산 |
| **L2 기준** | §16 라벨 강제 |
| **L3 결손** | 결손 항목도 자리를 만들고 "확인 중" 표기 |
| **L4 법적** | 인상 계획 옆에 법적 상한 병기 |
| **L5 가정** | `◇` 배지 + 전제 각주 |

### 17.1 합계는 계산합니다

당산동에서 연면적 300㎡ 오기가 있었고, **합계는 맞고 층별만 틀렸습니다.** 반대 경우도 생깁니다.

```js
// ✗ 합계를 문자열로 넣지 마십시오
rows.push(['합계', '1,141.15㎡', '']);

// ✓ 배열에서 계산합니다
const total = floors.reduce((a, f) => a + f.area, 0);
rows.push(['합계', `${total.toFixed(2)}㎡`, '']);
if (Math.abs(total - facts.grossArea) / facts.grossArea > 0.005) {
  throw new Error(`C19 위반 — 층별 합 ${total.toFixed(2)} vs 연면적 ${facts.grossArea}`);
}
```

### 17.2 결손도 자리를 만듭니다

```
✗   (최초 계약일 열 자체를 없앰)

✓   | 호실 | 임차인 | 최초 계약일 | 만료일  |
    | 101  | 고은약국 | 확인 중    | 2027-03 |
```

**열을 지우면 매수자가 물어보지 않습니다.** 5건 전부에서 최초 계약일이 누락되었는데, 없다는 사실 자체가 인식되지 않았던 이유입니다.

### 17.3 인상 계획에는 상한을 붙입니다

```
현재 2,600천원  →  계획 3,060천원 (+17.7%)
                   ※ 갱신 시 법정 상한 2,730천원 (5%) — 신규 계약 시에만 실현 가능
```

당산동 401호에서 실제로 걸린 사례입니다. 상한 없이 적으면 **실현 불가능한 수익을 제시한 것**이 됩니다.
