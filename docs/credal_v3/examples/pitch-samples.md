# 3. "이미 수임된 딜"의 파이프라인 반영 — 질문에 대한 답

## 3.1 원칙: Pitch는 도구이지 관문이 아니다

맞습니다 — 오프라인에서 이미 수임 동의를 받고 시작하는 딜이 다수이며, 설계는 이를 정확히 반영합니다. 핵심 규칙:

> **파이프라인의 '제안(pitch)' 단계는 선택적(skippable) 단계이며, 수임 사실의 기록(mandate)은 단계가 아니라 딜의 속성이다.**

- `deals.mandate_type`(전속/일반)과 `seller_consent_mode`(위임/건별)는 **어느 단계에서든 기록 가능한 독립 필드** — Pitch 문서 생성 여부와 무관
- 전이 매트릭스: `발굴 → 분석 → (제안) → 마케팅` 에서 제안 단계는 건너뛰기 허용 — `분석 → 마케팅` 직행 전이가 유효

## 3.2 딜 생성 시 수임 상태 분기 (UI)

딜 생성(메모→확인 칩) 직후 퀵 선택 1개가 뜬다:

```
이 매물의 수임 상태는? (1탭)
[✅ 이미 수임됨]  [⚔️ 수임 경쟁 중]  [📞 소유주 접촉 전]
```

| 선택 | 파이프라인 경로 | Pitch | 시스템 동작 |
|------|----------------|-------|-------------|
| **이미 수임됨** (다수 케이스) | 발굴→분석→**마케팅 직행** (제안 단계 스킵) | 생성 안 함 | 후속 2탭만: ①전속/일반 ②강화IM 공개 위임/건별 → 기록 완료. 다음 액션 = "렌트롤 채우고 티저 발행" |
| 수임 경쟁 중 | 발굴→분석→**제안** | 웜 모드 | 발송·열람 추적 → 수임 확정 시 [✍ 전속] 탭이 mandate 자동 기록 |
| 소유주 접촉 전 | 발굴(딜 이전 단계) | 콜드 모드 | 미팅 성사 → 웜 전환 또는 즉시 수임 기록 |

- "이미 수임됨"에서도 `seller_consent_mode`는 반드시 묻는다 — **IM-Pro 동의 체인(위임/건별)이 이 값에 의존**하므로, 이것이 오프라인 수임 딜에서 유일하게 필수인 입력이다 (2탭)
- 구두 수임(계약서 없음)도 현실이므로: mandate_type에 `verbal` 옵션 추가를 권장 — 이 경우 다음 액션으로 "수임 확인서 발송(전자서명)"을 제안하되 강제하지 않음

## 3.3 수임 후에도 Pitch 데이터는 재활용된다 (문서 없이)

Pitch를 건너뛰어도 그 **부품**은 딜 생애주기에서 계속 쓰인다:

- **주간 매각 리포트**(4️⃣ 블록): 수임 여부와 무관하게 매도인 보고용으로 자동 발송 가능 — 일반 수임 딜의 전속 전환 무기
- **가격 의견**(2️⃣ 블록): 티저 반응 수집 후 "슬라이더 예산 분포"와 결합해 호가 조정 설득 자료로 단독 생성 가능 (시나리오 C의 논현동 정체 딜 케이스)
- **물건 진단**(1️⃣ 블록): IM 생성 시 동일 데이터가 자동 상속 — 재입력 0 원칙

## 3.4 SDD 반영 사항 (v1.1 보완 노트)

본 문서로 다음 2건을 SDD에 명시화한다 (구현 시 반영):

1. **S1-T12 전이 매트릭스 보완**: `analysis → marketing` 직행 전이 유효 명시 + 딜 생성 플로우에 수임 상태 퀵 선택(1탭) 추가. `mandate_type`에 `verbal` 허용 검토
2. **S1-T13 주석**: Pitch 미생성 딜에서도 주간 리포트·가격 의견 블록의 단독 생성 API 경로 유지 (`pitch_blocks` 부분 재사용)

> **요지**: 수임 제안서는 "수임을 따내는 도구"이지 "딜을 시작하는 절차"가 아니다. 이미 수임된 딜은 1탭 분기 + 2탭 기록(전속/일반·공개 위임)만으로 마케팅에 직행하고, Pitch의 부품(보고·가격 의견·진단)은 문서 없이도 딜 전 생애에서 재활용된다 — 무마찰 원칙 그대로.
