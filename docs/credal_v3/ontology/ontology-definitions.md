# 🏗️ CREDEAL 자산 온톨로지 기초 정의서 v0.1

> **작성**: 2026.07.23 · 심층 리서치(공적 표준) + 기보유 문서(골디락스 온톨로지·기술 감사) 통합
> **동반 파일**: `credeal-ontology-v0.1.yaml` (구현용 스키마 — enum·제약·규칙·어휘·소스 매핑 포함)
> **적용 대상**: 모바일 IM 고도화(G1~G10), 매칭 엔진, 향후 P2P 네트워크 프로토콜

---

## 1. 설계 원칙

1. **온톨로지적으로 사고하고, 관계형으로 구현한다** — OWL/트리플스토어 없이 Zod 스키마 + Postgres enum + 계층 테이블 + 규칙 함수로 구현. 공리(전이성·기능성·대칭성)는 테이블 설계와 제약으로 번역
2. **모든 필드에 출처(4-tier provenance)와 등급 기여도를 부여한다** — public_data > expert_verified > broker_input > ai_inferred. 가정값(ai_inferred)은 반드시 '가정' 배지
3. **enum은 공적 분류를 준용한다** — 임의 분류를 만들지 않고 국토계획법·공간정보관리법·표준지 조사기준의 법정/실무 분류를 코드화 (P2P 네트워크에서 상호 운용의 전제)
4. **법정 상한값은 참고치, 조례가 우선** — 시행령 상한을 기본 탑재하되 `zoning_ordinance` 테이블에서 지자체 조례값 로드를 우선

## 3. 온톨로지 구조 요약

```
Asset (자산)
├─ 공통 코어: 식별(PNU·주소[블라인드])·토지(지목·용도지역·공시지가·도로접면)
│             거래(희망가·대출·명도 3속성)·재무 파생(NOI·Cap·WALT — 주입 전용)
├─ smallBuilding: 물리(연면적·용적률 여유분·주차·승강기) + 입지(역세권) + 렌트롤
├─ logisticsCenter: 물리(층고·하중·도크·램프·야드·저온·수전) + 입지(IC) + 마스터리스
├─ landSite: 형상·고저 + 규제(허가구역·인허가단계·기부채납) + 개발(규모검토 연계·사업수지)
└─ LeaseUnit: 층·업종[마스킹]·면적·보증금·월세·기간·대항력
```

- **필드 수**: 공통 17 + 꼬마빌딩 16 + 물류 17 + 개발부지 11 + 렌트롤 9 = **약 70개 표준 슬롯**
- **enum 사전**: 용도지역(21)·지목(28)·도로접면(12)·형상(6)·고저(5)·명도상태(4)·명도조건(3)·점유자(4)·주차(3)·램프(4)·온도(4)·인허가(6)·아키타입(10)·권역(2계열)

## 4. 핵심 설계 결정과 근거

**① 용적률 여유분(farHeadroomPp)을 1급 시민으로.** `조례 상한 − 현재 용적률`은 밸류애드 판정(R02)의 핵심이자 개발부지·노후 꼬마빌딩 IM의 최대 소구점인데, 어느 조회 플랫폼도 이를 표준 필드로 제공하지 않는다. 자동 파생 가능(대장 용적률 + 조례 테이블)하므로 크리딜의 차별 데이터가 된다.

**② 명도를 3개 속성으로 분해.** 상태(evictionStatus: 진행 단계) × 조건(evictionCondition: 거래 조건) × 점유자(occupantType: 법적 권리)는 서로 다른 차원이다. 이 분해가 있어야 R09(소유자 점유+AsIs=고위험)와 R10(대항력 전무=안전) 같은 정밀 규칙이 성립한다. 개발부지 적합도 ⭐3→⭐5의 열쇠.

**③ 도로접면 가중치를 데이터로.** 12분류에 가격 가중치(중로한면=100)를 붙여, R07(코너 가중치 대비 저평가 탐지) 같은 정량 규칙과 B2C 어휘("코너 명당자리") 렌더링을 동시에 지원한다.

**④ 재무 파생 필드는 '주입 전용'.** financial_derived 그룹은 LLM 생성 금지 — 재무 엔진 산출값을 NLG 마스크로 렌더링만 한다(기술 감사 G2 반영).

**⑤ 물류 sanity 범위를 스키마에 내장.** 층고 4~15m, 바닥하중 0.5~6t/㎡ 등 실무 범위를 제약(C08)으로 두어, OCR·음성 입력의 오인식을 입력 단계에서 잡는다.

## 5. 제약 규칙 12종 (C01~C12) — constraint-validator.ts 구현 대상

수치 정합(C01 Cap Rate 일치, C04 자본구조 역전), 법규 정합(C02·C03 용적률·건폐율 상한, C09 맹지 개발 불가, C10 용도지역 기능성), 상식 정합(C05 날짜, C06 공실 범위, C08 물류 sanity), 정책(C07 권역 이탈 경고, C11 DCF A등급 게이트, C12 가정값 배지 의무). **위반 시 차단이 아닌 경고+수정 유도**가 기본, error 등급만 발행 차단.

## 6. 아키타입 규칙 10종 (R01~R10) — archetype-classifier.ts 구현 대상

초안정 수익형 / 밸류애드형 / 사옥 신축 적합 / 기관 물류 / 콜드체인 / 쾌속 개발 / 저평가 코너 / 자주식 사옥 / 명도 고위험(감점) / 명도 안전 개발. 출력은 ① IM investment_thesis 섹션의 근거 뼈대, ② 설명 가능 매칭의 사유, ③ 골든셋·프롬프트 선택 축으로 3중 활용된다. **브로커의 규칙 토글·수정 이력 자체를 암묵지로 수집**한다.

## 7. 데이터 충전 전략 (필드별 소스 우선순위)

| 충전 경로 | 커버 필드 (약 70개 중) | 비고 |
|-----------|------------------------|------|
| 공공 API 자동 (PNU 조인) | ~30개 (대장·용도지역·공시지가·토지특성·도로접면) | 주소 입력 즉시, 브로커 개입 0 |
| AI 파생 | ~10개 (용적률 여유분·역세권·IC거리·평당가·재무) | 전부 ai_inferred 배지 |
| OCR (계약서·등기부) | ~12개 (렌트롤·대출·대항력) | A등급 병목 해소 — P1 |
| 음성 메모 슬롯 매핑 | ~8개 (희망가·공실·명도·매도사유) | 기존 MemoParser 확장 |
| 브로커 직접 입력 | 잔여 ~10개 (물류 스펙 일부 등) | "자동 채움됨" 표시로 최소 노출 |

**결론: 표준 슬롯의 약 60%가 자동 충전 가능** — 온톨로지가 입력 부담을 늘리는 게 아니라 줄이는 구조.

## 8. 검증 계획 (베타 브로커 10인의 몫)

- [ ] 어휘 검증: enum 한글 명칭·B2C 어휘 샘플이 현장 용어와 일치하는가 (특히 명도·도로접면 표현)
- [ ] 필드 실용성: 브로커가 실제로 아는/모르는 필드 구분 → required_for_grade 가중치 보정
- [ ] 가중치 검증: 도로접면 가중치·아키타입 임계값(공실 3%·WALT 2.5년 등)이 강남·성수 실감과 맞는가
- [ ] 누락 탐지: "IM에 꼭 쓰는데 슬롯이 없는 정보" 수집 → v0.2 반영
