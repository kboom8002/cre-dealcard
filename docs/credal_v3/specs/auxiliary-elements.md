# 🧩 온톨로지 기반 부속 요소 고도화 방안 (MECE)

> **버전**: v1.0 (2026.07.23) · 온톨로지 v0.1 · DEV_SPEC v2.0과 정합
> **범위**: 모바일 IM **본체를 제외한**, 온톨로지를 소비하는 부속 요소 전체 (IM 본체는 DEV_SPEC Part B가 담당)
> **MECE 분해 기준**: 딜 퍼널 단계 — 하나의 딜이 흐르는 5단계에 각 요소를 1:1 배치. 단계는 상호 배타적이며, 소싱부터 연결까지 퍼널 전체를 포괄한다.

```
[E 수임 제안서]──소싱──▶[A 딜카드]──자산화──▶[B 카피라이팅]──유통──▶[C 리드 엔진]──반응──▶[D 딜 매칭]──연결──▶ 성사
        ▲                                                                                            │
        └────────────────────── 결과 데이터(성사가·무산사유) 환류 ──────────────────────────────────────┘
```

| 요소 | 퍼널 위치 | 답하는 질문 | 공유하는 온톨로지 자원 |
|------|-----------|------------|------------------------|
| A. 딜카드(블라인드 티저) | 자산화 | "무엇을 얼마나 공개할까" | 공개 슬롯 화이트리스트 · 아키타입 · 등급 게이트 |
| B. 카피라이팅 엔진 | 유통 | "어떻게 말해야 열어볼까" | 슬롯 조립 문법 · 아키타입 소구 사전 · lexicon(B2B/B2C) |
| C. 리드 포획·스코어링·너처링 | 반응 | "누가 진심이고 무엇에 반응하나" | 행동↔슬롯 매핑 · 관심 프로파일 |
| D. 딜 매칭 (내부+크로스) | 연결 | "누구에게 연결해야 성사되나" | 규칙 R01~10 · enum 정확 매칭 · 거절 학습 |
| E. 수임 제안서(Pitch) | 소싱 | "왜 나에게 맡겨야 하나" | 비교사례 유사도 · 집합 지식 · 아키타입 마케팅 플랜 |

---

## A. 딜카드(블라인드 티저) 고도화

**현재**: 카톡 메모 붙여넣기 → AI 추출 → 민감정보 숨김 딜카드. 숨김 대상이 휴리스틱(주소·임차인명·매도 사정)이고, 공개 정보의 구성이 건별로 비일관.

### A1. 블라인드 정책의 온톨로지화 `P0`
- 슬롯 단위 공개 정책을 스키마에 고정: `public`(권역·자산군·가격밴드·Cap밴드·아키타입) / `gated`(상세 스펙·렌트롤 요약 — Gate 승인 후) / `never`(주소·임차인 실명·매도 사유·협상 메모)
- 효과: 블라인드가 "AI의 판단"에서 "정책"이 됨 — 유출 사고 구조적 차단 + **P2P 크로스 매칭의 익명 요약 표준과 동일 규격** (딜카드=네트워크 프로토콜의 단위)

### A2. 아키타입 뱃지·정량 신호 카드 `P1`
- `archetype-classifier` 산출을 티저 첫 줄 뱃지로 (예: 🏛️ 초안정 수익형 · 🔧 밸류애드형)
- 익명이어도 판단 가능한 구조화 신호 노출: 도로접면 등급(가중치 밴드), 용적률 여유분 밴드, WALT 밴드, 명도 상태 — "주소 없이도 프로가 3초에 거를 수 있는" 티저가 차별점
- 수치는 밴드(구간)로만 — 정밀값은 Gate 뒤로

### A3. 등급 게이트·독자별 버전 `P1~P2`
- data_grade 기반 표시 제한: 검증 안 된 수익률(C·D등급)은 티저에 미노출 — "크리딜 딜카드의 숫자는 믿을 수 있다"는 시장 평판이 자산
- 매수자 유형별 강조 슬롯 스위칭: 개발형 독자→용적률 여유·명도, 수익형 독자→Cap밴드·WALT (B의 레지스터와 연동)

**지표**: 딜카드→열람 전환율, 열람→Gate 요청률, 블라인드 위반 사고 0건

## B. 카피라이팅 엔진 (리드 극대화) 고도화

**현재**: 골든셋 제목 20선, OG 메타 수동 편집, 캠페인 카피 AI(인스타/블로그/문자) — 각각 독립 동작, 소구 논리가 브로커 감에 의존.

### B1. 슬롯 조립 헤드라인 문법 `P1`
- 제목·서브제목을 자유 생성이 아닌 **문법 조립**으로: `[입지 신호] + [아키타입 소구] + [정량 훅]`
  - 예: `역삼역 도보 5분`(subwayWalkMin) + `만실 안정 수익형`(R01) + `Cap 3.9% · WALT 2.8년`(검증 슬롯)
- NLG 마스크와 동일 원칙: 수치·팩트는 검증 슬롯만, 형용은 LLM — 카피에서도 환각·과장 원천 차단 (기존 금지표현 가드레일 공유)

### B2. 아키타입별 소구 사전 `P1`
- 골든셋을 아키타입 축으로 재분류하고, 아키타입→소구 포인트 매핑을 사전화:

| 아키타입 | 1순위 소구 | 금지 소구 |
|----------|-----------|----------|
| STABLE_INCOME | 공실 Zero · WALT · 우량 임차 | 개발 잠재력(혼선) |
| VALUE_ADD | 용적률 여유 Xp · 신축/증축 시나리오 | 현 수익률(불리) |
| HQ_READY | 명도 완료 · 진입도로 폭 · 즉시 착공 | 임대수익 |
| INSTITUTIONAL_LOGI | 마스터리스 · WALT 5년+ · Cap 5.5%+ | 감성 표현 |
| UNDERPRICED_CORNER | 코너 가중치 대비 가격 포지션 | "저평가" 단정(가드레일) |

### B3. 채널 스펙 테이블 + 자동 변환 `P2`
- 채널별 제약을 데이터로: OG(제목 25자·설명 40자), 카톡 문구(3줄+링크), 문자(90바이트), 블로그(SEO 롱폼) — 한 소스에서 채널별 자동 파생 (기존 캠페인 AI를 딜 문서 탭으로 흡수)
- B2B/B2C 레지스터는 lexicon 축 재사용 — 같은 딜, 기관용/자산가용 카피 동시 생성

### B4. 성과 학습 루프 `P2`
- 카피 변형별 열람·클릭·체류 추적(OG 버전 파라미터) → 아키타입×권역별 `top_selling_points` 집계 → 소구 사전 자동 보정 + 홈 브리핑 환류("이번 주 성수에서는 '리모델링 시나리오' 소구가 클릭 1.8배")
- 브로커의 카피 수정 diff도 골든셋 수집과 동일 경로 (im_edit_diffs 재사용)

**지표**: OG 클릭률(CTR), 카톡 공유→열람 전환, 카피 A/B 승률 누적, 가드레일 위반 0건

## C. 리드 포획·스코어링·너처링 고도화

**현재**: 행동별 고정 가중치 스코어(명함 +5, IM 열람 +25, 멀티채널 +30), Hot Lead 80점 알림. "얼마나 봤나"는 알지만 "무엇을 봤나"는 모름.

### C1. 관심의 온톨로지 태깅 — "무엇을 봤나" `P1`
- 열람 이벤트에 섹션·슬롯 태그 부착: income_analysis 3분 체류 → `interest:수익성`, risk_check 반복 → `concern:리스크`, 규모검토 클릭 → `interest:개발`
- 스마트톡 질문도 슬롯 매핑: "명도는요?" → `concern:evictionStatus` — 질문이 곧 리드 신호

### C2. 매수자 관심 프로파일 자동 생성 `P1`
- 익명 방문자의 열람 딜 슬롯 분포(권역·가격밴드·아키타입)를 집계 → 로그인/연락처 전환 시 `buyer_intents` 초안 자동 제안 ("이 고객은 성수 30~50억 밸류애드형을 보고 있습니다 — 의향서로 등록할까요?")
- 브로커의 승인·수정이 프로파일 라벨 (암묵지 수집)

### C3. 프로파일 기반 너처링 트리거 `P2`
- "관심 아키타입의 신규 딜 등록 시 알림" — 매수자별 맞춤 딜 피드의 시작
- 매거진 큐레이션을 구독자 프로파일 기반으로: 개발형 관심 구독자에게 규모검토 콘텐츠 우선
- CTA 개인화: 개발 관심자→"신축 시나리오 보기", 수익 관심자→"임대차 현황 요청"

### C4. 스코어 모델의 결과 캘리브레이션 `P3`
- 고정 가중치 → Hot Lead 판정과 실제 결과(미팅 성사·계약 진행)의 상관을 분기별 검증해 가중치 보정 — 스코어가 "규칙"에서 "학습"으로

**지표**: Hot Lead→미팅 전환 30%+, 의향서 초안 승인율, 너처링 알림→재방문율

## D. 딜 매칭 (내부 + 크로스) 고도화

**현재**: S/A/B/C 등급 블랙박스, 본인 등록 의향만 대상 (네트워크 효과 부재).

### D1. 3단 하이브리드 매칭 `P1`
1. **하드 필터**: enum 정확 매칭 — 자산군·권역(계층 테이블로 광역 확장: "성수 희망"이면 성동구 전체 후보 포함)·예산 밴드·토지거래허가 수용 여부
2. **아키타입 정합**: buyer_intents의 딜 유형(사옥/수익/개발) ↔ deals.archetypes — R09(명도 고위험)는 감점, 개발형 수요엔 R03·R10 가점
3. **소프트 유사도**: 잔여 슬롯 벡터 유사도(도로접면 가중치·층고·WALT 등) — 순위 결정

### D2. 설명·확장 제안 `P1`
- match_reasons 표시 의무(기 확정) + **불일치 사유도 표시**: "예산 10% 초과지만 아키타입 정합 · 협상 여지 밴드 내" — 브로커가 판단할 수 있는 경계 매칭을 버리지 않음
- 역매칭: 신규 의향 등록 시 기존 딜 전체 재스캔, 신규 딜 등록 시 전체 의향 재스캔 — "놓친 매칭 주간 리포트"

### D3. 거절 학습 루프 `P2`
- tacit_labels(match_rejected: 가격/입지/명도/시기) → 브로커별·전역 임계값 보정 제안 ("이 고객은 명도 미완료를 3회 거절 — 하드 필터로 승격할까요?")

### D4. 크로스 매칭 프로토콜 (S5 연동) `M5`
- 교환 단위 = A1의 공개 슬롯 표준 (딜카드와 동일 규격 — 별도 포맷 없음)
- 매칭 엔진 재사용: 대상만 "타 브로커 옵트인 딜·의향"으로 확장, Gate 3단계 공개·평판 가중은 S5 스펙 준용

**지표**: 매칭 확인율(사유 열람) 70%+, 매칭→공유 전환, 거절 태깅 응답률 60%+, 크로스 매칭 진행 3건+

## E. 수임 제안서(Pitch) 고도화

**현재**: DEV_SPEC에 골격 정의(Asset+비교사례+아키타입 근거+추적 데모+집합 지식). 여기서는 온톨로지 결합의 정밀화.

### E1. 비교사례 선정의 근거화 `P1`
- 유사도 기준을 명시적 슬롯 거리로: 권역(계층) > 용도지역 > 도로접면 등급 > 대지면적 밴드 > 준공연대 — 선정 사례마다 "왜 이 사례인가" 표기
- 매도인 설득의 핵심인 호가 조정 논리를 가중치로 정량화: "귀 물건은 중로각지(105)로 비교사례 소로한면(90) 대비 접면 우위 — 평단가 보정 근거"

### E2. 아키타입 기반 마케팅 플랜 `P1`
- "이 매물은 VALUE_ADD형입니다 → 타깃 매수자는 시행·리모델링 수요 → 소구는 용적률 여유 X%p → 예상 딜 사이클 권역 평균 N개월" — 분류→타깃→소구→기간이 하나의 논리로
- 집합 지식 인용(v_collective_insights): 권역 무산 사유 분포를 리스크 사전 대응 플랜으로 제시 ("이 권역 무산 1위는 대출(34%) — 저는 초기에 대출 한도 검증을 진행합니다")

### E3. 추적 리포트 약속 `P2`
- 제안서에 "주간 마케팅 리포트 샘플"(열람 수·Hot Lead·문의) 포함 — 전속 수임의 대가로 투명한 보고를 약속하는 구조. 수임 후 자동 발송 (매거진 인프라 재사용)

**지표**: 제안서 발송→수임 전환율, 전속 수임 비중, 브로커당 월 발송 1건+

## 공통 구현 노트 (DEV_SPEC 정합)

- **공유 모듈**: A~E 전부 `asset-ontology.ts`·`archetype-classifier.ts`·`nlg-mask-engine.ts`·`grade-engine.ts`를 소비 — 부속 요소용 별도 분류기·정규화기 신설 금지
- **신규 모듈**: `copy-grammar.ts`(B1~B3), `interest-tagger.ts`(C1~C2), `match-engine.ts` 확장(D1~D3), `pitch-generator.ts` 확장(E1~E3), 딜카드는 기존 생성기에 A1 정책 테이블 주입
- **이벤트 추가**: `copy_variant_impression/click`, `interest_tagged`, `intent_draft_proposed/approved`, `match_expanded_shown`, `pitch_report_sent`
- **우선순위**: P0(A1 블라인드 정책) → P1(B1·B2, C1·C2, D1·D2, E1·E2, A2·A3) → P2(B3·B4, C3, D3, E3) → M5(D4)
- **금지**: 카피·티저의 비검증 수치 노출(DO NOT 준용), "저평가·확실·보장" 류 표현(가드레일 공유), 밴드 없는 정밀값의 public 슬롯 노출

> **요지**: 다섯 요소는 같은 온톨로지를 다섯 각도에서 소비한다 — 딜카드는 **공개 정책**으로, 카피는 **조립 문법**으로, 리드는 **관심 태깅**으로, 매칭은 **규칙+유사도**로, 수임 제안서는 **근거화된 비교**로. 온톨로지가 깔린 순간 부속 요소의 고도화는 각자 따로가 아니라 하나의 스키마 위 다섯 개의 뷰가 된다.
