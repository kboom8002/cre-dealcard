# 📊 Full IM (pptx) — 골디락스 스펙 및 작성 방법론 v1.0

> **버전**: v1.0 (2026.07.23) · 입력: cre-fullim 감사 4종(AUDIT-00~03) · 정합: DEV_SPEC v2.0 · IM 이원화 스펙 · 온톨로지 v0.1
> **결론 요약**: ① cre-fullim의 자산은 **반드시 활용**한다 — 특히 Expert Patch·Gate Review·Evidence 체계는 크리딜 로드맵 3개 항목(S6·데이터룸·검토 게이트)의 기구현체다. ② 단, Full IM을 별도 시스템으로 병행 운영하지 않는다 — **같은 Deal/Asset SSoT의 제3 렌더 타깃**으로 재포지셔닝하고, 스키마·가드레일·골든셋을 단일화한다. ③ 골디락스는 "전통 30~50p IM의 재현"이 아니라 **"모바일 IM 승인본을 코어로 상속하고, 기관 매수자가 요구하는 확장 섹션만 인간 검토를 거쳐 추가하는 문서"**다.

## 1. 포지셔닝 — 공개 사다리에서의 위치

```
티저 딜카드 ─▶ IM-Basic ─▶ IM-Pro ─▶ [Full IM] ─▶ 실사 데이터룸
 (익명·밴드)   (링크 공유)  (지정 열람)  (기관·대형 딜 한정)  (자료실)
                                        │
                              발동 조건 미충족 시 생략 —
                              꼬마빌딩 개인 매수자 딜의 기본 종착은 IM-Pro
```

### 1.1 발동 조건 (Full IM은 예외 경로다)

| 트리거 | 기준 | 근거 |
|--------|------|------|
| 매수자 유형 | 법인·리츠·펀드·패밀리오피스 (buyer_intents.buyerType) | 기관은 내부 투심용 전통 IM 포맷을 요구 |
| 딜 규모 | [100억+] (브로커 조정 가능) | 소형 딜에 18섹션은 과잉 — 마찰만 증가 |
| 자산군 | 물류센터·대형 오피스 기본 제안, 꼬마빌딩은 요청 시만 | 물류 기관 딜은 Full IM이 관행 |
| 딜 유형 | NPL·S&LB·포트폴리오 매각 | 복잡 구조는 확장 섹션 필수 |

- **원칙**: 시스템이 트리거 충족 시 "Full IM 제작 제안" 카드를 딜 워크스페이스에 표시 — 기본값은 항상 모바일 사다리

### 1.2 Too Cold / Goldilocks / Too Hot

| 축 | Too Cold 🥶 | **Goldilocks 🏆** | Too Hot 🔥 |
|----|------------|-------------------|------------|
| 분량 | 모바일 IM의 pptx 변환뿐 | **코어 7섹션 상속 + 확장 11섹션 선별** (딜 유형별 12~18섹션 가변) | 전 딜 18섹션 강제 |
| 워크플로 | 브로커 혼자 AI 초안 그대로 | **AI 초안 → 에디터 정리 → 필요 섹션만 전문가 패치 → 축약 Gate** | 8게이트 전건 통과·5역할 전원 관여 |

## 2. cre-fullim 자산 재사용 맵

### 2.1 그대로 채택 (핵심 가치)

| cre-fullim 자산 | 크리딜에서의 역할 | 매핑 |
|-----------------|-------------------|------|
| **Expert Workbench** (assignments·patches·edit_tags·섹션 단위 권한) | **S6 전문가 딜룸의 기구현체** — 세무·감평·건축·법률 전문가의 섹션 기고. Full IM에서 먼저 가동 후 IM-Pro 기고 모듈로 역이식 | `deal_parties(role='professional')` + `expert_contributions`와 통합 |
| **Gate Review Console** (8게이트·P0 차단·buyer_ready 승인) | Full IM·IM-Pro의 **인간 검토 게이트**. 자동 게이트(constraint-validator)와 2층 구조 형성 | 축약 운영: §4.3 |
| **Evidence Files + Visibility 등급** (private_truth/buyer_ready) | **실사 데이터룸의 기초 구조** — 증빙 인덱싱·열람 등급이 이미 설계됨 | 데이터룸 스펙(후속)의 출발점 |
| **Deal Room Q&A Pack** | 매수자 예상 Q&A → 스마트톡 FAQ 소스·데이터룸 동봉 자료 | NLG 마스크 인용 원칙 적용 후 채택 |
| **packages/contracts** (Zod 공유 계약) | 크로스앱 계약 패턴 — **온톨로지 v0.1을 이 계약의 스키마로 승격** | §5.1 |
| **역할·RLS 체계** (expert는 배정 섹션만) | S6 권한 모델의 검증된 구현 | 그대로 |
| **상태 전이 규칙** (명시적 전이 함수만, 임의 뮤테이션 금지) | 크리딜 전체 규약으로 승격 | DEV_SPEC Part 0 추가 |

### 2.2 개조 후 채택

| 자산 | 문제 | 개조 방향 |
|------|------|-----------|
| **Full B-SSoT** (`building_ssot_full`) | 모바일 SSoT와 이중화 — 스키마 분기·재입력·정합 붕괴 위험 (감사 개선권고 1과 동일 맥락) | **폐지 방향**: 온톨로지 v0.1을 슈퍼셋으로 확장(v0.2 — Full 전용 필드 흡수: 시장분석 파라미터·ESG·상세 CAPEX 등)하고 `assets` 단일 원본으로. Full IM 전용 슬롯은 `attrs`에 네임스페이스(`full.*`) |
| **Handoff (스냅샷 복사)** | 복사 시점 이후 원본 변경이 미반영 — 두 시스템 간 데이터 표류 | **스냅샷 → 참조+버전 고정**: Full IM 프로젝트는 asset의 특정 버전을 참조, 갱신 시 diff 알림("원본 렌트롤이 변경됨 — 반영할까요?") |
| **Readiness (1~100점)** | 크리딜 grade-engine(A~D 커버리지)과 이중 기준 | grade-engine으로 통일 — Full IM 발동 요건은 "grade A + 확장 섹션별 필수 슬롯" |
| **AI Draft (GPT-4o·자체 프롬프트)** | 모바일 IM 파이프라인(가드레일 4중·NLG 마스크·골든셋)과 별개 스택 — 품질·정책 드리프트 | 모바일 writer 파이프라인을 **섹션 라이브러리로 추상화**해 공용화. 수치는 동일 NLG 마스크, 가드레일·법정 문구 체크 단일 구현 공유 |
| **Golden Dataset 파이프라인** | 모바일 골든셋·im_edit_diffs와 분리 수집 | 수집 스키마 통합 — expert_patches diff도 `im_edit_diffs`로 (G8 단일 루프) |
| **Export (pptx placeholder)** | 감사 지적: 명세 placeholder 수준 | §6 pptx 스펙으로 구체화 |

### 2.3 채택 보류

- **owner 역할의 상시 참여**: 매도인은 동의·증빙 업로드 접점만 (IM 이원화 스펙의 동의 체인으로 충분) — 별도 로그인 워크플로는 마찰
- **8게이트 전건 강제**: §4.3 축약 체계로 대체
- **admin/analytics 콘솔 별도 운영**: 크리딜 관리 콘솔로 흡수

## 3. 골디락스 섹션 구조 — 7→18 상속 매핑

### 3.1 코어 상속 (모바일 IM 승인본 = Full IM의 시드)

| 모바일 7섹션 | Full IM 대응 섹션 | 상속 방식 |
|--------------|-------------------|-----------|
| ① 자산 개요 | 1. Executive Summary / 2. 자산 개요 | 승인본 + 확장(연혁·시설 상세) |
| ② 입지·접근성 | 3. 입지 분석 / 4. 상권·수요 분석 | 승인본 + 시장 데이터 확장 |
| ③ 임대차 현황 | 5. 렌트롤 상세 / 6. 임차인 분석 | 승인본 + 호실별 정밀(Pro 수준) |
| ④ 수익 분석 | 7. 재무 분석 / 8. 민감도·시나리오 | 승인본 + DCF 상세(A등급 전제) |
| ⑤ 리스크 | 9. 리스크·권리분석 | 승인본 + 전문가 패치 대상 1순위 |
| ⑥ 투자 하이라이트 | 10. Investment Thesis | 승인본 + 아키타입 근거 확장 |
| ⑦ 다음 단계 | 18. 거래 구조·프로세스 | 승인본 + 일정·입찰 안내 |

### 3.2 확장 섹션 (Full 전용 — 딜 유형별 선별)

11. 시장 동향(권역 리포트) · 12. 비교 거래 사례 상세 · 13. 건물 상태·CAPEX 계획 · 14. 법률·인허가 검토(전문가) · 15. 세무 구조(전문가) · 16. ESG·에너지 · 17. 부록(증빙 인덱스 — Evidence 연동)

- **선별 규칙**: 딜 유형 템플릿이 기본 세트 결정 (물류 기관 딜: 11~15+17 / 꼬마빌딩 요청 건: 11·12·17만) — "18섹션 전부"는 기본값이 아니다
- 확장 섹션 필수 슬롯은 온톨로지 v0.2 `full.*` 네임스페이스에 정의, grade-engine이 섹션별 준비도 표시

## 4. 작성 방법론 — "모바일 퍼스트 상속 + 선별적 인간 검토"

### 4.1 워크플로우

```
[전제] 딜의 IM-Basic/Pro가 승인·발행된 상태 (grade A)
 1. 발동: 트리거 충족 → 딜 워크스페이스에 "Full IM 제작" 카드
 2. 구성: 딜 유형 템플릿 선택 → 섹션 세트 확정 (7 상속 + 확장 선별)
 3. 상속: 코어 7섹션에 모바일 승인본 자동 주입 (재작성 없음 — 톤 변환만)
 4. 확장 초안: 확장 섹션만 AI 초안 (공용 파이프라인 + NLG 마스크)
 5. 에디터 정리: 3-panel 에디터 (초기엔 운영팀이 im_editor 겸임)
 6. 전문가 패치: 리스크·법률·세무 섹션만 선별 배정 (Expert Workbench)
 7. 축약 Gate: §4.3 — 자동 게이트 + 인간 리뷰 1회
 8. Export: pptx/pdf (buyer_ready 워터마크) → IM-Pro grant 체계로 배포
```

### 4.2 시간 목표 (방법론의 성패 기준)

- 전통 Full IM: 2~4주 / cre-fullim 단독: 수일 / **목표: 코어 상속 덕에 확장 섹션만 작업 → 2~3일** (전문가 패치 대기 포함)
- 코어 7섹션 작업 시간 = 0이 이 방법론의 존재 이유 — 상속이 재작성으로 변질되면 실패

### 4.3 축약 Gate 체계 (8 → 2층 구조)

| 층 | 게이트 | 방식 |
|----|--------|------|
| 자동 (기존 크리딜) | Data(C01~12) · Disclosure(정책 계층) · Financial(NLG 마스크·가정 박스) · 법정 문구 | constraint-validator + 가드레일 — 통과 없이 인간 검토 진입 불가 |
| 인간 (cre-fullim 채택) | Risk·Expert 완결성·최종 Buyer-ready | reviewer 1인 1회 통합 검토 (P0 위반 시 차단 유지) |

- 8게이트의 정신(체계적 검증)은 유지하되, 자동화 가능한 게이트를 기계에 넘겨 인간 검토를 1회로 압축

## 5. 통합 아키텍처

### 5.1 스키마 단일화 (최우선)

```
packages/contracts  ←  온톨로지 v0.1 → v0.2 (Full 슬롯 흡수)를 계약 스키마로 승격
  ├─ credeal (모바일):  assets.attrs — 기존
  └─ cre-fullim:        building_ssot_full 신규 쓰기 중단 → assets 참조로 마이그레이션
```

- 이행 순서: ① contracts에 온톨로지 스키마 탑재 ② fullim 읽기 경로를 assets 참조로 전환 ③ building_ssot_full 신규 생성 중단(기존 프로젝트는 동결 유지) ④ Full 전용 필드를 `attrs.full.*`로 이관
- RLS 리스크(감사 권고 1): 스키마 공유 대신 **단일 원본 + 뷰 권한**으로 구조 자체를 단순화

### 5.2 파이프라인 공용화

- `mobile-im/writer` → `im-core` 패키지로 추상화: 섹션 생성기·가드레일·NLG 마스크·Judge를 양쪽이 공유. 차이는 섹션 세트·프롬프트 페르소나·토큰 한도 설정값뿐
- 골든셋·편집 diff·전문가 패치 diff → 단일 수집 스키마 (G8)

### 5.3 이벤트·퍼널 연결

- `full_im_proposed/started/expert_patched/gate_passed/exported` → 딜 Activity 타임라인 합류
- Full IM 열람은 IM-Pro grant 체계 재사용 (워터마크 pptx/pdf, 재공유 감지) — 리드 스코어 최고 가중 유지

## 6. pptx 생성 스펙 (placeholder 구체화)

- **템플릿**: 슬라이드 마스터 2종(기관용 정격·브로커 브랜드형) — 표지·목차·섹션 표지·본문(1단/2단/표/차트)·부록 레이아웃. 브로커 로고·컬러 화이트라벨
- **콘텐츠 매핑**: 섹션 md → 슬라이드 분해 규칙 (h2=새 슬라이드, 표=네이티브 표, 히어로 지표=차트 위젯). 수치는 전부 NLG 마스크 산출값 — 슬라이드에 출처 각주 자동
- **생성 경로**: 서버 워커(비동기 Job — 감사 권고 3 수용: Vercel 타임아웃 회피, export_jobs 재사용) + python-pptx 또는 동급 라이브러리
- **워터마크 체계**: draft(전면 DRAFT) / buyer_ready(하단 열람자 각인 — grant 연동) / internal(내부용 표기)
- **금지**: 템플릿 무한 커스텀 (2종 고정 시작 — Too Hot 방지)

## 8. DoD·DO NOT

**Definition of Done**
- [ ] Full IM 코어 7섹션에 수동 재작성 0 (상속 자동 주입 검증)
- [ ] assets 단일 원본 — Full IM 생성 시 재입력 필드 0
- [ ] pptx 수치 전수가 NLG 마스크 산출 + 출처 각주 (샘플 감사)
- [ ] 자동 게이트 미통과 문서의 인간 검토 진입 불가
- [ ] Full IM 배포가 grant 체계 경유 (직링크 0)

**DO NOT**
