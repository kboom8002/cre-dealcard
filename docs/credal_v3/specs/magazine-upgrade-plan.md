# 📰 모바일 매거진 시스템 고도화 계획 v1.0

> **버전**: v1.0 (2026.07.25) · 입력: 「모바일 매거진 시스템 아키텍처·기능 명세」(5모듈·14 API·881줄 뷰어·1,550줄 에디터)
> **정합**: 기획안 v2.0(매거진=리드 너처링 모듈 재정의) · 온톨로지 v0.1 · 티저 스펙(공개 슬롯 표준) · 부속요소 C절(리드 엔진) · 3대 효과(K1·K4) · 무마찰 UX 문서 · SDD v1.1
> **한 줄 결론**: 현행 매거진은 "잘 만든 발행 도구"다. 고도화의 방향은 콘텐츠를 더 만드는 것이 아니라 — **매거진을 크리딜 데이터 해자의 유통 채널이자, 구독자를 매수자 프로파일로 전환하는 너처링 엔진이자, 모든 정기 발송(매각 리포트·자산 리포트)의 공용 레일로 승격**시키는 것이다.

## 2. 재정의 — 매거진의 4가지 역할

```
① 리드 너처링 엔진   구독자를 익명→프로파일→매수 의향으로 승격 (v2.0 재정의의 실행)
② 신뢰 자산          필드노트(육성) + 집합 지식(크리딜만의 통계) = 브로커 권위의 주간 증명
③ AEO 원천           인용 가능한 권역 통계 블록 → /agora·AI 답변엔진의 콘텐츠 공급
④ 공용 발송 레일      위클리 · 주간 매각 리포트(매도인) · 분기 자산 리포트(건물주 K4)를
                     하나의 구독·배포·분석 인프라로
```

## 3. 고도화 항목 (M-1 ~ M-10)

### M-1. 매물 카드의 티저 표준화 `P0 — 유출 방어`
- `DealSnippet` 폐기 → 매거진 주목 매물 카드 = **티저 public 슬롯 투영(TeaserView) 그대로** (아키타입 뱃지·밴드·구조 신호 3칩)
- **발행 게이트 공유**: 매거진에 실리는 매물은 재식별 시뮬레이터 통과본만 — `teaser_configs.status='published'`인 딜만 선택 가능
- 데이터 원천을 building_ssot_lite → `assets`(온톨로지)로 전환 (SDD 이관 정책 준용)
- 효과: 매거진·티저·크로스매칭의 매물 표현이 단일 규격 — "하나의 스키마 위 여러 뷰" 원칙 완성

### M-2. 집합 지식 섹션 신설 `P0 — 차별화 코어`
- 신규 섹션 `collective_insights` (MVP 코어로 승격): "이 권역의 현실" — 평균 성사 기간·호가-성사가 갭·무산 사유 분포·금주 반응 좋은 소구 (v_collective_insights, N≥5 표기 의무)
- AI 브리핑 프롬프트에 집합 지식 주입 — "크리딜 표본 23건 기준" 인용 문체
- **Give-to-Get 정합**: 매거진 노출은 공개 계층(얕은 집계)만 — 심화 계층은 앱 내 기여자 전용 유지(K1 침해 금지)

### M-3. 수치 생성 전환 — 마스크 + 게이트 2차화 `P1`
- 수치 포함 문장(온도 근거·실거래 요약·집합 통계)은 **NLG 마스크 렌더**로 전환, LLM은 내러티브(브리핑 서사·테마) 전담 — IM G2와 동일 원칙, `nlg-mask-engine` 재사용
- 기존 품질 게이트는 폐기하지 않고 **2차 안전망으로 격하** (마스크 미적용 구간 + LLM 서사의 수치 혼입 감시)
- 효과: needs_review 불합격률 구조적 감소 → 월요일 아침 검토 마찰 제거

### M-4. 구독자 프로파일 개인화 `P1 — 너처링의 심장`
- `magazine_subscribers` 확장: `client_id`(고객 CRM 연결) · `interest_profile`(관심 아키타입·권역·가격밴드 — 열람·클릭 행동 자동 집계) · `segment`(buyer/seller/owner 자동 판정)
- **개인화 3지점**: ①주목 매물 큐레이션 = 프로파일 정합 딜 우선(매칭 엔진 재사용) ②섹션 순서 = URL 파라미터 → 구독자별 자동 ③발송 알림톡 문구 = 관심 소구 반영("관심 두신 밸류애드형 신규 1건")
- **행동→리드 승격 파이프라인**: 매물 클릭 2회+ 또는 IM 전환 시 → intent 초안 제안(브로커 확인 칩) → 승격 시 `buyer_intents` 편입 — 부속요소 C2와 동일 경로
- 섹션 체류는 관심 태깅(C1)으로: 경매 픽 체류 → `interest:특수딜`, 심리지수 체류 → `concern:타이밍`

### M-5. 5분 발행 플로우 — 에디터 무마찰화 `P1`
```
[신규 기본 플로우 — 3스크린]
① 필드노트 (음성 우선)                  ② 원스크린 확인                ③ 발행
  🎤 "이번 주 시장 한 문장으로?"          AI 초안+온도+키워드+매물        [🚀 발행]
  → 5필드를 음성 문답으로 순차 수집        +집합 지식 — 전부 한 화면,       → 알림톡
  (운전 중·이동 중 가능, 메모 FAB 패턴)    수정할 것만 탭하여 인라인 편집
```
- 기존 8탭 에디터는 **[고급 편집]으로 강등** (뉴스 큐레이션·테마 색상 등은 원할 때만)
- 홈 액션 큐 연동: 월요일 아침 카드 "이번 주 매거진 초안이 준비됐습니다 — 필드노트만 남았어요 [🎤 시작]"
- 목표: 발행 소요 중앙값 5분 이내 실측 (현재는 목표 선언뿐, 계측 없음)

### M-6. 발송 레일 일반화 `P1~P2 — 인프라 승격`
- `magazine_editions.edition_type` 확장: `weekly` | `seller_report`(주간 매각 리포트 — Pitch 4️⃣블록 자동 생성) | `owner_report`(분기 자산 리포트 — K4) | `special`
- 구독자 세그먼트 분리: 투자자(위클리) / 매도인(매각 리포트 — 수임 딜별 자동 구독) / 건물주(자산 리포트 — 성사 시 자동 구독)
- 효과: 구독·배포·수신거부·분석을 3개 상품이 공유 — K4(최우선 킬러)의 개발이 "신규 시스템"에서 "에디션 타입 추가"로 축소
- HMAC 수신거부·5건 병렬 발송 등 기존 메커니즘 그대로 재사용

### M-7. AEO·아고라 연계 `P2`
- 구조화 데이터: `Article` + **`Dataset`**(집합 지식 블록) + `FAQPage`(용어 해설 코너 — "각지가 왜 비싼가" 류) schema.org 마크업
- **인용 가능 블록 설계**: 집합 지식 섹션에 고정 anchor·버전·출처 문구("크리딜 성사 데이터 기준, 2026 W30, N=23") — AI 답변엔진이 인용하기 좋은 형태
- /agora 연동: 발행 매거진의 공개 계층(브리핑·집합 지식·용어 코너)이 아고라 피드로 자동 신디케이션 — 매물 카드는 티저 규격 유지, 문의는 브로커 라우팅
- 용어 코너 신설(주 1개): 온톨로지 enum의 대중 번역 — 콘텐츠 비용 0의 AEO 자산

### M-8. 매거진 반응 → 발행 전 시뮬레이터 연료 `P2`
- 섹션별 체류·완독률·소구별 클릭을 아키타입×권역 반응 함수에 합류 (K2 반응 시뮬레이터의 데이터 소스 확장)
- 역방향 소비: 발행 확인 스크린에 "지난 호 대비 예상 반응" 등급 표시 — 필드노트 소구 개선 제안

### M-9. 기술 부채 정리 `P0 동반`
- `broker_id` 타입 통일(UUID, slug는 별도 컬럼) — M-4의 client 조인 전제
- `magazine_issues` 캐시 이원화 검토: editions 단일화 + ISR로 흡수 가능하면 듀얼 쓰기 제거
- 분석 이벤트를 `teaser_events`와 동일 규격으로 정렬 (visitor_fp 통일 — 크로스 채널 리드 스코어 정확도)

### M-10. 마케팅 에이전트 준비 `Stage 5`
- L2: 매주 월요일 "초안+추천 매물+집합 지식+발송 대상" 완비 상태로 대기 — 브로커는 필드노트 음성 5문답+발행 1탭 (M-5가 그대로 에이전트 UX가 됨)
- L3(수락률 70%+ 후): 필드노트 제외 전 과정 자동, 필드노트 없는 주는 "데이터 요약호"로 자동 발행 제안
- 발행 제안 수락률·수정률이 자율성 승격 데이터

## 4. 시너지 맵 (다른 기능과의 연결 총괄)

| 연결 | 방향 | 내용 |
|------|------|------|
| 티저 | 매거진 → 티저 | 주목 매물 카드 = 티저 뷰 (M-1) — 매거진이 티저 유통 채널 |
| 리드 엔진 (C1~C3) | 매거진 → 리드 | 열람 행동 → 관심 태깅 → intent 초안 (M-4) |
| Pitch | 레일 공유 | 주간 매각 리포트 = seller_report 에디션 (M-6) — 전속 전환 무기 |
| K4 자산 라이프사이클 | 레일 공유 | 분기 자산 리포트 = owner_report 에디션 (M-6) — 최우선 킬러의 최단 구현 |
| K1 Give-to-Get | 계층 준수 | 매거진=공개 계층, 앱=기여자 계층 (M-2) |
| K2 시뮬레이터 | 데이터 상호 | 매거진 반응 → 반응 함수 → 발행 전 예상 등급 (M-8) |
| /agora·AEO | 콘텐츠 공급 | 공개 계층 신디케이션 + 인용 블록 (M-7) |
| 에이전트 2막 | UX 승계 | 5분 플로우 → L2 대기 → L3 자동 (M-5→M-10) |
| Hot Lead·스마트톡 | 기존 유지 | 열람→스코어→알림 파이프라인 그대로, visitor_fp만 통일 (M-9) |

## 5. 단계 배치·지표

| 배치 | 항목 | 완료 기준 |
|------|------|-----------|

## 6. DO NOT (매거진 특화)

```yaml
- "재식별 게이트 미통과 딜의 매거진 노출 (DealSnippet 경로 포함 — M-1 전까지 기존 경로 동결)"
- "심화 집합 지식(기여자 계층)의 매거진 공개 (K1 침해)"
- "N<5 표본 통계 인용"
- "필드노트의 AI 대필 (육성 진정성 = 매거진의 존재 이유. AI는 다듬기만)"
- "구독자 프로파일의 크로스 브로커 공유 (리드 소유권 불변)"
- "매물 카드 정밀값·외관 사진 노출 (티저 정책 동일 적용)"
- "발행 자동화의 일괄 ON (에이전트 승격 규칙 준수)"
- "매도인·건물주 리포트의 플랫폼 명의 발송 (항상 브로커 화이트라벨)"
```

---

> **요지**: 이 계획의 무게중심은 M-1(유출 방어)·M-2(차별화)·M-4(너처링)·M-6(공용 레일) 넷이다. 특히 M-6이 전략적 지렛대다 — 이미 완성된 구독·배포·분석 인프라를 위클리 전용에서 공용 레일로 승격시키면, **Pitch의 주간 매각 리포트와 K4 자산 리포트(최우선 킬러)가 '신규 개발'이 아니라 '에디션 타입 하나 추가'가 된다.** 매거진은 콘텐츠 상품이 아니라 크리딜의 정기 접촉 인프라다.
