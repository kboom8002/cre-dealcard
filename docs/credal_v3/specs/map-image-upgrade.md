# 🗺️ 모바일 IM 맵·이미지 고도화 방안 v1.0

> **버전**: v1.0 (2026.07.25) · 입력: 「맵 이미지 기능 명세」(3계층: Static Map·뷰어 OSM 그리드+갤러리·두 지점 캡처 도구)
> **정합**: 온톨로지 v0.1 · 티저 스펙(공개 정책·photo-safety) · IM 이원화 스펙(Basic/Pro 렌더) · SDD v1.1 · 부속요소(아키타입 소구 사전)
> **한 줄 결론**: 현행 맵은 "위치를 보여준다". 고도화의 방향은 **맵을 '입지의 논증'으로, 사진을 '건물의 논증'으로** 바꾸는 것 — 그리고 그 전에, 공개 사다리와 맵의 정합(블라인드인데 정확 좌표 노출)이라는 구멍부터 막아야 한다.

| G-5 | 개발부지·대지의 시각 자산 전무 (필지 경계·형상·접면을 보여줄 수단 없음) | landSite 적합도 ⭐3의 시각적 원인 — 항공+지적 오버레이 부재 |
| G-6 | OSM 타일 의존 — 한글 라벨·한국 상세도 약함 + tile.openstreetmap.org 대량 사용 정책 리스크 | 품질·운영 리스크 동시 존재 |
| G-7 | 이미지별 반응 데이터 미수집 (갤러리 카드 체류·클릭) | "어떤 이미지가 파는가"의 암묵지 유실 |

## 2. 설계 원칙 4

1. **맵은 공개 사다리를 따른다**: 지도의 정밀도 = 문서 tier의 공개 수준. 티저(권역)→Basic(퍼지 반경)→Pro(정확 핀)→캡처 이미지(Pro 이상)
2. **맵은 논증이다**: 마커가 아니라 주석(annotation) — 온톨로지 검증 슬롯의 시각화. 주석의 모든 수치는 NLG 마스크와 동일하게 검증값+배지
3. **온톨로지가 아는 것은 묻지 않는다**: 두 지점·POI·경계는 슬롯에서 자동 제안 — 브로커는 승인·조정만
4. **창작 금지 유지**: POI·경계 데이터 없으면 해당 시각 요소 자동 생략 (기존 안티 환각 원칙의 시각 확장)

## 3. 고도화 항목 (MI-1 ~ MI-9)

### MI-1. Tier별 맵 공개 정책 `P0 — 구멍 막기`

| Tier | 맵 표현 | 딥링크 | 구현 |
|------|---------|--------|------|
| 티저 (`/dc`) | **권역 폴리곤/라벨만** — 핀 없음 ("역삼권" 하이라이트) | 없음 | location_hierarchy 기반 권역 셰이프 |
| IM-Basic | **퍼지 원** — 중심을 무작위 오프셋(±150m)한 반경 400m 원 + "상세 위치는 열람 신청 후" | 없음 | 오프셋 시드는 딜별 고정(매 렌더 동일) |
| IM-Pro (grant) | 정확 핀 + POI 주석 + 카카오맵 딥링크 (현행) | 있음 | 현행 유지 |
| 데이터룸·캡처 이미지 | 전체 (두 지점·경계 포함) | 있음 | — |

- 재식별 게이트와의 정합: 티저의 공개 슬롯 조합 검증에 "맵 표현"도 포함 — 퍼지 원조차 밴드 조합과 결합해 후보<K가 되면 원 반경 자동 확대 제안
- **DO NOT**: Basic 이하에서 정확 좌표가 클라이언트로 전송되는 것 자체를 금지 (오프셋은 서버에서 적용 — TeaserView 타입 원칙과 동일)

### MI-2. 입지 스토리 맵 (Location Story Map) `P1 — 소구력 코어`

마커 1개짜리 맵을 **온톨로지 슬롯의 시각 논증**으로 교체 (Pro 기준, Basic은 퍼지 원 위에 주석만):

```
┌─────────────────────────────────────┐
│        [지도 타일]                    │
│     🚇 역삼역 ●───── 도보 4분 ⚙       │  ← subwayWalkMin (파생 슬롯)
│              ╲ 320m                  │
│         ┌────📍────┐                 │
│         │  코너 입지 │ ← roadContactType│  ← 접면 방향 강조선 2면
│         └──────────┘                 │
│   ☕18  🅿4  🍴32  (반경 500m) ⚙       │  ← poiCounts 칩
│                    [카카오맵 보기 →]   │
└─────────────────────────────────────┘
```

- **주석 레이어 자동 구성**: ①최근접역 연결선+도보 시간 ②코너/접면 강조(각지면 두 도로변 하이라이트 — 도로접면 enum의 시각화) ③POI 밀도 칩 ④(물류) IC 연결선+거리
- 아키타입별 강조 프리셋: STABLE_INCOME→역·상권 / HQ_READY→도로폭·진입 / 물류→IC·야드 (부속요소 B2 소구 사전과 동일 논리)
- 주석 수치는 전부 슬롯 렌더 + ⚙/✓ 배지 — LLM이 맵 주석 텍스트를 생성하지 않음
- 구현: 서버 사이드 SVG 오버레이 합성(타일 위) → 정적 이미지로 캐시 (뷰어 성능·일관성)

### MI-3. 사진 파이프라인 자동화 `P1`

- **업로드 시 자동 분류**: 비전 모델이 14타입 중 제안 + photo-safety 검사(티저용 외관·간판 검출 — 기존 스펙 재사용) 동시 수행 → 브로커는 칩 확인만
- **캡션 자동 제안**: 온톨로지 연계 — "1층 임차 공간 (전용 28평·카페)" (lease_units 조인), "옥상 — 증축 여유 검토 대상" (farHeadroomPp 연계) → 편집 가능, 편집 diff는 골든셋 경로
- **히어로 이미지 선정 로직**: 아키타입별 우선순위 (수익형→외관/로비, 개발형→항공/대지, 물류→도크/내부 층고) + 해상도·구도 스코어
- **Tier별 갤러리 필터**: Basic=photo-safety 통과분(내부·디테일 중심), Pro=전체(외관 포함) — 갤러리가 렌더 정책을 읽음

### MI-4. 캡처 도구의 파이프라인 통합 `P1`

- **자동 제안 모드**: 딜에서 진입 시 A지점=매물(자동), B지점 후보 칩 제시 — 최근접역(subwayWalkMin)·최근접 IC(nearestIc)·주요 랜드마크(POI) → 수동 입력 제거
- **[IM에 삽입] 버튼**: 캡처 → `photos(type:'map', caption 자동)` 직행 (다운로드→재업로드 루프 제거) — 단, **Pro 전용 슬롯으로 저장**(정확 위치 노출물이므로 MI-1 정책 적용)
- 물류 전용 템플릿: "IC 거리 맵"(매물↔IC, 주행거리 라벨) 원클릭 — logisticsCenter IM의 표준 삽입물
- 기존 8색·4프리셋·인쇄 기능 유지

### MI-5. 필지·항공 레이어 — 개발부지의 시각 무기 `P1~P2`

- **vworld 항공사진 + 연속지적도 오버레이**(공공 API — 기존 PNU 파이프라인 재사용): 필지 경계 하이라이트 + 면적·지목·형상 라벨 + 접면 도로 폭 표시
- 개발부지 IM의 표준 시각 세트: ①경계 오버레이 항공맵 ②접면·형상 다이어그램 ③(규모검토 연계 시) 신축 볼륨 개념도 자리(S2-T4 massing 파싱 결과)
- 효과: landSite 적합도 ⭐3→⭐5의 시각적 완성 — "말로 설명하던 땅"이 보이는 땅이 됨
- Tier 정책 적용: 경계 오버레이는 위치 특정물이므로 **Pro 이상**

### MI-6. 타일 소스 교체·캐시 `P1 기술`

- OSM 직접 호출 → **vworld 타일(한국 최적·한글·공공 무료)** 기본 + OSM 폴백, 자체 프록시 캐시(타일 사용 정책 준수·속도)
- 기존 3×3 그리드 로직 유지 (타일 URL만 교체 가능하도록 소스 추상화)

### MI-7. 갤러리의 스토리 재배열 + 섹션 인라인 `P2`

- 갤러리 순서를 IM 서사와 동기화: 입지 맵 → (Pro)외관 → 내부·임차공간 → 평면도 → 주변 — "읽는 순서대로 보이는 순서"
- **섹션 인라인 삽입**: 입지 섹션에 스토리 맵, 임대차 섹션에 평면도+임차공간, 리스크 섹션에 관련 사진(위반 해소 부위 등) — 갤러리와 별개로 해당 섹션 문맥에 1장씩
- VALUE_ADD 아키타입 전용: 리모델링 전/후 비교 슬라이더(브로커가 시안 보유 시)

### MI-8. 이미지 반응 수집 `P2 — 암묵지`

- 갤러리 카드별 체류·라이트박스 진입·스와이프 이탈 이벤트 (teaser_events 규격·visitor_fp 통일)
- 집계: 아키타입×타입별 "파는 이미지" 통계 → 히어로 선정 로직(MI-3) 보정 + 브로커 인사이트("이 딜은 옥상 사진에서 체류가 깁니다 — 증축 관심 신호")

### MI-9. Static Map URL 정리 `P2 부채`

- 저장만 되고 뷰어 미사용인 `mapImageUrl` — 용도를 **OG 이미지·PDF 내보내기 전용**으로 명시(문서화)하거나 생성 중단. 미사용 자산의 암묵적 유지 금지

## 6. DO NOT

```yaml
- "Basic 이하 tier에서 정확 좌표의 클라이언트 전송 (퍼지 오프셋은 서버 적용)"
- "티저·Basic의 카카오맵 딥링크 (좌표 노출 경로)"
- "맵 주석 텍스트의 LLM 생성 (슬롯 렌더+배지만)"
- "POI·경계 데이터 부재 시 시각 요소 창작 (자동 생략 원칙)"
- "캡처 이미지(정확 위치물)의 Basic 이하 갤러리 노출"
- "photo-safety 미통과 사진의 티저·Basic 노출 (외관·간판)"
- "OSM 공용 타일 서버의 무캐시 대량 직접 호출"
- "퍼지 원 오프셋의 렌더마다 재생성 (시드 고정 — 반복 열람 삼각측량 방지)"
```

---

> **요지**: 우선순위는 명확하다 — **MI-1(구멍 막기)이 소구력 개선보다 먼저다.** 블라인드 문서에 정확 좌표 지도가 실리는 현행 구조는 티저의 재식별 게이트 전체를 무력화한다. 그 다음이 소구력의 본론: 맵을 마커에서 논증으로(MI-2), 사진을 수동에서 자동 스토리로(MI-3), 땅을 말에서 그림으로(MI-5). 그리고 모든 시각 요소는 문서와 같은 규율을 따른다 — 검증 슬롯, 배지, tier, 그리고 창작 금지.
