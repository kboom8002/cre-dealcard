# 📑 수임 제안서 (Pitch) — 개발 상세 스펙 v1.0

> **버전**: v1.0 (2026.07.23) · 정합: DEV_SPEC v2.0(S2) · 티저 스펙 · IM 이원화 스펙 · 온톨로지 v0.1 · 부속요소 방안(E절)
> **핵심 설계 사상**: 수임 제안서는 **"역방향 IM"**이다 — IM이 매수자를 설득한다면, Pitch는 매도인을 설득한다. 같은 Asset SSoT·같은 NLG 마스크·같은 열람 추적을 쓰되, 독자와 논증 구조만 뒤집는다. 그리고 **매도인도 리드다**: Pitch 열람 추적이 수임 전환의 신호가 된다.
> **전략적 위상**: 브로커 최대 병목(매물 소싱)을 직접 해소하는 유일한 도구 — 채택 유인 1순위 (전략 문서 P1).

---

## 1. 포지셔닝과 두 가지 모드

### 1.1 파이프라인 위치

```
[콜드 모드]                     [웜 모드]
소유주 발굴 → Pitch(공공데이터판) → 미팅 → 정보 확보 → Pitch(풀 데이터판) → 수임 → 티저→IM 사다리
                                                            │
                                              전속 + 강화IM 일괄 위임 + 주간 리포트 조항
```

### 1.2 두 모드 (핵심 설계 결정)

| | **콜드 모드** (Cold Pitch) | **웜 모드** (Warm Pitch) |
|---|---|---|
| 상황 | 소유주 콜드 아웃리치·방문, 매물 정보 없음 | 매도 의사 확인 후, 수임 경쟁 |
| 입력 | **주소(PNU)만** | 주소 + 브로커 확보 정보(호가·렌트롤 일부) |
| 데이터 | 공공 자동충전만 (~30슬롯: 대장·용도지역·공시지가·도로접면·용적률 여유·실거래) | 자동충전 + broker_input |
| 내용 | 물건 잠재력 진단 + 권역 시장 브리핑 + 크리딜 방식 소개 | + 가격 의견·맞춤 마케팅 플랜·수임 조건 |
| 생성 시간 목표 | **10분 이내** (시나리오 D) | 30분 이내 |
| 목적 | 미팅 확보 ("이 정도 분석을 들고 오는 중개인") | 수임 계약 (전속 우선) |

- 콜드 모드가 존재 이유: 소싱은 정보가 없는 상태에서 시작된다 — 공공데이터 60% 자동충전이 있어야 가능한, 조회 플랫폼이 못 만드는 무기

## 2. 문서 구성 (골디락스)

### 2.1 웜 모드 표준 구성 (6블록)

| # | 블록 | 내용 | 데이터 소스 |
|---|------|------|-------------|
| 1 | **물건 진단** | 아키타입 판정 + 근거("귀 물건은 초안정 수익형 — 공실 0%·WALT 2.8년·역세권 4분"), 강점 3·보완점 2 (정직성이 신뢰) | archetype-classifier·grade-engine |
| 2 | **가격 의견** | 비교 실거래 3~5건(선정 근거 명시: 권역>용도지역>도로접면>면적 밴드>연대) + 접면 가중치 보정 논리 + **범위 제시** ("78~83억 — 시장 소화 가능 구간") | comparable + 도로접면 weight |
| 3 | **마케팅 플랜** | 아키타입→타깃 매수자 풀→소구 포인트→채널·일정. 티저·IM 실물 미리보기 삽입("귀 물건은 이렇게 보입니다") | copy-grammar·티저 프로젝터 |
| 4 | **투명 보고 약속** | 주간 리포트 샘플(열람 수·관심자·문의) — "뿌리고 끝이 아니라 매주 데이터로 보고" | 열람 추적 실데이터 데모 |
| 5 | **집합 지식** | "이 권역 평균 성사 {N}개월·무산 1위 {사유} — 대응 플랜" (익명 집계, N≥5) | v_collective_insights |
| 6 | **수임 조건** | 전속/일반 옵션 비교표, **강화IM 일괄 위임 조항**, 기간·보수(법정 요율 명시), 서명란 | 계약 템플릿 |

### 2.2 콜드 모드 구성 (4블록)

블록 1(공공데이터 진단: 용적률 여유·접면 등급·권역 포지션) + 블록 2 축약(실거래 동향만, 가격 의견 없음 — 정보 부족 상태의 가격 제시는 신뢰 훼손) + 블록 5 + "크리딜 방식" 소개(티저 샘플·추적 데모). **매도 의사를 가정하지 않는 톤** — "매각을 검토하신다면"

### 2.3 렌더·산출

- 모바일 페이지(기본, 열람 추적) + PDF(인쇄 방문용, QR로 모바일 연결) — 매도인 연령대 고려 이중 제공
- 수치는 전부 NLG 마스크 — IM과 동일 원칙. 브로커 명의 화이트라벨(명함·로고)

## 3. 법적·신뢰 가드레일 (Pitch 특화)

| 리스크 | 규칙 |
|--------|------|
| **감정평가 오인** | 가격 의견 블록 고정 문구: "본 가격 의견은 감정평가가 아니며, 중개 목적의 시장 참고 자료입니다" — 감정평가사법 저촉 방지. '감정가·평가액' 단어 금지, '시장 참고 범위' 사용 |
| 성사 보장 오인 | "N개월 내 매각 보장" 류 표현 P0 차단 (기존 Risk Boundary 확장 — pitch 전용 패턴 추가) |
| 타 매물 정보 유출 | 마케팅 플랜의 사례 인용은 익명·집계만 — 타 딜 정보 식별 불가 검증 |
| 보수 표시 | 법정 요율 상한 명시 의무 — 컴플라이언스 체크에 포함 |

## 4. 매도인 = 리드 (추적·전환 설계)

- Pitch 열람 추적: 열람·재열람·블록별 체류(가격 의견 3분+ = 강한 매각 의사 신호) → 브로커 알림 "매도인이 가격 의견을 다시 봤습니다 — 후속 연락 타이밍"
- 전환 이벤트: `pitch_sent → pitch_viewed → pitch_meeting → mandate_signed(전속/일반)` — 수임 퍼널이 딜 파이프라인 '제안' 단계의 서브 퍼널
- 수임 성사 시 자동 연결: `deals.mandate_type` 기록 + `seller_consent_mode`(강화IM 위임 조항 수락 시 'delegated') + 주간 리포트 구독 자동 개시(매거진 인프라 재사용)
- 무산 태깅: 수임 실패 시 1탭 사유(타사 선택/보류/호가 이견) → 암묵지 (소싱 전환율 개선 데이터)

## 5. 구현

### 5.1 모듈·데이터

```
src/domain/deal/pitch/
├── pitch-generator.ts       # 모드별 블록 조립 (asset + market + insights)
├── price-opinion.ts         # 비교사례 선정(명시적 슬롯 거리) + 접면 보정 + 범위 산출
└── pitch-templates.ts       # 웜/콜드 블록 템플릿 + 수임 조건 계약 템플릿
```

```sql
CREATE TABLE pitches (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  deal_id uuid REFERENCES deals(id),        -- 콜드 모드는 deal 없이 asset만 (사전 딜)
  asset_id uuid NOT NULL REFERENCES assets(id),
  mode text NOT NULL,                       -- 'cold'|'warm'
  blocks jsonb NOT NULL,                    -- 블록 구성·내용 스냅샷
  price_opinion jsonb,                      -- {low, high, comparables[], method_note}
  status text DEFAULT 'draft',              -- 'draft'|'sent'|'viewed'|'meeting'|'won'|'lost'
  lost_reason text,
  seller_contact jsonb,                     -- 발송 대상 (열람 바인딩)
  created_at timestamptz DEFAULT now()
);
```

### 5.2 API·이벤트·플래그

```
POST /api/broker/pitch                    # 생성 (mode, asset_id | address→자동 asset 생성)
POST /api/broker/pitch/{id}/send          # 발송 (모바일 링크 + PDF)
GET  /api/public/pitch/{token}            # 매도인 열람 (추적)
POST /api/broker/pitch/{id}/outcome       # won(mandate_type)/lost(사유)
```

- 이벤트: `pitch_generated/sent/viewed/block_dwell/meeting_set/mandate_signed/pitch_lost_tagged` (DEV_SPEC 0.2 등재분과 정합)
- 플래그: `ff_pitch_warm`(M2) → `ff_pitch_cold`(M3 — 공공 자동충전 안정화 후) → `ff_pitch_insights`(M5 — 집합 지식 블록)

### 5.3 마일스톤 (DEV_SPEC 재확인)

| 시기 | 범위 |
|------|------|
| M2 (주 4~7) | 웜 모드: 블록 1·2·3·6 + 모바일/PDF + 열람 추적 |
| M3 (주 8~10) | 콜드 모드(주소만 10분) + 블록 4(추적 데모) + 무산 태깅 |

## 6. KPI·DoD·DO NOT

**KPI**: 브로커당 월 발송 1건+(90일 목표) · 발송→미팅 전환 · 미팅→수임 전환 · 전속 비중 · 강화IM 위임 수락률 · 콜드 Pitch 생성 시간 10분 이내

**Definition of Done**
- [ ] 콜드 모드: 주소 입력→발송 가능까지 10분 이내 (E2E 타이머)
- [ ] 가격 의견 전 건에 감정평가 부인 문구 + 범위 표시 (스냅샷 테스트)
- [ ] 비교사례마다 선정 근거 표기 누락 0
- [ ] Pitch 수치 전수 NLG 마스크 경유
- [ ] 수임 성사→deals 연결(mandate_type·consent_mode·리포트 구독) 자동화

**DO NOT**
```yaml
- "콜드 모드에서 가격 의견(범위 포함) 제시 (정보 부족 상태의 가격 = 신뢰 훼손)"
- "'감정가'·'평가액'·'매각 보장' 표현 (P0)"
- "타 딜 식별 가능 정보의 사례 인용"
- "집합 지식 N<5 구간 인용"
- "법정 보수 요율 미표시 수임 조건 블록"
- "Pitch 전용 별도 비교사례 엔진 신설 (comparable 공유 강제)"
```

---

> **요지**: Pitch는 IM 데이터의 90%를 재활용하는 "역방향 IM"이자, 크리딜 퍼널의 **입구를 여는 문서**다. 콜드 모드(주소만 10분)가 소싱 병목을 뚫고, 웜 모드가 전속+강화IM 위임을 확보하며, 열람 추적이 매도인을 리드로 바꾼다. 수임이 늘면 매물이 늘고, 매물이 늘면 유통망이 산다 — Pitch는 기능이 아니라 공급 엔진이다.
