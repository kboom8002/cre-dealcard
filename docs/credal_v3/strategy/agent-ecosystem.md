# 🤖 CREDEAL 3막 구조 — 개인 AI 도구 → 브로커 에이전트 → 에이전트 생태계 허브

> **버전**: v1.0 (2026.07.23) · 개념 설계 문서 (비전·아키텍처·로드맵)
> **정합**: DEV_SPEC v2.0 · 3대 효과 극대화 방안 · 확장 로드맵 ('Deal OS' 서사의 완결편)
> **한 줄 요약**: 크리딜의 종착은 SaaS가 아니라 — **모든 브로커가 자기 이름을 단 AI 에이전트를 고용하고, 그 에이전트들이 표준 온톨로지로 대화하며 딜을 교환하는 시장 인프라**다. 지금까지 설계한 모든 부품(온톨로지·사다리·가드레일·암묵지)이 이 구조의 전제조건이었다.

---

## 1. 3막 구조 총괄

```
1막: 개인 AI 업무 도구 (현재~1년차)
     브로커가 조작한다 — 메모·문서 생성·추적·매칭
     축적: 온톨로지 데이터 + 암묵지 라벨 + 반응 함수
              │
              ▼  (자율성은 데이터로 '획득'된다)
2막: 브로커 AI 에이전트 (2~3년차)
     브로커를 대신해 일한다 — 감시·초안·응대·제안, 승인은 인간
     축적: 정책 학습 (무엇을 언제 어떻게 하면 성사되는가)
              │
              ▼  (에이전트가 늘면 에이전트끼리 만난다)
3막: 에이전트 생태계 허브 (3~5년차)
     에이전트들이 거래한다 — A2A 블라인드 딜 교환·서드파티 에이전트 입점
     크리딜 = 프로토콜·레지스트리·평판·정산의 소유자
```

**핵심 논리**: 각 막은 이전 막의 데이터 없이 불가능하다. 1막의 암묵지·반응 함수가 없으면 2막 에이전트는 환각 행동을 하고, 2막의 에이전트 밀도가 없으면 3막 허브는 빈 장터다. **자율성과 생태계는 선언하는 것이 아니라 축적으로 획득하는 것** — 이것이 경쟁사가 "에이전트"를 선언해도 따라올 수 없는 이유다.

## 2. 2막 — 브로커 AI 에이전트 설계

### 2.1 에이전트의 정의 (포지셔닝 불변식)

> **"브로커의 이름을 달고 일하는 무급 직원"** — 대체가 아니라 증강. 에이전트의 모든 대외 행동은 브로커 명의·브로커 승인·브로커 책임 하에 있다. 플랫폼이 브로커를 우회하는 순간 신뢰 해자가 죽는다 (리드 소유권 원칙의 에이전트 판).

### 2.2 아키텍처 — 이미 존재하는 부품의 재조립

| 에이전트 구성요소 | 정의 | 크리딜 기구현 부품 |
|-------------------|------|---------------------|
| **인식 (Perception)** | 세계의 변화를 감지 | 58종+ activity_events · 열람 추적 · 공공데이터 변동(등기·대장) · 티저 반응 |
| **세계 모델 (World Model)** | 시장·자산의 구조적 이해 | **온톨로지 v0.x** — 자산 슬롯·아키타입·제약. 에이전트가 환각 없이 추론하는 기반 |
| **기억 (Memory)** | 브로커의 이력·선호·고객 | Deal/Asset SSoT · 고객 타임라인 · tacit_labels(개인 암묵지 = 에이전트 개인화의 원료) |
| **정책 (Policy)** | 무엇을 할지 판단 | 아키타입 규칙 + 반응 함수 + 임계값 자동 튜닝(F4) + 브로커별 규칙 토글 |
| **행동 (Action)** | 실행 수단 | 문서 생성(티저·IM·Pitch) · 발송 · 스마트톡 응대 · 매칭 제안 · 일정 |
| **안전 (Safety)** | 해서는 안 되는 것 | 4중 가드레일 · NLG 마스크 · 재식별 게이트 · DO NOT 목록 — **에이전트 행동 공간의 울타리가 이미 완비됨** |
| **승인 (HITL)** | 인간 확정 지점 | "제안 + 브로커 1탭 확정" 패턴 — 기존 원칙이 곧 에이전트 UX |

### 2.3 서브에이전트 5종 (업무별 분업)

| 서브에이전트 | 하는 일 | 자율성 진입 조건 |
|--------------|---------|------------------|
| **소싱 에이전트** | 등기 변동·보유기간·공실 신호 감시 → 매물화 가능 물건 발굴 → 콜드 Pitch 초안 대기 | 공공데이터 파이프라인 + Pitch 콜드 모드 |
| **마케팅 에이전트** | 티저·IM 발행 최적 타이밍/대상 제안 → 반응 감시 → 후속 액션(Basic 발송 대상 추천) | 반응 함수 표본 축적 (K2 시뮬레이터) |
| **응대 에이전트** | 스마트톡 1차 응대·야간 커버·예약 접수 (기존 lite의 승격) | 검증 슬롯 인용 원칙 유지 |
| **딜 매니저 에이전트** | 파이프라인 감시 — 정체 딜 경고·만료 알림·태깅 요청·다음 액션 제안 | 파이프라인 데이터 |
| **네트워크 에이전트** | 크로스 매칭 후보 상시 탐색 → 상대 브로커 에이전트와 사전 조건 교환(3막 예비) | S5 개방 + 평판 데이터 |

### 2.4 단계적 자율성 (Graduated Autonomy) — 핵심 설계 원칙

| 레벨 | 정의 | 예시 | 승격 조건 |
|------|------|------|-----------|
| L0 | 도구 — 인간이 시작 | 현재 전부 | — |
| L1 | 알림 — 감지·보고 | "이 물건 등기 변동 — 매물화 신호" | 기본 |
| L2 | 초안 — 준비해두고 대기 | "콜드 Pitch 준비 완료 [검토]" | 해당 업무 제안 수락률 50%+ |
| L3 | 제안 실행 — 1탭 확정 | "반응자 4인에게 Basic 발송할까요? [승인]" | 수락률 70%+ |
| L4 | 사전 승인 실행 — 사후 보고 | 야간 응대·예약 접수·정기 리포트 발송 | 브로커 명시 위임 + 오류율 임계 이하 |
| L5 | 위임 교섭 — 조건 범위 내 자율 | "78~81억 범위 내 일정 조율은 맡김" (3막) | 법률 검토 + 건별 위임장 |

- **승격은 업무별·브로커별 개별** — 수락률·오류율 데이터가 자율성을 부여한다. 일괄 "에이전트 모드 ON"은 금지 (신뢰 파괴의 지름길)
- **법적 원칙**: 중개행위의 법적 책임 주체는 항상 브로커(인간) — 에이전트는 준비·조율까지, 의사표시의 확정은 인간. L5도 위임 범위 내 사무 보조로 설계

### 2.5 에이전트의 개인화 — 암묵지의 완성형

- 같은 크리딜 에이전트라도 **브로커 A와 B의 에이전트는 다르게 행동한다**: A의 태깅·토글·편집·성사 이력이 A 에이전트의 정책 — "내 방식을 아는 조수"
- 이것이 L2 수집 체계(암묵지 레이어)의 최종 용도이자, 브로커 이탈 방지의 궁극(에이전트를 데려갈 수 없다 — 데이터가 곧 에이전트)

## 3. 3막 — 에이전트 생태계 허브/포털

### 3.1 개념

브로커 에이전트가 임계 밀도에 도달하면, 딜 교환의 주체가 인간에서 에이전트로 확장된다:

```
[브로커 A 에이전트]  ←── A2A 프로토콜 (온톨로지 = 공용어) ──→  [브로커 B 에이전트]
   "STABLE_INCOME · 성수 · 80억대       "내 매수 의향과 87% 정합.
    옵트인 딜 보유. 조건 교환할까?"        Gate 1단계 요청 + 평판 제시"
                    │
                    ▼ (양측 브로커 1탭 승인 후 인간 협상으로 이관)
              [크리딜 허브]
   레지스트리 · 프로토콜 검증 · 평판 원장 · 감사 로그 · 정산
```

### 3.2 허브의 4대 기능

| 기능 | 내용 | 크리딜 기반 |
|------|------|-------------|
| **레지스트리** | 에이전트 신원·소속 브로커·권한 범위·자격 검증 | 브로커 프로필·자격 정보 |
| **프로토콜** | A2A 딜 교환 표준 — 메시지 스키마는 **온톨로지 공개 슬롯**(티저 규격과 동일), 단계 공개는 Gate 체계 | 온톨로지 = 언어, 사다리 = 절차 |
| **평판 원장** | 에이전트/브로커의 응답·성사·이행 이력 — A2A 신뢰의 기반 | S5 평판 + Buyer Passport(K3) 확장 |
| **감사·정산** | 모든 A2A 교섭의 감사 로그(분쟁 대비) + 성사 정산 연동 | activity_events + 법률 구조(사업계획 7.3) |

### 3.3 서드파티 에이전트 입점 (포털화)

허브가 열리면 브로커 에이전트만이 아니라 **딜 주변의 모든 역할이 에이전트로 입점**한다:

- **전문가 에이전트**: 세무사 사무소의 "양도세 시뮬레이션 에이전트" — 딜룸 초대 시 자동 기고 초안, 전문가 검토·서명 (S6의 에이전트화)
- **금융 에이전트**: 제휴 금융기관의 대출 사전심사 에이전트 — IM-Pro의 대출 시뮬레이션이 실제 심사 조건 조회로 (무산 1위 사유의 구조적 해결)
- **매수자측 에이전트**: 자산가·법인의 매수 조건 에이전트 — 조건 등록·신규 딜 알림·1차 질의. 단, **반드시 매도측 브로커 에이전트를 경유** (탈중개화 금지)
- **감정평가·법무 에이전트**: 실사 데이터룸 단계의 자동 검토 보조
- 표준 인터페이스: 업계 표준(MCP/A2A 계열) 채택으로 외부 개발 생태계 개방 — **온톨로지 스키마가 곧 개발자 문서**

### 3.4 허브의 사업 모델 진화

| 막 | 모델 | 성격 |
|----|------|------|
| 1막 | 브로커 SaaS 구독 | 좌석당 |
| 2막 | 에이전트 구독 (자율성 레벨·처리량 기반 요금) | 좌석이 아닌 **일의 양** 과금 — "무급 직원의 급여" |
| 3막 | 허브 수수료 (A2A 성사 정산·서드파티 입점료·프로토콜 라이선스) | 인프라 지대 — 참여자가 늘수록 한계비용 0 |

### 3.5 왜 크리딜만 이 허브를 만들 수 있는가

1. **언어**: A2A 교환은 표준 온톨로지 없이 불가 — 크리딜이 이미 보유·선점 중
2. **신뢰 절차**: 블라인드→단계 공개→동의 체인은 에이전트 교섭의 안전 프로토콜 그 자체
3. **정책 데이터**: 에이전트의 판단력은 암묵지·반응 함수·성사 데이터에서 나옴 — 후발주자는 빈 에이전트
4. **브로커 편 포지션**: 매수자측 에이전트조차 브로커 경유로 설계 — 업계가 허브를 적이 아닌 인프라로 수용할 유일한 구도

## 4. 리스크와 원칙

| 리스크 | 원칙 |
|--------|------|
| 에이전트 워싱 (설익은 자율 행동 → 신뢰 파괴) | 자율성은 선언이 아니라 **수락률·오류율로 획득** — 업무별·브로커별 개별 승격 |
| 브로커 대체 공포 → 채택 거부 | "브로커의 이름을 단 직원" 불변식 — 플랫폼 직접 행동 금지, 서사도 '증강'으로 통일 |
| 법적 (자동 응대·교섭의 중개행위성) | 의사표시 확정은 항상 인간 · L5는 위임 범위 명시 · 감사 로그 전수 보존 · 법률 검토 선행 |
| A2A 담합·조작 (에이전트 간 가격 신호 왜곡) | 허브 감사 로그 + 교섭 범위 제한 + 이상 패턴 탐지 — 거버넌스를 프로토콜에 내장 |
| 조기 착수로 코어 훼손 | 2막은 1막 KPI 달성 후, 3막은 에이전트 밀도(권역 브로커 50%+) 후 — 게이트 준수 |

## 5. 로드맵 (기존 계획과의 접합)

| 시기 | 마일스톤 | 기존 계획 접합점 |
|------|----------|------------------|
| 1년차 | L1 상시화 (알림·감시는 이미 에이전트의 눈) + 암묵지 수집 극대화 | M1~M5 그대로 — **1막이 곧 2막의 훈련 데이터 수집기** |
| 2년차 | 서브에이전트 3종 L2~L3 (소싱·마케팅·딜매니저) + 응대 L4(야간) | K2 시뮬레이터·F4 튜닝이 정책 엔진으로 승격 |
| 3년차 | 네트워크 에이전트 + A2A 파일럿 (신뢰 브로커 쌍) + 허브 레지스트리 v1 | S5 크로스 매칭의 에이전트화 |
| 4년차 | 서드파티 에이전트 입점 (전문가·금융) + 프로토콜 공개 | S6·딜 금융의 에이전트화 |
| 5년차 | 'Deal OS' 완성 — 멀티 도메인 허브 (확장 로드맵과 합류) | 온톨로지 마켓 = 에이전트 마켓 |

> **요지**: "크리딜은 브로커의 가장 중요한 개인 AI 업무 도구인가?" — 그렇다, 그리고 그것이 1막이다. 도구가 브로커의 방식을 배우면 에이전트가 되고(2막), 에이전트들이 표준 언어로 만나면 시장이 된다(3막). 이 3막을 관통하는 것은 하나 — **온톨로지는 언어, 사다리는 절차, 암묵지는 판단력, 브로커는 언제나 주인.** 미래적으로 보이지만 신규 발명은 없다. 지금 짓고 있는 것을 끝까지 짓는 것뿐이다.
