## Part 3. 추가 가치 문서 3종 (신설)

### V1. `TASKS.md` — 마스터 태스크 인덱스 `최우선`
- **문제**: 태스크 ID가 3개 네임스페이스(S·MG·MI)로 분산 — AI 에이전트가 "다음에 뭘 하지"를 3개 문서에서 조합해야 함 (문서 체계의 탐색 마찰)
- **내용**: 전 태스크 단일 표(ID·트랙·스테이지·의존·플래그·상태) + **교차 의존 그래프**(예: MI-3 → S3-T10 / MG-A4 → S3-T19) + 스테이지 게이트 체크리스트 + 이벤트·플래그 통합 대장(C7)
- **효과**: 착수 순서의 단일 소스 — "S0-T1부터"가 "TASKS.md 위에서부터"로 단순화. PR-태스크 추적 자동화 기반

### V2. `tests/e2e-scenarios.md` — E2E 시나리오 팩
- **원천 재활용**: pipeline-playbook 시나리오 A~D + UI/UX 시나리오 A~C를 **공식 E2E 테스트 시나리오로 승격** — "역삼동 85억 딜의 메모→종결 풀 파이프라인"이 최상위 통합 테스트가 됨
- 시나리오마다: 전제 데이터(픽스처)·단계별 기대 이벤트·탭 수 상한(무마찰 지표의 테스트화)·검증 포인트
- **효과**: 전략 문서와 테스트의 정합 — 시나리오가 바뀌면 테스트가 바뀐다

### V3. `examples/` — 예시의 골든셋 시드화
- 산출물 예시 4종·Pitch 샘플의 문장들을 **NLG 마스크 템플릿(S3-T1)과 골든셋의 초기 시드로 공식 지정** — GAP-3(템플릿 부족)의 부트스트랩을 이미 만든 자산으로 해결
- 시드 규약: 예시 문서의 각 마스크형 문장에 `<!-- mask-seed: capRate.b2c -->` 주석 태깅 → S3-T1 착수 시 추출 스크립트로 초기 세트 생성
- **효과**: 예시 문서가 "보여주기 자료"에서 "학습 자산"으로 — 추가 비용 0의 가치 전환

### V4. `ci/ci-checks.md` — CI 검증 스크립트 스펙
- 산재한 CI 요구(YAML↔코드 diff·provenance lint·라우트 스냅샷·플래그 등재·좌표 전송 차단 네트워크 테스트·N<5 가드)를 스크립트 단위로 명세 — 각 스크립트의 실패 메시지·수정 가이드 포함
- **효과**: DO NOT 목록(현재 3개 문서 35종+)의 상당수가 리뷰 의존에서 **기계 강제**로 이동

### V5 (경량). `CHANGELOG.md` + 버전 정책 1페이지
- 문서 개정 이력 단일화(v1.1→v1.2 등) — "어느 판이 최신인가" 질문 제거. 스키마는 semver, 문서는 날짜+버전
