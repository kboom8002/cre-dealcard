# 📄 크리딜 모바일 IM — 최적 개선 방향

> **버전**: v1.0 (2026.07) · 대상: 모바일 IM v4.0
> **위상**: 「제품 전략 및 고도화 방안」·「플랫폼 재구성 및 서비스 기획안」의 모바일 IM 실행 상세
> **한 줄 요약**: IM을 "빨리 만드는 문서"에서 **"신뢰할 수 있고, 스스로 리드를 만들어내는 딜 자산"**으로 격상시킨다.

## 1. 현재 상태 진단 (v4.0)

### 잘하고 있는 것 (유지)
- **5분 생성 + 카톡 네이티브 유통**: 7섹션 모바일 포맷, OG 정규화(1200×630), 1탭 공유 — 시장 유일의 구조
- **3중 가드레일**: Disclosure(블라인드) / Hallucination / Risk Boundary
- **열람 추적 연동**: IM이 발행 후에도 리드를 생산하는 자산으로 작동
- **골든셋 체계**: 제목 문체 20선 내장, 현장 언어 수집 루프 설계

### 핵심 문제 (개선 대상)
| # | 문제 | 근거 | 심각도 |
|---|------|------|--------|
| 1 | **재무 수치 신뢰성 균열** | NOI 공식이 문서 간 불일치(관리비를 비용/수입으로 상반 처리). 부족한 입력으로 10년 DCF·WACC·NPV까지 산출하는 과잉 정밀. Cap 1.7% 같은 이상값 무경고 노출 | 🔴 최상 |
| 2 | **고품질 IM의 입력 병목** | 층별 렌트롤(+15점)을 모바일 수동 타이핑에 의존 — A등급 도달의 실질 장벽 | 🔴 상 |
| 3 | **발행 UX 마찰** | 투자요약/OG 이중 저장, 카카오 캐시 수동 초기화(디버거 접속) 안내 | 🟠 상 |
| 4 | **단일 버전 IM** | 기관(법인·리츠)과 개인 자산가가 같은 문서를 받음 — 설득 언어가 다름 | 🟡 중 |
| 5 | **개발·신축 시나리오 약함** | 토지/개발부지 적합도 ⭐3. "이 매물을 사서 무엇을 할 수 있나"가 얇음 | 🟡 중 |
| 6 | **골든셋 수집이 양식 의존** | 브로커는 마크다운 양식을 제출하지 않음 — 수집 루프 미작동 위험 | 🟡 중 |

## 2. 개선 원칙

1. **검증 없는 수치는 고객 앞에 내보내지 않는다** — 모든 고객 대면 수치는 검증된 필드값 + 출처 + (필요시) 범위 표시
2. **입력은 사진·음성·공공데이터로 끝낸다** — 타이핑은 마지막 수단
3. **IM은 딜(Deal) 객체의 파생 문서다** — 같은 데이터에서 딜카드·수임 제안서·카톡 문구가 함께 나온다 (입력 1번, 산출 N번)
4. **브로커의 편집이 곧 학습 데이터다** — 쓰게 만드는 것이 최고의 데이터 수집

## 3. 영역별 개선 방향

### A. 재무 엔진 — 신뢰성 복원 `P0`

- **NOI 공식 단일화**: `NOI = 연간 임대수입(월세×12) − 운영경비(OPEX)` 하나로 확정하고, 관리비의 처리(임차인 부담분은 수입·소유주 부담분은 비용)를 명문화. 문서·코드·툴팁 전체 일치 검증
- **DCF/WACC/NPV는 조건부**: 데이터 품질 A등급에서만 옵션 표시. B등급 이하는 Cap Rate·자기자본 수익률·비교 실거래 중심 — 꼬마빌딩 매수자(개인 자산가)의 실제 의사결정 지표에 맞춤
- **범위 표시**: 추정이 섞인 수치는 점 추정 대신 범위로 (`Cap Rate 3.7~4.1%`), 산출 근거를 탭하면 계산식·입력값 표시
- **이상값 경고**: Cap Rate가 권역 평균 대비 ±α 이탈 시 발행 전 경고 ("Cap 1.7%는 강남 평균 3%대 대비 낮습니다 — 강조하지 않는 것을 권장")
- **정합성 검증 규칙 (SHACL식)**: `CapRate ≡ NOI÷매각가`, `용적률 ≤ 용도지역 상한`, `보증금+대출 vs 매각가` 관계 등 발행 전 자동 체크 — 위반 시 차단이 아닌 경고+수정 유도

### B. 데이터 충전 — 입력 병목 해소 `P1`

| 입력 경로 | 채워지는 것 | 구현 포인트 |
|-----------|------------|------------|
| **임대차계약서 촬영 OCR** | 렌트롤(층·업종·보증금·월세·기간) 자동 파싱 | A등급 병목의 근본 해소. 파싱 결과는 확인 화면에서 1탭 수정 |
| **등기부 촬영 OCR** | 소유·근저당(선순위 대출) | 대출 잔액 수기 입력 대체 |
| **음성 렌트롤** | "1층 카페 보증금 5천 월세 300…" → 구조화 | 기존 MemoParser 확장 |
| **공공데이터 자동 파생** | 용도지역·용적률 여유분·도로접면·공시지가 추이 | 주소 입력 즉시. 브로커에게 "자동 채움됨" 표시 |
| **규모검토 PDF 업로드** | 디스코·밸류맵 산출물 → "신축 시나리오" 섹션 변환 | 경쟁사 산출물을 재료로 소비 — 차별화 기능 |

- 데이터 보강 바텀시트는 **"남은 항목만"** 노출: 자동 채움된 필드는 접고, 미충족 필드와 등급 상승에 필요한 항목만 강조

### C. 생성 품질 — 통제된 생성 + 이중 버전 `P1~P2`

- **NLG 마스크 도입**: 핵심 수치 문장은 LLM 자유 생성 대신 `검증 필드값 + 통제 템플릿`으로 생성. LLM은 내러티브 연결·투자 가설에만 사용 → 환각·법적 리스크 구조적 축소
- **B2B/B2C 이중 IM**: 동일 데이터에서 두 버전 자동 생성
  - B2B(법인·리츠·패밀리오피스): Cap Rate·NOI·WALT·bp 비교, 격식 문체
  - B2C(개인 자산가): "보증금 빼고 실제 들어가는 돈", "지갑에 남는 알짜 순수익" — 직관 어휘
  - 발행 시 매수자 유형 선택 또는 두 링크 동시 생성
- **자산군별 특화 심화**:
  - 꼬마빌딩: 비교 실거래(반경·기간·유사도 명시) + 리모델링 밸류애드 시나리오
  - 물류센터: 기존 17개 특화 필드 + 도로접면·야드폭·마스터리스·수전용량 보강, NPL·S&LB 딜 유형 표현 지원
  - 개발부지: 명도 상태·점유자 리스크 등급, 토지거래허가, 기부채납, 규모검토 연계 사업수지 — ⭐3 → ⭐5로
- **골든셋 자동 수집 전환**: 양식 제출 대신 **브로커의 실제 편집 diff를 기본 수집 경로**로 (동의 기반). AI 초안 대비 편집률을 품질 KPI로 삼아 하향 추세 관리

### D. 발행 워크플로 — 마찰 제거 `P0`

- **저장 통합**: 투자 요약 + OG 메타 → 단일 "발행 준비" 화면, 저장 버튼 1개
- **OG 자동 동기화**: IM 제목·서브제목 수정 시 OG 타이틀·설명 기본값 자동 반영 (수동 편집 시에만 분리)
- **캐시 버스팅 서버 처리**: 공유 URL에 버전 파라미터 자동 부여 — 카카오 디버거 수동 초기화 안내 제거
- **발행 전 체크리스트 1화면**: 정합성 경고 · 블라인드 확인 · 품질 등급 · 법정 문구 포함 여부를 한 번에 확인 후 "🚀 발행"

### E. 뷰어·전환 — 문서에서 대화로 `P2`

- **IM 내 채팅 위젯 (스마트톡-lite)**: 고객이 보다가 그 자리에서 질문. 자동응답은 **검증 필드 인용 + 출처 표기만**, 새 재무 계산 금지, 모르면 "중개인 확인 후 답변" + 방문 예약 접수로 에스컬레이션
- **부재 모드**: 야간 문의 → 정보 안내 + 예약 접수 → 아침 요약 인계 (리드 이탈 방지)
- **CTA 위계 정리**: ① 채팅/질문 (가장 가벼움) → ② 프라이빗 IM 신청 → ③ Gate 상세 요청 (가장 무거움) — 문턱 낮은 순으로 배치해 전환 깔때기 형성
- **전문가 기고 뱃지 (3단계)**: 세무사·건축사·법무사의 실명 기고 모듈 삽입 시 "전문가 검증" 표시 — 'AI 문서'에서 '검증 문서'로 격상

### F. 파생 산출물 — IM 데이터의 재활용 `P1`

- **수임 제안서(Pitch) 원클릭**: IM 데이터 90% 재활용 + 마케팅 계획(딜카드·IM 샘플 + 열람 추적 데모) → 매도인용 "이렇게 팔겠습니다" 문서. **브로커 최대 병목(매물 확보)을 IM 기능이 직접 지원**
- **카톡 소개 문구·매거진 소재 자동 파생**: 기존 기능 유지하되 딜 워크스페이스 문서 탭으로 통합

## 4. 우선순위 로드맵

| 우선순위 | 항목 | 기대 효과 | 시점 |
|----------|------|-----------|------|
| **P0** | 재무 엔진 단일화·검증 규칙·이상값 경고 | 수치 사고 0건 — 신뢰의 전제 | 즉시 (~주 3) |
| **P0** | 발행 플로우 통합·OG 자동화·캐시 버스팅 | 발행 소요 50%↓, "5분 생성" 약속 실현 | 즉시 (~주 3) |
| **P1** | 계약서·등기부 OCR, 음성 렌트롤, 공공 파생 | A등급 IM 비율 50%+ | 주 4~10 |
| **P1** | 수임 제안서 파생 | 채택 유인 — 매물 확보 직접 지원 | 주 4~7 |
| **P1** | 규모검토 PDF → 신축 시나리오 변환 | 개발부지 적합도 격상 + 차별화 | 주 8~10 |
| **P2** | NLG 마스크, B2B/B2C 이중 IM | 환각·법적 리스크 축소 + 설득력 | 주 11~13 |
| **P2** | IM 내 채팅 위젯·부재 모드 | 야간 리드 이탈 방지 | 주 11~13 |
| **P2** | 골든셋 diff 자동 수집 | 품질 개선 루프 상시화 | 주 11~13 |
| **P3** | 전문가 기고 모듈 | IM 신뢰 격상 + 수익화 | 분기 3~4 |
| 보류 | TTS 음성 브리핑, Full IM 18섹션 | — | 코어 안정 후 |

## 6. 하지 말아야 할 것

- ❌ B등급 이하 데이터로 DCF·NPV 자동 표시 (과잉 정밀 = 신뢰 훼손)
- ❌ 고객 대면 자동응답에서 새로운 재무 수치 생성 (가정 금리 레버리지 계산 등)
- ❌ 규모검토·설계 엔진 자체 개발 (소비가 정답 — 공수 대비 효익 낮음)
- ❌ 렌트롤 수동 입력을 전제로 한 품질 등급 설계
- ❌ 발행된 공유 링크가 깨지는 어떤 변경 (카톡에 이미 뿌려진 링크 = 신뢰)

> **결론**: 모바일 IM의 다음 단계는 섹션을 늘리는 것이 아니라, **① 믿을 수 있게(P0) → ② 채우기 쉽게(P1) → ③ 더 잘 설득하고 대화하게(P2)** 만드는 것이다. 이 순서를 지키면 IM은 문서가 아니라 크리딜 유통망의 핵심 자산이 된다.
