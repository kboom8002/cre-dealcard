## 1. 전략 기반 (요약 — 상세는 전략 문서)

**비전**: 브로커 편에 서서, 딜 문서를 만들고, 말단에서 리드를 잡고, 표준 어휘로 네트워크를 연다.

**3대 원칙**: ① 리드는 광장이 아니라 말단에서(중앙 커뮤니티 배제, IM·딜카드가 리드 포획 접점) ② 철저히 브로커 편(비공개 데이터 격리 — B2C 트래픽 플랫폼이 취할 수 없는 포지션) ③ 검토 자료가 아니라 딜 문서(고객에게 보내지고 추적되는 설득 자산).

**3루프 구조**: 루프 1(매일 앵커: 메모·CRM — 리텐션) → 루프 2(딜 자산화: 딜카드→IM→추적 — 코어·수익화) → 루프 3(브로커 네트워크: Gate 크로스 매칭 — 해자).

**v2.0 추가 원칙 (4번째)**: **모든 상호작용은 암묵지를 낳는다** — 브로커의 행동(편집·채택·거절·무시·태깅)을 라벨된 지식으로 변환하는 수집 장치를 각 서비스에 내장한다. 이것이 시간이 갈수록 복제 불가능해지는 최종 해자다.

### 2.1 딜(Deal) 중심 객체 모델 (v1 계승 + 온톨로지 확정)

| 객체 | 정의 | v2.0 확정 사항 |
|------|------|----------------|
| **Deal** | 하나의 매각 건 — 모든 것의 허브 | 파이프라인 7단계(발굴→분석→제안→마케팅→협상→계약→종결) + `dealArchetype`(규칙 엔진 산출) + 무산 사유 태그 |
| **Asset** | 매물 자체 | **온톨로지 v0.1 스키마 적용**: 공통 17 + 자산군별(꼬마빌딩 16·물류 17·개발부지 11) + LeaseUnit 9 슬롯. 모든 필드에 4-tier provenance |
| **Document** | 딜 산출물 | 딜카드·IM(B2B/B2C 이중)·수임 제안서·카톡 문구 — 전부 Asset에서 파생, 버전 관리, NLG 마스크 렌더링 |
| **Party** | 딜 관계자 | 역할 enum에 `co_broker`·`professional` **처음부터 예약** (루프 3 스키마 무변경 확장) |
| **Activity** | 딜 이벤트 | 기존 58종 이벤트 + 🆕 태깅 이벤트(무산 사유·거절 사유·규칙 토글) → 딜 타임라인 |
| **Client** | 고객 | 의향 조건 + 행동 프로파일(열람·반응 함수) + 리드 스코어 + 접촉 타임라인 |

### 2.2 데이터 레이어 상세 (온톨로지 v0.1 적용)

- **표준 슬롯 ~70개**: 필드마다 타입·단위·출처 tier·등급 기여도 정의 (`credeal-ontology-v0.1.yaml`)
- **enum 14계열**: 용도지역 21종(시행령 건폐율·용적률 상한 내장, 조례 테이블 우선), 지목 28종, 도로접면 12분류(+가격 가중치), 명도 3속성(상태×조건×점유자), 물류 스펙(램프 4형·온도 4형) 등 — 전부 공적 분류 준용(P2P 상호운용의 전제)
- **차별 파생 필드**: `farHeadroomPp`(용적률 여유분 = 조례 상한−현재) — 밸류애드 판정 핵심, 조회 플랫폼 미제공, 자동 산출 가능
- **충전 파이프라인 5경로**: 공공 API 자동(~30슬롯, PNU 조인) → AI 파생(~10) → OCR(계약서·등기부, ~12) → 음성 메모 슬롯 매핑(~8) → 브로커 직접 입력(잔여 ~10, "자동 채움됨" 표시로 최소 노출). **약 60% 자동 충전**
- **제약 12종(C01~C12)**: 수치 정합(Cap Rate 일치·자본구조 역전) / 법규 정합(용적률·건폐율 상한, 맹지, 용도지역 기능성) / 상식 정합(날짜·범위·물류 sanity) / 정책(권역 이탈 경고, **DCF A등급 게이트**, 가정값 배지 의무). error만 발행 차단, 나머지는 경고+수정 유도
- **품질 등급 재정의**: 자산군별 필드 커버리지 기준(A: required+enhanced 90%+ → DCF 허용 / B / C / D) — 범용 7포인트 점수제 폐기

### 3.3 홈(오늘) 재구성 — v2.0 보강

3. 파이프라인 스냅샷 / 주간 성과 (v1 동일)

## 4. 서비스 상세 기획 (L3) — v2.0 고도화판

### S1. 메모·고객 CRM (루프 1 — 매일 앵커)

- **핵심 기능**: 음성/텍스트 메모→AI 분류→딜·고객·일정 1탭 전환(유지) / 🆕 **메모의 온톨로지 슬롯 매핑** — "1층 카페 보증금 5천 월세 300, 명도는 협의 중" → `rentRoll[0]`, `evictionStatus=IN_PROGRESS` 자동 충전 / 고객별 타임라인(문서·열람·채팅·통화·미팅 시간순) / 🆕 **'감' 필드** — 구조화 불가한 현장 감각("뒤가 어두워", "층고 애매")을 비정형 감성 슬롯으로 보존
- **암묵지 장치**: 메모 자체가 시장 감각의 원천 데이터. '감' 표현의 자산군별 사전화(골든셋 확장)
- **정책**: 고객 데이터 브로커 소유·격리(계약 명시), 플랫폼은 익명 집합 통계만

### S2. 딜 워크스페이스 (루프 2 — 코어)

**5탭 구성**: ① 개요(파이프라인 단계·핵심 지표·`dealArchetype` 뱃지·액션) ② 데이터(온톨로지 슬롯 편집 + 충전 현황 + 품질 등급 + 제약 경고) ③ 문서(딜카드·IM B2B/B2C·수임 제안서·카톡 문구 — 생성·버전·발행) ④ 관계자(매수 후보·공유 이력·[2단계] 공동중개·[3단계] 전문가) ⑤ 활동(열람·Gate·채팅·일정 타임라인)

**IM 생성 파이프라인 — 기술 감사 G1~G10 통합 스펙**:

| 단계 | v2.0 스펙 | 반영 |
|------|-----------|------|
| 입력 검증 | 상태 머신 첫 전이에 `constraint-validator`(C01~C12) 게이트 — 모순 데이터 사전 차단 | G4 |
| 아키타입 분류 | `archetype-classifier`(R01~R10) → investment_thesis 뼈대·골든셋 선택 축 | G5 |
| 생성 | 수치 문장은 **NLG 마스크 주입**(LLM 생성 금지), LLM은 내러티브 전담. B2B/B2C 렌더링 프로파일 | G2·G10 |
| RAG | **승인·발행본만 인덱싱**, provenance 태그 랭킹(golden>approved), 자기 제외 — 자기 오염 차단. 패싯 필터를 온톨로지 축(가격대·명도·도로접면)으로 확장 | G3·G1 |
| 재무 | 가정값(운영비율·리모델링 단가·WACC) 외부화·범위화·`ai_inferred` 배지. DCF·민감도는 A등급 게이트 | G7·G6 |
| 품질 | 4중 가드레일 유지 + 법정 문구 준수 체크 추가. cross-validator는 2차 안전망으로 격하 | — |
| 평가 | LLM-as-Judge + **브로커 편집거리 캘리브레이션** — diff는 골든셋 후보 자동 수집 | G8 |
| 재생성 | 필드→섹션 의존성 맵 기반 **부분 재생성** (매각가 수정 → ④⑥만) | G9 |

**발행 단일 플로우**: 편집→검증 경고 확인→발행 1버튼(투자요약+OG 통합 저장, OG 자동 동기화, 캐시 버스팅 서버 처리).

**수임 제안서**: Asset 데이터+비교 실거래+아키타입 근거+마케팅 계획(열람 추적 데모)을 묶은 매도인용 문서 — 브로커 최대 병목(매물 확보)을 직접 지원. 🆕 집합 지식 인용("이 권역 유사 매물 평균 성사 기간 X개월, 저는 추적 데이터로 단축합니다").

**암묵지 장치**: 편집 diff 자동 수집(동의 기반) / 호가 조정 이력 기록 / 딜 종결 시 제시가 vs 성사가 자동 대조(결과 회귀).

### S3. 유통·추적·인박스 (루프 2)

- 카톡/LINE 공유·열람 추적·리드 스코어링·Hot Lead 알림톡(유지) / 인박스 통합(Gate 승인·거절·전화 + 열람 피드 + 채팅 — 단일 처리 지점)
- **스마트톡-lite**: IM 뷰어 내 채팅 위젯. FAQ 자동응답은 **검증 슬롯 인용+출처 배지만**(NLG 마스크 재사용), 새 재무 계산 금지, 미응답 가능 질문은 에스컬레이션+예약 접수. 부재 모드=정보 안내+예약+아침 요약 인계. @계산 등 재무 생성은 브로커 코파일럿 전용(확인 후 전송). `chat_rooms.sender_type`에 `co_broker`·`professional` 예약 — 딜룸 토대
- **CTA 위계**: 채팅(가벼움)→프라이빗 IM 신청→Gate 상세 요청(무거움) — 전환 깔때기
- **암묵지 장치**: 열람 패턴(체류 섹션·재방문)×매수자 유형 = 반응 함수 데이터 / Hot Lead 무시 시 1탭 사유

### S4. 매칭 (루프 2→3 가교)

- **설명 가능 매칭**: 아키타입 규칙 공유 — 매칭 사유 표시("공실률 3% 미만 ∧ WALT 2.5년 이상 → 초안정 수익형 적합"), 명도 고위험(R09) 감점·경고, 브로커별 규칙 토글·임계값 조정
- **암묵지 장치**: 매칭 거절 시 1탭 사유(가격/입지/명도/시기) → 규칙 임계값 보정 데이터 / **규칙 토글·수정 이력 자체를 수집** — 현장 판단 기준의 크라우드 튜닝

### S5. 공동중개 네트워크 (루프 3 — 2단계 개방)

- 블라인드 딜카드 네트워크 공개 옵트인 → 크로스 매칭 알림(익명 요약) → Gate 단계적 공개(권역→상세→주소) → 수수료 배분 사전 합의 템플릿 → 평판 프로필(성사 이력·응답 속도)
- **온톨로지가 프로토콜**: 교환되는 딜카드는 표준 슬롯·enum으로 기술 — 브로커 A와 B가 같은 어휘로 매물을 말하는 것이 크로스 매칭의 전제
- **법률 구조 선결**: 수익화 전 공인중개사법 검토 확정(중개법인 자회사 / 성사 연동 구독 등급 / SW 이용료 구조 중 택일) — 사업계획서 7.3 준용
- **개방 순서**: 상호 신뢰 브로커 2~3쌍 수동 파일럿(90일 계획 내) → 관행 학습 → 시스템 개방

### S6. 전문가 딜룸 (루프 3 — 3단계)

- 딜 단위 전문가 초대(세무사·건축사·법무사, 역할 권한: 담당 섹션만), 실명·자격 표시 기고 모듈(양도세 시뮬레이션·가설계·권리분석)이 IM에 삽입 → 'AI 문서'에서 '전문가 검증 문서'로 격상 + 법적 방어 근본 보강
- 기고 필드는 온톨로지 `expert_verified` tier로 저장 — 데이터 신뢰도 자체가 상승
- 수익화: 협력 벤더 디렉토리 + 성사 정산 (마켓플레이스)

### 5.2 설계 원칙

1. **묻지 말고 관찰** — 행동이 곧 라벨. 1탭 질문은 정보 가치 최대 순간(무산·거절·무시)에만, 옵션 4개 이하
2. **환류가 인센티브** — 익명 집합 통계를 홈 브리핑·수임 제안서로 반환: "기록할수록 내가 강해진다"의 체감
3. **격리와 집합의 분리** — 개인 데이터 격리(계약), 집합·익명 통계만 상품화. 위반은 신뢰 해자의 자살
4. **아웃컴 스키마 준비** — 온톨로지 v1.0에 성사가·무산사유·사이클 필드 추가 → **성사 가능가 모델**(기관 대상 데이터 상품)의 학습 데이터

## 6. 신뢰·컴플라이언스 레이어

- **네트워크 수익 법률 구조**: P2P 수익화 전 확정(§4 S5) — 자금 계획에 법률 비용 반영

- ❌ 아고라형 중앙 커뮤니티 (이중 콜드스타트·리드 소유권 갈등 — 필요시 최후순위 블라인드 공개 피드로 대체)

- ❌ 고객 대면 자동응답의 신규 재무 계산 (가정 금리 레버리지 등)

## 11. 결론

v2.0의 본질은 세 문장이다.

1. **아래에는 개념을**: 온톨로지 v0.1이 파이프라인 전체(생성·검증·검색·매칭·네트워크)가 공유하는 공용어가 된다 — 텍스트를 잘 다루는 시스템에서 딜을 이해하는 시스템으로.
2. **위에는 딜을**: 흩어진 24개 화면이 '딜'이라는 업무 단위로 재조립된다 — 부품은 대부분 존재하므로 재구성은 연결과 정리의 프로젝트다.
3. **사이에는 암묵지를**: 모든 상호작용이 라벨된 지식으로 축적되고 집합 지식으로 환류된다 — 브로커가 늘수록 데이터가, 데이터가 늘수록 제품이, 제품이 좋아질수록 브로커가 느는 복리 구조. 시간이 크리딜 편이 되는 설계다.

실행은 M1(신뢰·기반)부터다. 신뢰 없이는 채택이 없고, 채택 없이는 데이터가 없으며, 데이터 없이는 해자가 없다.
