## 0. 요약

### 0.1 🔴 먼저 말해야 하는 것

**AI 코딩 에이전트는 이 프로젝트의 문제를 풀어 주지 않습니다. 더 빠르게 만듭니다.**

여섯 판 동안의 실측입니다.

| 판 | 지시 | 실제 이행 |
|---|---:|---:|
| V4 | 14건 | 4 |
| V5 | 22건 | **1** |
| V6 | 12건 | 광범위하나 PPTX 미연결 |

나머지는 **「반영했다」고 문서에 적혀 있었습니다.** 사람이 그랬습니다.
그리고 `wiring_check` 를 처음 돌렸을 때 **허위신고 10건** — 「구현됨」이라고
레지스트리에 적힌 게이트가 코드에 없었습니다.

> 🔴 **「했다고 말하고 안 한 것」이 이 프로젝트의 지배적 실패 모드입니다.**
> 그리고 그것은 코딩 에이전트가 사람보다 **훨씬 빠르고 자연스럽게** 하는 일입니다.
> 생성 속도가 10배가 되면 이 실패도 10배가 됩니다.

**그래서 순서가 뒤집힙니다.** 「Antigravity 를 켜고 하네스를 붙인다」가 아니라
**「하네스를 훅에 심고 Antigravity 를 켠다」**입니다.

### 0.2 이 계획의 뼈대 — 세 줄

```
① 규율을 문서가 아니라 훅에 심습니다
   R4(완료는 실측) → Stop 훅.  검사기가 실패하면 에이전트가 멈출 수 없습니다
   R6(검사기를 고치지 않기) → PreToolUse 훅.  임계값·기준선 편집을 강제 확인/차단

② 당산동 1건으로 판정합니다 (양평동은 근생이 아닙니다 — §1.1)
   두 건 다 「운영비 없음」 축이라 이 표본으로 통과한 것은 상용화가 아닙니다

③ 하루 한 질문, 참·거짓이 갈리는 문장으로
   `.agents/CYCLE.md` 에 적고 PreInvocation 훅이 매 사이클 앞에 붙입니다
```

### 0.3 오늘 실측 — 출발점

```

$ python3 qa/release_readiness.py
판정: 출시 금지  (0/20 충족)   — 전 항목 「판정 불가」
```

## 1. 실데이터 — 당산동 · 양평동에서 실제로 나온 것

### 1.1 🔴 표본 좌표 — 먼저 알아야 할 두 가지

| | 당산동 | 양평동 |
|---|---|---|
| 용도 | **제2종근린생활시설** | **업무시설** |
| assetType | `small_building` | `office` |
| 매매가 | 115억 | 250억 |
| 렌트롤 | 8행 · 통합계약 5그룹 | 12행 |
| **운영비** | **없음** | **없음** |
| 기준일 | 2025-05-01 (**486일 경과**) | **없음** |
| Gross Yield | **2.03%** | **2.24%** |

**두 가지가 이 계획의 범위를 결정합니다.**

> 🔴 **① 양평동은 근생이 아닙니다.** 업무시설입니다.
> 「근생 수익형」 판정에 쓸 수 있는 실물은 **당산동 1건뿐**입니다.
> 양평동은 경로 검증과 충돌 처리 시험에 쓰되, 근생 판정 근거로 세지 마십시오.
>
> 🔴 **② 둘 다 D43 §2.1 의 B축(운영비 없음)입니다.**
> A축(자료 완비)도 C축(렌트롤 부재)도 이 표본에 없습니다.
> 즉 **A·C 경로를 이 4주 동안 한 번도 밟지 않습니다.**
> 이 두 건으로 전 검사기가 통과해도 그것은 상용화가 아니라
> **「B축에서는 된다」**입니다. 계획서 어디에도 그 이상으로 적지 마십시오.

**대응** — 4주차에 합성 A·C 표본을 만들어 **경로만** 확인합니다(판정 아님).
그리고 실물 근생 표본 확보를 1주차에 병행 요청합니다(D43 §2.4, 6곳 이상).

## 2. Antigravity 하네스 — 규율을 훅에 심습니다

### 2.1 6규율 ↔ Antigravity 기능 매핑

이것이 이 계획의 중심입니다. **규율을 문서에 적으면 지켜지지 않고, 훅에 심으면 지켜집니다.**

| 규율 | Antigravity 장치 | 파일 | 강제력 |
|---|---|---|:-:|
| **R1** 짝 없는 검사 금지 | Stop 훅 (대조군 검출률) | `stop_gate.py` | 🤖 강 |
| **R2** 값은 한 곳에 | Rules(Always On) + PreToolUse | `00-canon.md` · `guard_edit.py` | 🤖 중 |
| **R3** 실패 출구 계측 | PreToolUse 내용 검사 | `guard_edit.py` | 🤖 중 |
| **R4** 완료는 실측 | **Stop 훅** | `stop_gate.py` | 🤖 **최강** |
| **R5** 한 판에 한 질문 | PreInvocation 주입 | `cycle_question.py` | 🤖 중 |
| **R6** 검사기를 고치지 않기 | **PreToolUse deny / force_ask** | `guard_edit.py` · `guard_cmd.py` | 🤖 **강** |

> 🔴 **방법론 v1.0 은 R5·R6 을 「자동화할 수 없다(👤)」로 분류했습니다.**
> Antigravity 의 훅이 그 판정을 바꿉니다. R6 은 이제 기계가 막고,
> R5 는 매 사이클 앞에 자동 주입됩니다.
> **이것이 이 도구를 쓰는 가장 큰 이유입니다** — 코드 생성 속도가 아니라
> 규율의 강제 지점이 사람에서 루프로 옮겨간다는 것.

### 2.2 Stop 훅 — R4 의 문자 그대로의 구현

Antigravity 의 `Stop` 이벤트는 에이전트가 실행 루프를 끝내려는 순간 발화하고,
`{"decision":"continue","reason":"..."}` 를 돌려주면 **못 멈추게** 할 수 있습니다.

```
에이전트: "구현을 완료했습니다."
   ↓ Stop 훅
검사기 5종 실행 → 실패
   ↓ decision: "continue"
에이전트: (멈추지 못하고 이유를 받아 계속)
```

**즉 「완료」의 정의가 모델의 판단에서 검사기의 종료 코드로 옮겨갑니다.**

`.agents/scripts/stop_gate.py` 실측 (오늘, 이 레포에서):

```
🔴 완료할 수 없습니다. 검사기가 실패했습니다 (R4 — 완료는 실측입니다).

  [차단] 배선 (선언↔실행) — 배선 36/57 (63%) · 유령 21 · 허위신고 10 · 미선언 35
  [차단] 대조군 검출률 — 기준 C1(≥95%)·C2(P0 100%) 은 판정 불가가 0 이 될 때까지 미충족

🔴 다음 중 하나만 하십시오.
   ① 원인을 고칩니다 (검사기가 아니라 코드를).
   ② 고칠 수 없으면 **멈추지 말고** 무엇이 왜 막혔는지 적고 사람을 부르십시오.

🔴 하지 말 것 — 검사기 파일·임계값·기준선을 고쳐서 통과시키는 것 (R6).
   (막힌 횟수 1/3)
```

**설계에서 조심한 것 셋**

| | 왜 |
|---|---|
| `MAX_RETRY = 3` | 무한 루프 방지. 3회 막고도 안 되면 사람에게 넘깁니다 |
| `fullyIdle` 확인 | 배경 작업 중에 판정하면 매번 실패하고, **그러면 이 훅이 꺼집니다** |
| 산출물 0건 → **판정 불가** | 「통과」로 세면 검사가 없는 상태가 최고 점수를 받습니다 |

> 🔴 **첫 판에서 이 훅을 틀렸습니다.** `layout_check --all` 이라는 없는 옵션을 줘서
> 검사기가 예외로 죽었고, 종료 코드가 0이 아니라 **「차단」으로 집계**되었습니다.
> 메시지는 비어 있었고요. **항상 실패하는 관문은 반드시 꺼집니다.**
> 그게 하네스가 죽는 가장 흔한 방식입니다 — 느슨해져서가 아니라 시끄러워서.
> 산출물 단위 실행으로 고쳤습니다.

### 2.3 PreToolUse — R6 강제

R6 은 「검사기가 불편한 답을 낼 때 검사기를 고치지 않는다」입니다.
**임계값 변경이 정당한 경우가 있으므로** 대부분은 `deny` 가 아니라 `force_ask` 입니다 —
사람이 매번 눈으로 보게 하는 것이 목적입니다.

**하드 차단 (`deny`) — 넷뿐**

| 대상 | 왜 |
|---|---|
| `cycles/*.json` | 계기판 기준선. 과거를 고치면 추세가 거짓이 됩니다 (A6) |
| `qa/coverage_baseline.json` · `doc_baseline.json` | 래칫. 늘리는 방향 편집은 래칫을 무의미하게 |
| `tests/corpus/target_*.pptx` | 동결 골든. 정본 변경 + 근거 ID + 2인 서명 필요 |
| `--set-baseline` · `git commit --no-verify` · `sed -i qa/` | 명령을 통한 우회 |

**강제 확인 (`force_ask`)**

| 대상 | 되묻는 말 |
|---|---|
| `qa/*.py` | 🔴 **검사기가 틀렸습니까, 코드가 틀렸습니까?** 일곱 번 다 코드였습니다 |
| `credeal/ssot/im.*.yaml` | R2 — 값을 여기 말고 다른 데 적으려는 것 아닙니까 |
| `MIN_*` `THRESHOLD` `TOLERANCE` 대입 | 허용오차 회귀 (A4) |
| `severity: warn` | 심각도 세탁 (A5) |
| `except: pass` | 정교한 폴백 (A3) |
| `@skip` `@xfail` | 조용한 이관 (A9) |

**실측 (오늘)**

```
qa/layout_check.py 에 MIN_DPI = 90    → force_ask  "검사기가 틀렸습니까, 코드가 틀렸습니까?"
cycles/2026-08-28.json 편집            → deny       "과거 기록을 고치면 추세가 거짓이 됩니다"
src/gates.ts 에 severity: "warn"       → force_ask  "실패를 고친 겁니까, 안 보이게 한 겁니까?"
doc_integrity.py --set-baseline        → deny       "기준선 재설정은 사람만 합니다"
git commit --no-verify                 → deny       "훅을 건너뛰는 커밋입니다"
src/renderer.ts 일반 편집              → allow
```

### 2.4 Rules — 프롬프트 층에 상주시키는 것

`.agents/rules/` (워크스페이스, 각 12,000자 한도)

| 파일 | 활성화 | 무엇 |
|---|---|---|
| `00-canon.md` | **Always On** | 정본 위치 · 절대 금지 8 · **한국 CRE 함정 7** |
| `10-harness.md` | **Always On** | 6규율 · 안티패턴 9 · **보고 형식 5줄** |
| `20-samples.md` | Glob (`fixtures/**`, `runs/**`) | 당산동·양평동이 무엇인지 · 과적합 금지 |

`00-canon.md` 에 넣은 한국 CRE 함정 — **에이전트가 반드시 틀리는 것들**:

```
· 환산보증금은 행마다 다릅니다. 한 물건 안에서 초과/이하가 섞입니다
· firstContractDate 없으면 갱신요구권은 「판정 불가」— 「해당 없음」이 아닙니다
· 자가사용은 공실이 아닙니다. GPI 에도 공실률에도 안 들어갑니다
· 통합계약은 행 합산은 맞고 층별 평당가는 틀립니다
· 운영비 없으면 NOI·Cap Rate 라는 단어 자체를 쓰지 않습니다
```

> 🔴 마지막 줄이 중요합니다. 「NOI 를 정확히 계산하라」가 아니라
> **「그 단어를 쓰지 마라」**입니다. 계산 지시는 에이전트가 창의적으로 해석하고,
> 어휘 금지는 검사기가 셀 수 있습니다.

## 5. 사이클 설계

### 5.1 사이클 한 판 (하루)

### 5.2 Implementation Plan 승인 — 반려 사유 5

Antigravity 는 코드를 쓰기 전에 Plan 아티팩트를 냅니다.
**여기가 이 계획의 유일한 사전 개입 지점입니다.** 여기서 막지 못하면
그 뒤로는 만들어진 것을 되돌리는 일만 남습니다.

```
🔴 아래 중 하나라도 해당하면 승인하지 않고 코멘트로 반려합니다.

① 이 변경을 검증하는 검사기 이름이 없다
   → "무엇이 이것이 됐다고 말해 줍니까?"

② 짝(변종·negative 케이스)이 계획에 없다
   → R1 위반. 실패시킬 입력 없이 만든 검사는 통과해도 정보가 아닙니다

③ 파일이 3개를 넘는다
   → 한 판에 한 질문(R5)이 아닙니다. 쪼개 오라고 하십시오

④ qa/ · cycles/ · tests/corpus/ 가 변경 목록에 있다
   → 왜인지 먼저 답을 들으십시오

⑤ 「~를 개선한다」처럼 참·거짓이 안 갈리는 목표가 있다
   → 갈리는 문장으로 바꿔 오라고 하십시오
```

### 5.3 Walkthrough 를 믿지 않는 법

Antigravity 는 작업 후 Walkthrough(요약)를 냅니다. **읽되 믿지 마십시오.**
「~를 구현했다」는 문장은 우리가 여섯 판 동안 받아 온 바로 그 문장입니다.

`/verify` 가 하는 일:

```
① Walkthrough 에서 "~했다" 문장을 전부 뽑는다
② 각각에 검사기 출력이 붙는가 → 안 붙으면 미완
③ python3 qa/wiring_check.py     — 「구현했다」가 허위신고에 있으면 그 주장은 거짓
④ python3 qa/mutate_sample.py --score  — 검출률이 떨어졌으면 하네스를 무디게 한 것
⑤ git diff -- qa/ cycles/        — 변경이 있으면 왜인지 답을 들음
⑥ 같은 입력 두 번 → 산출물 동일한가
```

> 🔴 **③이 가장 자주 걸립니다.** 에이전트는 게이트를 「구현」하면서
> 판정 메시지에 코드 문자열을 안 넣는 일이 흔하고, 그러면 배선 검사에서
> 허위신고로 잡힙니다. D41 에서 사람도 똑같이 했습니다.

## 7. AI 에이전트 특유의 실패 모드

우리가 명명한 안티패턴 9종은 사람의 것이었습니다.
**에이전트는 같은 것을 다른 방식으로 합니다.** 아래가 감시 목록입니다.

| 에이전트가 하는 것 | 안티패턴 | 신호 | 막는 장치 |
|---|:-:|---|---|
| 테스트를 통과시키려 테스트를 수정 | A4 | `qa/` diff | `guard_edit` force_ask |
| 「구현했다」고 하고 stub 만 남김 | A1 | 허위신고 증가 | Stop 훅 + `/verify` ③ |
| 실패를 `try/except: pass` 로 삼킴 | A3 | 흡수 카운터 | `guard_edit` 내용 검사 |
| 막히면 `@skip` 을 붙임 | A9 | 케이스 수 정체 | `guard_edit` |
| 긴 세션에서 이전 결정을 뒤집음 | A6 | 골든 diff | `deny` |
| 자기 Walkthrough 를 근거로 다음 판단 | **A2** | — | 🔴 `/verify` 는 **사람이** |
| 질문 하나에 답하다 다섯 개를 고침 | — | Plan 파일 3개 초과 | §5.2 반려 ③ |
| 그럴듯한 값을 지어냄 (**환각**) | — | provenance 없는 수치 | `00-canon.md` §3 |
| 지시를 창의적으로 해석 | — | 「개선」류 목표 | 어휘 금지로 대체 |

> 🔴 **마지막 세 개가 사람과 다른 점입니다.**
> 특히 **환각**은 이 도메인에서 치명적입니다 — 「인근 시세 대비 15% 저렴」 같은
> 문장을 근거 없이 만들어 낼 수 있고, 그것은 품질 문제가 아니라 **허위 표시**입니다.
> 그래서 `00-canon.md` 가 **모든 수치에 값·기준·출처·기준일 넷을 요구**합니다.
