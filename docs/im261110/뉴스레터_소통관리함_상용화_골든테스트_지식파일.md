- **데스크톱 3-Column 표준 레이아웃 (`>= 1280px`)**:

### 1.2 뉴스레터 스튜디오 (`📰 뉴스레터`) 아키텍처
| 구분 | 경로 / 식별자 | 역할 및 핵심 동작 |
|:---|:---|:---|
| **편집실 메인 라우트** | `/broker/magazine-editor` | 3단계(`① 제목` → `② 내용` → `③ 보내기`) 뉴스레터 작성·매물 큐레이션·발행·발송 워크스페이스 |
| **레거시 리다이렉트** | `/broker/w/magazine` | 쿼리스트링 보존하여 `/broker/magazine-editor`로 즉시 리다이렉트 (`data-testid="magazine-workspace-redirect"`) |
| **수신자 공개 뷰어** | `/magazine/[brokerSlug]/[issueDate]`<br>`/magazine`, `/m/[slug]` | 고객이 카톡·문자로 받은 링크를 열었을 때 렌더링되는 공개 매거진/뉴스레터 뷰어 |
| **초안/목록 조회 API** | `GET /api/magazine/editions?broker_id=me&type=all` | 로그인 중개사의 에디션 목록(`editions`), `brokerSlug`, `brokerName`, `subscriberCount`, `highInterestCount` 반환 |
| **내 매물 목록 API** | `GET /api/broker/buildings` | 뉴스레터에 담을 수 있는 중개사 본인 보유 매물 목록 반환 (`DealSlotAssigner` 연동) |
| **통합 발행·저장 API** | `POST /api/magazine/issues` | Zod 검증(`IssueBodySchema`) → `magazine_editions` 업데이트(`status: "published"`) → `magazine_issues` 공개 테이블 Upsert → `publicUrl` 반환 |
| **구독자 발송 연동 API** | `POST /api/broker/inbox/actions` (`action: "send_magazine"`) | 발행된 뉴스레터 URL을 소통 관리함 발송 이력 및 공유 액션과 연동 |
| **로컬 초안 스토리지** | `localStorage["cre-newsletter-local-draft-v2"]` | 미발행 로컬 초안 자동 보존 (`localStorageMode: "local_only"`, `saveState: "dirty"`) |

#### 📌 뉴스레터 핵심 불변 규칙 (`NL-01 ~ NL-13`)
1. **NL-01 (실제 매물 수만 표시)**: 에디션 목록의 `dealCount`는 `featured_deal_ids.length` 실측값만 표시하며, 임의의 기본값(예: 3건 고정)으로 부풀리지 않는다.
2. **NL-02 (가짜 샘플 사진 폴백 금지)**: 매물에 실제 업로드된 사진이 없으면 `photoUrl: null`을 유지하며, Unsplash 등 외부 샘플 빌딩 사진을 넣지 않는다.
3. **NL-03 / NL-04 (정직한 발행·복사·카톡 공유 피드백)**:
   - 표지 제목(`headline`) 미입력 시 발송/공유를 차단하고 `① 제목` 탭으로 이동시키며 안내 배너(`"표지 제목을 입력하면 바로 보낼 수 있어요"`)를 띄운다.
   - `POST /api/magazine/issues`가 실제 `200 OK`를 반환하고 `copyText()`가 `true`일 때만 `"링크를 복사했어요"` / `"카카오톡 공유 창을 열었어요"` 성공 배너를 표시한다.
4. **NL-05 (로컬 임시저장 vs 서버 발행 엄격 구분)**: 브라우저 `localStorage`에만 저장된 상태는 `"이 기기에만 임시 저장됨"`(`local_only` / `dirty`)으로 표시하고, 서버 DB(`magazine_editions` + `magazine_issues`)에 반영된 후에만 `"저장됨 ✓"`(`saved`) 및 발행 URL을 노출한다.
5. **NL-06 (블라인드 주소 정제)**: 뉴스레터에 실린 매물 주소는 `sanitizeDealAddress()`를 거쳐 상세 지번 노출을 통제한다.

| 구분 | 경로 / 식별자 | 역할 및 핵심 동작 |
|:---|:---|:---|
| **소통함 메인 라우트** | `/broker/w/inbox` | 고객 열람 요청 승인/거절, 전용 링크 발급/잠금(Revoke), 수치 정정 공지, 통화 기록, 신규 고객 등록 통합 CRM 워크스페이스 |
| **통합 스레드 조회 API** | `GET /api/broker/inbox?workspace=1` | `requireBroker` 인증 필수. 본인 소유 빌딩(`building_ssot_lite`), 열람 요청(`gate_requests`), 등록 고객(`broker_clients` / `customClients`), 빠른 IM(`quickImRecords`) 통합 반환 |
| **소통함 통합 액션 API** | `POST /api/broker/inbox/actions` | `requireBroker` + `verifyBrokerOwnership` 검증 후 7대 액션 수행 (아래 표 참조) |
| **고객 딜카드 접점** | `/d/[token]`, `/dc/[buildingId]` | 매수고객(테스터 B)이 블라인드 딜카드에서 이름·연락처·소속·메시지를 적어 IM 상세 열람을 신청하는 진입점 |
| **고객 IM Lite 뷰어** | `/im-lite/[buildingId]?token=[shareToken]` | 승인된 전용 토큰으로 고객이 열람하는 모바일 IM 화면 (링크 잠금 시 즉시 차단, 정정 공지 시 상단 배너 노출) |
| **로컬 캐시 스토리지** | `localStorage["credeal-w-inbox-v4"]` | 레거시 가짜 시드 키(`v2`, `v3`)는 마운트 즉시 삭제하며 서버 응답과 병합 |

#### 📌 소통 관리함 7대 서버 액션 (`POST /api/broker/inbox/actions`)
| 액션 코드 (`action`) | 파라미터 | 서버 처리 및 상태 전이 (`status` / `gateStatus`) |
|:---|:---|:---|
| **`approve_gate`** / **`send_im`** | `threadId`, `buildingId`, `ttlDays(기본 30)` | `issueShareLinkToken()`으로 전용 토큰 발급 → `gate_requests.status = 'approved'` → `activity_events` 기록 → `shareUrl` (`/im-lite/[id]?token=...`) 반환 및 클립보드 자동 복사 |
| **`reject_gate`** | `threadId`, `buildingId` | `gate_requests.status = 'rejected'` 업데이트 → 스레드 `gateStatus: "rejected"` 전환 |
| **`send_dealcard`** | `threadId`, `buildingId` | `/dc/[buildingId]` 공유 URL 반환 및 카톡/클립보드 전달 |
| **`send_magazine`** | `threadId`, `buildingId`, `slug`, `publicUrl` | 발행된 뉴스레터 공유 URL 반환 및 발송 이력 기록 |
| **`revoke_link`** / **`restore_link`** | `threadId`, `buildingId`, `shareToken`, `reason` | `revokeShareLinkToken()` / `restoreShareLinkToken()` 호출 + `document_objects.body.is_revoked` 갱신 → 스레드 `status: "revoked"` ↔ `"active"` 전환 |
| **`correction_notice`** / **`clear_correction_notice`** | `buildingId`, `message` | `setBuildingCorrectionNotice()` + `document_objects.body.correction_notice` 저장/삭제 → 수신자 IM 상단에 정정 공지 배너 즉시 표시/해제 |
| **`add_call_note`** / **`log_call`** | `threadId`, `buildingId`, `note` | `"통화 기록: ..."` 형식으로 `broker_custom_clients.notes` 및 `activity_events`(`call_note_recorded`)에 영속 저장 |
| **`upsert_client`** | `clientName`, `clientPhone`, `clientGrade`, `budget`, `preferredRegion`, `buildingId`, `newsletterSubscribed` | `broker_clients` 테이블 Insert + `customClients` 등록 (`010-0000-0000` 같은 가짜 전화번호 생성 절대 금지) |

#### 📌 소통 관리함 핵심 불변 규칙 (`IB-01 ~ IB-26`)
1. **IB-01 / IB-02 / IB-03 (멀티테넌트 소유권 격리)**:
   - 미인증 요청은 `?workspace=1` 여부를 불문하고 `401 Unauthorized`로 차단한다.
   - 타 중개사(예: 테스터 B의 중개사 계정 #2)가 테스터 A의 `buildingId`나 `threadId`로 `approve_gate`, `revoke_link`, `add_call_note` 등을 호출하면 `verifyBrokerOwnership()`이 `403 Forbidden`으로 즉시 차단한다.
2. **IB-05 / IB-16 (네이티브 `window.prompt` / `alert` 사용 금지)**:
   - 링크 잠금(`revoke_link`) 시 브라우저 기본 `prompt()` 창 대신 인라인 확인 카드(`confirmLockOpen`)를 띄워 UX 흐름을 끊지 않는다.
3. **IB-09 (익명 리드 JSON 문자열 원문 노출 금지)**:
   - `gate_requests.reason`에 저장된 `{"name":"박매수","phone":"010-9999-8888","company":"케이리츠","message":"투심위 검토용"}` 또는 `[신청자: ... / 연락처: ...]` 문자열은 서버·클라이언트 양측 `parseGateRequestReason()`에서 정제되어 고객명·연락처·소속·메시지 필드로 깔끔하게 분리 표시된다.
4. **IB-20 (가짜 고객 시드 0건 & 가짜 번호 금지)**:
   - 데이터가 없을 때는 가짜 더미 고객을 만들지 않고 빈 상태 안내를 표시하며, 전화번호 미입력 고객에게 `010-0000-0000`을 채워 넣지 않는다.

## 3. 인간 테스터(A·B) + AI 합동 E2E 골든테스트 4-Wave 시나리오

### 🌊 Wave 1. 뉴스레터 스튜디오 제작 · 3대 매물 큐레이션 · 발행 · 수신 뷰어 검증 (`NL-G01 ~ NL-G08`)
- **수행 주체**: 테스터 A (작성·발행) → 테스터 B (수신 열람) + AI (API·렌더링 검증)
- **상세 절차**:
  1. **[NL-G01] 빈 제목 발송 방어 (Poka-Yoke)**: 테스터 A가 `/broker/magazine-editor` 진입 후 제목을 비운 채 `[구독자에게 보내기]` 또는 `[링크 복사]` 클릭 → `① 제목` 단계로 자동 포커스 이동 및 에러 배너 노출 확인.
  2. **[NL-G02] 표지 메타 & 로컬 임시저장(`local_only`)**: `2026년 11월호` 선택, 표지 제목 `"2026년 11월 프라임·알짜 빌딩 투자 브리핑 (동교·부천·역삼 특집)"`, 한 줄 요약 입력 → 상단 저장 배지가 `"이 기기에만 임시 저장됨"`으로 표시되고 `F5` 새로고침 후에도 입력값이 유지되는지 확인.
  3. **[NL-G03] 시장 브리핑 서식 막대 & AI 코멘트**: `② 내용` 단계에서 브리핑 본문 작성, 서식 도구(`소제목`, `강조`, `구분선`) 적용 및 `[AI 코멘트 추천]` 버튼 동작 확인.
  4. **[NL-G04] 매물 3건 큐레이션 & 코멘트 부여**: 보유 매물 목록에서 **동교동 THE.PARK(77억)**, **부천 동아빌딩(58억)**, **역삼동 여삼빌딩(2,000억)** 3건을 체크 선택하고 매물별 한 줄 추천 포인트를 입력 → 우측 실시간 미리보기(Column 3)에 3건이 정확한 가격(`77억`, `58억`, `2,000억`)과 블라인드 주소로 렌더링되는지 확인 (가짜 샘플 사진 0건).
  5. **[NL-G05] 타깃 세그먼트 선택 & 서버 발행(`POST /api/magazine/issues`)**: `③ 보내기` 단계에서 발송 대상(`전체 고객` / `매수 관심 고객`) 선택 후 **`[구독자에게 보내기]`** (또는 `[링크 복사]`) 클릭 → 저장 상태가 `"저장됨 ✓"`으로 바뀌고 공개 URL(`/magazine/[brokerSlug]/[issueDate]?edition=...`)이 클립보드에 복사되는지 확인.
  6. **[NL-G06] 수신자(테스터 B) 공개 뉴스레터 열람**: 테스터 B가 시크릿 창(비로그인)에서 전달받은 뉴스레터 공개 URL 접속 → 중개사 프로필, 시장 브리핑, 추천 매물 3건 카드가 깨짐 없이 렌더링되는지 확인.
  7. **[NL-G07] 뉴스레터 → 딜카드/IM 전환 퍼널**: 테스터 B가 뉴스레터 내 매물 카드를 클릭했을 때 해당 매물의 딜카드/상세 요청 페이지로 끊김 없이 이동하는지 확인.
  8. **[NL-G08] 에디션 목록 실측 카운트**: 테스터 A가 좌측 `① 고르기` 목록을 봤을 때 방금 발행한 호수의 매물 수가 실제 선택한 `3건`으로 정확히 표시되는지 확인(`NL-01`).

### 🌊 Wave 2. 딜카드 열람 요청 → 소통 관리함 입고 · 정제 · 승인 · 전용 토큰 발급 E2E (`IB-G01 ~ IB-G08`)
- **수행 주체**: 테스터 B (열람 신청) → 테스터 A (인박스 승인·발송) → 테스터 B (전용 토큰 열람)
- **상세 절차**:
  1. **[IB-G01] 매수고객(테스터 B) 열람 요청 접수**: 테스터 B가 시크릿 창에서 매물 #1(동교동) 및 매물 #3(역삼동) 블라인드 딜카드 링크에 접속해 신청자 정보(`이름: 박매수 상무`, `연락처: 010-8888-7777`, `소속: 케이리츠자산운용`, `메시지: 투심위 상정용 렌트롤 및 상세 IM 요청드립니다`)를 입력하고 열람 신청 제출.
  2. **[IB-G02] 소통함 실시간 입고 & JSON 정제(`IB-09`)**: 테스터 A가 `/broker/w/inbox` 접속 시 `할 일(todo)` 필터에 박매수 상무의 요청 스레드가 상단에 뜨고, `{"name":...}` 같은 날것의 JSON 문자열이 절대 노출되지 않고 이름·연락처(`010-8888-7777`)·소속·메시지가 깔끔하게 분리 표시되는지 확인.
  3. **[IB-G03] 1클릭 승인 및 전용 토큰 링크 발급(`approve_gate`)**: 테스터 A가 가운데 컬럼(`할 일` 탭)에서 **`[승인하고 IM 보내기]`** 클릭 → `POST /api/broker/inbox/actions` (`action: "approve_gate"`)가 호출되어 `shareToken`이 포함된 전용 URL(`/im-lite/[id]?token=...`)이 발급·자동 복사되고, 스레드 상태가 `승인 대기` → `열람 가능(approved)`으로 즉시 바뀌는지 확인.
  4. **[IB-G04] 승인 이벤트 타임라인 기록**: 가운데 컬럼 `소통 기록(history)` 탭에 `"IM 열람 요청을 승인하고 전용 링크를 발급했습니다."` 이벤트가 타임라인 최상단에 추가되는지 확인.
  5. **[IB-G05] 수신자(테스터 B) 전용 토큰 IM 열람**: 테스터 B가 전달받은 전용 링크(`/im-lite/[id]?token=...`)를 시크릿 창에서 열었을 때 블라인드가 해제된 상세 IM(주소, 층별 임대 현황, 수익률, 사진)이 정상 표시되는지 확인.
  6. **[IB-G06] 열람 카운트(`openCount`) 및 고관심(`high_interest`) 전환**: 테스터 B가 전용 링크를 3회 이상 열람했을 때 테스터 A의 소통함에서 열람 횟수(`openCount`)가 증가하고 고관심 리드로 식별되는지 확인.
  7. **[IB-G07] 열람 요청 거절(`reject_gate`) 흐름**: 테스트용 보조 요청 건에 대해 테스터 A가 `[거절]` 클릭 시 상태가 `rejected`로 전환되고 토스트 피드백이 뜨는지 확인.
  8. **[IB-G08] 카톡/클립보드 맞춤 메시지 발송(`message` 탭)**: 테스터 A가 `메시지 보내기` 탭에서 헤드라인·안내 문구를 수정하고 `IM 전용 링크` / `딜카드 링크` / `뉴스레터 링크` 공유 버튼을 눌렀을 때 수정한 문구와 함께 복사/공유되는지 확인.

### 🌊 Wave 3. 소통 관리함 CRM 심화 — 신규 고객 등록 · 통화 메모 · 수치 정정 공지 · 링크 잠금(Revoke)/복구 (`IB-G09 ~ IB-G16`)
- **수행 주체**: 테스터 A (조작) ↔ 테스터 B (수신 화면 즉시 반영 확인)
- **상세 절차**:
  1. **[IB-G09] 신규 VIP 고객 수동 등록 모달(`upsert_client`, `IB-26`)**: 테스터 A가 좌측 상단 **`[+ 새 고객 등록]`** 클릭 → 모달에서 `Escape` 키 닫기 동작 확인 후 다시 열어 `이름: 최대표`, `연락처: 010-5555-4444`, `등급: VIP`, `예산: 60억`, `선호권역: 부천·수도권 역세권`, `관심매물: 부천 동아빌딩` 입력 후 저장 → 스레드 목록에 즉시 추가되고 `F5` 새로고침 후에도 서버(`broker_clients` / `customClients`)에서 유지되는지 확인 (연락처 비입력 테스트 시 `010-0000-0000` 가짜 번호가 생성되지 않는지도 확인).
  2. **[IB-G10] 통화 메모 기록 및 영속성(`add_call_note`)**: 테스터 A가 `최대표` 또는 `박매수 상무` 스레드의 `소통 기록(history)` 탭에서 `"통화 완료: 다음 주 화요일 오후 2시 현장 실사 확정, 주차타워 수익 내역서 지참 요망"` 입력 후 저장 → 타임라인에 즉시 반영되고 `F5` 새로고침 후에도 메모가 날아가지 않는지 확인.
  3. **[IB-G11] 매물 수치 정정 공지 발송(`correction_notice`)**: 매물 #1(동교동)의 매매가가 77억→72억으로 인하된 후, 테스터 A가 소통함에서 **`[수치 정정 안내 띄우기]`** 실행 → 안내 문구(`"매도인 희망 매매가가 77억 원에서 72억 원(Cap 3.12%)으로 전격 인하 조정되었습니다."`) 저장.
  4. **[IB-G12] 수신자(테스터 B) 화면 정정 공지 배너 실시간 노출**: 테스터 B가 기존에 받은 매물 #1 IM 링크를 새로고침했을 때 상단에 정정 공지 배너가 명확히 표시되고, 테스터 A가 `[정정 안내 내리기]`(`clear_correction_notice`)를 누르면 배너가 사라지는지 확인.
  5. **[IB-G13] 인라인 확인 UI 기반 링크 즉시 잠금(`revoke_link`, `IB-16`)**: 테스터 A가 매물 #3(역삼동) 스레드에서 **`[공유 링크 잠그기]`** 클릭 → 브라우저 `window.prompt`가 아닌 **인라인 확인 박스(`confirmLockOpen`)**가 열리는지 확인 후 잠금 확정 → 스레드 상태가 `열람 제한됨(revoked)`으로 즉시 변경되는지 확인.
  6. **[IB-G14] 잠긴 링크 수신자 열람 완벽 차단(Kill-Switch)**: 테스터 B가 방금 잠긴 매물 #3 전용 링크(`/im-lite/[id]?token=...`)를 새로고침하거나 재접속했을 때 **매물 데이터가 0바이트도 노출되지 않고 `"열람 권한이 회수(만료)된 링크입니다"` 차단 화면**이 뜨는지 확인.
  7. **[IB-G15] 공유 링크 잠금 해제(`restore_link`) 및 재열람 복구**: 테스터 A가 소통함에서 **`[링크 잠금 해제]`** 클릭 → 테스터 B가 다시 새로고침했을 때 정상적으로 IM 열람이 복구되는지 확인.
  8. **[IB-G16] 검색 및 필터(`할 일` / `열람 현황` / `전체 고객`) 정합성**: 고객명(`박매수`, `최대표`), 매물명(`동교동`, `부천`), 권역(`강남`) 검색 시 즉시 필터링되고 탭 전환 시 건수 배지가 일치하는지 확인.

### 🌊 Wave 4. 멀티테넌트 보안 격리(RLS 401/403) & 모바일(375px) 완결성 검증 (`SEC-G01 ~ SEC-G06`)
- **수행 주체**: 테스터 B (타 중개사 계정 #2 & 비로그인 시크릿 창 & 모바일 뷰) + AI 에이전트
- **상세 절차**:
  1. **[SEC-G01] 비로그인 API/라우트 완벽 차단(`401`)**: 비로그인 시크릿 창에서 `/broker/magazine-editor`, `/broker/w/inbox` 접속 시 `/login`으로 즉시 리다이렉트되며, `GET /api/broker/inbox?workspace=1`, `POST /api/broker/inbox/actions`, `POST /api/magazine/issues` 호출 시 모두 `401 Unauthorized` 반환 확인.
  2. **[SEC-G02] 타 중개사 계정(#2) 소통함 데이터 격리(`IB-02`)**: 테스터 B가 **중개사 계정 #2**로 로그인해 `/broker/w/inbox` 접속 시 테스터 A(중개사 #1)의 고객(`박매수`, `최대표`) 및 매물 열람 요청이 **단 1건도 보이지 않는지** 확인.
  3. **[SEC-G03] 타 중개사 계정(#2) 액션 위변조 공격 차단(`403 Forbidden`)**: 중개사 계정 #2 세션에서 테스터 A의 `buildingId` / `threadId`를 지정하여 `POST /api/broker/inbox/actions` (`approve_gate`, `revoke_link`, `add_call_note`) 호출 시 서버 `verifyBrokerOwnership`이 **`403 Forbidden`**으로 차단하는지 확인.
  4. **[SEC-G04] 타 중개사 계정(#2) 뉴스레터 수정 공격 차단(`403/404`)**: 중개사 계정 #2 세션에서 테스터 A의 `editionId`로 `POST /api/magazine/issues` 덮어쓰기 시도 시 `assertOwnsRow`에 의해 차단되는지 확인.
  5. **[SEC-G05] 모바일 375px 뉴스레터 편집실 & 공개 뷰어 반응형**: `375×812` 뷰포트에서 `/broker/magazine-editor` 및 공개 뉴스레터 뷰어(`/magazine/...`)의 가로 스크롤(`scrollWidth <= clientWidth`)이 0px이고 하단 액션 바와 터치 타깃(`>= 44px`)이 정상 동작하는지 확인.
  6. **[SEC-G06] 모바일 375px 소통 관리함 리스트↔상세 푸시 내비게이션**: `375×812` 뷰포트에서 `/broker/w/inbox` 접속 시 고객 리스트가 먼저 보이고(`mobileStayOnList`), 스레드 탭 시 상세 화면으로 전환되며 `[← 목록으로]` 버튼으로 복귀할 수 있는지 확인.
