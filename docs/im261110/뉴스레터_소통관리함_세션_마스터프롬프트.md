```markdown
### 1. 수행할 4단계 마스터 워크플로우 (순차 실행)

#### ▶ Phase 1: AI 사전 리허설(Dry-Run) & Poka-Yoke 선제 결함 제거
인간 테스터가 투입되기 전에 AI가 먼저 코드와 API/UI를 정밀 점검하여 막힘 포인트를 0건으로 만든다.
1. **뉴스레터(`NL-G01 ~ NL-G08`) 점검**:
   - 빈 제목 발송 방어(`NL-03`), 로컬 초안(`cre-newsletter-local-draft-v2`) vs 서버 발행(`POST /api/magazine/issues`) 상태 배지 구분(`NL-05`), 보유 매물 3건(동교동 77억·부천 58억·역삼동 2,000억) 큐레이션 시 가짜 샘플 사진 미노출(`NL-02`) 및 실측 `dealCount` 표시(`NL-01`), 발행된 공개 URL(`/magazine/[brokerSlug]/[issueDate]?edition=...`)의 비로그인 시크릿 창 렌더링 무결성을 검증하라.
2. **소통 관리함(`IB-G01 ~ IB-G16`) 점검**:
   - 딜카드 열람 신청(`gate_requests`) 시 익명 리드 JSON 문자열이 날것으로 노출되지 않고 `parseGateRequestReason()`으로 정제되는지(`IB-09`) 확인하라.
   - 7대 핵심 액션(`approve_gate`, `reject_gate`, `send_dealcard`, `send_magazine`, `revoke_link`/`restore_link`, `correction_notice`/`clear_correction_notice`, `add_call_note`, `upsert_client`)의 API 응답·클립보드 복사·타임라인 이벤트 반영·`F5` 새로고침 영속성을 검증하라.
   - 링크 잠금(`revoke_link`) 시 `window.prompt` 없이 인라인 확인 UI(`confirmLockOpen`, `IB-16`)가 작동하고, 잠긴 전용 토큰 링크(`/im-lite/[id]?token=...`) 접속 시 매물 데이터가 100% 차단되는지 확인하라.
   - 신규 고객 등록(`upsert_client`) 시 가짜 전화번호(`010-0000-0000`)나 가짜 시드 데이터가 생성되지 않는지(`IB-20`) 확인하라.
3. **보안 격리 & 모바일 반응형(`SEC-G01 ~ SEC-G06`) 점검**:
   - 비로그인 요청 `401` 차단, 타 중개사 계정(#2)의 스레드 조회/액션 위변조 시도 시 `403 Forbidden`(`verifyBrokerOwnership`, `assertOwnsRow`) 차단, 모바일 `375×812` 뷰포트에서 가로 스크롤 `0px` 및 리스트↔상세 푸시 내비게이션을 검증하라.
4. 발견된 UI/API/파서 마찰 포인트가 있다면 즉시 수정(Poka-Yoke)하라.

#### ▶ Phase 2: `credeal.net/testguide` 워크벤치 고도화 & 테스터 A·B 전용 실행 가이드 산출
인간 테스터 A(발신 공인중개사 #1)와 테스터 B(수신 매수고객 & 타 중개사 #2)가 클릭 복붙만으로 15~20분 내에 30개 항목(`NL-G01~08`, `IB-G01~16`, `SEC-G01~06`)을 완주할 수 있도록 준비하라:
1. **`/testguide` 워크벤치 확장**:
   - 뉴스레터 표지 제목·요약·시장 브리핑 샘플 원문·매물 3건 추천 코멘트 **1클릭 복사 버튼** 탑재
   - 소통 관리함 테스트용 신청자 정보(박매수 상무·케이리츠자산운용), 신규 VIP 고객 등록 정보(최대표·예산 60억), 통화 기록 샘플, 수치 정정 공지 문구 **1클릭 복사 버튼** 탑재
   - 30개 체크항목(`NL-G01~08`, `IB-G01~16`, `SEC-G01~06`) `PASS`/`FAIL` 실시간 채점 및 마크다운 결과서(`.md`) 다운로드 연동
2. **테스터 A / 테스터 B 전용 진행 가이드(`.md`) 작성**:
   - `docs/im261110/뉴스레터_소통함_테스터A_진행가이드.md` (중개사 #1용)
   - `docs/im261110/뉴스레터_소통함_테스터B_진행가이드.md` (매수고객 시크릿 창 & 타 중개사 #2용)

#### ▶ Phase 3: Playwright 자동화 드라이런 E2E 검증 & 프로덕션 배포 (`credeal.net`)
1. Playwright 스크립트로 `NL-G01~08`, `IB-G01~16`, `SEC-G01~06` 핵심 시나리오를 자동 실행하여 **100% PASS**를 확인하라.
2. `npx tsc --noEmit` 에러 0건을 확인하고 단일 줄 커밋 메시지로 `git push origin main` 배포(바이너리 파일 커밋 절대 금지)한 뒤, `https://credeal.net/testguide`, `/broker/magazine-editor`, `/broker/w/inbox` 라이브 응답을 검증하라.

#### ▶ Phase 4: 인간 테스터 결과 대조 준비 및 보고
- 수행 완료된 사전 리허설 결과표, 라이브 배포 주소, 테스터 A·B 가이드를 요약 보고하고 인간 테스터 결과 투입 대기 상태로 전환하라.
```

## 💡 새 세션 운영 팁 (참고사항)

1. **초기 실행 방식**:
   - 새 세션을 열고 위 마스터 프롬프트만 붙여넣으면, AI가 `docs/im261110/뉴스레터_소통관리함_상용화_골든테스트_지식파일.md`를 즉시 읽어들여 **이전 세션의 맥락 손실 0%**로 바로 Phase 1부터 착수합니다.
2. **단계별 끊어 가기 원할 때**:
   - 만약 한 번에 Phase 1~3까지 모두 돌리는 대신 단계별로 승인하며 진행하고 싶다면, 프롬프트 맨 마지막 줄에 **"우선 Phase 1(AI 사전 리허설 및 결함 점검)부터 수행하고 결과를 보고해줘."** 한 줄만 덧붙이시면 됩니다.
3. **인간 테스터 결과 취합 후**:
   - 인간 테스터 A·B가 `/testguide`에서 다운로드한 채점 결과 `.md` 파일을 새 세션 채팅창에 붙여넣어 주시면, AI가 즉시 AI 오라클 결과와 대조하여 최종 상용화 Sign-off 리포트를 완성합니다.
