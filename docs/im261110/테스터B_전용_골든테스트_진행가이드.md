## 1. Phase 1: 테스터 A가 매물 3건을 만드는 동안 할 일 (교차 검증 & 보안 사전 확인)

테스터 A가 매물 #1(동교동 77억) → 매물 #2(부천 58억) → 매물 #3(역삼동 2,000억)을 순서대로 생성하는 동안, 테스터 B는 아래 두 가지를 진행합니다.

### ▶ Step 1-1. 타 중개사 계정 #2에서 남의 매물 노출 여부 확인 (보안 사전 점검)
1. **창 ① (중개사 계정 #2 로그인 상태)**에서 IM 스튜디오(`https://credeal.net/broker/w/im`)와 딜카드(`https://credeal.net/broker/w/dealcards`) 목록을 새로고침(`F5`)합니다.
2. 테스터 A(중개사 계정 #1)가 방금 만든 **동교동 더파크빌딩, 부천 동아빌딩, 역삼동 여삼빌딩**이 **중개사 #2의 화면 목록에는 단 1건도 나타나지 않는지** 확인합니다. (내 매물만 보여야 정상입니다!)

### ▶ Step 1-2. 매물 #1·#2·#3 산출물(PPTX & 모바일 IM) 더블 체크

| 매물 | 테스터 B가 함께 확인해 줄 핵심 숫자 | 실패(`FAIL`)로 체크해야 하는 경우 |

## 2. Phase 2: Wave C 합동·보안 미션 6단계 (`/testguide` 탭 ④)

테스터 A가 매물 3건 생성을 마치면 `/testguide` 상단 탭에서 **`[🤝 4. Wave C 합동·보안 미션]`**을 클릭합니다. 여기서부터는 **테스터 B가 주인공**입니다!

### ▶ 미션 C-1. 블라인드 딜카드 열람 및 상세 지번 은닉 확인 (`시크릿 창`)
1. 테스터 A에게 전달받은 **블라인드 딜카드 공유 링크(`/d/...`)**를 **창 ② (비로그인 시크릿 창)** 주소창에 붙여넣어 엽니다.
2. **🔒 보안 검수 포인트 (가장 중요!)**:
   - 아직 열람 승인을 받기 전이므로, 화면에 **구체적인 지번 번지수(`189-6`, `176-1`, `648-23`)나 건물 실명이 노출되지 않고 블라인드(예: `마포구 동교동 역세권 리테일 빌딩` 등) 처리**되어 있는지 확인합니다!
   - 크롬 시크릿 창에서 `Ctrl + U`(페이지 소스 보기) 또는 `Ctrl + F`로 `189-6`을 검색했을 때도 번지수가 평문으로 새어 나오지 않는지 확인합니다.
3. 화면 하단의 **`[상세 정보 / IM 열람 요청하기]`** 버튼을 눌러 테스트용 이름(예: `김매수 대표`)과 연락처를 입력해 제출합니다.
4. 이상이 없으면 `/testguide` 탭 ④의 **`[C-1]` 카드에서 `[PASS]`**를 클릭합니다.

### ▶ 미션 C-2. 테스터 A의 1·2단계 승인 후 상세 주소·Pro IM 해금 확인 (`시크릿 창`)
1. 테스터 A에게 *"열람 요청 보냈으니 인박스(`④ 인박스`)에서 1단계·2단계 승인해 주세요!"*라고 요청합니다.
2. 테스터 A가 승인을 완료하면 **창 ② (시크릿 창)**에서 **`F5`(새로고침)**를 누르거나 승인된 링크를 엽니다.
3. **확인 포인트**:
   - 아까 가려져 있던 **정확한 지번 주소, 건물 실명, 층별 렌트롤 상세표, 모바일 IM(IM-Lite) 및 Pro IM(PPTX 다운로드)**이 정상적으로 열렸는지 확인합니다.
4. 정상 해금되었다면 `/testguide` 탭 ④의 **`[C-2]` 카드에서 `[PASS]`**를 클릭합니다.

### ▶ 미션 C-3. 주간 뉴스레터(매거진) 3건 묶음 수신 및 카드 클릭 확인 (`시크릿 창 / 스마트폰`)
1. 테스터 A가 `③ 뉴스레터` 워크스페이스에서 매물 3건을 담아 발행한 **뉴스레터 웹 링크(`/magazine/...`)**를 전달받습니다.
2. **창 ② (시크릿 창)** 및 **스마트폰**에서 해당 뉴스레터 링크를 엽니다.
3. **확인 포인트**:
   - 상단 **AI 마켓 브리핑 문구**와 오늘 등록한 **매물 3건(동교동 77억, 부천 58억, 역삼동 2,000억) 요약 카드 + 대표 사진**이 깨짐 없이 수려하게 나오는지 확인합니다.
   - 각 매물 카드를 클릭했을 때 해당 매물의 상세 화면으로 정상 연결되는지 확인합니다.
4. 정상 동작하면 `/testguide` 탭 ④의 **`[C-3]` 카드에서 `[PASS]`**를 클릭합니다.

### ▶ 미션 C-4. 타 중개사 계정(#2) 무단 접근 차단 검증 — RLS 보안 테스트 (`일반 창`)
1. 테스터 A에게 방금 테스터 A가 작업한 매물의 **내부 편집 URL**(예: 브라우저 주소창의 건물 ID나 `/broker/buildings/[id]/studio` 주소)을 알려달라고 합니다.
2. **창 ① (중개사 계정 #2로 로그인된 일반 창)** 주소창에 테스터 A의 매물 주소를 그대로 붙여넣고 `Enter`를 누릅니다.
3. **🔒 합격(`PASS`) 기준**:
   - 중개사 #2에게 테스터 A의 매물 데이터나 편집 화면이 **절대 열리면 안 됩니다!**

4. 확인 후 `/testguide` 탭 ④의 **`[C-4]` 카드에서 `[PASS]`**를 클릭합니다.

## 3. Phase 3: PPTX 10대 정밀 검수 & 채점표 제출 (`/testguide` 탭 ⑤)

1. `/testguide` 상단 탭에서 **`[📊 5. PPTX 검수 & 채점표 제출]`**을 클릭합니다.
2. 매물 #1·#2·#3의 PPTX 파일을 열어 **Slide 1(표지) ~ Slide 10(디스클레이머)**을 넘겨보면서 **PPTX 10대 정밀 검수표**의 10가지 항목을 체크합니다:
   - **1~3번 (숫자·면적·점유율 정확성)**: 공실 오판이나 `NaN` 없이 정확한가?
   - **4~5번 (시각 자료 — 사진 4장 & 공시지가·지적도)**: 첨부한 사진 4장(`JPG 2 + PNG 1 + WebP 1`)이 선명하게 들어갔고, 지적도 빨간 경계선과 개별공시지가가 정상 표기되었는가?
   - **6~8번 (디자인·용어 품격)**: 글씨 겹침, 한자 네모 깨짐(`□□□`), 금지 약어(`NOI`, `WALE` 단독 표기), 미완성 문구(`추후 입력 예정`)가 없는가?
   - **9~10번 (10장 구성 & 포스처 변경 반영)**: 정확히 10장(Slide 1~10)으로 구성되었고, Wave B에서 바꾼 투자 목적에 맞춰 본문 강조점이 달라졌는가?
3. 테스트 중 발견한 버그나 개선 의견이 있다면 하단 **발견된 결함(Bug) & UX 개선 요청 기록장**에 적어주세요.
4. 맨 아래 **`[📋 채점 결과 마크다운 전체 복사]`** 또는 **`[⬇️ 채점 결과 .md 파일 다운로드]`** 버튼을 눌러 결과를 저장해 전달해 주시면 테스터 B의 모든 미션이 완료됩니다!
