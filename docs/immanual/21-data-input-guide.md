# CreDeal 시스템 활용 가이드 — 제2부: 데이터 입력 실전 가이드

> **목적**: CreDeal 시스템에 **어떤 화면에서 무엇을 입력하는지** 단계별 안내
> **선행**: [제1부 — 데이터 준비](./20-data-preparation-guide.md) 완료

---

## 제1장. 딜카드 생성 → 자동 조회 흐름

### 1.1 딜카드 생성 단계

```
[STEP 1] 대시보드 → "새 딜카드" 클릭

[STEP 2] 기본 정보 입력
  ├─ 주소 입력 (지번 또는 도로명)
  │   → 입력 즉시 카카오맵 주소 검색 API 호출
  │   → 후보 목록에서 정확한 주소 선택
  │   → PNU(필지번호) 자동 확정
  │
  ├─ 자산 유형 선택
  │   └─ 오피스 / 근린생활시설 / 상가 / 집합건물 / 주거 / 물류 / 숙박 / 기타
  │
  └─ 투자 관점(포스처) 선택
      └─ 임대수익형 / 자가사용형 / 개발형 / 운영형 / 단기매매형

[STEP 3] "딜카드 생성" 클릭
  → 백그라운드에서 공공데이터 자동 조회 시작
```

### 1.2 주소 입력 시 자동으로 일어나는 일

```
주소 입력 → PNU 확정
    ↓
┌─ 건축물대장 API ──→ 대지면적, 연면적, 층수, 준공일, 구조, 엘리베이터
├─ 토지이용계획 API ──→ 용도지역, 건폐율, 용적률, 용도지구, 용도구역
├─ 공시지가 API ──→ ㎡당 공시지가, 평당 환산
├─ 지적도 WMS ──→ 지적도 이미지 (PPTX 부록용)
├─ 카카오맵 API ──→ 최근접 지하철역, 도보시간, 주변 POI
└─ 실거래가 API ──→ 주변 유사 건물 거래 내역
```

> 💡 이 자동 조회만으로 P축(물건 해상도) 슬롯의 상당 부분이 채워집니다.
> 주소를 정확하게 입력하는 것이 등급 향상의 첫걸음입니다.

### 1.3 주소 입력 주의사항

| 상황 | 올바른 입력 | 잘못된 입력 |
|------|-----------|-----------|
| 지번 주소 | "서울시 강남구 역삼동 123-45" | "역삼동 부근" |
| 도로명 주소 | "서울시 강남구 테헤란로 123" | "테헤란로 근처" |
| 건물명으로 검색 | "NH농협캐피탈빌딩" → 후보에서 선택 | "농협빌딩" (모호) |
| 미등기/신축 | 지번 주소 직접 입력 | 도로명 주소 (미등록 가능) |

## 제2장. 포스처 선택 의사결정 트리

아래 5가지 질문으로 포스처를 결정합니다:

```
Q1. 매수자가 이 건물을 직접 사용할 예정인가?
    ├─ YES → 🏠 자가사용형 (owner_occupied)
    └─ NO → Q2로

Q2. 기존 건물을 철거하고 신축할 예정인가?
    ├─ YES → 🏗️ 개발형 (development)
    └─ NO → Q3로

Q3. 호텔·요양원 등 직접 운영하여 매출을 올리는 시설인가?
    ├─ YES → 🏨 운영형 (operating)
    └─ NO → Q4로

Q4. 1~3년 내 매도하여 시세 차익을 얻을 목적인가?
    ├─ YES → 📈 단기매매형 (trading)
    └─ NO → Q5로

Q5. 임차인이 있고, 임대수익이 핵심인가?
    └─ YES → 🏢 임대수익형 (income) ← 기본값
```

> ⚠️ 포스처를 나중에 변경하면 IM을 처음부터 다시 생성해야 합니다.
> 처음에 정확하게 선택하는 것이 중요합니다.

## 제3장. 보강 정보 입력 — 공통 필드

딜카드가 생성된 후, "보강 정보" 탭에서 추가 데이터를 입력합니다.

### 3.1 매매가

| 필드명 | 입력 형식 | 예시 | 설명 |
|--------|----------|------|------|
| `asking_price_manwon` | 숫자 (만원) | 2500000 | 250억 원 = 2,500,000만원 |

> 💡 **만원 단위** 입력입니다. 250억 → 2500000 입력

### 3.2 사진 업로드

| 필드 | 형식 | 제한 |
|------|------|------|
| `photos_v2` | 이미지 파일 업로드 | 최대 12장 |

**촬영 권장 카테고리**:
1. 건물 외관 전면 (필수 — 표지 사진)
2. 건물 외관 측면
3. 로비 / 공용부
4. 엘리베이터 홀
5. 주차장 (입구, 내부)
6. 옥상 전경
7. 대표 층 내부 (가장 좋은 상태의 층)
8. 공실 층 내부 (있을 경우)
9. 주변 도로 / 전경
10. 1층 상가 외관
11. 기계실 / 전기실 (상태 확인)
12. 건물 명판 / 간판

### 3.3 브로커 코멘트

| 필드명 | 형식 | 예시 |
|--------|------|------|
| `broker_highlight` | 텍스트 (1~2문장) | "역삼역 도보 3분, 만실 빌딩. 앵커 NH농협캐피탈 장기 계약" |

> 이 코멘트는 IM 요약에 반영되며, AI가 투자 포인트 생성 시 참고합니다.

### 3.4 융자 정보

| 필드명 | 형식 | 예시 | 설명 |
|--------|------|------|------|
| `loan_amount_manwon` | 숫자 (만원) | 1200000 | 채권최고액 120억 원 |
| `loan_bank` | 텍스트 | "NH농협은행" | 융자 은행 |

## 제4장. Income 전용 입력

### 4.1 기본 임대 정보

| 필드명 | 형식 | 예시 | 설명 |
|--------|------|------|------|
| `monthly_rent_total_krw` | 숫자 (원) | 37600000 | 월세 총액 3,760만원 |
| `vacancy_status` | 텍스트 | "5층 전체 공실" | 공실 설명 |
| `vacancy_pct` | 숫자 (%) | 9.47 | 정확한 공실률 |
| `total_deposit_manwon` | 숫자 (만원) | 108000 | 보증금 합계 10.8억 |
| `mgmt_fee_total_manwon` | 숫자 (만원) | 860 | 관리비 월합계 |
| `opex_total_krw` | 숫자 (원) | 120000000 | 연간 운영비 1.2억 |
| `estimated_yield_pct` | 숫자 (%) | 4.5 | 예상 수익률 |

### 4.2 층별 렌트롤 입력 (floor_leases)

**등급 향상에 가장 큰 영향을 주는 핵심 입력**입니다.

각 층별로 아래 필드를 입력합니다:

| 필드 | 형식 | 필수 | 예시 | 설명 |
|------|------|------|------|------|
| `floor` | 텍스트 | ✅ | "1F", "B1", "3F~4F" | 층 표기. 병합 가능 |
| `tenant_type` | 텍스트 | | "약국", "NH농협캐피탈(주)" | 업종 또는 임차인명 |
| `area_pyeong` | 숫자 | | 45 | 전용면적 (평) |
| `deposit_manwon` | 숫자 | | 10000 | 보증금 (만원). 1억=10000 |
| `rent_manwon` | 숫자 | | 400 | 월세 (만원) |
| `mgmt_fee_manwon` | 숫자 | | 90 | 관리비 (만원) |
| `lease_start` | 날짜 | | "2024-01-01" | 계약 시작일 |
| `lease_end` | 날짜 | | "2026-12-31" | 계약 종료일 |
| `is_vacant` | 체크 | | true | 공실이면 체크 |
| `rent_type` | 선택 | | "fixed" | 아래 참조 |

**임대료 유형 (`rent_type`)**:

| 유형 | 설명 | 추가 필드 |
|------|------|----------|
| `fixed` | 고정 임대료 (기본값) | — |
| `revenue_linked` | 매출연동 (매출의 N%) | `revenue_linked_pct` (%) |
| `stepped` | 단계적 인상 (계약에 명시) | `note`에 인상 조건 기재 |
| `base_plus_percentage` | 기본+매출연동 | `base_rent_manwon`, `revenue_linked_pct` |

**매출연동 추정 범위** (rent_type이 revenue_linked일 때):
```
estimated_rent_range:
  low:  200  ← 보수적 월 추정 수입 (만원)
  mid:  350  ← 중간 추정
  high: 500  ← 낙관적 추정
```

**입력 예시 — 10층 건물**:

```
층: "B2"  | 업종: "주차장"     | 면적: 80평 | 공실: false | 비고: 주차전용
층: "B1"  | 업종: "기계실"     | 면적: 60평 | 공실: false | 비고: 비임대
층: "1F"  | 업종: "GS25"      | 면적: 25평 | 보증금: 10000 | 월세: 380 | 관리비: 50 | 시작: 2025-01-01 | 종료: 2027-03-31
층: "2F"  | 업종: "이비인후과"  | 면적: 45평 | 보증금: 15000 | 월세: 450 | 관리비: 90 | 시작: 2024-06-01 | 종료: 2026-12-31
...
층: "5F"  | (공실 체크)        | 면적: 45평 | ← is_vacant: true
...
```

> ⚠️ **자주 하는 실수**: 공실 층을 아예 입력하지 않는 것 → 공실률이 0%로 계산됩니다.
> 공실 층도 반드시 입력하고 `is_vacant: true`를 체크하세요.

### 4.3 부가수입 입력 (ancillary_incomes)

건물 옥상 통신장비, 주차수입 등 임대료 외 수입이 있으면 입력합니다:

| 필드 | 형식 | 예시 |
|------|------|------|
| `type` | 선택 | 아래 8종 중 택1 |
| `label` | 텍스트 | "옥상 통신장비 임대" |
| `annualAmountKrw` | 숫자 (원) | 24000000 (연 2,400만원) |
| `provenance` | 선택 | "broker_input" |
| `note` | 텍스트 | "SK텔레콤 5년 계약, 2027년 만기" |

**부가수입 유형 8종**:

| 코드 | 설명 |
|------|------|
| `telecom_antenna` | 통신장비 임대 (옥상 안테나) |
| `telecom_electric` | 통신장비 전기료 |
| `parking` | 주차 수입 (외부 차량 유료 주차) |
| `signage` | 간판/옥외광고 수입 |
| `vending` | 자판기 수입 |
| `rooftop_solar` | 태양광 발전 수입 |
| `ev_charging` | 전기차 충전 수입 |
| `other` | 기타 |

### 4.4 비교사례 직접 입력 (manual_comps)

시스템이 자동 조회한 실거래가 외에 중개인이 직접 알고 있는 거래 사례를 추가합니다:

| 필드 | 형식 | 예시 |
|------|------|------|
| `address` | 텍스트 | "서교동 395-12" |
| `dealAmount` | 숫자 (만원) | 850000 (85억) |
| `area` | 숫자 (㎡) | 450 |
| `dealYear` | 숫자 | 2025 |
| `dealMonth` | 숫자 | 8 |
| `buildingUse` | 텍스트 | "근린생활시설" |
| `floors` | 숫자 | 5 |

## 제5장. Owner Occupied 전용 입력

자가사용형의 핵심 입력은 `occupancySpec`입니다.
기본적으로 **매매가 + 건물 규모**가 핵심이며, 렌트롤은 입력하지 않습니다.

| 필드 | 형식 | 설명 |
|------|------|------|
| `asking_price_manwon` | 숫자 | 매매 희망가 |
| `total_floor_count` | 숫자 | 총 층수 |
| `building_age_years` | 숫자 | 건물 연식 |
| `broker_highlight` | 텍스트 | "전층 단독 사용 가능, 간판 설치 가능" |

## 제6장. Development 전용 입력

| 필드 | 형식 | 설명 |
|------|------|------|
| `developmentSpec` | 객체 | 개발 사양 (목표 용도, 목표 규모) |
| `vacateSpec` | 객체 | 명도 사양 (명도 예상 비용·기간) |
| `permitSpec` | 객체 | 인허가 사양 (사전 검토 결과) |

> **특이사항**: 개발형은 **매매가 없이도 IM 생성 가능**합니다 (주소만으로 가능).
> 토지 정보만으로 건축 가능 규모를 분석합니다.

## 제7장. Operating 전용 입력

| 필드 | 형식 | 예시 | 설명 |
|------|------|------|------|
| `hospitalitySpec.monthly_revenue_manwon` | 숫자 (만원) | 45000 | 월 매출 4.5억원 |
| `monthly_revenue_manwon` | 숫자 (만원) | 45000 | 월 매출 (별도 필드) |
| 객실수 | 숫자 | 150 | 바텀시트에서 입력 |
| ADR (평균 객실 단가) | 숫자 (원) | 120000 | 12만원 |

> **A등급 달성 조건**: 주소 + 공공데이터 + 매출 + 매매가 + 객실수 모두 충족

## 제8장. Trading 전용 입력

단기매매형은 입력이 가장 간단합니다:

| 필드 | 형식 | 설명 |
|------|------|------|
| `asking_price_manwon` | 숫자 (만원) | 매매 희망가 |
| `manual_comps[]` | 배열 | 비교사례 직접 입력 (제4장 참조) |

> A등급 달성: **주소 + 공공데이터 + 매매가** 3개면 충분

### 9.2 하역 시설

| 필드 | 형식 | 설명 | 예시 |

### 9.3 냉동·냉장

### 9.4 부대시설·접근성

| 필드 | 형식 | 설명 | 예시 |

## 제10장. 스태킹플랜 입력

스태킹플랜은 **건축 입면 셋백 다이어그램**으로, 층별 면적·임차인·셋백을 시각화합니다.

### 10.1 기본 입력 (층별)

| 필드 | 형식 | 설명 |
|------|------|------|
| `floor` | 텍스트 | "11F", "B1F", "B3~B5F" (병합) |

## 제12장. FAQ — 데이터 입력 관련

**Q: 층별 렌트롤 입력이 번거로워요. 월세 총액만 넣으면 안 되나요?**
A: 월세 총액(`monthly_rent_total_krw`)만으로도 IM 생성은 가능합니다. 다만 WALE, 앵커 비율, 스태킹플랜 시각화가 생략되고 B등급 달성이 어렵습니다. 최소 주요 층 3~4개라도 입력하면 품질이 크게 향상됩니다.

**Q: 매출연동 임대차를 어떻게 입력하나요?**
A: `rent_type`을 "revenue_linked"로 선택하고, `revenue_linked_pct`에 매출 대비 비율(%)을 입력합니다. `estimated_rent_range`에 보수적/중간/낙관적 월 추정 수입을 입력하면 시나리오 분석에 활용됩니다.

**Q: 보증금이 없는 층(월세만 있는 층)은 어떻게 입력하나요?**
A: `deposit_manwon`을 0으로 입력합니다. 빈칸으로 두지 마세요 — 빈칸은 "모름"이고, 0은 "보증금 없음"입니다.

**Q: 3층~4층을 하나의 임차인이 쓰는데 어떻게 입력하나요?**
A: `floor` 필드에 "3F~4F"로 병합 입력하면 됩니다. 면적·보증금·월세는 해당 층 합계를 입력합니다.

**Q: 아키타입을 직접 선택할 수 있나요?**
A: `archetype_override` 필드로 중개인이 수동 선택 가능합니다. 시스템이 자동 추천한 아키타입이 맞지 않을 때 사용합니다. (예: 시스템이 R-INC-01(안정형)을 추천했지만, 실제로는 R-INC-05(공실해소형)이 적합한 경우)

**Q: 물류센터 전용 필드를 모두 채워야 하나요?**
A: 아닙니다. 아는 항목만 입력하면 됩니다. 천장고(`ceiling_height_m`)와 도크 수(`dock_count`)가 가장 중요합니다.
