## 제1장. 산출물 등급 이해

### 1.1 발행 등급 5종 (Release Tier)

CreDeal은 데이터 품질에 따라 **자동으로 발행 등급을 결정**합니다.

| 등급 | 코드 | 용도 | 데이터 등급 | 포함 콘텐츠 |
|------|------|------|-----------|------------|
| ① 내부초안 | `internal_only` | 내부 검토용 | D~C | 기본 정보만 |
| ② 사실OM | `fact_om` | 매물 소개 | C+ | 사실 기반 개요 |
| ③ 분석IM | `analysis_im` | 수익 분석 | B | NOI, Cap Rate, 렌트롤 포함 |
| ④ 의사결정IM | `decision_im` | 매수 판단 | A | DCF, 민감도, 전체 분석 |
| ⑤ 전문가요청 | `expert_required` | 감정평가 필요 | 특수 | 외부 전문가 검토 필요 |

### 1.2 현재 등급 확인법

IM 생성 후 상단에 배지가 표시됩니다:

```
🟢 A등급 — 투자 검토 가능 (verified)      → 의사결정IM
🟡 B등급 — 기본 수익률 산출 (partial)      → 분석IM
🟠 C등급 — 건물 정보만 (reference)         → 사실OM
⚠️ D등급 — 데이터 보강 권장 (draft)        → 내부초안 (발행 차단)
```

### 1.3 등급에 따라 잠기는 콘텐츠

| 콘텐츠 | D | C | B | A |
|--------|---|---|---|---|
| 자산 개요 (건물 기본 정보) | ✅ | ✅ | ✅ | ✅ |
| 입지 분석 (교통, POI) | ✅ | ✅ | ✅ | ✅ |
| 토지 상세 (용도지역, 용적률) | ✅ | ✅ | ✅ | ✅ |
| 투자 포인트 (3대 매력) | ❌ | ✅ | ✅ | ✅ |
| 리스크 (3대 위험) | ❌ | ✅ | ✅ | ✅ |
| 렌트롤 테이블 | ❌ | ❌ | ✅ | ✅ |
| NOI / Cap Rate 산출 | ❌ | ❌ | ✅ | ✅ |
| 레버리지 분석 | ❌ | ❌ | ✅ | ✅ |
| 총수익률 (Total Return) | ❌ | ❌ | ❌ | ✅ |
| DCF 분석 | ❌ | ❌ | ❌ | ✅ |
| 수익률 민감도 분석 | ❌ | ❌ | ❌ | ✅ |
| PPTX 재무 확장 슬라이드 (6면) | 0면 | 0면 | 2면 | 6면 |
| **발행(공유) 가능** | ❌ 차단 | ✅ | ✅ | ✅ |

## 제2장. 등급 향상 전략

### 2.1 시스템이 제안하는 "다음 한 단계"

IM 생성 결과에 **NextStep** 안내가 포함됩니다:

```
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  📈 등급 향상 제안 (현재: C등급)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  🎯 다음 목표: B등급
  📋 추가 입력 필요: 렌트롤 (lease_roll)
  ⏱ 예상 소요 시간: 15분
  🔓 해금 콘텐츠: NOI, Cap Rate, 레버리지 분석
  📊 예상 점수 상승: +25점
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

이 안내를 따라 해당 데이터를 추가하면 가장 효율적으로 등급이 올라갑니다.

### 2.2 최소 노력 최대 효과 데이터

시스템은 **effort-efficient actions** (효과 대비 노력이 적은 순서)로 정렬된 추천을 제공합니다:

| 순위 | 슬롯 | 점수 기여 | 소요 시간 | 효율 |
|------|------|----------|----------|------|
| 1 | 렌트롤 (lease_roll) | +25점 | 15분 | ★★★★★ |
| 2 | 재무 입력 (financial_input) | +15점 | 5분 | ★★★★ |
| 3 | 건물 기본 (building_basic) | +15점 | 3분 | ★★★★ |
| 4 | 토지 정보 (land_parcel) | +15점 | 자동 | ★★★★★ |
| 5 | 용도지역 (zoning) | +10점 | 자동 | ★★★★★ |
| 6 | 권리관계 (title_encumbrance) | +10점 | 5분 | ★★★ |
| 7 | 시장비교 (market_comp) | +5점 | 10분 | ★★ |
| 8 | 접도 (road_access) | +5점 | 5분 | ★★ |

> 💡 **전략**: 토지 정보·용도지역은 주소 입력만으로 자동 획득 (효율 최고).
> 렌트롤 입력이 "최소 노력 대비 최대 효과"입니다.

### 2.3 출처(Provenance) 업그레이드

같은 데이터라도 **출처를 명확히 하면** 등급 점수가 올라갑니다:

```
예시: "연면적 2,816㎡"

  assumed (분석 가정)     → 계수 0.30 → 기여: 15 × 0.30 = 4.5점
  broker (중개인 입력)    → 계수 0.60 → 기여: 15 × 0.60 = 9.0점
  ledger (계약서 확인)    → 계수 0.70 → 기여: 15 × 0.70 = 10.5점
  public_api (건축물대장)  → 계수 0.95 → 기여: 15 × 0.95 = 14.25점
  registry (등기부)       → 계수 1.00 → 기여: 15 × 1.00 = 15.0점
  
  → 같은 숫자라도 "건축물대장에서 확인"하면 점수가 3배 이상 차이남
```

## 제3장. 아키타입 변경

### 3.1 아키타입이란

같은 포스처(예: 임대수익형)라도 매물의 특성에 따라 **강조 포인트와 슬라이드 구성이 달라집니다.**
이를 아키타입(archetype)이라고 합니다.

### 3.2 Income 6종 아키타입

| 코드 | 이름 | 강조 | 언제 선택 |
|------|------|------|----------|
| R-INC-01 | 안정수익형 | WALE, 앵커 비중, 공실 0% | 만실+장기 계약 빌딩 |
| R-INC-02 | 밸류애드형 | 임대료 인상 여력, 리모델링 | 저평가·공실 해소 여력 |
| R-INC-03 | NNN임대형 | 트리플넷 구조, 신용도 | 단일 임차인 장기 NNN |
| R-INC-04 | 고수익 소형형 | 근린 임대료 단가 | 소형 근생 (10억 이하) |
| R-INC-05 | 공실해소형 | 공실률 개선 시나리오 | 공실 30%+ 빌딩 |
| R-INC-06 | 매출연동형 | 매출연동 수입 범위 | 리테일·식음·호텔 매출연동 |

### 3.3 아키타입 변경 방법

```
보강정보 > 고급 설정 > archetype_override

예시:
  시스템 자동 추천: R-INC-01 (안정수익형)
  중개인 오버라이드: R-INC-05 (공실해소형)
  
  → IM 재생성 시 공실 해소 시나리오 분석이 강조됨
  → PPTX에서 vacancy 슬라이드가 추가됨
```

### 3.4 특수 아키타입

| 코드 | 이름 | 트리거 | 효과 |
|------|------|--------|------|
| R-TRD-04 | 출구 제약형 | 단기매매+토지거래허가구역 | `exit_constraint` 섹션 자동 삽입 |
| R-OPR-04 | 용도적법성 경고 | 운영형+허가 미확인 | 법적 리스크 강조 |

## 제4장. Mobile IM 검수 및 수정

### 4.1 섹션별 검수 포인트

IM 생성 후 Mobile IM 뷰어에서 각 섹션을 확인합니다:

```
[섹션 1: 자산 개요]
  □ 면적(대지·연면적)이 건축물대장과 일치하는가?
  □ 층수, 준공일이 맞는가?
  □ 평당가가 정확한가? (매매가 ÷ 연면적)

[섹션 2: 입지 분석]
  □ 최근접 지하철역과 도보시간이 맞는가?
  □ 권역 분류가 적절한가? (GBD, YBD, CBD 등)

[섹션 3: 임대차 현황] (Income만)
  □ 렌트롤 테이블의 각 층 데이터가 입력한 것과 일치하는가?
  □ 공실률 계산이 맞는가?
  □ WALE 계산이 합리적인가?

[섹션 4: 수익 분석] (Income만)
  □ NOI 계산이 맞는가? (총수입 − 운영비)
  □ Cap Rate가 합리적 범위인가? (2~15%)
  □ 레버리지 수익률이 정확한가?

[전 섹션]
  □ "◇ 분석가정" 뱃지가 달린 수치 중 실값으로 교체할 수 있는 것은?
  □ 특정 연령/계층 직접 지칭 표현이 없는가?
  □ 영문 약어에 한국어 풀이가 병기되어 있는가?
```

### 4.2 프로베넌스 뱃지 확인

각 수치 옆에 출처 뱃지가 표시됩니다:

| 뱃지 | 의미 | 조치 |
|------|------|------|
| 🟢 공적장부 (registry) | 등기부·건축물대장 출처 | 확인 완료 |
| 🔵 공공API (public_api) | 정부 API 자동 조회 | 확인 완료 |
| 🟡 중개인 입력 (broker_aug) | 중개인이 직접 입력 | 정확성 재확인 |
| 🟠 매도인 고지 (seller) | 매도인 제공 자료 | 교차 확인 필요 |
| ◇ 분석가정 (assumed) | 시스템이 가정한 값 | **실값으로 교체 권장** |

### 4.3 "분석가정" → 실값 교체 방법

```
1. "◇ 분석가정" 뱃지가 달린 수치를 찾음
   예: "운영비 비율: 20% [◇ 분석가정]"

2. 보강정보로 돌아가서 실값을 입력
   예: opex_total_krw = 120000000 (연 1.2억)

3. IM 재생성
   → "운영비: 1.2억 원 [🟡 중개인 입력]"으로 변경됨
   → 등급 점수도 상승 (0.30 → 0.60)
```

## 제5장. PPTX 스튜디오 수정

### 5.1 스튜디오 8단계 워크플로우

```
S00 초기화         → 프로젝트 생성, 테마 선택
S10 컴포지션      → 슬라이드 순서 결정 (자동)
S20 카피           → AI가 텍스트 초안 생성 (자동)
S30 레이아웃      → 레이아웃 템플릿 적용 (자동)
S40 프리뷰        → 미리보기 (수동 확인)
S50 게이트 체크   → 품질 검사 (자동)
S60 편집 승인     → 사람이 내용 승인 (수동)
S70 파일 승인     → 최종 파일 승인 (수동)
```

### 5.2 수정 가능 항목 (S40~S60)

**프리뷰 단계(S40)** 이후 수정할 수 있는 항목:

| 수정 항목 | 방법 | 예시 |
|-----------|------|------|
| **텍스트 수정** | 토큰 에디터에서 직접 수정 | "공실률 9.5%" → "공실률 10.2%" |
| **슬라이드 순서** | 드래그&드롭 | 리스크 슬라이드를 뒤로 이동 |
| **슬라이드 숨기기** | 토글 스위치 | 불필요한 슬라이드 비공개 처리 |
| **테마 색상** | 테마 선택기 | 기업 CI 색상 적용 |
| **사진 교체** | 사진 드롭존에 새 사진 | 더 좋은 외관 사진으로 교체 |

### 5.3 수정 시 주의사항

| 규칙 | 설명 |
|------|------|
| **본문 면수 16면 상한** | 본문은 16면 이내. 부록(공부발췌 등)은 제외 |
| **좌/우 분할 비중복** | A04/A05 레이아웃에서 좌·우에 같은 내용 중복 금지 |
| **면책조항 유지** | 마지막 슬라이드의 면책조항은 절대 삭제하지 않음 |
| **수치 정합** | 한 슬라이드의 숫자를 바꾸면 다른 슬라이드도 확인 |

## 제6장. 품질 게이트 대응

### 6.1 "발행 차단" — 원인과 해결

| 오류 메시지 | 원인 | 해결 |
|------------|------|------|
| "D등급 — 데이터 보강 필요" | 데이터 부족 (40점 미만) | 매매가·주소·기본 정보 입력 후 재생성 |
| "Pro IM은 B등급 이상 필요" | 데이터 C등급 이하 | 렌트롤·재무 데이터 추가 |
| "IM 생성 타임아웃" | 105초 초과 | 사진 수 줄이기, 재시도 |
| "매각 희망가 또는 월 임대료 필요" | income/trading 최소 데이터 미충족 | 매매가 또는 월세 입력 |
| "주소 또는 대지정보 부족" | development 최소 데이터 미충족 | 주소 입력 |

### 6.2 Cap Rate 경고

| 경고 | 의미 | 대응 |
|------|------|------|
| "Cap Rate 1.5%: 매우 낮음" | 가격 대비 수입이 너무 적음 | 매매가 또는 월세 데이터 재확인 |
| "Cap Rate 18%: 비정상적으로 높음" | 데이터 입력 오류 가능성 | 월세 입력 단위(원 vs 만원) 확인 |

> ⚠️ **가장 흔한 실수**: 월세를 "만원"이 아닌 "원"으로 입력하여 Cap Rate가 비정상적으로 높게 나오는 경우.
> 예: 월세 3,760만원을 37,600,000(원)으로 입력해야 하는 필드에 3,760으로 입력

### 6.3 주소 미입력 경고

```
경고: "주소가 입력되지 않아 건축물대장·토지이용계획 등 공적장부를
      조회하지 못했습니다. 주소를 입력하면 데이터 등급이 향상됩니다."

대응: 보강정보에서 resolved_address 또는 resolved_pnu 입력 후 재생성
```

### 6.4 데이터 신선도 경고

| 경고 | 의미 | 대응 |
|------|------|------|
| 🟡 "데이터 갱신 권장 (7일 초과)" | 공공데이터 조회가 7일 이상 전 | 큰 문제 아님, 갱신 권장 |
| 🔴 "데이터 갱신 필요 (30일 초과)" | 공공데이터 조회가 30일 이상 전 | 재조회 필요 |

## 제7장. 재생성 vs 수동 수정 판단

### 7.1 판단 기준

| 상황 | 권장 조치 | 이유 |
|------|----------|------|
| 데이터를 새로 추가/수정함 | **재생성** | AI가 새 데이터를 반영한 전체 분석 갱신 |
| 포스처를 변경함 | **재생성** | 섹션 구성·슬라이드가 완전히 달라짐 |
| 아키타입을 변경함 | **재생성** | 강조 포인트가 달라짐 |
| 텍스트 표현만 수정 | **수동 수정** | 재생성하면 다시 AI 텍스트로 돌아감 |
| 사진만 교체/추가 | **수동 수정** | 스튜디오에서 드롭존 교체 |
| 슬라이드 순서만 변경 | **수동 수정** | 스튜디오에서 드래그&드롭 |
| 특정 슬라이드만 숨김 | **수동 수정** | 스튜디오에서 토글 |

### 7.2 재생성 시 주의

```
⚠️ 재생성하면 이전에 수동으로 수정한 텍스트가 모두 초기화됩니다.
  → 수동 수정 내용을 메모해두고, 재생성 후 다시 적용하세요.
  → 또는 "수동 수정 부분만 따로 기록해두기" 습관을 들이세요.
```

## 제8장. 최종 발행 절차

### 8.1 발행 전 승인 흐름

```
[S60 편집 승인]
  ├─ 모든 섹션 텍스트 최종 확인
  ├─ 수치 정합성 확인
  ├─ 프로베넌스 뱃지 확인 (◇ 분석가정 → 실값 교체 완료?)
  └─ "편집 승인" 클릭

[S70 파일 승인]
  ├─ PPTX 미리보기 최종 확인
  ├─ PDF 다운로드 테스트
  └─ "파일 승인" 클릭 → 상태: published
```

### 8.2 승인 게이트 (자동 검사)

시스템이 자동으로 `runApprovalGate()`를 실행합니다:

```
✅ passed = true  → 발행 완료
❌ passed = false → 422 에러 + blockers 목록 표시

blockers 예시:
  - "Cap Rate 미산출 (월세 미입력)"
  - "면적 정합성 오류 (건축물대장 vs 입력값 ±10%)"
  - "면책조항 누락"
```

> blockers를 모두 해소해야 발행됩니다. 각 blocker에 대응하는 해결 방법이 함께 표시됩니다.

### 8.3 발행 후 활용

```
[정본 다운로드]
  ├─ PPTX 파일 (.pptx)
  ├─ PDF 파일 (.pdf)
  └─ Mobile IM 뷰어 URL

[공유]
  ├─ 카카오톡 공유 링크 (Mobile IM)
  ├─ 이메일 첨부 (PPTX/PDF)
  └─ QR코드 생성 (Mobile IM 뷰어)
```

## 제9장. 포스처별 산출물 최적화 팁

### 9.1 Income — 자주 나오는 문제와 해결

| 문제 | 원인 | 해결 |
|------|------|------|
| Cap Rate가 너무 낮음 (1~2%) | 매매가 입력 단위 오류 | 만원 단위 확인 |
| 렌트롤에 공실이 안 보임 | 공실 층 미입력 | 공실 층도 is_vacant=true로 입력 |
| WALE이 0으로 표시 | 계약 시작/종료일 미입력 | lease_start, lease_end 입력 |
| 앵커 비율이 안 나옴 | 임차인 카테고리 미설정 | tenant_type에 업체명 입력 또는 category='anchor' |
| 부가수입이 반영 안 됨 | ancillary_incomes 미입력 | 통신장비·주차 등 부가수입 별도 입력 |

### 9.2 Owner Occupied — 자주 나오는 문제와 해결

| 문제 | 원인 | 해결 |
|------|------|------|
| TCO 비교가 안 나옴 | 매매가 미입력 | 매매가 필수 입력 |
| 렌트롤이 나타남 | 포스처 income으로 잘못 선택 | 포스처를 owner_occupied로 변경 후 재생성 |
| "네이밍 라이츠" 표현 | AI 생성 텍스트 오류 | "사옥 단독 명칭 표기(간판 설치권)"으로 수정 |

### 9.3 Development — 자주 나오는 문제와 해결

| 문제 | 원인 | 해결 |
|------|------|------|
| 사업수지가 안 나옴 | 데이터 등급 B 미달 | 개발 목표 용도·규모 입력 (A등급 필수 조건) |
| 용적률이 틀림 | 공공데이터 조회 오류 | 토지이용계획확인서로 수동 교차 확인 |
| 명도 분석이 없음 | vacateSpec 미입력 | 기존 임차인 명도 계획 입력 |

### 9.4 Operating — 자주 나오는 문제와 해결

| 문제 | 원인 | 해결 |
|------|------|------|
| GOP가 안 나옴 | 월매출 미입력 | monthly_revenue_manwon 입력 |
| RevPAR이 안 나옴 | 객실수 또는 ADR 미입력 | 두 값 모두 입력 필요 |
| 계절성 분석이 없음 | 12개월 데이터 미제공 | 월별 매출 자료 직접 입력 |
| "캡레이트" 표현 | AI 텍스트 오류 | "연 순수익률 (Cap Rate)"로 수정 |

### 9.5 Trading — 자주 나오는 문제와 해결

| 문제 | 원인 | 해결 |
|------|------|------|
| 비교사례가 부실 | 자동 조회 사례 부족 | manual_comps로 3건 이상 직접 입력 |
| 할인율 계산이 안 됨 | 비교사례 없음 | 최소 1건 비교사례 필요 |
| 렌트롤이 나타남 | 포스처 income으로 잘못 선택 | trading으로 변경 (lease_status suppress됨) |

## 제10장. FAQ — 산출물 관련

**Q: IM을 생성했는데 D등급이라 발행이 안 돼요.**
A: D등급은 데이터 점수 40점 미만입니다. 가장 빠른 해결: ① 주소를 정확히 입력 (+20점), ② 매매가 입력 (+15~25점). 이 두 가지만으로 C등급 이상으로 올라갑니다.

**Q: 재생성할 때마다 AI 텍스트가 달라져요.**
A: AI 생성 특성상 매번 약간 다른 텍스트가 생성됩니다. 중요한 수정 사항은 수동으로 확정한 뒤, 불필요한 재생성을 피하세요.

**Q: PPTX에서 슬라이드가 16면을 초과해요.**
A: 본문은 16면 상한이지만, 부록(공부발췌, 권리관계, 지적도)은 제외됩니다. 본문이 16면을 초과하면 자동으로 절삭됩니다. 렌트롤 다단 테이블이나 갤러리가 여러 면이면 정상입니다.

**Q: "분석가정" 뱃지가 너무 많아요. 어떻게 줄이나요?**
A: 각 "◇ 분석가정" 항목에 대해 실제 값을 보강정보에서 입력하세요. 가장 영향이 큰 것부터:
1. 운영비 (opex_total_krw) → 관리비 정산 내역에서 확인
2. 공실률 (vacancy_pct) → 현장 확인
3. 관리비 (mgmt_fee_total_manwon) → 관리사무소 확인

**Q: 이전에 만든 IM을 다시 열어서 수정할 수 있나요?**
A: 네. 딜카드에서 해당 IM을 열고 보강정보를 수정한 뒤 재생성하거나, 스튜디오에서 직접 수정할 수 있습니다.

**Q: 매매가가 바뀌면 어떻게 하나요?**
A: `asking_price_manwon`을 수정하고 재생성하세요. 매매가는 Cap Rate, 평당가, 레버리지 등 모든 재무 지표에 영향을 미치므로 반드시 재생성이 필요합니다.

**Q: 카카오톡으로 공유할 때 미리보기가 안 나와요.**
A: Mobile IM 뷰어 URL이 published 상태여야 카카오 OG 미리보기가 정상 작동합니다. S70 파일 승인까지 완료했는지 확인하세요.
