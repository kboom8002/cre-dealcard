## 0. 제품 정의

### 0.1 목표

본 제품은 중개인 개인이 다음 자료를 수집·입력하면, AI와 결정론적 계산엔진이 외부 배포 가능한 분석형 IM을 생성하는 것을 목표로 한다.

- 공부와 공공데이터
- 매도인 제공자료
- 임대차·렌트롤
- 현장 확인자료
- 중개인이 수집한 비교사례
- 거래·임대시장에 대한 중개인 판단

최종 산출물은 단순 매물소개서보다 깊고, 전문가 참여형 Full Advisory보다는 범위가 제한된다.

> Broker Goldilocks IM은 매수자가 현장답사, 추가자료 요청, 예비가격 협상, LOI 조건 설정을 판단할 수 있는 증거기반 매수검토자료다.

### 0.2 06번 문서와의 관계

| 구분 | 07 Broker Goldilocks | 06 Full Advisory 방향 |
|---|---|---|
| 작성 책임 | 중개인 개인 또는 중개팀 | 분야별 전문가 공동 |
| 주요 증거 | 공부·계약·수납·현장·비교사례 | 07 + 법률·건축·세무·기술·금융 |
| 결론 수준 | 예비검토·협상조건 | 최종투심·DD·계약구조 |
| 개발분석 | 개발 가능성 스크리닝 | 건축 가능규모·사업수지 확인 |
| 법률 | 권리사항 사실 요약 | 법적 효과·위험 의견 |
| 세금 | 사용자 입력 또는 범위 안내 | 거래구조별 세무 검토 |
| CAPEX | 중개인 추정·견적 기반 | 전문가 범위·견적 검토 |
| 가치 | 비교·수익·시나리오 범위 | 독립 가치검토 또는 감정평가 |
| 외부 표시 | 중개인 분석·예비검토 | 전문가 검토 상태 표시 |

06번 문서는 다음 단계의 상위 목표다. 07번은 그 전에 실제 중개 현장에서 반복 생산할 수 있는 제품 범위를 고정한다.

### 0.3 성공 기준

1. 중개인이 일반 매물 입력 외에 45~90분의 구조화된 확인을 수행하면 초안이 생성된다.
2. AI가 공부·렌트롤·비교사례를 재정리하되 없는 사실을 채우지 않는다.
3. 매수자가 10분 안에 가격, 수익, 위험, 추가확인 필요성을 이해한다.
4. 핵심 숫자는 입력자료와 계산식으로 재현된다.
5. 전문가 확인이 필요한 부분은 확정 결론으로 표현되지 않는다.
6. 자료가 부족한 물건은 등급을 낮추거나 발행을 차단한다.

시간은 제품 운영 목표이며 모든 딜에 대한 보장은 아니다.

## 1. 제품 등급

### 1.1 외부 산출물 등급

| 등급 | 명칭 | 자료 수준 | 허용 산출물 | 외부 사용 |
|---|---|---|---|---|
| B0 | Draft | 주소·가격·일부 제원 | 내부 초안 | 금지 |
| B1 | Broker Fact OM | 공부·사진·현장 기본 | 사실형 OM | 가능 |
| B2 | Broker Analysis IM | B1 + 렌트롤 또는 비교사례 | 분석형 IM | 가능 |
| BG | Broker Goldilocks | B2 + 포스처 핵심증거·시나리오 | 매수의사결정지원 IM | 가능 |
| EX | Expert Required | 전문가 판단 없이는 핵심결론 불가 | 내부 검토·자료목록 | 제한 |

### 1.2 BG의 의미

BG는 모든 분석이 확정됐다는 뜻이 아니다. 다음이 충족됐다는 뜻이다.

- 자산이 정확히 식별됐다.
- 핵심 데이터의 출처와 기준일이 있다.
- 숫자 합계와 계산식이 재현된다.
- 중개인 확인사항과 매도인 진술이 구분된다.
- Base/Upside/Downside 또는 이에 준하는 비교가 있다.
- 추가 실사와 계약조건이 구체적으로 제시된다.
- 전문가 확인 전에는 확정할 수 없는 내용을 분리했다.

### 1.3 포스처별 BG 가능범위

| 포스처 | 중개인 단독 BG | 비고 |
|---|:---:|---|
| income | 가능 | 07의 우선 상용 대상 |
| owner_occupied | 가능 | 실제 매수자 요구 입력 필요 |
| development | 제한 가능 | Development Screening으로 명명 |
| operating | 제한 가능 | Seller-provided Operating Review |
| trading | 내부·제한 가능 | 권리·거래이력 구현 전 외부 제한 |

## 2. 중개인의 역할과 책임

### 2.1 중개인이 직접 확인할 것

- 물건 주소·지번·필지·건물
- 매도 희망가격과 거래조건
- 공부 발급 또는 공공데이터 조회결과
- 현장 사진과 실제 이용현황
- 매도인 제공 렌트롤·임대차 자료
- 임차인·공실·연체에 대한 매도인 설명
- 중개인이 직접 확인한 인근 임대·매매 사례
- 매도 사유·협상가능성·일정
- 매수자가 중요하게 보는 사용·수익·개발 목적

### 2.2 중개인이 판단할 수 있는 것

- 대상물건과 비교사례의 실무적 유사성
- 대로변·이면·코너·가시성·접근성
- 임대료 수준의 시장 적합성
- 공실 원인에 대한 중개시장 가설
- 임대인·임차인 협상 가능성
- 현실적인 매각·임대 마케팅 기간
- 예상 매수자군과 소구 포인트
- 추가로 받아야 할 자료와 실사 우선순위

### 2.3 중개인이 확정해서는 안 되는 것

- 법적 권리의 유효성·우선순위에 대한 법률의견
- 건축법·소방법·구조·설비의 최종 적법성
- 실제 증축·용도변경 허가 가능성
- 하자 부재 또는 공사비 확정
- 세금·중과·법인구조의 확정 결론
- 대출 승인·감정평가액·금리 확약
- 감정평가 또는 보장된 시장가치
- 투자수익 보장

### 2.4 책임 표시

외부 문서의 각 결론은 다음 중 하나로 표시한다.

- 공부 확인
- 계약서 확인
- 매도인 제공
- 중개인 현장 확인
- 중개인 시장의견
- 계산값
- 분석가정
- 미확인

AI 생성이라는 표시는 내부 이력에 남기되 외부에서는 근거유형을 표시한다. AI가 생성한 문장이라도 근거가 공부이면 공부 확인, 근거가 중개인 판단이면 중개인 시장의견이다.

## 3. 작성 워크플로

### 3.1 9단계

    1. 딜 생성
       주소, 지번, 가격, 포스처, 매도인 연락상태

    2. 자산 식별
       필지·건물·집합/일반·거래대상 확인

    3. 공부 자동조회
       건축물대장, 토지이용, 공시지가, 실거래

    4. 매도인 자료 입력
       렌트롤, 계약, 수납, 비용, 매도조건

    5. 현장 확인
       사진, 실제 용도, 공실, 주차, 설비, 하자 관찰

    6. 시장사례 입력
       중개인 임대사례, 실거래, 경쟁매물

    7. 전략·가정 승인
       임대조정, 공실기간, 비용, 가격범위

    8. AI 분석·QA
       충돌, 계산, 위험, 페이지 초안

    9. 중개인 최종승인·발행
       사실, 표현, 공개범위, 연락처 확인

### 3.2 화면 단위

| 화면 | 중개인 질문 | 주요 결과 |
|---|---|---|
| Deal Identity | 무엇을 파는가 | DealIdentity |
| Seller Facts | 매도인이 무엇을 말했는가 | Seller Statement |
| Public Records | 공부와 무엇이 다른가 | Fact/Conflict |
| Rent/Use | 누가 어떻게 사용 중인가 | Rent Roll/Occupancy |
| Field Check | 실제 현황은 무엇인가 | Field Evidence |
| Market | 무엇과 비교할 것인가 | Comparable Set |
| Strategy | 무엇을 바꿀 수 있는가 | Action Candidates |
| Assumptions | 어떤 가정을 쓸 것인가 | Approved Assumptions |
| Release Review | 무엇이 미확인인가 | Gate Report |

### 3.3 한 번만 입력하는 값

다음 값은 모든 페이지에서 동일 객체를 참조한다.

- 거래가격
- 대지면적
- 연면적
- 임대면적
- 보증금
- 월 임대료
- 관리비
- 공실률
- 기준일
- 수익률과 basis
- 대출금·금리

PPTX 문장에서 다시 파싱하여 기준값으로 사용하지 않는다.

## 5. 증거와 신뢰도

### 5.1 출처등급

| 등급 | 중개인 버전 정의 | 예 |
|---|---|---|
| S1 | 원본 확인 | 발급 공부, 계약 원본, 입금자료 |
| S2a | 공공 API 원시 | 건축물대장 API, RTMS |
| S2b | 공공자료 + 중개인 식별 | 마스킹 실거래 특정 |
| S3 | 매도인·중개인 진술 | 수기 렌트롤, 인터뷰 |
| S4 | 결정론적 계산 | 수익률, 단가, 시나리오 |
| S5 | AI 또는 중개인 가설 | 공실원인, 잠재 업종 |

### 5.2 확인상태

- unverified
- broker_checked
- reconciled
- conflicted
- stale
- not_available

전문가 확인상태는 07 범위에서 사용하지 않는다. 필요한 경우 expert_required 플래그를 설정한다.

### 5.3 충돌 규칙

다음 충돌은 자동 탐지한다.

- 도로명·지번·필지 불일치
- 대장 면적과 중개 입력 면적 불일치
- 공부 용도와 현장 용도 불일치
- 렌트롤 합계와 요약 합계 불일치
- 임대차계약과 렌트롤 금액·만기 불일치
- 만실 서술과 공실 데이터 공존
- 매매가와 페이지별 단가 불일치
- 실거래 사례의 건물 식별 불확실
- 수익률 값과 basis 불일치

충돌은 조용히 우선순위로 덮어쓰지 않는다. 충돌 객체를 만들고 중개인이 처리한다.

### 5.4 미확인 표시

미확인 내용은 해당 주장 옆에 표시하고 마지막 체크리스트에도 모은다.

좋은 예:

> 정상화 순수익은 운영비 내역 미제출로 확정하지 않았습니다.

나쁜 예:

> 자세한 내용은 추후 확인이 필요합니다.

## 6. 공통 Broker Goldilocks 섹션

| 순서 | 섹션 | 핵심 질문 | 필수 |

| 1 | Cover | 어떤 자산인가 | 필수 |
| 2 | Broker Decision Snapshot | 왜 검토하고 무엇을 확인해야 하나 | 필수 |
| 3 | Fact & Evidence Status | 어떤 자료가 확인됐나 | BG 필수 |
| 4 | Property & Public Records | 토지·건물·공부 현황은 무엇인가 | 필수 |
| 5 | Location & Market | 수요·접근·시장근거는 무엇인가 | 필수 |
| 6~N | Posture Modules | 포스처 핵심 경제성은 무엇인가 | 포스처별 |
| N-4 | Price Position | 매도가가 시장과 수익에 비해 어떤가 | B2/BG 필수 |
| N-3 | Risks & Unknowns | 무엇이 틀릴 수 있는가 | 필수 |

| N | Disclosure & Contact | 자료범위와 연락처 | 필수 |

### 6.1 Broker Decision Snapshot

한 면에 다음을 표시한다.

- Asking Price
- 핵심 수익 또는 가치 지표
- 중개인 판단: 검토 / 조건부 검토 / 자료보강 우선
- 핵심 투자논리 3개 이하
- 성립조건 3개 이하
- 핵심 위험 3개 이하
- 다음 행동

추천·비추천을 단정하지 않는다. 중개인 판단의 근거와 조건을 표시한다.

### 6.2 Price Position

가격을 한 점으로 확정하지 않는다.

- 매도 희망가
- 비교사례 범위
- 수익기준 범위
- 중개인 협상범위
- 범위가 성립하는 가정

시장사례나 수익자료가 부족하면 Price Position 페이지는 가격판단 대신 추가자료 필요성을 표시한다.

## 7. 수익형 Income

### 7.1 제품 목표

수익형은 Broker Goldilocks의 우선 상용 포스처다. 중개인이 확보할 수 있는 계약·렌트롤·시장자료를 최대한 활용하되, 실제 수납·운영비가 없는 경우 수익 수준을 과장하지 않는다.

### 7.2 발행등급 결정

| 자료 | 가능 등급 |
|---|---|
| 임대료 합계만 있음 | B1 또는 B2 |
| 호실별 렌트롤 있음 | B2 |
| 렌트롤 + 계약 주요조건 확인 | BG 후보 |
| 위 자료 + 수납 + 운영비 | BG 상단 |

hasRentRoll=false이면 income 분석형 IM을 발행하지 않는다. Fact OM으로 전환한다.

### 7.3 중개인 입력표

| 그룹 | 필수 필드 |
|---|---|
| 호실 | 층, 호, 업종, 점유상태 |
| 면적 | 임대면적, 면적 basis |
| 금액 | 보증금, 월세, 관리비, VAT |
| 계약 | 시작일, 종료일, 인상, 갱신, 해지 |
| 수납 | 최근 수납여부, 연체, 확인기간 |
| 현장 | 실제 점유, 공실상태, 시설상태 |
| 시장 | 시장 월세범위, 임대사례 |

상호는 외부 공개정책에 따라 마스킹하되 업종은 유지한다.

### 7.4 허용 계산

| 계산 | 조건 | 외부 라벨 |
|---|---|---|
| Gross Scheduled Rent | 렌트롤 | 계약상 연 임대료 |
| Gross Yield | 월세·가격 | 총임대수입 기준 수익률 |
| EGI | 공실·연체 입력 | 유효총수입 |
| NOI | 실제 또는 승인된 운영비 | 순영업소득 |
| Current Cap Rate | NOI 존재 | 현재 NOI 기준 |
| Stabilized NOI | 시장임대·공실·비용 가정 | 분석가정 기준 |
| Stabilized Cap Rate | Stabilized NOI | 안정화 가정 기준 |
| Simple Debt Scenario | 대출금·금리·상환방식 | 참고 금융 시나리오 |

운영비가 없으면 NOI와 Cap Rate를 산출하지 않는다. Gross Yield를 순수익률로 표기하지 않는다.

### 7.5 중개인 밸류애드 범위

## 9. 개발형 Development Screening

### 9.1 제품 명칭

중개인 단독 버전은 Development Feasibility가 아니라 Development Screening으로 외부 표시한다.

허용 결론:

- 공부상 개발 관련 조건
- 법정 FAR·BCR
- 이론적 상한
- 필지·도로·규제 확인사항
- 개발상품 가설
- 비교 토지·Exit 사례
- 단순 사업수지 시나리오
- 건축사 확인이 필요한 쟁점

금지 결론:

- 실제 건축 가능 연면적 확정
- 허가 가능 확정
- 공사비 확정
- 분양가·사업이익 보장
- 적정 토지가 확정

### 9.2 필수 입력

- 필지목록
- 토지·건축물 공부
- 토지이용계획
- 지적도
- 도로접면과 현장사진
- 기존 임차·명도상태
- 토지 실거래
- 예상 상품의 임대·매각사례
- 중개인 가정 공사비·일정

### 9.3 이론적 개발규모

    Theoretical BCR Area = 대지면적 × 법정 건폐율
    Theoretical FAR Area = 대지면적 × 법정 용적률

반드시 다음 문구를 함께 표시한다.

> 위 값은 공부상 법정 비율을 적용한 이론적 상한이며, 도로·높이·주차·일조·지구단위계획·설계조건 등을 반영한 실제 건축 가능규모가 아닙니다.

### 9.4 간이 사업수지

중개인 버전에서 허용하는 목적은 가설 비교다.

- 토지가
- 취득부대비용 입력값
- 목표 연면적 가정
- 공사비 가정
- 기타비용률 가정
- 사업기간 가정
- 예상 임대·매각단가
- 단순 개발이익
- 손익분기 Exit

모든 기본값을 표시하고 중개인이 승인해야 한다. 값이 없으면 일반 fallback으로 자동 완성하지 않는다.

### 9.5 필수 시나리오

- 계획 A: 현상유지 또는 임대운영
- 계획 B: 단순 리뉴얼

개발 가설에는 공사비 +20%, 일정 +6개월, Exit -10%를 기본 스트레스로 적용한다.

| C2 | 중개분석 | Gross Yield, 임대료 Gap |

| EX | 전문가 필요 | 세후 IRR, 법적 개발가능규모 |

### 12.3 기본 민감도

| 포스처 | 기본 변수 |
|---|---|
| income | 임대료, 공실, 안정화기간, Cap Rate, 금리 |
| owner | 보유기간, 임차료상승, 금리, 잔존가치 |
| development | 공사비, 기간, Exit, 연면적 |
| operating | 매출, 가동률, 원가, 인건비 |
| trading | Exit 가격, 매각기간, 금리, 해결비용 |

변수 수를 과도하게 늘리지 않는다. 매수결정에 가장 큰 영향을 주는 3~5개를 선택한다.

## 13. 중개인 전략 입력

### 13.1 자유서술만 받지 않는다

중개인 의견은 구조화한다.

| 필드 | 예 |
|---|---|
| observation | 3층 6개월 공실 |
| market_reason | 전용면적이 크고 임대료가 인근 대비 높음 |
| proposed_action | 2개 호실로 분할 마케팅 |
| evidence | 인근 30평 임대사례 3건 |
| prerequisite | 분할공사·소방 검토 |
| estimated_time | 4~6개월 |
| confidence | 중간 |
| expert_required | true |

### 13.2 투자논거 생성

AI는 승인된 Fact·Calculation·Broker Opinion만 사용한다.

투자논거는 다음 형식을 따른다.

    근거
    → 의미
    → 매수자에게 주는 효과
    → 성립조건

예:

> 계약 확인 기준 2개 층이 12개월 내 만료됩니다. 인근 임대사례 대비 현재 임대료가 낮아 갱신 협상 여지가 있으나, 실제 인상 가능성은 임차인 협의와 계약조건 확인을 전제로 합니다.

### 13.3 금지 문구

- 확실한 수익
- 안전한 투자
- 무조건 상승
- 리스크 없음
- 개발 확정
- 대출 가능
- 감정가 예상 확정
- 세금 문제 없음
- 명도 문제 없음
- 우량 임차인 확정

## 21. Definition of Done

### 중개인

- 중개인 한 명이 도움 없이 입력 흐름을 완료할 수 있다.
- 매도인 진술, 중개인 확인, 원본 확인을 구분한다.
- 비교사례 채택·제외와 가정을 직접 승인한다.
- 최종 문서의 위험·미확인·공개범위를 확인한다.

### 데이터

- 모든 핵심 숫자에 출처·기준일이 있다.
- 합계·단위·basis가 일치한다.
- 미확인값이 자동 확정되지 않는다.
- 자료 변경 시 관련 계산과 페이지가 갱신된다.

### 분석

- 포스처 핵심 질문에 답한다.
- 현재 사실과 분석가정이 분리된다.
- Upside에는 실행행위·조건·기간·위험이 있다.
- 가격은 범위와 조건으로 제시된다.
- 전문가 필요사항이 EX로 식별된다.

### 산출물

- 본문이 포스처 권장범위에 수렴한다.
- 렌트롤·사례·공부 세부는 부록으로 보존된다.
- 핵심 페이지 자동 절삭이 없다.
- PPTX 종단검사에서 차단 위반이 없다.
- PII와 제3자 이미지 문제가 없다.

### 상용화

- income 5건, owner 3건, development screening 3건을 사람 검수한다.
- 중개인과 매수자 피드백을 기록한다.
- 외부 문서 명칭·면책·업무범위를 내부 법률검토한다.
- 06 전문가 참여형과 데이터·Claim 구조를 공유한다.

## 22. 최종 제품 원칙

1. 중개인이 확인할 수 없는 것은 확인한 것처럼 쓰지 않는다.
2. 전문가가 필요한 결론을 면책문구로 대신하지 않는다.
3. 자료가 부족하면 페이지를 채우지 말고 등급을 낮춘다.
4. 임대료와 수익률보다 먼저 계약·수납·운영비 basis를 확인한다.
5. 개발 가능성이 아니라 개발 스크리닝 결과라고 표현한다.
6. 운영자료는 매도인 제공과 중개인 분석을 구분한다.
7. 비교사례는 건수보다 식별·유사성·채택이유를 중시한다.
8. 밸류애드는 아이디어가 아니라 대상·행위·조건·기간·비용·위험으로 작성한다.
9. 가격은 한 점이 아니라 범위·전제·철회조건으로 제시한다.
10. AI는 중개인의 생산성과 일관성을 높이지만 중개인의 확인책임을 대신하지 않는다.

## 부록 B. 외부 문서 표준 경계문
