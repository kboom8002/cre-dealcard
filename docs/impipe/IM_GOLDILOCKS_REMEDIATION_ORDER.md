### BL-C · 같은 2.41%에 두 개의 기준이 붙었습니다

| 면 | 표기 |
|:-:|---|
| 4 | 연 수익률(Cap Rate, **기준: 총임대료**) 2.41% |
| 10 | 연 순수익률 산출 기준 — **NOI(순영업소득) ÷ 매매가격** |

4면은 정직해졌습니다(D32 BL-3 반영). 10면은 그대로입니다.
그 결과 **하나의 숫자가 서로 배타적인 두 정의를 갖게 됐습니다.**
불변조건 22 · `G28` · `C-BASIS` 정면 위반이며, **BL-3을 절반만 이행해서
새로 생긴 결함**입니다.

**원인** `02 §4.1` 11단계 중 **10단계 「Cap Rate 표준 라벨 교정」**.
이것은 문자열 치환입니다. 계산 경로를 보지 않고 라벨을 표준형으로 덮어씁니다.
숫자와 라벨이 서로 다른 경로로 이동합니다.

**지시** 라벨을 값에서 파생시키십시오. 문자열 교정을 폐기합니다.

```ts
// 🔴 라벨은 교정 대상이 아니라 계산 결과입니다.
type Yield = {
  value: number;
  basis: 'GPI' | 'EGI' | 'NOI';
  deductions: Array<{ name: string; amount: number }>;   // basis='NOI' 이면 ≥1
  denominator: 'asking_price' | 'net_of_deposit';
};
const label = (y: Yield) => `연 수익률 (기준: ${BASIS_KR[y.basis]} ÷ ${DENOM_KR[y.denominator]})`;
```

`basis`가 `NOI`인데 `deductions.length === 0`이면 `G38`로 **차단**합니다.
전 슬라이드가 **같은 `Yield` 객체 하나**를 참조하게 하십시오. 두 번 쓰면 두 번 갈립니다.

| 면 | 진술 |

```ts
// 만실 / 공실 없음 / 100% 임대 / 풀 임대  ↔  vacancyRate > 0
const FULL = /만실|공실\s*(없|0)|100%\s*임대|풀\s*임대/;
if (FULL.test(text) && metrics.vacancyRate > 0) block('G41');
```

동일 계열로 **신축 ↔ 준공연도**, **역세권 ↔ 도보 분수**, **단독소유 ↔ 공유자 수**도

## 6. 검사기 자기 지적 — 내 §9.1이 리터럴이었습니다

V4를 처음 채점했을 때 「역레버리지 경고 **누락**」이 떴습니다.
4면에 ⚠️ 배지가 **있는데도** 그랬습니다.

원인은 제 `standard_check.py`였습니다.

```python
('역레버리지 경고', r'대출을 늘릴수록'),   # ← 제 문장 그대로를 찾고 있었습니다
('사진 면 존재',   r'건물 사진|사진'),     # ← 사진을 글자로 세고 있었습니다
```

D30에서 V2 리터럴 검사가 빗나간 것을 지적해 놓고, **제 검사기가 같은 실수를
하고 있었습니다.** 세 항목을 고쳤습니다.

| 항목 | 이전 | 이후 |
|---|---|---|
| 역레버리지 경고 | `대출을 늘릴수록` | `역레버리지\|대출을 늘릴수록` |
| 사진 면 존재 | 텍스트에 「사진」 | **도형 개수** (센티널) |
| 인근 매물 · 리스크 | 단일 리터럴 | 동의 표현 병기 |

검증 — 대조군이 느슨해지지 않았는지 확인했습니다.

```
V4    누락 10 → 7    (실제 있는 것을 인정)
V3    누락 10 → 10   (대조군 불변 — 느슨해지지 않았습니다)
목표본 15/15 유지
```

**이 정정이 없었다면 이 지시서는 있는 개선을 없다고 적었을 것입니다.**

## 7. 수용 기준

1. `layout_check` 위반 **0** · 주의 0 — 면수와 무관하게
2. `standard_check` 위반 **0** · §9.1 **15/15**
3. 하나의 수익률에 **하나의 basis** — 전 면 동일 객체 참조

5. 동일 문단 반복 **0건**

9. income 아키타입 코드가 세 문서와 정본에서 **동일**
10. `G31~G45`가 목록이 아니라 **실행 경로**에 있고, 위반 시 throw
11. 같은 입력 2회 렌더 시 sha256 동일

## 8. 하지 말 것

- **면을 더 늘리지 마십시오.** 배치를 고치기 전의 증면은 결함의 증식입니다.
  V3→V4에서 면당 위반이 1.09 → 1.33으로 **올랐습니다.**
- **폴백 문구를 더 다듬지 마십시오.** 이미 세 면에 같은 문단이 들어갔습니다.
  다듬을수록 결손이 잘 숨습니다.
- **`PAGE_HARD_LIMIT`을 20으로 두고 테스트를 「A:16~20p」로 고착시키지 마십시오.**
  테스트가 정본 위반을 보증하게 됩니다.
- **라벨 교정(문자열)을 확장하지 마십시오.** BL-C의 모순이 정확히 그 기법에서 나왔습니다.
- 마스킹 자동화는 **DEC-IMG-01**로 대상이 아닙니다. 승인 레코드는 유지됩니다.

        BL-C 값·라벨 단일 객체화
