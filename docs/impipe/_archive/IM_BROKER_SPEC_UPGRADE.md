## 1. 채택 — 07이 옳게 본 것

### 1.1 자료가 부족하면 등급이 아니라 **제품**을 바꿉니다

```
현행 CREDEAL   A/B/C/D — 같은 IM 의 품질 등급. D 만 차단
07             B0/B1/B2/BG/EX — 자료 수준에 따라 산출물 종류가 바뀜
               hasRentRoll=false → 분석형 IM 대신 Fact OM 으로 전환 (§7.2)
```

D33 S-5에서 「렌트롤 플래그가 없어 원장 0행 물건에서도 렌트롤 면이 열린다」를
지적했습니다. 07의 답이 더 낫습니다 — **면을 닫는 것이 아니라 문서 종류를 바꿉니다.**

필동3가(L=R0)가 정확히 이 경우입니다. 지금은 「수익형 IM인데 수익 칸이 빈」
산출물이 나옵니다. 07을 따르면 **Fact OM**이 나오고, 그건 결손이 아니라 완성품입니다.

### 1.2 값은 한 번만 입력하고 문장에서 다시 파싱하지 않습니다

> §3.3 — 「PPTX 문장에서 다시 파싱하여 기준값으로 사용하지 않는다」

D32 BL-3과 같은 결론입니다. V4의 「4면 총임대료 ↔ 10면 NOI」 모순이
정확히 문장 재파싱에서 나왔습니다.

### 1.3 계산마다 조건과 외부 라벨을 못박습니다 (§7.4)

| 계산 | 조건 | 외부 라벨 |
|---|---|---|
| Gross Yield | 월세·가격 | **총임대수입 기준 수익률** |
| NOI | **실제 또는 승인된 운영비** | 순영업소득 |
| Current Cap Rate | **NOI 존재** | 현재 NOI 기준 |

> 운영비가 없으면 NOI와 Cap Rate를 산출하지 않는다.
> Gross Yield를 순수익률로 표기하지 않는다.

이 두 문장이 V4의 가장 위험한 결함을 원천 차단합니다.
V4는 GPI를 250억으로 나눠 2.41%를 만들고 「NOI 기준」이라 적었습니다.

### 1.4 충돌을 덮어쓰지 않고 객체로 만듭니다 (§5.3)

> 충돌은 조용히 우선순위로 덮어쓰지 않는다. 충돌 객체를 만들고 중개인이 처리한다.

9종 충돌 목록에 **「만실 서술과 공실 데이터 공존」**과 **「수익률 값과 basis 불일치」**가
명시돼 있습니다. 제가 `G41`·`G38`로 신설한 것과 같습니다. 독립적으로 같은 결론에 도달했습니다.

### 1.5 미확인 표시의 좋은 예/나쁜 예 (§5.4)

| | 문구 |
|---|---|
| 좋은 예 | 정상화 순수익은 **운영비 내역 미제출로** 확정하지 않았습니다 |
| 나쁜 예 | 자세한 내용은 추후 확인이 필요합니다 |

V4 6·9·11면에 반복된 문단이 정확히 「나쁜 예」입니다.
**결손의 원인을 적으면 폴백이 될 수 없습니다.** 원인은 물건마다 다르기 때문입니다.

### 1.6 절삭과 빈 면 (§16.2 · §16.3)

> 앞 N면 슬라이스 **금지**
> 초과 후에도 의사결정 핵심 페이지가 남으면 **빌드 중단**
> 사진 없음·등기 없음·비교사례 없음·렌트롤 없음·운영비 없음 → **빈 페이지를 만들지 않는다**

D35 §4.2에서 지적한 「앞 16면만 유지가 DCF를 먼저 버린다」의 해답입니다.

### 1.7 밸류애드를 Action Card로 (§7.6)

대상 층·호실 / 현재 상태 / 실행행위 / 선행조건 / 예상기간 / 월 임대료 변화 /
비용 / NOI 변화 / 위험 / 근거 — 10칸.

> 전문가 필요 전략은 `idea_only`로 표시하고 금액효과를 확정하지 않는다.

V4 12면 「밸류애드 리스크 없는 완성형 수익자산」이 이 규율 하나로 불가능해집니다.

### 1.8 중개인 의견을 자유서술로 받지 않습니다 (§13.1)

`observation` · `market_reason` · `proposed_action` · `evidence` ·
`prerequisite` · `estimated_time` · `confidence` · `expert_required`

**의견을 구조화하면 게이트를 걸 수 있습니다.** 자유서술은 검사할 수 없습니다.

### 1.9 개발형을 Feasibility가 아니라 **Screening**으로 (§9.1)

이론적 상한 계산에 필수 경고문을 붙이고, 실제 건축 가능 연면적 확정을 금지합니다.
잠원동 사고(400% 일괄 적용)를 명칭 단계에서 막습니다.

| 계산 등급 | (없음) | **C1 · C2 · C3 · EX** |

D30에서 네임스페이스 충돌(`C19`·`G13`·`F`·`X`)을 정리했고, D35에서
`G17`·`G28`이 옛 의미로 부활한 것을 잡았습니다. **07을 그대로 넣으면 다섯 축이 더 늘어납니다.**

**개선안** 07의 **의미**를 채택하고 **코드는 기존 체계로 흡수**합니다.

```yaml
# 발행 등급 — A/B/C/D 를 버리지 않고 산출물 종류를 직교축으로 추가
release:
  tier:  [fact_om, analysis_im, decision_im, internal_only]   # 07 의 B1/B2/BG/EX
  grade: [A, B, C, D]                                          # 기존 L×P 유지
  # 🔴 두 축입니다. "C등급 decision_im" 은 불가, "C등급 fact_om" 은 가능
```

- 출처: 07의 `S2b`(공공자료 + 중개인 식별)는 **현행에 없는 유용한 구분**입니다.
  `ProvenanceKind`에 `public_api_identified`를 추가하고 SourceTier 매핑표를 만듭니다.
  **S 체계를 별도로 두지 않습니다.**
- 게이트: `B01~B12`를 `G48~G59`로 재부여하거나, 기존 코드에 매핑합니다.
  (예: `B05` 합계·단위·basis 불일치 → 기존 `G28`+`G38`)
- 승인 게이트 `H-B01~H-B06`은 **사람 행위**라 기계 게이트와 층이 다릅니다.
  `approval.*` 네임스페이스로 분리하면 충돌하지 않습니다.

### 2.2 면수 — 착상은 옳고 숫자는 조정이 필요합니다

| 출처 | income 면수 |
|---|---|
| 정본 `IM_STANDARD_수익형 §3.1` | **12~16** |
| 05 §7 | 권장 12 · 상한 16 |
| **07 §16.1 · §7.7** | **본문 16~20 + 부록** |

07이 **부록**을 도입한 것이 핵심입니다. 지금까지 「렌트롤 전량 표기(불변조건 18)」와

```
본문   12~16면   상한 초과 시 → 빌드 중단 (절삭 금지)
부록   무제한     렌트롤 전량 · 계약 주요조건 · 비교사례 원장 · 공부 발췌
       면 번호를 A-1, A-2 로 분리 · 본문 면수에 산입하지 않음
```

이러면 정본 §3.1과 불변조건 18이 **처음으로 양립**합니다.
07의 「본문 16~20」은 부록을 본문에 섞어 센 결과로 보이므로 16으로 내립니다.

## 3. 🔴 한국형 결손 — 07에도 CREDEAL에도 없는 것

이 절이 이 문서의 고유 기여입니다. 아래 항목은 **양쪽 문서 어디에도 없고**,
한국 상업용 부동산 거래에서 **매수자 의사결정에 직접 영향**을 줍니다.

### 3.1 🔴 토지거래허가 — 거래 성립 자체를 막습니다

2025년 10월 20일자로 **서울 25개 자치구 전역**이 토지거래허가구역으로 지정됐고,
2026년 12월 31일까지 유지되도록 설정돼 있습니다. 도시지역 기준면적은
상업지역·공업지역 150㎡가 기준이며, 지정권자가 기준면적의 10~300% 범위에서
따로 정할 수 있습니다 — 서울 2025.10 지정은 주거지역을 18㎡에서 6㎡로 낮췄고,
상업·공업지역도 같은 비율(15㎡)로 알려져 있습니다.

**우리 표본 3건에 적용하면:**

| 물건 | 소재 | 대지 | 판정 |
|---|---|---:|---|
| 양평동4가 | 영등포구 · 준공업 | 518.7㎡ | 기준면적 초과 — **허가 대상 가능성 높음** |
| 필동3가 | 중구 · 제2종일반주거 | ~217㎡ | 초과 — **허가 대상 가능성 높음** |
| 당산동5가 | 영등포구 | 수백㎡ | 초과 — **허가 대상 가능성 높음** |

허가를 받으면 **이용의무기간**이 따라붙고, 허가받은 목적대로 이용하지 않으면
**취득가액의 10% 이내에서 매년 이행강제금**이 부과됩니다.
250억 물건이면 연 최대 25억입니다. 임대수익률 2.41%짜리 자산에
이것은 수익 구조를 뒤집는 크기입니다.

🔴 **07 §4.1 필수 입력에도, CREDEAL 9개 공공 API에도 이 항목이 없습니다.**

**개선안**

```yaml
# 필수 입력 (07 §4.1 토지 그룹에 추가)
land:
  land_transaction_permit_zone: bool        # 토지거래허가구역 해당 여부
  permit_threshold_sqm: number              # 해당 자치구 고시 기준면적
  permit_required: derived                  # land_sqm > threshold
  permit_use_obligation: string             # 이용의무기간 · 허가 목적
```

- 데이터 원천: 서울부동산정보광장 `land.seoul.go.kr` 토지거래허가구역 지정현황 ·
  토지이음 고시. **10번째 공공 조회로 추가**합니다.
- 표시 위치: `Property & Public Records` 면 + `Risks & Unknowns` + `DD/LOI Conditions`
- 게이트: 허가 대상인데 미표시면 **발행 차단**. 07 §2.3(중개인이 확정해서는 안 되는 것)에
  따라 **허가 가능 여부를 단정하지 않고** 「해당 여부 · 기준면적 · 확인 필요」만 적습니다.

> 🔴 지정 현황과 기준면적은 자치구 고시로 수시 변경됩니다.
>   값을 코드에 박지 말고 **조회 시점과 함께 저장**하십시오(`records_as_of`).
>   그리고 이것은 법률 자문이 아닙니다 — 최종 확인은 관할 구청 소관입니다.

### 3.2 🔴 환산보증금과 상가임대차보호법 적용 구간

서울 기준 환산보증금 **9억 원**(= 보증금 + 월세 × 100)이 적용 경계입니다.
초과하더라도 **대항력 · 10년 계약갱신요구권 · 권리금 회수보호 · 3기 연체 해지**는
동일하게 적용됩니다. 갈리는 것은 **임대료 인상률 5% 상한 · 우선변제권 · 확정일자 ·
묵시적 갱신** 등입니다.

**왜 IM에 필요한가** — 매수자가 「갱신 시 임대료를 시장 수준으로 올린다」는
밸류애드를 검토할 때, 환산보증금 이하 구간이면 **연 5% 상한**에 걸립니다.
07 §7.5 「임대차 갱신 시 임대료 조정」과 §11 Market Rent Gap의 전제가 여기서 갈립니다.

V4 표본 9면에 「11개 호실 전원 환산보증금 9억 이하」라는 문장이 실제로 있습니다.
**시스템이 이 개념을 이미 다루면서 스펙에는 없습니다.**

**개선안** 렌트롤 각 행에 파생 필드를 둡니다.

```
환산보증금 = 보증금 + 월세 × 100
sla_applicable = 환산보증금 ≤ 지역 기준(서울 9억)
→ Market Rent Gap 면에서 5% 상한 적용 행과 미적용 행을 분리 표시
→ 상한 적용 행에 「인상률 상한 검토 필요」 확인사항
```

### 3.3 권리금 회수기회 보호

상가 임대차에서 임대인은 임차인의 권리금 회수기회를 방해할 수 없습니다.
매수 후 **명도·업종 교체·재임대 계획**에 직접 영향을 줍니다.

07은 §7.5에 「임차인 믹스 개선」·「공실 마케팅과 목표 업종」을 밸류애드로 넣었는데,
권리금 문제를 언급하지 않습니다. **입주 임차인을 내보내고 업종을 바꾸는 계획**은
권리금 분쟁 가능성을 동반합니다.

**개선안** Action Card의 `위험` 칸에 권리금 항목을 필수화하고,
`prerequisite`에 「임차인 협의 · 권리금 처리 방안」을 명시. 확정 결론은 금지(§2.3).

### 3.4 위반건축물 등재

건축물대장 위반건축물 표시는 **대출 실행을 제한**합니다.
현행 CREDEAL은 `hasViolation` 플래그가 있고 `loan` 면을 억제합니다(03 §3.2.3).
07 §4.1은 `known_encumbrance` 하나로 뭉뚱그렸습니다.

**개선안** 07 필수 입력의 건물 그룹에 `violation_registered` · `violation_detail`을
분리 신설. Financing Scenario 면과 연결.

### 3.5 부가가치세와 포괄양수도

건물분 VAT는 매매대금 자금계획에 직결되고, 포괄양수도로 처리하면 VAT가
발생하지 않습니다. 07 §7.3에 `VAT` 필드가 있으나 **거래 구조 항목이 없습니다**.

**개선안** `Price Position`·`Financing Scenario` 면에
`거래구조: 일반과세 / 포괄양수도 / 미정` + 「세무 확인 필요」 표시.
07 §2.3에 따라 **확정하지 않습니다.**

### 3.6 관리비 정산 구조

실비 정산인지 정액인지에 따라 NOI가 달라집니다. 07 §7.3에 `관리비` 금액 필드는
있으나 **정산 방식**이 없습니다.

**개선안** `관리비_구조: 실비정산 / 정액 / 혼합` 필수화.
정액이면 관리비 잉여가 NOI에 산입되고, 실비면 산입되지 않습니다.

### 3.7 그 밖의 확인 항목

| 항목 | 왜 필요한가 | 넣을 자리 |
|---|---|---|
| 정비구역 지정 여부 | 재건축·재개발 구역이면 개발·매각 전략이 바뀜 | Public Records |
| 제소전화해 조서 | 명도 소요 기간 추정의 근거 | Rent Roll 부록 |
| 소방 완비증명 · 정화조 용량 | 근생 업종 변경 가능 범위 | Risks & DD |
| 자금조달계획서 제출 대상 | 매수자 준비 사항 | DD & LOI |
| 중개보수 요율 | 총취득원가 구성 | Price Position |

## 5. 수용 기준

1. `hasRentRoll=false`인 income 물건에서 `analysis_im` 이상이 **발행되지 않음**
2. 운영비 없는 물건에서 「NOI」·「순수익률」 문자열 **0건**
3. 하나의 수익률에 하나의 `basis` — 본문·부록 전 면 동일 객체 참조
4. 본문 면수 **12~16** · 초과 시 절삭이 아니라 **빌드 중단**
5. 부록에 렌트롤 **전량**(불변조건 18) · 본문 면수 미산입
6. **토지거래허가 해당 여부**가 전 서울 물건에 표시 (§3.1)
7. 환산보증금 기준 적용 여부가 렌트롤 행별로 표시 (§3.2)
8. Action Card 10칸 전량 충족 · `idea_only`에 금액효과 **없음**
9. 빈 면 **0건** · 동일 문단 반복 **0건**(`G42`)
10. `layout_check` 위반 **0** — 본문·부록 모두
11. 같은 입력 2회 → 구조·수치·게이트 판정 **동일**
12. 네임스페이스 신설 **0개** — 07의 5축이 기존 체계로 흡수됨

## 6. 하지 말 것

- **07을 그대로 구현하지 마십시오.** 등급·출처·게이트 체계가 세 벌이 됩니다.
  의미를 채택하고 코드는 흡수하십시오(§2.1).
- **면수를 20으로 올려 해결하지 마십시오.** 부록으로 분리하는 것이 답입니다(§2.2).
- **토지거래허가 가능 여부를 단정하지 마십시오.** 해당 여부와 기준면적만 적고
  판단은 관할 구청과 매수자에게 남깁니다 — 07 §2.3의 원칙 그대로입니다.
- **환산보증금·권리금을 법률 결론으로 쓰지 마십시오.** 「해당 / 미해당 / 확인 필요」
  세 상태만 표시합니다.
- 마스킹 자동화는 **DEC-IMG-01**로 대상이 아닙니다. 07 §7.3
  「상호는 마스킹하되 업종은 유지」는 정본 불변조건 23과 일치하므로 그대로 채택합니다.
