# 베이직 IM(Basic IM) 정의 및 작성 가이드

> 이 문서는 소형 상업용 부동산 매각 시 사용하는 "베이직 IM(Investment Memorandum / Offer Memorandum)"의
> 정의, 표준 구조, 작성 원칙, 디자인 시스템, 그리고 지도·지적도·스태킹 플랜 등 보조 이미지의
> 렌더링 방안을 한 곳에 정리한 레포 문서입니다. 새로운 매물 IM을 만들거나 이 스펙을 확장할 때
> 참조 기준으로 사용합니다.
>
> 참고 구현체: `basic_im/` (Word/docx 템플릿), `seocho_im/` (PPTX 샘플). 두 구현 모두 아래 스펙을
> 공유하며, 매체(문서/슬라이드)에 따라 레이아웃만 다르게 적용합니다.

---

## 1. 정의

**베이직 IM**은 소형·중형 상업용 빌딩을 매각할 때, 중개인이 건물주·매수 법인 담당자에게 제시하는
투자제안서의 최소 완결 형태입니다. "베이직"이라는 이름은 두 가지 의미를 갖습니다.

1. **작성 난이도가 낮다** — 등기부등본, 건축물대장, 임대차계약서 정도의 기본 서류만으로 완성할 수
   있습니다. 감정평가, DCF, 민감도 분석 같은 고급 분석은 포함하지 않습니다.
2. **신뢰를 얻기 위한 최소 조건을 갖춘다** — 숫자만 나열한 표가 아니라, 사진·지도·수익률 계산까지
   포함해 "이 중개인이 물건을 제대로 이해하고 있다"는 인상을 줍니다.

**타깃 독자**는 50~70대 건물주, 법인 자산관리 담당자입니다. 화려한 카피보다 **명확한 숫자와 근거**,
**충분한 글자 크기와 여백**, **과장 없는 표현**을 우선합니다.

**타깃 작성자**는 초심자 상업용 부동산 중개인입니다. 빈칸을 채우듯 작성할 수 있도록, 각 섹션에
"무엇을, 어떤 형식으로, 어떤 근거로" 써야 하는지 구체적인 예시를 함께 제공합니다.

## 2. 문서 구조 (표준 9단계)

실제 중개법인이 작성한 매각자료 2건(서초동 1364-28 FM빌딩, 신사동 590 ICL빌딩— 제이에스부동산중개법인,
2025) 및 CBRE 스타일의 티저 메모랜덤(스태킹 플랜 포함)을 분석해 정리한 순서입니다. 실무 자료는 대부분
6~8슬라이드로 구성되며, 아래 9단계는 그 관행에 "요약"과 "투자수익률 분석"을 더해 신뢰도를 높인 버전입니다.

| # | 섹션 | 필수 | 핵심 내용 | 실무 관행 |
|---|------|------|-----------|-----------|
| 1 | 표지 | ✅ | 건물명·주소, 매각가, 작성일, 중개법인명 | **건물 사진을 넣지 않는다.** 스카이라인 실루엣 등 추상적 배경만 사용 |
| 2 | 요약 (Executive Summary) | 권장 | 핵심 숫자 스탯 6개 + 투자 포인트 3개 | 실무 자료엔 드물지만, 신뢰도·전달력을 위해 베이직 IM에 추가 권장 |
| 3 | 물건 개요 | ✅ | 공부 정보(소재지·대지면적·건폐율·용적률·준공·층수·주차) + 건물 외관 사진 | 표(구분/내용)와 사진을 **좌우 배치**. 매각가는 별도 소표로 분리 |
| 4 | 입지 정보 | ✅ | 지도 + 역/도로/랜드마크 + 짧은 해설 | 문단형 해설보다 **불릿 3개 이내**로 압축. 지도 위에 라벨을 직접 얹는 방식 |
| 5 | 토지 정보 | ✅ | 지적도(형상·도로접함) + 용도지역·건폐율·용적률 해설 | 사다리꼴/코너 등 **형상 특징**과 **도로 접함 면수**를 반드시 언급 |
| 6 | 건물 사용 현황 (렌트롤) | ✅ | 층별 임차 현황 표 + **스태킹 플랜** | 관리비 컬럼 없음. 공실은 하이라이트. 스태킹 플랜을 표 좌측에 배치 |
| 7 | 투자수익률 분석 | 권장 | 표면임대수익률 계산, 공실 반영 현재값 + 안정화 시나리오 | 실무 자료엔 드묾 — 밸류애드 스토리를 만드는 베이직 IM만의 차별점 |
| 8 | 현장 사진 | ✅ | 정면·후면·주차장·내부·옥상 등 6컷 그리드 | 사진 유무가 신뢰도를 가장 크게 좌우함 |
| 9 | 문의 및 유의사항 | ✅ | 담당자 연락처 + 면책조항 | 면책조항은 짧아도 반드시 포함 |

> **선택(심화) 섹션**: 매각가 100억 원 이상 또는 복잡한 딜에서는 ⑩ 항공뷰, ⑪ 주변 매물 시세(비교사례)를
> 추가합니다. 이 두 섹션은 실제 시장 데이터(실거래가, 인근 매물)가 확보되지 않으면 **절대 임의로
> 채우지 않습니다** — 가짜 비교사례는 법적·신뢰 리스크가 큽니다.

## 3. 작성 원칙

실제 매각자료를 분석하며 확인한 관행을 원칙으로 정리합니다.

### 3.1 표기 규칙

- **렌트롤 컬럼**: `층수 · 면적(㎡/평) · 임차인 · 보증금 · 월세 · 계약종료`. 관리비는 넣지 않습니다
  (관리비는 실비 성격이라 수익률 계산에서도 제외).
- **공실 표기**: `공실` / `공실(임대예정)`처럼 상태를 구분하고, 표에서 해당 행을 옅은 주황색
  배경 + 주황색 글자로 강조합니다.
- **특이 임차 조건**(예: 특수관계인의 시세보다 낮은 임대료)은 반드시 각주로 밝힙니다. 숫자를
  숨기지 않는 것이 신뢰를 만듭니다.
- **가정치 표기**: 실측이 아닌 추정값에는 `◇ 분석가정` 배지를 붙입니다. CreDeal 시스템의
  프로베넌스(출처 표시) 개념을 그대로 계승합니다.
- **플레이스홀더**: 중개법인명·담당자·연락처처럼 문서마다 달라지는 값은 `[담당자명]`처럼
  대괄호로 표시합니다.
- **작성 가이드 박스**: 중개인이 참고할 메모는 회색 점선 박스(✎ 작성 가이드)로 넣고, "고객
  전달 전 삭제" 문구를 반드시 포함합니다. 실제 IM 내용(초록/주황/금색 박스)과 시각적으로
  분리해 실수로 남겨 보내는 일을 방지합니다.

### 3.2 문장 스타일

- 문단형 해설을 줄이고 **불릿 또는 표**로 압축합니다. 실무 자료는 슬라이드당 텍스트가 매우
  적습니다.
- "위치가 좋습니다" 대신 "**도보 7분**", "**공실 0**"처럼 검증 가능한 숫자로 씁니다.
- 미확정 정보는 단계를 구분합니다: 예정 / 계획 / 확정. 미확정을 확정처럼 쓰지 않습니다.
- 투자수익률 등 계산값에는 **산출 공식을 그대로 노출**합니다 (숫자만 보여주고 끝내지 않음).

### 3.3 투자수익률 공식 (표준)

```
표면 임대수익률 = 연간 임대료 합계(관리비 제외) ÷ (매매가 − 승계 보증금 합계)
```

공실이 있는 매물은 **현재(As-Is)** 값과, 공실을 인근 동일 용도 층 수준으로 채웠다고 가정한
**안정화(Stabilized) ◇분석가정** 값을 나란히 제시해 밸류애드 스토리를 만듭니다. 안정화 값은
반드시 "무엇을 가정했는지"(예: 3F 사무실 평당 임대료 적용) 한 줄로 밝힙니다.

### 3.4 금기 사항

- 과장 전망("무조건 오릅니다"), 세후 수익률과 세전 수익률의 혼용, 실거래가 없는 비교사례 임의
  기재, 미확정 개발계획의 확정형 서술을 금지합니다.
- 실제 존재하는 특정 건물·주소를 다룰 때, **없는 사진이나 실제 지도 스크린샷을 생성 이미지로
  대체하지 않습니다.** 아래 5장의 방식대로 개략도/자리표시로 대체합니다.

## 5. 지도 · 지적도 · 스태킹 플랜 렌더링 방안

### 5.1 왜 실제 이미지를 생성하지 않는가

실제 주소가 있는 매물의 지도·건물 사진·지적도를 AI가 생성한 이미지로 대체하면, 사실이 아닌
정보를 사실처럼 제시하는 결과가 됩니다. 따라서 이 스펙은 두 가지 방식만 사용합니다.

1. **자리표시(placeholder)** — 건물 사진, 실제 지도 캡처, 실제 지적도등본처럼 "현장에서만
   구할 수 있는" 자료는 회색 점선 박스 + 카메라 아이콘 + 교체 안내 문구로 자리만 표시합니다.
2. **개략도(schematic diagram)** — 위치 관계, 토지 형상, 임대 구성처럼 "구조를 설명하는" 자료는
   matplotlib으로 직접 그린 개략도를 사용합니다. 이때 반드시 "실제 지도/지적도가 아닌 개념
   설명용 개략도입니다" 각주를 넣습니다.

두 방식 모두 실제 자료로 교체하는 것을 전제로 하며, 개략도는 "구조 이해를 돕는 임시 시각자료"
그 이상의 역할을 하지 않습니다.

### 5.2 공통 구현 방식

세 이미지 모두 `matplotlib` + 한글 폰트(`NanumGothic` 또는 `Noto Sans CJK`, 시스템에서
`fc-list :lang=ko`로 탐색)로 렌더링합니다. 공통 패턴:

```python
import matplotlib.font_manager as fm
font_path = ...  # NanumGothic 또는 fc-list 결과의 첫 한글 폰트
fm.fontManager.addfont(font_path)
def kfont(size, weight='normal'):
    return fm.FontProperties(fname=font_path, size=size, weight=weight)

NAVY, GOLD, TEAL = '#132A3A', '#B8860B', '#2E6E82'
```

- 배경은 흰색(`facecolor='white'`), 저장은 `bbox_inches='tight'`로 여백을 최소화합니다.
- 모든 개략도 하단에는 8.5pt 회색(`#8A8A8A`) 각주로 "실제 자료가 아님"을 명시합니다.
- 라벨이 원·마커·다른 라벨과 겹치지 않도록, 좌표를 충분히 띄우고(최소 1.0 단위 이상) 렌더링
  후 반드시 눈으로 확인합니다. 겹침은 가장 흔한 실패 지점입니다.

### 5.3 위치 개략도 (location_map.png)

교차하는 두 도로(간선/이면) + 본건 마커(★, gold) + 도보 반경 원(점선) + 역/랜드마크 아이콘으로
구성합니다.

```python
# 도로
ax.add_patch(Rectangle((6.7, 0), 0.85, 8, facecolor='#E3E7EA', edgecolor='#C6CBCF'))   # 간선도로(수직)
ax.add_patch(Rectangle((0, 4.55), 12, 0.8, facecolor='#E3E7EA', edgecolor='#C6CBCF'))  # 이면/보조도로(수평)

# 본건
ax.add_patch(Circle((subj_x, subj_y), 0.36, facecolor=GOLD, edgecolor=NAVY, linewidth=1.8))
ax.text(subj_x, subj_y, '★', ha='center', va='center', color='white')

# 도보 반경
ax.add_patch(Circle((subj_x, subj_y), 1.35, facecolor='none', edgecolor=TEAL,
                     linewidth=1.3, linestyle='--'))
ax.text(subj_x, subj_y + 1.4, '도보 5분', ha='center', va='bottom', color=TEAL,
        bbox=dict(boxstyle='round,pad=0.15', fc='#F7F9FA', ec='none'))  # 도로선과 겹치지 않게 흰 배경 박스
```

**체크리스트**: 역 마커와 본건 마커 사이 거리는 최소 2.0 단위 이상 확보 → 라벨 텍스트가 겹치지
않음. 랜드마크 라벨은 반경 원 바깥쪽에 배치.

### 5.4 지적도 개략도 (land_diagram.png)

`matplotlib.patches.Polygon`으로 대지 형상(사각형/사다리꼴/코너 절취형 등 실제 형상에 맞는
좌표)과 건물 footprint(빗금 해칭)를 그리고, 전면·측면 도로 접함을 별도 색 띠로 표시합니다.

```python
site = np.array([[0.4, 0], [7.6, 0], [8.4, 5.4], [1.6, 6.2], [0, 3.0]])  # 실제 형상에 맞게 조정
ax.add_patch(Polygon(site, closed=True, facecolor='#F4ECD8', edgecolor=NAVY, linewidth=2.2))

footprint = np.array([[1.3, 0.9], [6.9, 0.9], [7.5, 4.9], [2.1, 5.5]])
ax.add_patch(Polygon(footprint, closed=True, facecolor='#D7E6EC', edgecolor=TEAL,
                      linewidth=1.6, hatch='//'))
```

대지 형상 좌표는 공부상 형상 설명(예: "사다리꼴", "코너 절취")에 맞춰 다각형 꼭짓점을 직접
조정합니다. 정확한 비율을 재현하는 것이 아니라 **형상의 특징(코너/사다리꼴/도로 몇 면 접함)을
직관적으로 이해시키는 것**이 목적입니다.

### 5.5 스태킹 플랜 (stacking_plan.png)

CBRE 등 기관 IM에서 쓰는 표준 시각자료로, 건물 층 구성을 쌓은 막대로 표현합니다. 베이직 IM에서는
"⑥ 건물 사용 현황" 슬라이드의 **렌트롤 표 좌측**에 배치합니다.

**데이터 구조**: 층별 `(라벨, 임차인/상태 텍스트, 분류, 색상, 상대높이)` 리스트를 위(고층)에서
아래(저층)로 정의합니다.

```python
floors = [
    ('옥탑', '연면적 제외',                    'none', '#E7E9EA', 0.6),
```

**색상 매핑 규칙**:

- 만기 연도별로 서로 다른 색을 지정합니다(2025=더스티로즈 `#C9A9A6`, 2026=세이지그린
  `#93B3A0` 등). 같은 연도에 만기가 몰려 있는 것 자체가 공실 리스크 정보이므로, 색으로 즉시
  드러나야 합니다.
- 공실은 별도 색이 아니라 **빗금 해칭**으로 표시합니다(`hatch='////'`, 연한 회색). 채워진
  색과 혼동되지 않도록 명확히 다른 질감을 씁니다.
- 범례(`* 만기시점`)는 그림 맨 위에 컬러칩 + 라벨로 자동 생성하고, 실제 사용된 연도만
  표시합니다(사용하지 않는 연도는 범례에서 제외).

```python
y = top
for label, text, kind, color, h in floors:
    y -= h
    ax.add_patch(Rectangle((x0, y), w, h, facecolor=color, edgecolor='#5B6B73', linewidth=1.1))
    if kind == 'vac':
        ax.add_patch(Rectangle((x0, y), w, h, facecolor='none', edgecolor='#B9BDC0',
                                hatch='////', linewidth=0))
    ax.text(x0 + 0.15, y + h / 2, label, va='center', fontproperties=kfont(12, 'bold'), color=NAVY)
    ax.text(x0 + 1.15, y + h / 2, text,  va='center', fontproperties=kfont(10.5), color='#33414A')
```

**확장 규칙(다층 동일 임차인)**: 한 임차인이 여러 층을 쓰는 경우, CBRE 예시처럼 해당 층들을
하나의 색 블록으로 합쳐서 그립니다(층 경계선만 얇게 유지). 이 문서의 서초동 샘플은 층마다
임차인이 달라 단순 1층=1블록 구조를 썼지만, 대형 빌딩에는 병합 로직이 필요합니다.

**PPTX/Word 삽입 규격**: 원본 이미지는 200dpi로 저장하고, 삽입 시 원본 가로세로 비율을
유지합니다(`h = w * img_h_px / img_w_px`). 렌트롤 표와 나란히 둘 때는 스태킹 플랜에 전체
슬라이드/페이지 너비의 35~40%를, 표에 나머지를 배분합니다.

### 5.6 렌더링 → 검수 루프

1. `python3 make_assets.py` 로 PNG 생성.
2. Word: `soffice.py --headless --convert-to pdf` → `pdftoppm` → 이미지로 라벨 겹침·잘림
   확인. PPTX도 동일한 스크립트(`pptx` 스킬의 `scripts/office/soffice.py`)를 사용합니다.
3. 겹침이 보이면 좌표를 조정하고 **해당 이미지만** 재생성 — 전체 문서를 다시 만들지 않습니다.
4. 표·박스가 포함된 문서는 `cantSplit`(docx) 또는 슬라이드 여백 확인(PPTX)까지 함께 점검합니다.
