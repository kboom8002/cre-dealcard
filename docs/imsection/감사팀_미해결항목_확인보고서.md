### 122초 분해 추정

| 구간 | 소요 시간 | 방식 |
|---|---:|---|
| 외부 API 8종 수집 | 3~5초 | `Promise.all` 병렬 |
| RAG 임베딩 + RPC | 1~2초 | 순차 |
| **7섹션 LLM 생성 + Judge** | **105~120초** | **순차 (for-await)** |
| 후처리 + DB 저장 | 1~2초 | 순차 |
| **합계** | **~122초** | |

### 병목 원인

**7개 섹션을 순차 호출**하는 것이 122초의 85% 이상을 차지합니다. 이전 섹션의 맥락(`sectionCtx`)을 다음 섹션 프롬프트에 주입하기 위한 의도적 설계입니다. 섹션당 LLM 호출이 **2회**(본문 + Judge)이므로 총 14회 LLM API 호출이 순차 발생합니다.

### Vercel 60초 제한과의 관계

`route.ts:15`에 `export const maxDuration = 120;`이 명시되어 있어 Vercel Pro 플랜에서 120초까지 허용됩니다. 122초는 이 제한의 경계에 있어 간헐적 타임아웃 위험이 있습니다. (`vercel.json`의 60초 설정과 route 레벨 120초 설정이 공존하며, route 레벨 설정이 우선합니다.)

> **참고:** PPTX 생성은 이 사이클에서 수행되지 않습니다. 별도 엔드포인트 `/api/public/im-lite/[buildingId]/pptx/route.ts`에서 동기 호출됩니다.

## #3 실거래가 API 소형 상업용 커버리지

### 코드 분석 결과

2개의 실거래가 API 호출 경로가 존재합니다:

| 파일 | API | 용도 |

| `price-prediction.ts` | `RTMSOBJSvc` (비주거용 실거래 상세) | ETL 배치 적재 |

### 소형 상업용 커버리지 제한

**`price-prediction.ts` L77에 하드코딩된 필터:**

```typescript
if (isNaN(price) || price < 2_000_000_000) continue; // 20억 미만 제외
```

| 구간 | 포함 여부 |
|---|---|
| 20억 미만 꼬마빌딩 | ❌ **코드에서 명시적 제외** |
| 20억~50억 꼬마빌딩 | ✅ 포함 |
| 50억~300억 | ✅ 포함 |
| 300억 초과 | ❌ 제외 |

### 용도 필터

`price-prediction.ts` L81에서 `근린생활시설`, `업무시설`, `주상복합`, `상업용`만 필터링합니다. 주거용(아파트, 다세대)은 제외됩니다.

### API 키 상태

`.env.local`에 `MOLIT_API_KEY`가 존재합니다 (fb53be41…). 만료 여부는 실제 호출로만 확인 가능합니다.

> **결론:** 소형 상업용(50억 이하) 커버리지는 **20억~50억 구간만 포함**됩니다. 제이에스의 주력 타겟인 20억 미만 꼬마빌딩은 코드 레벨에서 하드코딩 제외되어 **비교사례 데이터가 원천적으로 누락**됩니다.
