## 0. 🔴 두 가지를 정정합니다

### 0.1 "Golden에 사실 오류 0건"은 검증이 아니었습니다

SSoT v1.2에서 **"오염은 형식(이모지 128건)일 뿐 사실 오류는 0건"** 이라고 보고했습니다. **틀렸습니다.**

> **합성 데이터는 사실 오류를 가질 수 없습니다. 대조할 사실이 없기 때문입니다.**

Golden 164건은 콜드스타트 때문에 **LLM이 생성한 가상 물건**입니다. 존재하지 않는 건물의 면적이 "틀렸다"고 말할 수 없습니다. 제가 센 것은 **내부 정합성**이었고, 그것을 사실 정확성으로 보고한 것이 오류입니다.

| 이전 보고 | 실제 |
|---|---|
| 형식 오염 **93.9%** | 유지 — 이모지·페르소나는 실재 |
| **사실 오류 0건** | **판정 불가 — 대조 대상 없음** |
| 정제하면 쓸 수 있다 | **재구축해야 한다** |

### 0.2 폐순환이 실재합니다 — 퓨샷 경로

SSoT v1.1에서 **"RAG가 죽어 있으므로 열린 사슬"** 이라고 판단했습니다. RAG 부분은 맞지만 **결론이 틀렸습니다.**

```
명세 예시 → 퓨샷 → 생성물 → Judge → Golden 축적 → 퓨샷
              ↑                                      │
              └──────────────────────────────────────┘
```

`buildIMFewShotBlock()`이 `im_golden_sets`를 조회합니다(SSoT §7.2). **Golden이 시스템 자기 출력이면 고리가 닫힙니다.**

무엇이 순환하는지가 중요합니다.

| 순환하는 것 | 영향 |
|---|---|
| 문체·구조 | 경미 — 오히려 일관성 |
| **잘못된 계산 패턴** | **치명** |

기존 Golden은 **`NOI = 임대료 × 0.85`, 용적률 400%, 목표가 = 매입가 × 1.2**가 적용된 시스템이 만들었습니다. 상수를 코드에서 지워도 **퓨샷 예시가 같은 형태를 다시 가르칩니다.**

> **단계 2(가정값 외부화)만으로는 부족합니다.** Golden을 함께 갈아야 합니다.

## 1. 출처 3등급

**"진짜 데이터냐"가 아니라 "어느 사실에 정박했느냐"로 나눕니다.**

| 등급 | 사실 | 문체 | 정의 |
|:-:|:-:|:-:|---|
| **S** | 진짜 | **진짜 중개인** | 중개인이 실제 물건으로 작성한 IM |
| **A** | **진짜** | 우리 표준 | 공개 매물자료의 **사실에 정박**해 표준 방법론으로 저작 |
| **C** | 없음 | 시스템 자기출력 | **순수 합성 — 폐기** |

### 1.1 A등급도 합성입니다

**중개인이 아니라 우리가 썼습니다.** 이 점을 숨기지 않습니다. 차이는 **모든 수치가 외부 공개자료에 대조 가능**하다는 것입니다.

```ts
export type GoldenGrade = 'S' | 'A' | 'C';

export interface GoldenProvenance {
  grade: GoldenGrade;
  sourceUrl: string | null;        // A등급 필수
  harvestedAt: string | null;      // A등급 필수
  authoredBy: 'broker' | 'standard_method';
  verifiedFacts: string[];         // 외부 대조 가능한 필드 목록
}
```

### 1.2 퓨샷 우선순위

```sql
SELECT markdown FROM im_golden_sets
WHERE section_type = $1 AND posture = $2 AND price_band = $3
  AND is_active = true
  AND grade IN ('S','A')                    -- ★ C 제외
ORDER BY (grade = 'S') DESC, judge_score DESC
LIMIT 3;
```

**S를 먼저 씁니다.** 진짜 중개인 문체가 우선이고, A는 커버리지를 메웁니다.

## 3. 🔴 용적률 400% — 5건 전부 상한 미만입니다

## 4. 저작 규칙

### 4.1 기사 문장을 옮기지 않습니다

| 가져온다 | **가져오지 않는다** |
|---|---|
| 면적 · 가격 · 용도지역 | **문장 · 표현 · 단락 구성** |
| 거래 이력 · 공시지가 | 기자의 평가·전망 |
| 도로 조건 · 준공년도 | **"희소성" 같은 수식** |

**사실은 저작물이 아니지만 표현은 저작물입니다.** 모든 문장을 표준 어휘로 새로 씁니다.

### 4.2 출처를 남깁니다

```json
    "harvestedAt": "2026-08-23",

    "kind": "공개 매물 기사"
  }
}
```

**A등급은 `sourceUrl` 없이 승격할 수 없습니다.**

### 4.3 마스킹

| 항목 | 처리 |
|---|---|
| 지번 | **제외** — 동까지 |

각 골든은 **섹션 7개 마크다운**을 냅니다. 아키타입이 아니라 섹션 단위입니다(D3 §9).

### 5.1 금지어

### 7.3 밴드 불일치 예시를 넘기지 않습니다

```sql
-- 같은 밴드를 우선하고, 없으면 인접 밴드까지만 허용한다
SELECT markdown, price_band FROM im_golden_sets
WHERE section_type = $1 AND posture = $2 AND grade IN ('S','A') AND is_active
  AND price_band = ANY($4)          -- 요청 밴드 + 인접 1단계
ORDER BY (price_band = $3) DESC, (grade = 'S') DESC, judge_score DESC
LIMIT 3;
```

```ts
export function adjacentBands(b: PriceBand): PriceBand[] {
  const order: PriceBand[] = ['B1', 'B2', 'B3', 'B4'];
  const i = order.indexOf(b);
  if (i < 0) return order;                       // 주력 밖 — 전체 허용
  return order.slice(Math.max(0, i - 1), i + 2);
}
```

**B4 요청 시 B3까지만 허용됩니다.** 50억 예시로 400억 물건 IM을 쓰면 어휘와 규모 감각이 어긋납니다. **인접 1단계를 넘는 예시는 빈 결과보다 나쁩니다.**

### 7.4 밴드가 올라가면 매수 주체가 바뀝니다

| 밴드 | 매수 주체 (통상) | 어휘 |
|:-:|---|---|
| B1·B2 | 개인 자산가 · 소형 법인 | 월 순현금 · 실투자금 중심 |
| B3 | 법인 · 자산관리회사 | + 총취득원가 · LTV 시나리오 |
| **B4** | **법인 · 기관 · 시행사** | **+ 실사 자료 수준 · 권리관계 정밀도** |

**B4 골든이 없다는 것은 기관 매수인 대상 어휘의 표본이 없다는 뜻입니다.**

### 7.5 operating 0건

숙박·요양 공개 매물 자료를 찾지 못했습니다. **operating 포스처는 보류 상태이므로 지금 필요하지 않습니다.** 재개 조건 충족 시 별도 조사합니다.

> 다만 역설계 자료에 **호텔 300억(94실)** 이 있습니다. 이 물건은 **B4 구간이자 operating 포스처**이므로, Opex/GOP 충돌(§10 A)이 해소되면 **B4 공백과 operating 공백을 동시에 메울 수 있는 유일한 후보**입니다.

### 7.6 다음 재구축 우선순위

| 순위 | 대상 | 이유 |
|:-:|---|---|
| **1** | **B4 (300~500억)** | 골든·comps 동시 공백 · 주력 상단 |
| 2 | operating | 포스처 유일 공백 · B4와 겹칠 수 있음 |
| 3 | B1 보강 (현재 1건) | 밴드 최소 2건 확보 |
| 4 | 준공업·상업지역 | 용적률 400%가 실제로 유효한 유일 구간 |
