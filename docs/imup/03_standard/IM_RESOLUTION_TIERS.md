# IM 해상도 등급 체계 — 부분 자료로도 발행 가능한 구조

> 표준 양식은 하나로 유지하되, **채워진 만큼만 만들고 못 채운 것은 확인사항으로 옮깁니다.**
> 실매물 렌트롤 2건을 실측 판정해 설계했습니다.

| | |
|---|---|
| **적용** | PPTX IM · 모바일 IM · 딜카드 |
| **핵심 원칙** | 결손은 사라지지 않고 **이동**한다 |
| **템플릿** | `CREDEAL_렌트롤_표준양식_v1.2.xlsx` |
| **최종 수정** | 2026-08-23 |

## 0. 왜 등급이 필요한가 — 실측

두 실매물 렌트롤이 **서로 다른 방식으로** 불완전합니다.

| 필드 | 양평동 | 당산동 |
|---|:-:|:-:|
| 호실 · 업종 · 보증금 · 월세 · 만료일 | ○ | ○ |
| 관리비 | **○** | ✗ |
| 현 계약 시작일 | **○** | ✗ |
| 임대면적 | ✗ | **○** |
| **최초 계약일** | ✗ | ✗ |
| **적용법령** | ✗ | ✗ |
| **대항력** | ✗ | ✗ |

**컬럼 수는 8개 대 7개로 비슷하지만 할 수 있는 판단이 다릅니다.**

| 기능 | 양평동 | 당산동 |
|---|:-:|:-:|
| 렌트롤 표 · 만료 타임라인 · 총액 수익률 | ○ | ○ |
| 월 총수입 정확 | ○ | ✗ |
| 평당 단가 · 층별 단가 논리 | ✗ | ○ |
| 환산보증금 · 상임법 판정 | ✗ | ✗ |
| 갱신요구권 · 명도 계획 · 임대료 정상화 | ✗ | ✗ |
| **합계** | **4/11** | **5/11** |

> 그래서 등급은 **컬럼 개수가 아니라 열리는 기능**으로 정의해야 합니다.

### 0.1 🔴 두 칸이 절반을 잠그고 있습니다

**`적용법령`과 `최초 계약일`** — 이 둘이 없어서 법적 판정 4종이 전부 막힙니다.

그런데 **둘 다 중개인이 이미 아는 정보**입니다. 상가인지 주택인지 모르는 중개인은 없고, 최초 입주 시점도 매도인에게 물으면 됩니다. **렌트롤 양식에 칸이 없어서 안 적혔을 뿐입니다.**

이것이 표준 양식의 실질적 가치입니다. 새 정보를 요구하는 게 아니라 **이미 아는 것을 적을 자리를 만드는 것**입니다.

## 1. 렌트롤 해상도 3단

### 1.1 정의

| 등급 | 요건 | 열리는 기능 |
|---|---|---|
| **R0 미달** | 총액만 (합계 보증금·월세) | 총액 수익률 · 공실률(개수) |
| **R1 최소형** | 호실 · 업종 · 금액 · 만료일 · 임대상태 | **+ 렌트롤 표 · 만료 타임라인 · 임차 구성 서술** |
| **R2 필요형** | R1 + 면적 · 적용법령 · 관리비 · 시작일 | **+ 평당 단가 · 층별 단가 논리 · 환산보증금 · 상임법 판정 · 월 총수입** |
| **R3 표준형** | R2 + 최초계약일 · 대항력 | **+ 갱신요구권 · 명도 계획 · 임대료 정상화 시뮬** |

### 1.2 등급별 발행 권한

| 등급 | 딜카드 | 모바일 Basic | 모바일 Pro | PPTX |
|---|:-:|:-:|:-:|:-:|
| R0 | ○ | ○ | ✗ | ✗ |
| **R1** | ○ | ○ | ○ | **○ (법적 판정 없이)** |
| R2 | ○ | ○ | ○ | ○ |
| R3 | ○ | ○ | ○ | ○ (완전) |

**R1이 발행 최소선입니다.** 두 실매물 모두 R1이므로 **현재 자료로도 IM은 나옵니다** — 다만 법적 판정 칸이 "확인 필요"로 찍힙니다.

### 1.3 실측 판정 결과

| 물건 | 판정 | 다음 한 칸 |
|---|:-:|---|
| 양평동 | **R1** | 적용법령 → 환산보증금·상임법 / 임대면적 → 평당 단가 |
| 당산동 | **R1** | 적용법령 → 환산보증금·상임법 / 관리비 → 월 총수입 |

> `CREDEAL_렌트롤_*.xlsx` 「자동검증」 시트가 이 판정을 자동 출력합니다.

### 1.4 부분 커버리지 — 행 단위 판정

12행 중 8행만 면적이 있는 경우처럼 **일부만 채워진 상황**이 흔합니다.

| 커버리지 | 처리 |
|---|---|
| 100% | 완전 렌더 |
| 50~99% | **부분 렌더** + "N개 호실 면적 미상" 병기 · **합계는 미산출** |
| < 50% | 해당 기능 숨김 → 확인사항 이관 |

**합계성 지표(총 평단가·전체 정상화 시뮬)는 100%를 요구합니다.** 일부 행만으로 합계를 내면 틀립니다.

## 2. 처리 아키텍처

### 2.1 흐름

```
입력 → 해상도 판정 → 기능 해제 → 요소별 렌더/축약 → 결손 이관 → 등급 반영
```

### 2.2 기능 정의

```ts
export type Capability =
  | 'yield_gross' | 'rentroll_table' | 'expiry_timeline'
  | 'conv_deposit' | 'monthly_net' | 'unit_rate' | 'floor_rate_logic'
  | 'renewal_right' | 'vacate_plan' | 'rent_normalization';

export interface CapabilitySpec {
  id: Capability;
  requires: SlotKey[];        // 전 행 필수
  minCoverage: number;        // 0.0 ~ 1.0
  degrade: 'hide' | 'placeholder' | 'partial';
  placeholder?: string;
  deficiency: string;         // 확인사항 페이지에 실릴 문장
}

export const CAPABILITIES: CapabilitySpec[] = [
  { id: 'rentroll_table', requires: ['unitLabel','tenantBusiness','deposit','monthlyRent'],
    minCoverage: 1.0, degrade: 'hide',
    deficiency: '호실별 임대 내역을 확보하지 못했습니다.' },

  { id: 'conv_deposit', requires: ['deposit','monthlyRent','legalBasis'],
    minCoverage: 1.0, degrade: 'placeholder', placeholder: '확인 필요',
    deficiency: '호실별 적용 법령(상가/주택)이 확인되지 않아 환산보증금을 산출하지 못했습니다.' },

  { id: 'unit_rate', requires: ['monthlyRent','leaseArea'],
    minCoverage: 0.5, degrade: 'partial',
    deficiency: '일부 호실의 임대면적이 확인되지 않았습니다.' },

  { id: 'renewal_right', requires: ['legalBasis','firstContract'],
    minCoverage: 1.0, degrade: 'placeholder', placeholder: '확인 필요',
    deficiency: '최초 계약일이 없어 갱신요구권 잔여를 산출하지 못했습니다.' },

  { id: 'rent_normalization', requires: ['monthlyRent','leaseArea','legalBasis','firstContract'],
    minCoverage: 1.0, degrade: 'hide',
    deficiency: '임대료 정상화 시뮬레이션에 필요한 자료가 부족합니다.' },
```

### 2.3 해상도 판정

```ts
export function resolveCapabilities(rows: LeaseUnit[]): Map<Capability, number> {
  const live = rows.filter(r => r.leaseState === '임대중');
  const out = new Map<Capability, number>();
  for (const spec of CAPABILITIES) {
    const ok = live.filter(r => spec.requires.every(k => r[k] != null && r[k] !== ''));
    const cov = live.length === 0 ? 0 : ok.length / live.length;
    if (cov >= spec.minCoverage) out.set(spec.id, cov);
  }
  return out;
}
```

### 2.4 🔴 결손 이관 — 이 표준의 핵심

**축약된 요소는 조용히 사라지지 않습니다.** 확인사항 페이지의 한 줄이 됩니다.

```ts
export interface Deficiency {
  capability: Capability;
  sentence: string;
  missingFields: SlotKey[];
  coverage: number;
  severity: 'blocking' | 'material' | 'minor';
}

export function buildDeficiencyLedger(
  have: Map<Capability, number>, rows: LeaseUnit[],
): Deficiency[] {
  return CAPABILITIES
    .filter(s => !have.has(s.id))
    .map(s => ({
      capability: s.id,
      sentence: s.deficiency,
      missingFields: missingOf(s, rows),
      coverage: coverageOf(s, rows),
      severity: s.degrade === 'hide' ? 'material' : 'minor',
    }));
}
```

**출력 예 (양평동, R1)**

```
확인 필요
· 호실별 적용 법령(상가/주택)이 확인되지 않아 환산보증금을 산출하지 못했습니다.
· 최초 계약일이 없어 갱신요구권 잔여를 산출하지 못했습니다.
· 호실별 임대면적이 확인되지 않아 평당 단가를 산출하지 못했습니다.
```

세 줄이 생겼습니다. **빈 페이지가 아니라 실사 목록입니다.**

### 2.5 다음 한 칸 — 한계 가치 안내

진행률(%)이 아니라 **무엇이 열리는지**를 보여줍니다.

```ts
export function nextBestField(rows: LeaseUnit[]): { field: SlotKey; unlocks: Capability[] } | null {
  const now = resolveCapabilities(rows);
  const cands = ALL_INPUT_SLOTS.filter(f => !isFullyFilled(rows, f));
  let best: { field: SlotKey; unlocks: Capability[] } | null = null;
  for (const f of cands) {
    const after = resolveCapabilities(fillAll(rows, f));
    const gain = [...after.keys()].filter(c => !now.has(c));
    if (gain.length && (!best || gain.length > best.unlocks.length)) {
      best = { field: f, unlocks: gain };
    }
  }
  return best;
}
```

**화면 문안**

```
❌ "입력 완성도 62%"
✅ "「적용법령」을 채우면 환산보증금과 상임법 판정이 열립니다"
```

중개인에게 **다음 행동**을 줍니다. 퍼센트는 행동을 만들지 않습니다.

### 2.6 승급 경로

자료가 나중에 채워지면 재발행 시 자동으로 풍부해집니다.

| 시점 | 등급 | IM 상태 |
|---|:-:|---|
| 접수 직후 | R1 | 발행 · 확인사항 3줄 |
| 매도인 회신 후 | R2 | 재발행 · 확인사항 1줄 |
| 계약서 확인 후 | R3 | 재발행 · 확인사항 0줄 |

`POST_PUBLISH_SPEC.md`의 재발행 트리거에 **해상도 승급**을 추가합니다.

## 3. 다른 섹션의 해상도 등급

렌트롤 외에 **유연 적용이 필요한 섹션 8개**입니다. 우선순위 순입니다.

### 3.1 투자 구조 (p6) — 최우선

| 등급 | 요건 | 산출 |
|---|---|---|
| **L1** | 매매가 · 보증금 | 실투자금(무대출) · 총액 수익률 |
| **L2** | + 취득세율 · 중개보수율 · 금리 가정 | **총취득원가 · LTV 시나리오 · 역레버리지 판정** |
| **L3** | + 감정가 · 대출 승인조건 · 운영비 | 실제 월 순현금 · DSCR |

> **L2가 실질 목표선입니다.** 취득세율(4.6%)과 금리는 물건 정보가 아니라 **가정값**이므로 자료 없이도 채울 수 있습니다. 실매물 IM 2건이 L1에 머문 것은 자료 부족이 아니라 **계산을 안 한 것**입니다.

축약 규칙 — 운영비 미확보 시 차감하지 않되 **"운영비 미반영"을 반드시 병기**합니다. 임의 추정 금지.

### 3.2 가격 근거 · 인근 매물 (p7)

| 등급 | 요건 | 산출 |
|---|---|---|
| **L1** | 0건 | **섹션 삭제** → 확인사항 이관 |
| **L2** | 2~3건 | 참고 표기 · **시세 구간 미제시** |
| **L3** | 4건 이상 + 조사기준 명시 | 시세 구간 제시 · 대상 위치 표기 |

> 당산동은 4건 + 조사기준("토지 100평 이상, 도로변, 유흥건물 제외")으로 **L3**입니다. 양평동은 **L1(0건)**.

**표본 3건 이하로 시세 구간을 제시하지 않습니다.** 통계적 근거가 없습니다.

### 3.3 개선 여력 (p8)

| 등급 | 요건 | 산출 |
|---|---|---|
| **L1** | 공실·자가사용 면적 | 정성 서술 ("공실 임대 시 수입 증가") |
| **L2** | + 인근 임대 시세 근거 | **정량 시뮬 · ◇가정 표기 필수** |
| **L3** | + 갱신요구권 판정 (렌트롤 R3) | **실현 가능 시점 명시** |

> 🔴 **L1에서 숫자를 내면 안 됩니다.** 양평동 생성물이 근거 없이 "평당 5만원 → 월 638만원"을 확정치처럼 제시한 것이 이 위반입니다.
>
> 당산동은 층별 환산평당가 근거가 있어 **L2**, 다만 갱신권 미확인이라 **실현 시점을 말할 수 없습니다.**

### 3.4 물건 개요 (p3)

| 등급 | 요건 |
|---|---|
| **L1** | 대지 · 연면적 · 층수 · 준공연도 |
| **L2** | + 건폐율 · 용적률 · 용도지역 · 공시지가 + 기준연도 |
| **L3** | + 건축물대장 원본 대조 · 위반건축물 확인 · 필지별 정보 |

> 두 물건 모두 **L2 자료는 원본에 있었으나 생성물이 누락**했습니다 (건폐율·공시지가). 자료 문제가 아니라 렌더 문제입니다.

### 3.5 권리 관계 (p13 권장)

| 등급 | 요건 | 산출 |
|---|---|---|
| **L1** | 소유자 수 | "소유자 N인" |
| **L2** | + 등기부 확인 | 근저당 유무 · 권리제한 유무 |
| **L3** | + 채권최고액 · 공동담보 그룹 · 매각 동의 | 인수 조건 · **C32 공동담보 판정** |

> 🔴 **L1에서 "권리제한사항 없음"이라 쓸 수 없습니다.** 등기부 없이는 없다는 것을 확인할 수 없습니다.

### 3.6 입지 (p4)

| 등급 | 요건 |
|---|---|
| **L1** | 주소 · 최근접역 · 도보 시간 |
| **L2** | + 지도 이미지 · 배후 특성 · 간선도로 |
| **L3** | + 유동인구·상권 데이터 (출처 명기) |

> **역 등급(급행/일반)은 역 DB 대조 없이 표기 금지.** 소요시간은 L3 전까지 표기하지 않습니다.

### 3.7 사진

| 등급 | 장수 | 구성 |
|---|:-:|---|
| **L1** | 3장 | 외관 · 1층 · 내부 1 |
| **L2** | 6장 | + 주차 · 계단/EV · 전면도로 |
| **L3** | 9장+ | + 층별 · 옥상 · 기계실 |

**L1 미만(2장 이하)이면 사진 페이지를 넣지 않고 확인사항에 기록합니다.**

### 3.8 한 장 요약 (p2) — 항상 렌더

**이 페이지는 축약되지 않습니다.** 칸이 개별적으로 degrade될 뿐입니다.

| 칸 | 자료 없을 때 |
|---|---|
| 매매가 · 평당가 | 필수 · 없으면 IM 자체 불가 |
| 실투자금 | "산출 불가 (대출 조건 미확인)" |
| 월 순현금 | "산출 불가 (운영비 미반영)" |
| 임대 요약 | "임대 내역 미확보" |
| **확인 필요** | **결손이 많을수록 길어짐** |

### 3.9 리스크 · 확인사항 (p9) — 역방향

**유일하게 자료가 적을수록 내용이 많아지는 페이지입니다.**

```
자료 완비  → 확인된 리스크 위주 · 짧음
자료 부족  → 미확인 사항 위주 · 김
```

**따라서 항상 작성 가능하며, 비어 있으면 안 됩니다.**

## 4. 공통 원칙 4가지

### 4.1 결손은 이동한다

```
축약된 요소  →  확인사항 페이지 한 줄
```

**섹션이 조용히 사라지면 매수인은 그런 게 있었는지도 모릅니다.** 이관하면 실사 목록이 됩니다.

### 4.2 부분은 부분으로 표시한다

```
❌ 8/12행만 면적이 있는데 8행 합계를 전체 합계처럼 표기
✅ 8개 호실 평당 단가 표기 + "4개 호실 면적 미상 · 합계 미산출"
```

### 4.3 가정은 계산해도 되지만 표시한다

```
✅ ◇ 지하층 평당 5만원 가정 시 월 638만원 (비교 사례 미확보)
❌ 지하층 임대 시 월 638만원
```

### 4.4 등급은 낮춰 잡되, 기능은 개별로 연다

**종합 등급**은 여러 기능 중 가장 낮은 것을 따릅니다. 하나라도 미달이면 그 등급은 미달입니다.

**그러나 개별 기능은 자기 요건만 보고 열립니다.** 둘은 다른 층위입니다.

#### 실측 사례 — 양평동 갱신본

| | |
|---|---|
| 보유 | 최초계약일 ○ · 대항력 ○ · 적용법령 ○ · 관리비 ○ |
| 미보유 | **임대면적 ✗** |
| 종합 등급 | **R1** (면적이 없어 R2 미달) |
| 그런데 갱신권 잔여 | **호실별 2.1 ~ 5.5년 산출됨** |

**갱신요구권은 `적용법령 + 최초계약일`만 요구하므로 면적과 무관하게 열립니다.** 종합 등급이 R1이라고 해서 R3 기능이 잠기지 않습니다.

```
종합 등급  →  중개인에게 보여주는 요약 · 다음 행동 안내용
개별 기능  →  실제 렌더 판정 기준
```

**렌더는 반드시 개별 기능으로 판정합니다.** 종합 등급으로 렌더를 막으면, 이미 있는 자료로 만들 수 있는 것까지 버리게 됩니다.

## 5. 등급별 IM 실제 모습 — 양평동 예시

동일 물건, 렌트롤 등급만 달라졌을 때.

| 요소 | R1 (현재) | R2 | R3 |
|---|---|---|---|
| 렌트롤 표 | ○ 11행 | ○ + 면적·평당가 | ○ + 갱신권 잔여 |
| 수익률 | 2.24% (총임대료) | 2.24% + 평당 단가 | 동일 |
| 환산보증금 | **확인 필요** | ○ 11건 전원 9억 이하 | 동일 |
| 갱신요구권 | **확인 필요** | **확인 필요** | ○ 호실별 잔여 |
| 명도 계획 | **섹션 없음** | **섹션 없음** | ○ 타임라인 |
| 임대료 정상화 | **섹션 없음** | 정성 서술만 | ○ 정량 시뮬 |
| 확인사항 | **3줄** | 2줄 | 0줄 |
| PPTX 분량 | 12p | 13p | 15p |

**R1에서도 12페이지 IM이 나옵니다.** 이것이 이 설계의 목적입니다.
