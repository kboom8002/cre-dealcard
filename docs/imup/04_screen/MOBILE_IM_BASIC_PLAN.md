## 1. 누가, 언제, 어떤 상태로 읽는가

기존 명세는 이 질문을 건너뛰고 "무엇을 담을까"부터 시작했습니다. 다시 봅니다.

### 1.1 실제 상황

```
중개인이 카톡으로 링크를 보냄
   ↓
매수자는 지하철에서 폰으로 엽니다
   ↓
이미 이번 주에 받은 물건 링크가 4~5개 있습니다
   ↓
30초 안에 "이건 나중에 제대로 보자"가 결정됩니다
```

### 1.2 여기서 나오는 세 가지

**① Basic은 다른 Basic과 경쟁합니다.**

"이 건물이 좋은가"가 아니라 **"받은 5개 중 어느 걸 먼저 볼까"** 가 실제 질문입니다. 기존 설계는 단독 열람을 가정했습니다.

**② 30초 안에 걸러집니다.**

7문을 스크롤하는 사람은 이미 관심이 큰 사람입니다. **Basic의 목적은 10분 쓸 가치가 있는지 판단시키는 것인데, 7문 자체가 10분입니다.** 목적과 형식이 어긋나 있었습니다.

**③ 첫 숫자가 매각가면 안 됩니다.**

매각가 42억은 매수자에게 정보가 아닙니다. 알고 싶은 것은 **"내 돈이 얼마나 들어가나"** 입니다. 보증금 승계와 대출을 반영해야 비로소 자기 예산과 대조됩니다.

## 2. 설계 판단 5가지

### 판단 ① — 첫 숫자는 실투자금

```
기존   매각가 42억  →  임대수익률 1.86%  →  ...
개정   실투자금 39억 →  권역 대비 수익률  →  ...
```

**"보증금 3.3억 승계 후"** 를 함께 적습니다. 계산 과정 없이 결과만 주면 검증할 수 없고, 검증 못 하는 숫자는 믿지 않습니다.

#### 대출을 첫 화면에 넣지 않습니다

이 물건은 **역레버리지**입니다.

```
대출금리 4.8%  >  표준 Cap Rate 1.34%
→ 대출을 쓸수록 자기자본 수익이 나빠집니다
```

"LTV 55%면 실투자금 15.6억"이 숫자로는 매력적이지만 **수익은 마이너스**입니다. 첫 화면에 두면 유인이 아니라 기만이 됩니다. 대출 시나리오는 접힌 섹션에서 **역레버리지 경고와 함께** 제시합니다.

> 이것이 Basic 설계의 시금석입니다. **매력적으로 보이게 만드는 것과 정확하게 보여주는 것이 충돌할 때 정확을 택합니다.** 실사에서 드러나면 그 딜만 잃는 게 아니라 중개인을 잃습니다.

### 판단 ② — 7문을 3문 + 4접기로

| | 펼침 | 접힘 |
|---|---|---|
| **Q1** | 이 돈으로 무엇을 사는가 | |
| **Q2** | 얼마나 벌고, 더 벌 수 있나 | |
| **Q3** | 무엇이 걸리는가 | |
| | | ▸ 입지는 어떤가 |
| | | ▸ 층별 임대 현황 |
| | | ▸ 대출을 쓰면 어떻게 되나 |
| | | ▸ 권리 관계 |

**`<details>` 태그로 구현합니다** — 스크립트 없이 접기가 되고, 접근성도 확보됩니다.

부수 효과가 큽니다. **어느 섹션을 펼쳤는지가 관심의 방향을 알려줍니다.** 스크롤 깊이보다 정확한 신호입니다 (`POST_PUBLISH_SPEC` S01).

### 판단 ③ — 권역 벤치마크를 병기합니다

```
기존   임대수익률  1.86%
개정   임대수익률  1.86%    연남 근생 평균 1.9%
```

**이것이 CREDEAL만 할 수 있는 것입니다.** 개별 중개인은 권역 통계를 갖고 있지 않습니다. 그리고 §1.2 ①에서 봤듯 매수자의 실제 과제는 비교입니다. 비교를 대신 해주면 우리 물건이 먼저 열립니다.

| 규칙 | |
|---|---|
| 표본 수 **명시** | "N=23" — 없으면 신뢰하지 않습니다 |
| 표본 10건 미만 | **표시하지 않습니다** (신호가 아니라 잡음) |
| 불리해도 표시 | 평균보다 낮으면 낮다고 씁니다 |

마지막이 중요합니다. 유리할 때만 보여주면 매수자가 곧 알아챕니다.

### 판단 ④ — CTA를 딜카드와 다르게

딜카드는 [질문] [관심] [상세 요청] 3단입니다. Basic에서 그대로 쓰면 **상세 요청의 문턱이 너무 높습니다** — NDA를 요구하기 때문입니다.

```
딜카드   질문 · 관심 · 상세 요청(NDA)
Basic    질문 · 자료 더 받기 · 현장 보기
              └ 연락처만        └ NDA + 일정
```

**「자료 더 받기」가 중간 계단입니다.** 연락처만 받고 Pro 대신 보조 자료(등기부 요약·주변 실거래)를 보냅니다. 관계를 만들고 나서 NDA를 요청합니다.

### 판단 ⑤ — 업종은 대분류로

```
기존   1F 카페 / 2F 학원 / 3F 의원
개정   1F 근린생활(식음) / 2F 근린생활(교육) / 3F 주택
```

**"역삼동 5층 건물 3층에 XX의원"이면 검색으로 특정됩니다.** Basic은 링크 공유가 가능하므로 통제 밖으로 나갑니다. 상호와 업종 소분류는 Pro에서 공개합니다.

### 3.1 Q3가 Q2 뒤에 오는 이유

**벌 수 있는 것을 말한 직후 걸리는 것을 말합니다.** 순서를 바꾸면 리스크가 변명처럼 읽히고, Q3를 접으면 숨긴 게 됩니다. 먼저 밝힌 약점은 신뢰를 만듭니다.

### 3.2 접힌 4문이 접혀 있는 이유

| 문 | 왜 접는가 |
|---|---|
| 입지 | 지도 이미지가 이미 답했습니다 |
| 층별 현황 | 표라서 30초 판단에 기여하지 않습니다 |
| 대출 시나리오 | 관심 있는 사람만 봅니다 |
| 권리 관계 | 실사 영역입니다 |

## 4. 지도 · 이미지 에셋 정책

### 4.1 왜 지금까지 없었나

기존 산출물은 **전부 텍스트·도형**입니다. Safari 안정성과 블라인드 정책 때문이었는데, 그 대가로 모바일에서 가장 강력한 요소를 포기했습니다.

**사진은 텍스트보다 먼저 인지됩니다.** 30초 안에 걸러지는 문서에서 이건 큰 손실입니다.

### 4.2 단계별 정책

| 에셋 | 딜카드 | Basic | Pro |
|---|---|---|---|
| 지도 | 도형 개념도 | **정적 지도 · 반경 300m** | **정확 위치 핀** |
| 외관 사진 | ✗ | **1장 · 마스킹** | 전체 · 원본 |
| 내부 사진 | ✗ | ✗ | ○ |
| 층별 도면 | ✗ | ✗ | ○ |
| 항공/로드뷰 | ✗ | ✗ | ○ |

### 4.3 마스킹 규칙 — 재식별 방지

Basic 외관 사진에서 **반드시 가립니다.**

```
✗ 간판·상호        →  블러 또는 단색 마스크
✗ 번지 표기        →  마스크
✗ 차량 번호판      →  블러
✗ 주변 랜드마크 상호 →  프레이밍으로 제외
✓ 건물 형태·층수·외장재  →  유지 (판단 근거)
```

```ts
export interface AssetPolicy {
  tier: 'teaser' | 'basic' | 'pro';
  masks: Array<{ kind: 'signage'|'address'|'plate'|'landmark'; bbox: BBox }>;
  verifiedBy: string;      // 마스킹 검수자
  verifiedAt: string;
}
```

**마스킹은 사람이 검수합니다.** 자동 검출만 믿으면 반드시 새어 나가고, 한 번 새면 회수할 수 없습니다.

### 4.4 지도 사양

| 항목 | Basic | Pro |
|---|---|---|
| 형식 | 정적 이미지 (Static Map API) | 정적 이미지 |
| 중심 | **반경 원의 중심** (정확 위치 아님) | 정확 좌표 |
| 표시 | 반경 300m 원 · 역 · 주요 도로 | 핀 · 필지 경계 · 반경 |
| 크기 | 360×200 · 2x | 360×260 · 2x |
| 용량 | **≤ 60KB** | ≤ 120KB |
| 각주 | "개념도 · 정확 위치 비공개" | "지적도 기준" |

> **정적 이미지를 쓰는 이유** — 지도 SDK는 스크립트가 무겁고, 카카오 인앱 브라우저에서 실패율이 높습니다. Basic은 첫 화면 1.5초 예산이 있습니다.

### 4.5 성능 예산

```
첫 화면 (텍스트)        0.6s   ← 이미지 없이 완성
지도 이미지            +0.4s   lazy · placeholder 유지
외관 사진              +0.5s   lazy · Q1 진입 시
────────────────────────────
첫 화면 완료           1.5s 이내
```

| 규칙 | |
|---|---|
| **첫 화면은 이미지 없이 완성** | 이미지가 늦어도 판단 시작 가능 |
| `loading="lazy"` · `width`/`height` 명시 | 레이아웃 흔들림 방지 |
| 포맷 | WebP · AVIF 폴백 |
| 이미지 없는 물건 | **레이아웃이 깨지지 않아야 합니다** — 매물의 절반은 사진이 없습니다 |

마지막이 실무적으로 가장 중요합니다. 사진을 전제로 설계하면 사진 없는 물건에서 문서가 초라해집니다.

## 5. 관점별 변형

| posture | 첫 숫자 | 두 번째 | Q1 | Q2 |
|---|---|---|---|---|
| `income` | 실투자금 | 임대수익률 vs 권역 | 이 돈으로 무엇을 사는가 | 얼마나 벌고 더 벌 수 있나 |
| `development` | **총 사업비** | 토지비 부담 vs 권역 | 무엇을 지을 수 있는가 | 얼마가 들고 언제 되나 |
| `owner_occupied` | 실투자금 | **월 부담 vs 현 임차료** | 우리가 들어갈 수 있는가 | 임차보다 유리한가 |
| `operating` | 실투자금 | **객실당 vs 권역** | 무엇을 사는가 | 영업이 어떻게 되나 |
| `trading` | 실투자금 | 평단가 vs 권역 | 무엇을 사는가 | 되팔 수 있는가 |

**Q3(무엇이 걸리는가)는 전 관점 공통**입니다.

`development`의 첫 숫자가 실투자금이 아니라 **총 사업비(토지+공사비)** 인 것이 중요합니다. 개발형 매수자는 토지 가격만으로 판단하지 않습니다.

## 6. Pro 재설계

Basic이 바뀌면 Pro도 이어져야 합니다.

### 6.1 Pro의 역할 재정의

```
Basic   "제대로 볼 가치가 있는가"      → 30초
Pro     "얼마에 왜 사야 하고, 무엇을 확인해야 하는가"  → 30분
```

Pro의 마지막 목적은 **현장 실사 요청**입니다. 그렇다면 마지막 문이 "다음에 무엇을 확인할지"여야 합니다.

### 6.2 8문 → 9문

골든판 8문에 하나를 더합니다.

| # | 문 | 변경 |
|---:|---|---|
| ① ~ ⑧ | (골든판 유지) | — |
| **⑨** | **무엇을 확인하시겠습니까** | 🆕 실사 체크리스트 |

```
⑨ 무엇을 확인하시겠습니까

  □ 임대차계약서 원본 4건       최초 계약일·갱신 이력
  □ 운영경비 실적 12개월        NOI 가정을 실적으로
  □ 위반건축물 조회 결과        대출 가능 여부
  □ 등기부 최신본               권리 변동
  □ 현장 — 3층 누수 흔적 확인    중개인 메모

  [현장 실사 요청]
```

**우리가 아직 확인 못 한 것을 먼저 적습니다.** 매수자가 실사에서 발견하기 전에 밝히면 성의가 되고, 나중에 발견되면 은폐가 됩니다.

### 6.3 Pro 에셋

| 추가 | 내용 |
|---|---|
| 원본 자료 | 등기부·건축물대장·토지대장 PDF **첨부** |
| 사진 | 외관 전체 · 내부 · 공용부 · 문제 부위 |
| 도면 | 층별 평면 (있는 경우) |
| 지도 | 정확 위치 · 필지 경계 |

**"문제 부위 사진"이 신뢰를 만듭니다.** 누수·균열을 우리가 먼저 찍어 보여주면 실사가 확인 절차가 되고, 감추면 협상 카드가 됩니다.

### 6.4 grant 유효기간 재검토

기존 7일입니다. **실사 준비에는 짧습니다.**

```
기존   7일 고정
개정   14일 기본 · 중개인이 7/14/30일 선택 · 만료 3일 전 알림
```

만료로 인한 재요청은 매수자에게 마찰이고 중개인에게 일입니다.

## 7. 무엇을 포기했는가

솔직하게 적습니다. 이 설계에는 대가가 있습니다.

| 포기 | 이유 |
|---|---|
| 정보량 | 7문 전체 노출 → 3문. 접힌 것은 **덜 읽힙니다** |
| 대출 매력 | 역레버리지를 밝히면 "실투자금 15억"의 유인을 못 씁니다 |
| 사진의 힘 | 마스킹하면 덜 매력적입니다 |
| 상호 노출 | "스타벅스 입점"을 Basic에서 못 씁니다 |

앞의 둘은 **의도적**입니다. 뒤의 둘은 재식별 위험과의 교환이며, 위험이 더 큽니다.

> 다만 마지막은 재검토 여지가 있습니다. **앵커 테넌트(대형 프랜차이즈)는 물건 특정에 기여하지 않으면서 강력한 신호**입니다. 표본을 모아 재식별 위험을 실측한 뒤 판단하는 것이 맞습니다.
