# 매도인·매수인 진단 확장 명세

> 구현된 Owner Readiness(자료 준비도)를 **의사·상황 진단**으로 확장하고, 매수인 쪽에 없던 자가진단을 신설합니다.
> 기존 시스템은 `READINESS_SYSTEM.md`가 소유합니다. 이 문서는 **확장분만** 다룹니다.

| | |
|---|---|
| **온톨로지** | v0.4.0 |
| **라우트** | `/owner-readiness` (기존 확장) · `/buyer-readiness` (신설) |
| **공수** | **23.0 solo-day** (§10) |
| **최종 수정** | 2026-08-04 |

---

## 1. 왜 확장하는가

### 1.1 지금 진단은 자료만 봅니다

Owner Readiness 10항목은 전부 문서입니다 — 건축물대장·등기부·렌트롤·사진·평면도.

**그런데 중개인이 실제로 알고 싶은 것은 "이 사람이 팔 마음이 있나"입니다.**

```
자료 100점 · 시세 +30% 고집        →  시간 낭비
자료  40점 · 6개월 내 상속 정리 필요  →  최우선
```

### 1.2 이 진단이 먹힌 진짜 이유

점수 때문이 아닙니다.

| 메커니즘 | |
|---|---|
| 자가진단이라 **방어가 안 생김** | 중개인이 "자료 주세요"는 부담, 스스로 체크는 자기 발견 |
| 다음 행동이 명확 | 10개 체크박스 |
| **결과에 즉시 보상** | `≥20 → Deal Curiosity Report` |

**확장할 때 이 세 가지를 깨면 안 됩니다.**

## 2. 절대 원칙 세 가지

### 2.1 🔴 9번째 점수를 만들지 않습니다

CREDEAL에는 이미 점수가 **7개**입니다 (`READINESS_SYSTEM.md` §4). 여기에 딜 준비도 7축까지 8개고, Owner Readiness와 Layer Score는 문서에 명시된 대로 **같은 10카테고리 가중치를 공유**합니다 — 사실상 같은 것의 두 이름입니다.

**매각 의사를 점수로 만들면 9번째가 됩니다.**

```
✗   매각 의사 지수  72점 / B등급
✓   매각 의사 신호   ⚠ 3건
```

의사·상황은 **신호 플래그**로만 표현합니다. 순서가 필요하면 ⚠ 개수로 정렬합니다.

### 2.2 🔴 자가응답은 점수원이 아니라 대화 재료입니다

"언제까지 파실 건가요?"에 **"급하지 않아요"라고 답하는 것이 협상에 유리합니다.** 과장 편향이 구조적입니다.

| 쓰는 곳 | 쓰지 않는 곳 |
|---|---|
| 중개인에게 **무엇을 물어볼지** 제시 | 딜 준비도 축3 「매도 의사 확실성」의 입력 |
| 확인 필요 항목 도출 | 자동 필터링·자동 거절 |
| 대화 시작점 | 매칭 가중치 |

**축3은 중개인 관측으로 유지합니다** (`P1-2_너처링자동화_기능명세.md` §3).

### 2.3 🔴 진단은 문을 여는 도구지 닫는 도구가 아닙니다

한 발 걸치기가 **조작으로 느껴지면 역효과**입니다. 부동산은 반복 거래 시장이고 평판이 돕니다.

| 규칙 | |
|---|---|
| 매도인에게 **종합 등급을 보여주지 않습니다** | "D등급"은 자산가에게 모욕입니다 |
| 결과는 항상 **다음 단계 3개**로 표현 | 20점이어도 받을 것이 있어야 합니다 |
| 필터링은 **중개인 내부 화면에서만** | 딜카드에서 자료등급을 감춘 것과 같은 논리 |

## 3. 매도인 — 2축 확장

### 3.1 두 축을 곱하지 않습니다

```
자료 준비도   65 / 100        ← 기존. 지금 어떤 산출물이 가능한가
매각 의사     ⚠ 3건           ← 신설. 지금 시간을 쓸 가치가 있는가
```

성격이 다른 두 축을 합치면 정보가 사라집니다. **나란히 둡니다.**

### 3.2 의사 진단 4문 (+ 가격 §3.4)

#### Q1 — 계기

```
매각을 생각하시게 된 계기가 무엇인가요?

  ○ 자산 재조정        ○ 상속·증여 준비
  ○ 자금 필요          ○ 관리 부담
  ○ 아직 결정 전
```

`아직 결정 전` → **신호 ⚠**. 나머지는 동기가 특정되므로 정상.

#### Q2 — 시점

```
언제까지 정리되면 좋으시겠어요?

  ○ 3개월 내   ○ 6개월 내   ○ 1년 내
  ○ 시기 무관   ○ 조건 맞으면 언제든
```

`시기 무관` → ⚠. **"얼마나 급하신가요?"라고 묻지 않습니다** (§3.3).

#### Q3 — 소유 구조

```
이 건물의 소유 구조는 어떻게 되나요?

  ○ 단독        ○ 공동 (가족)
  ○ 공동 (비가족) ○ 법인

  [공동 선택 시]
  다른 소유자분들도 매각에 동의하셨나요?
  ○ 예   ○ 아니오   ○ 논의 중
```

`아니오`·`논의 중` → **⚠ (가장 무거운 신호)**. 당산동·연남동 사례처럼 공동소유는 딜 진행 자체를 좌우합니다.

#### Q4 — 매각 이력

```
매각을 시도해 보신 적이 있나요?

  ○ 이번이 처음
  ○ 이전에 내놨다가 거두었음
  ○ 현재 다른 곳에도 의뢰 중
```

둘 다 ⚠. `거두었음`은 철회 사유를, `다른 곳에도`는 전속 여부를 확인해야 합니다.

### 3.3 🚫 묻지 않는 것

| 금기 문항 | 왜 |
|---|---|
| "얼마나 급하신가요?" | 협상 카드를 내놓으라는 것으로 읽힙니다 |
| "대출이 얼마나 있나요?" | 재무 상태 캐기 — 등기부로 확인할 것 |
| "최저 얼마까지 가능하세요?" | 진단이 아니라 협상입니다 |
| "다른 곳은 얼마 불렀나요?" | 경쟁사 정보 캐기로 읽힙니다 |
| 소득·직업·가족관계 | 매각과 무관 |

**진단과 협상의 경계가 여기입니다.** 넘으면 신뢰를 잃습니다.

### 3.4 가격 위치 — 판정하지 않고 위치만

```
이 정도 건물이 최근 이 가격에 거래됐습니다

   38억 ├────────●────────┤ 52억
            중앙 44억
                        ▲ 희망하신 55억

   최근 12개월 · 마포 연남 · 상가주택 · 80~100평 · 실거래 9건

   ※ 위치·건물 상태·임대차 조건에 따라 달라집니다.
```

| 규칙 | |
|---|---|
| **판정 문구 없음** | "비쌉니다" ✗ · 위치만 보여줍니다 |
| 표본 수 명시 | 없으면 신뢰하지 않습니다 |
| **표본 5건 미만이면 밴드 미표시** | 신호가 아니라 잡음 |
| 중앙값 대비 ±20% 초과 | **⚠ 신호** (매도인 화면에는 표시 안 함) |

> **중개인이 "비쌉니다"라고 하면 싸움이고, 데이터가 보여주면 납득입니다.** 이것이 이 화면의 전부입니다.

### 3.5 매도인이 보는 결과

```
자료를 이만큼 갖고 계십니다        65 / 100

  지금 가능한 것
  ✓ 건물 요약 리포트
  ✓ 블라인드 티저

  이것만 채우시면 투자설명서까지 가능합니다
  ① 임대차 현황표          약 15분    +20
  ② 건물 사진 5장 이상      약 10분    +10
  ③ 평면도                 보유 시     +10

  [건물 요약 리포트 받기]        ← 즉시 보상
```

**신호(⚠)는 매도인 화면에 표시하지 않습니다.** 종합 등급도 없습니다.

## 4. 매수인 — 신설

### 4.1 지금 없는 것

`READINESS_SYSTEM.md` §2를 보면 매수인 쪽은 **메모 파싱(Buyer Intent)** 과 **인바운드 폼(Reverse Onboarding)** 뿐입니다. **자가진단이 없습니다.**

### 4.2 진단 5문

#### Q1 — 속도 ★ 판별력이 가장 높습니다

```
지금 계약하시면 잔금까지 며칠 정도 필요하세요?

  ○ 30일 내   ○ 60일 내   ○ 90일 내
  ○ 대출 승인에 따라   ○ 아직 모르겠음
```

**이 한 문항이 자금 여력·대출 준비·의사결정 구조를 동시에 드러냅니다.** 하나만 물어야 한다면 이것입니다.

#### Q2 — 자금

```
자금은 어떻게 준비되어 있나요?

  ○ 전액 보유
  ○ 일부 대출 예정 (금융기관 사전 상담 완료)
  ○ 일부 대출 예정 (아직 상담 전)
  ○ 보유 자산 매각 후
```

#### Q3 — 의사결정

```
매수 결정은 어떻게 이루어지나요?

  ○ 본인 단독   ○ 배우자·가족 협의
  ○ 법인 내부 절차   ○ 투자자 협의
```

#### Q4 — 경험

```
상업용 부동산을 매수해 보신 적 있나요?

  ○ 이번이 처음   ○ 1~2건   ○ 3건 이상
```

`처음` → 신호가 아니라 **응대 방식 조정 신호**입니다. 용어 설명을 더 붙입니다.

#### Q5 — 목적 → `investmentPosture`로 직결

```
어떤 목적으로 보고 계세요?

  ○ 임대수익   ○ 사옥·자가사용   ○ 개발·신축
  ○ 운영 (숙박·요양 등)   ○ 단기 매매
```

**3축의 `investmentPosture`와 같은 값입니다** (`CATALOG_ASSET_TYPES.md` §3). 매칭·IM 편성에 그대로 씁니다.

### 4.3 예산 현실성

```
예산 40억 · 마포 권역 · 임대수익 목적

  이 조건에 맞는 물건, 최근 1년 거래 12건
  평균 수익률 1.8% · 평균 대지 78평

  조건을 조금 넓히면
    예산 50억까지 →  28건
    서대문 포함    →  21건
    수익률 1.5% 이상 → 34건
```

**매수자는 자기 조건이 현실적인지 모릅니다.** 건수를 보여주면 스스로 조정합니다. 이것도 판정하지 않습니다.

### 4.4 매수인이 보는 결과

```
조건에 맞는 물건이 12건 있었습니다

  지금 받아보실 수 있는 것
  ✓ 마포 권역 최근 거래 요약
  ✓ 조건에 맞는 블라인드 티저 3건

  [권역 리포트 받기]
```

## 5. 골디락스 캘리브레이션

| 축 | 너무 약함 | **적정** | 너무 셈 |
|---|---|---|---|
| 질문 수 | 3문 미만 — 신뢰 안 생김 | **4~5문 · 2분** | 15문+ — 이탈 |
| 결과 표현 | "준비 부족합니다" | **다음 단계 3개** | "D등급" — 모욕 |
| 가격 | 언급 회피 | **밴드 위 내 위치** | "30% 비쌉니다" |
| 개인정보 | 익명 — 후속 불가 | **연락처 하나** | 소득·자산 증빙 |
| 필터링 | 전부 수용 | **내부 신호만** | 대놓고 거절 |
| 후속 | 없음 | **리포트 즉시 1건** | 영업 전화 |
| 저장 | 안 함 | **재방문 시 이어서** | 동의 없이 마케팅 활용 |

### 5.1 이탈 방지 규칙

```ts
export const DIAGNOSTIC_UX = {
  maxQuestions: 5,
  allowSkipAll: true,          // 모든 문항에 건너뛰기
  saveOnEachAnswer: true,      // 중간 이탈해도 보존
  requireContactAt: 'result',  // 연락처는 결과 직전에만
  showProgress: true,
};
```

**연락처를 앞에서 받지 않습니다.** 첫 화면에서 물으면 이탈률이 급등합니다. 진단을 마치고 리포트를 받을 때 받습니다.

## 6. 중개인 내부 화면

**이 화면이 진단의 실제 가치입니다.** 점수가 아니라 **물어볼 것 목록**입니다.

```
매도인 진단 결과 · 2026-08-04

  자료 준비도    65 / 100        렌트롤·사진 미보유
  매각 의사 신호  ⚠ 3건

    ✓ 시점      6개월 내 (관리 부담)
    ⚠ 소유      공동 (가족 2인) — 동의 논의 중
    ⚠ 이력      이전에 내놨다가 거둠
    ⚠ 가격      희망 55억 · 권역 중앙 44억 대비 +25%

  먼저 확인하실 것
    ① 공동소유자 두 분의 동의 여부와 시점
    ② 이전 매각 철회 사유
    ③ 55억의 근거 — 어떤 기준으로 산정하셨는지

  [통화 메모 남기기]  [딜카드 만들기]
```

| 규칙 | |
|---|---|
| 종합 등급 **없음** | ⚠ 개수로 정렬만 |
| **질문 문안을 제시** | "확인 필요"가 아니라 실제 문장 |
| 응답 원문 보존 | 요약만 남기면 맥락이 사라집니다 |

## 7. 데이터 모델

```sql
CREATE TABLE seller_intent_survey (
  id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  building_id     uuid REFERENCES building(id),
  broker_id       uuid REFERENCES broker(id),
  motive          text CHECK (motive IN ('rebalance','inheritance','liquidity','burden','undecided')),
  horizon         text CHECK (horizon IN ('m3','m6','m12','none','conditional')),
  ownership       text CHECK (ownership IN ('sole','joint_family','joint_other','corporate')),
  co_owner_consent text CHECK (co_owner_consent IN ('yes','no','discussing')),
  history         text CHECK (history IN ('first','withdrawn','multi_listed')),
  asking_price    bigint,
  contact_hash    text,
  answered_at     timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT joint_requires_consent
    CHECK (ownership NOT IN ('joint_family','joint_other') OR co_owner_consent IS NOT NULL)
);

CREATE TABLE buyer_intent_survey (
  id              uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  broker_id       uuid REFERENCES broker(id),
  speed           text CHECK (speed IN ('d30','d60','d90','loan_dependent','unknown')),
  funding         text CHECK (funding IN ('full_cash','loan_consulted','loan_unconsulted','after_sale')),
  decision        text CHECK (decision IN ('self','family','corporate','investors')),
  experience      text CHECK (experience IN ('first','one_two','three_plus')),
  posture         text NOT NULL,            -- investmentPosture와 동일 값
  budget_min      bigint,
  budget_max      bigint,
  regions         text[],
  contact_hash    text,
  answered_at     timestamptz NOT NULL DEFAULT now()
);

-- 신호는 저장하지 않고 파생합니다 (응답이 정본)
CREATE VIEW seller_intent_flags AS
SELECT id, building_id,
  (motive = 'undecided')                             AS flag_undecided,
  (horizon = 'none')                                 AS flag_no_horizon,
  (co_owner_consent IN ('no','discussing'))          AS flag_consent,
  (history IN ('withdrawn','multi_listed'))          AS flag_history
FROM seller_intent_survey;
```

### 7.1 신호를 저장하지 않는 이유

**응답이 정본이고 신호는 파생입니다.** 판정 기준이 바뀌면 뷰만 고치면 되고, 과거 응답의 의미가 사후에 바뀌지 않습니다. 어휘 사전에서 alias를 삭제하지 않는 것과 같은 이유입니다.

### 7.2 RLS

```sql
ALTER TABLE seller_intent_survey ENABLE ROW LEVEL SECURITY;
CREATE POLICY sis_own ON seller_intent_survey
  USING (broker_id = auth.uid()
         OR building_id IN (SELECT id FROM building WHERE broker_id = auth.uid()));
```

**진단 응답은 담당 중개인만 봅니다.** 조직 관리자에게도 열지 않습니다 — 매도인의 개인적 사정이 담깁니다.

## 8. 법적 · 개인정보 경계

### 8.1 수집 고지

진단 시작 전 1줄, 연락처 입력 시 정식 동의를 받습니다.

```
목적    매각·매수 상담 및 맞춤 자료 제공
항목    응답 내용 · 연락처
보유    2년 (또는 철회 시까지)
거부    거부하셔도 진단 결과는 보실 수 있습니다
```

**마지막 줄이 중요합니다.** 연락처 없이도 결과를 보여줍니다.

### 8.2 ⚠️ 세후 실수령액 계산기 — 조건부

매도인의 최대 관심사이지만 **세무 자문 경계**가 있습니다.

| 허용 | 금지 |
|---|---|
| 범위 제시 (최소~최대) | 단일 확정 금액 |
| 보유기간·취득가만 입력 | 세대 구성·타 자산·소득 |
| "세무사 확인 필수" 고정 문구 | 절세 방법 안내 |
| 계산 근거 공개 | 특정 거래 구조 권유 |

```
예상 세후 수령액   38억 ~ 41억   ⚙ 가정

  근거: 양도가 55억 − 취득가 32억 − 필요경비 추정
        보유 12년 · 장기보유특별공제 적용 가정
  ※ 실제 세액은 취득 시점·경비 증빙·기타 소득에 따라 크게 달라집니다.
     반드시 세무사와 확인하십시오.
```

> **🔴 출시 전 세무 검토 필수.** 이 기능은 세무사 자문을 받아 문구·산식·면책을 확정한 뒤에만 배포합니다. 검토 전에는 **비활성**으로 둡니다.

### 8.3 공인중개사법

진단 결과에 **투자 권유·가격 보장으로 읽힐 표현을 넣지 않습니다.** 가격 밴드는 실거래 사실 제시이며 평가가 아닙니다.

## 9. 지표

| 지표 | 정의 | 목표 (3개월) |
|---|---|---:|
| 진단 완주율 | 시작 → 결과 도달 | **75%** |
| 연락처 제공률 | 결과 도달 → 연락처 입력 | 45% |
| 매도인 진단 → 딜카드 생성 | 진단 후 30일 내 | 25% |
| **중개인 「먼저 확인할 것」 활용률** | 통화 메모에 반영된 비율 | **50%** |
| 매수인 진단 → 매칭 실행 | 진단 후 7일 내 | 60% |
| 이탈 지점 | 문항별 이탈률 | Q1 < 10% |

### 9.1 목표치의 한계

**전부 추정입니다.** 기존 Owner Readiness의 실측 완주율이 없어 기준선이 없습니다. 1개월 운영 후 재설정합니다.

**4번째 지표가 실질입니다.** 진단을 아무리 많이 받아도 중개인이 그 결과로 다르게 행동하지 않으면 의미가 없습니다.

### 착수 순서

```

```

**2번(가격 위치)을 먼저 하는 이유** — 실거래 API가 이미 붙어 있고(P1-2 축2), **매도인이 가장 놀라는 지점**입니다. 놀라야 대화가 시작됩니다.

**4번(매수인 5문)이 두 번째인 이유** — 매수 측에 진단이 아예 없어 공백이 가장 큽니다.
