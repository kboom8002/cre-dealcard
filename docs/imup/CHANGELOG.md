### 품질·교육 (`IM_QUALITY_TRAINING_PLAN.md` · `IM_SELF_REVIEW_PROMPTS.md` 신설)

실전 IM 5건에서 확인된 오류를 **5개 층위(L1 산술 / L2 기준 미명시 / L3 결손 / L4 법적판정 / L5 가정의 확정화)** 로 분류하고, 중개인이 AI 챗봇으로 자가 개선하는 8단계 프롬프트를 도출했습니다.

| 발견 | 빈도 |
|---|---|
| L2 기준 미명시 (용적률·수익률) | **5/5** |
| L3 결손 (최초계약일·취득비용·운영경비·제척) | **5/5** |
| L1 산술 오기 (당산동 300㎡ · 잠원동 40,000원) | 2/5 |
| L4 법적 불가 (당산동 401호 5% 상한 초과 인상 계획) | 1건 |
| L5 가정 확정화 (수택동 1,260% 지구단위계획 전제 미고지) | 1건 |

**설계 원칙 2가지.** ① 1단계(재계산)를 건너뛰면 이후 전부 무의미 — 틀린 숫자 위에 그럴듯한 분석이 쌓입니다. ② **AI의 법적 답변은 결론이 아니라 확인 목록** — 상임법·주임법 혼동이 잦아 3차 훈련을 "AI 오답 판별"에 배정했습니다.

훈련 공수 **12.0 solo-day**. 프롬프트 커버리지 — 실증 오류 11종 전부.

### 발행 후 관리 (`PRD_발행후관리.md` · `POST_PUBLISH_SPEC.md` 신설)

**발행 이후에 도는 최초의 코드군 2개를 신설했습니다.**

| 코드군 | 소유 질문 | 개수 |
|---|---|---:|
| **F** Freshness | 발행 후 낡았는가 | 10 |
| **S** Signal | 매수자 반응이 무엇을 말하는가 | 8 |

기존 8개 군과 충돌 없음. `E`는 향후 예외 계열을 위해 예약합니다.

**설계 핵심 — 판정의 정본은 하나입니다.** L1 산술·L2 기준은 발행 시 `C01~C32`·`G10`이 이미 판정했으므로 **재검사하지 않습니다.** AI는 `Hypothesis`·`Suggestion`만 생성하며 `Verdict`를 만들 수 없도록 타입 수준에서 차단합니다. `evidence` 없는 AI 출력은 DB 제약(`evidence_not_empty`)으로 저장이 불가능합니다.

**전략적 근거** — v3.1의 moat인 성사 관측(`outcome.recorded`)은 중개인이 발행 후 돌아와야 쌓입니다. 지금은 돌아올 이유가 없습니다. 이 기능이 재방문 이유를 만듭니다.

공수 **40.5 solo-day** (1차 P0 18.5 / 2차 P1 14.0 / 3차 8.0). AI 예상 호출 180회/월은 이론 상한의 3.6%.

### 매도인·매수인 진단 확장 (`READINESS_DIAGNOSTIC_SPEC.md` 신설)

구현된 Owner Readiness(자료 준비도)가 유용하다는 현장 피드백에서 출발해, **의사·상황 진단**으로 확장하고 매수인 쪽 공백을 메웁니다.

#### 문제 — 자료 준비도 ≠ 매각 의사

Owner Readiness 10항목은 전부 문서입니다. 자료 100점이어도 시세 +30%를 고집하면 시간 낭비고, 40점이어도 6개월 내 상속 정리 건이면 최우선입니다.

#### 💥 9번째 점수를 만들지 않았습니다

CREDEAL에는 이미 점수가 **8개**입니다 (`READINESS_SYSTEM.md` §4의 7개 + 딜 준비도 7축). Owner Readiness와 Layer Score는 **같은 10카테고리 가중치를 공유** — 사실상 같은 것의 두 이름입니다.

매각 의사를 점수로 만들면 9번째가 되므로, **신호 플래그**로만 표현합니다.

```
✗   매각 의사 지수  72점 / B등급
✓   매각 의사 신호   ⚠ 3건
```

DB에도 점수 컬럼이 없습니다. 응답이 정본이고 신호는 뷰로 파생합니다 — 판정 기준이 바뀌어도 과거 응답의 의미가 사후에 바뀌지 않습니다.

#### 자가응답은 점수원이 아닙니다

**"언제까지 파실 건가요?"에 "급하지 않아요"라고 답하는 것이 협상에 유리합니다.** 과장 편향이 구조적이라, 딜 준비도 축3(매도 의사 확실성)의 입력으로 쓰지 않습니다. 축3은 중개인 관측으로 유지합니다.

자가진단의 역할은 **중개인에게 무엇을 물어볼지 알려주는 것**입니다. 중개인 화면의 산출물은 점수가 아니라 질문 문안입니다.

#### 금기 문항을 명시했습니다

| 금기 | 왜 |
|---|---|
| "얼마나 급하신가요?" | 협상 카드를 내놓으라는 것 |
| "대출이 얼마나 있나요?" | 등기부로 확인할 것 |
| "최저 얼마까지 가능하세요?" | 진단이 아니라 협상 |

**진단과 협상의 경계**가 여기입니다.

#### 가격은 판정하지 않고 위치만 보여줍니다

실거래 밴드 위에 희망가 점 하나. "비쌉니다" 문구는 넣지 않습니다 — **중개인이 말하면 싸움이고 데이터가 보여주면 납득**입니다. 표본 5건 미만이면 밴드 자체를 표시하지 않습니다.

#### 매수인 진단 신설

기존에는 메모 파싱과 인바운드 폼뿐이었습니다. 5문 자가진단을 신설했고, **Q1 "지금 계약하면 잔금까지 며칠?"** 이 자금 여력·대출 준비·의사결정 구조를 동시에 드러내는 최고 판별 문항입니다. Q5(목적)는 `investmentPosture` 값과 동일해 매칭·IM 편성에 직결됩니다.

#### 경계

세후 실수령액 계산기는 **세무 검토 전 비활성**입니다. 범위 제시·근거 공개·세무사 확인 문구까지만 허용하고, 절세 안내·단일 확정 금액은 금지합니다.

공수 **23.0 solo-day** (세후 계산기 +4.0 별도). 출시 불변조건 **13** 추가.

### 어휘 사전 · SSoT 관리 (`CATALOG_LEXICON.md` · `ONTOLOGY_GOVERNANCE_SPEC.md` 신설)

**온톨로지에 어휘 계층이 아예 없었습니다.** `alias`·`canonical`·`b2cLabel` 전부 미정의 상태였고, `b2cLabel`은 `DEAL_CARD_SPEC.md`에서 카탈로그 등록 없이 도입되어 사용 중이었습니다.

#### 실증 — 같은 개념을 세 가지로

| 법인 | 표기 |
|---|---|
| 제이에스 (잠원동) | **"실질 용적률 247%"** |
| 제이에스 (당산동) | "용적률 221.8%" |
| Genesis (양평동) | "용적률 398.8%" |

전부 지상 연면적 기준입니다. 이 상태로는 메모 파싱(`IM_AUTHORING_SPEC` §3.2)의 확신도가 나오지 않습니다.

#### 라벨 3종 체계

```
canonical   개발·명세용     "지상 연면적 기준 용적률"
proLabel    Pro IM · PPTX  "용적률 (지상 연면적 기준)"
b2cLabel    딜카드 · Basic  "용적률"
```

`b2cLabel`이 `null`이면 대고객 산출물에 노출 불가입니다. `PPTX_TEMPLATE_SPEC.md` §16.2의 `CapRateBasis` 라벨표는 어휘 카탈로그로 **이관**되었습니다.

#### 💥 3층 편집 모델

| 층 | 편집 방법 | 재현성 영향 |
|---|---|---|
| 구조 (슬롯·규칙·계산식) | **PR only** | 치명적 |
| 값 (enum) | 제안 → 승인 → PR | 큼 |
| **어휘** | **화면 편집** | **없음** |

**화면 편집을 어휘에만 여는 근거는 재현성입니다.** alias는 입력 시점에만 작용하고, 발행·재렌더는 slot을 읽으므로 사전을 고쳐도 과거 IM 재현 결과가 바뀌지 않습니다. 구조·값은 그렇지 않습니다.

#### 수집은 이미 있는 것에서 시작합니다

`IM_AUTHORING_SPEC` §3.2의 `unmatched`가 지금은 IM 코멘트로 흘려보내고 버려집니다. **로깅만 붙이면 편집기 없이 수집이 시작됩니다.** 사전이 빈 상태로 편집기만 만들면 승인할 것이 없습니다.

#### 안전장치

- 전사 활성 alias의 `normalized`에 **DB 유니크 인덱스** — 한 단어가 두 슬롯에 매핑되는 것을 애플리케이션이 아니라 DB가 막습니다
- alias **삭제 불가**, 비활성화만 — 과거 파싱 로그의 해석이 사후에 바뀌면 안 됩니다
- 조직 관리자는 **전사 alias를 만들 수 없습니다** — 한 조직의 은어가 다른 조직 파싱을 오염시킵니다
- AI는 `suggestion`만 생성 · `Approval` 타입 생성 불가

시드 42항목 · 공수 **26.5 solo-day**. 출시 불변조건 **11·12** 추가.
