## 1. 테스트 목적

이번 세션(P0/P1/P2)에서 수행된 PPTX 고도화를 포함한 전체 5-포스처 메모→PPTX IM 파이프라인의 무결성을 검증합니다.

| Phase | ID | 개선 내용 | 검증 포커스 |
|-------|-----|-----------|-------------|
| **P0** | 1-A | A07 리스크 블록 3→5 동적 확장 | 5개 리스크 분야가 모두 렌더링되는가 |
| **P0** | 1-C | WALE 신호등 콜아웃 kind 자동 매핑 | 안정→🟢, 주의→🟡, 위험→🔴 색상 분기 |

## 2. 테스트 전략

### 2.1 파이프라인 단계별 검증점

```
┌──────────────────────────────────────────────────────────────────────┐
│ ① 메모 입력                                                          │
│    검증: 메모 파싱 품질 (매매가, 면적, 층수 추출)                       │
│    위험: 자유 서술 → 구조화 실패 시 NaN/undefined 오염               │
├──────────────────────────────────────────────────────────────────────┤
│ ② 딜카드 생성                                                        │
│    검증: investmentPosture 추론 정확도                                │
│    위험: 포스처 오분류 → 전체 섹션 편성 오류                          │
├──────────────────────────────────────────────────────────────────────┤
│ ③ 모바일 IM 섹션 생성                                                │
│    검증: 7개 섹션 완성, section_type 매핑 정확                        │
│    위험: LLM 이모지 과다, 페르소나 노출, 용어 오용                   │
├──────────────────────────────────────────────────────────────────────┤
│ ④ PPTX 데이터 바인딩                                                 │
│    검증: section_type → dataKey → archetype 매핑 무결성              │
│    위험: 마크다운 파싱 실패 → 빈 블록/폴백 슬라이드                  │
├──────────────────────────────────────────────────────────────────────┤
│ ⑤ PPTX 렌더링                                                       │
│    검증: 텍스트 잘림, 레이아웃 오버플로, 빈 슬라이드 없음             │
│    위험: CJK 텍스트 예산 초과, 동적 블록 수 레이아웃 깨짐            │
└──────────────────────────────────────────────────────────────────────┘
```

### 2.2 위험 시나리오 매트릭스

| # | 위험 시나리오 | 영향 슬라이드 | 검증 방법 |
|---|-------------|--------------|-----------|
| R1 | 리스크 분야 5개인데 3개만 렌더링 | A07 | `blocks.length` 검증 |
| R2 | WALE 콜아웃에 kind 미설정 → 회색 폴백 | A03 | kind 필드 존재 + 색상 검증 |
| R3 | 45자 초과 임차인명 말줄임 | A03 | 40-50자 셀 데이터 포함 |
| R4 | 벤치마크 표 없이 빈 공간 | A15 | `benchmarkTable` 필드 존재 |
| R5 | 서사 리드문 미감지 → 빈 콜아웃 | A04 | `callouts[0].kind === 'brass'` |
| R6 | 이모지 잔류 (PptxGenJS 렌더링 실패) | 전체 | 이모지 유니코드 잔존 검사 |
| R7 | 프로세스 4단계인데 3단계만 렌더링 | A09 | `steps.length >= 4` |
| R8 | 폴백 테이블 헤더 스타일 미적용 | fallback | 첫 행 fill 색상 검증 |
| R9 | `sanitizePersona`에서 NaN/undefined 잔류 | 전체 | NaN/undefined 텍스트 스캔 |
| R10 | 포스처 전용 섹션이 common 아키타입으로 오매핑 | 비소득 | dataKey ↔ archetype 크로스체크 |

### 2.3 입력 데이터 설계 원칙

1. **포스처별 1건**: 5건의 메모 원문, 각각 해당 포스처의 특수 섹션을 트리거하는 키워드 포함
2. **개선사항 트리거 데이터**:
   - 리스크 5개 분야 명시 (건축물 안전/임대차/권리관계/명도/설비)
   - WALE 양극단 키워드 포함 (안정 + 위험)
   - 45자 초과 임차인명
   - 벤치마크 비교표 마크다운
   - 이모지가 포함된 서사 문장
   - 프로세스 4단계 이상 기술
3. **엣지 케이스**: 빈 테이블, NaN 값, 페르소나 지칭 문구 포함

## 3. 포스처별 검증 체크리스트

### 3.1 income (임대수익형)

- [ ] `section_type: lease_status` → `dataKey: rentRoll` → `A03` 매핑
- [ ] A03 테이블: 45자 임차인명 말줄임 없이 표시
- [ ] A03 콜아웃: WALE 텍스트에 `kind: good/warn/bad` 자동 설정
- [ ] A05 수익분석: 스탯 6개 이상 추출
- [ ] A07 리스크: 5개 블록 동적 렌더링 (건축물/임대차/권리관계/명도/설비)
- [ ] A07: 4블록 시 12.5pt, 5블록 시 11.5pt 폰트 축소
- [ ] A15 투자포인트: 벤치마크 표가 pillar 카드 아래에 표시
- [ ] A15: ⭐→★ 이모지 안전 변환
- [ ] A09 프로세스: 4단계 렌더링
- [ ] 전체: `sanitizePersona`에서 이모지→라벨 변환 (🚇→[교통])

### 3.2 owner_occupied (자가사용형)

- [ ] `section_type: occupancy_fit` → `dataKey: plan` → `A04` 매핑
- [ ] `section_type: cost_comparison` → `dataKey: vsLease` → `A08` 매핑
- [ ] A04 건물개요: 서사 리드문이 brass 콜아웃으로 삽입
- [ ] A08 비용비교: 듀얼 테이블 렌더링 (임대 vs 자가사용)
- [ ] A07 리스크: 사옥 관련 리스크 (주차/통근/설비)
- [ ] `lease_status` 섹션 미생성 (suppress 확인)

### 3.3 development (개발형)

- [ ] `section_type: site_analysis` → `dataKey: landDetail` → `A04` 매핑
- [ ] `section_type: development_feasibility` → `dataKey: feasibility` → `A05` 매핑
- [ ] A07 리스크: 명도/인허가/환경/지장물/일조권 등 개발 리스크 5블록
- [ ] A04 토지분석: 다필지 병합 데이터 표시
- [ ] `lease_status`, `income_analysis` 미생성 (suppress)

### 3.4 operating (운영형)

- [ ] `section_type: operation_overview` → `dataKey: kpi` → `A13` 매핑
- [ ] `section_type: gop_analysis` → `dataKey: revenue` → `A05` 매핑
- [ ] A13 KPI: 가동률, ADR, RevPAR 등 운영 지표 표시
- [ ] 이모지→라벨: 🏢→[건물], 💰→[수익] 등 매핑 검증
- [ ] A07 리스크: 운영 리스크 (인력/시장/시설)

### 3.5 trading (단기매매형)

- [ ] `section_type: market_position` → `dataKey: marketPosition` → `A04` 매핑
- [ ] `section_type: comparable_analysis` → `dataKey: comps` → `A03` 매핑
- [ ] A03 비교매물 테이블: 동적 폰트 (5열+ 시 11pt)
- [ ] A15: 벤치마크 표에 별점(★) 표시
- [ ] A04: 서사 리드문 brass 콜아웃
