# CRE DealCard - Human E2E Test Guide Part 1: Data Pipeline
Version: v5.0
Date: 2026-08-18

본 문서는 50-60대 한국 꼬마빌딩 중개법인 임원 및 실무자(Tester)가 아무런 코딩 지식 없이, 카카오톡으로 받은 매물 정보를 복사-붙여넣기 하여 전체 데이터 파이프라인(메모 파싱 → 바텀시트 입력 → 엑셀 렌트롤 업로드 → 데이터 정제 → IM 생성)을 완벽하게 검증할 수 있도록 작성된 **복붙 실행용 E2E 가이드**입니다.

테스트를 시작하기 전 아래 사항을 확인하십시오.
- 모바일 화면 크기로 크롬 브라우저 창을 줄이거나(F12 개발자 도구 - 디바이스 툴바 활용), 실제 모바일 기기에서 진행하십시오.
- 스테이징 DB 데이터는 주 1회 초기화되므로 임의의 데이터를 생성하여도 실제 운영 서비스에는 영향을 미치지 않습니다.

# §1. 테스트 환경 준비

테스트를 원활하게 진행하기 위해 아래 항목이 모두 준비되었는지 체크합니다.

1. **테스트 브라우저**: Chrome 최신 버전 권장 (또는 Safari, Edge). 보안 확장 프로그램(AdBlock 등)은 꺼주세요.
2. **계정 로그인**: 
   - ID: `broker_tester_1@test.com` (또는 로컬/스테이징 환경 테스트 계정)
   - PW: `password123!` 
3. **기본 진입 URL**: 
   - 로컬 환경: `http://localhost:3000/broker/deal-card/new` 
   - 스테이징 환경: `https://staging.cre-dealcard.com/broker/deal-card/new`
4. **엑셀 템플릿 준비**: 렌트롤 테스트를 위해 빈 엑셀 파일(.xlsx)을 엽니다. 가이드 내 표를 그대로 드래그 복사하여 엑셀 A1 셀부터 붙여넣고 저장하면 됩니다. 각 케이스마다 별도의 엑셀 파일로 저장해 두면 편리합니다.

# §3. 엑셀 렌트롤 5대 포맷 변형 테스트

테스터는 아래 5가지 형태의 엑셀 파일을 모두 업로드하여 시스템이 다양한 실무 데이터를 정상적으로 파싱하는지 확인해야 합니다.

#### 1. 표준 포맷
가장 권장되는 형태의 렌트롤 형식입니다.
| 층 | 호실 | 용도/업종 | 임차인 | 보증금(만원) | 월세(만원) | 관리비(만원) |
|---|---|---|---|---|---|---|
| 1F | 101 | 상가 | A식당 | 5000 | 300 | 20 |
| 2F | 201 | 사무실 | B상사 | 3000 | 200 | 15 |
| 3F | 301 | 사무실 | C상사 | 3000 | 200 | 15 |
| 4F | 401 | 학원 | D학원 | 5000 | 300 | 20 |

#### 2. 비표준 포맷 (Bug #1 검증용)
A열이 카테고리(구분), B열이 층수인 형태입니다.
| 구분 | 층수 | 업종 | 보증금(만원) | 월세(만원) |
|---|---|---|---|---|
| 층 | 1F | 상가 | 5000 | 300 |
| 층 | 2F | 사무실 | 3000 | 200 |
| 층 | 3F | 학원 | 4000 | 250 |
| 층 | 4F | 피트니스 | 5000 | 350 |
- 기대값: '층수' 컬럼 값을 정상 인식, '구분'의 '층' 데이터를 층 이름으로 잘못 파싱하지 않아야 함.

#### 3. 다층 병합 포맷 (Bug #3 검증용)
여러 층을 한 임차인이 사용하는 경우의 표기 방식입니다.
| 층수 | 호실 | 업종 | 보증금 | 임대료 |
|---|---|---|---|---|
| B1-B2 | 지하전체 | 골프장 | 10000 | 800 |
| 1F | 101 | 편의점 | 5000 | 300 |
| 2-3F | 201 | 병원 | 20000 | 1000 |
| 4~5F | 401 | 학원 | 15000 | 800 |
- 기대값: 'B1-B2', '2-3F', '4~5F' 등 특수문자가 포함된 병합 형태를 그대로 DB에 저장하고 화면에 표출.

#### 4. 혼합 단위 (일부 원, 일부 만원)
금액 단위가 혼용되거나 컬럼명에 표시되지 않은 경우입니다.
| 층 | 보증금 | 월세 | 보증금(만원) | 월세(만원) |
|---|---|---|---|---|
| 1F | 50,000,000 | 3,000,000 | | |
| 2F | | | 3000 | 200 |
| 3F | 100,000,000 | | | 500 |
| 4F | | 4,000,000 | 5000 | |
- 기대값: 컬럼명에 (만원)이 없는 경우 원 단위로 인식하거나, 숫자의 자릿수를 기반으로 스케일 보정 처리(시스템 룰에 따름). 

#### 5. 공실 행 포함 (업종 빈칸 또는 '공실')
업종이 빈칸이거나 명시적으로 '공실'로 적힌 경우입니다.
| 층 | 호실 | 업종 | 보증금 | 임대료 | 비고 |
|---|---|---|---|---|---|
| 1F | 101 | 약국 | 5000 | 400 | |
| 2F | 201 | | 0 | 0 | 공실 |
| 3F | 301 | 공실 | 0 | 0 | |
| 4F | 401 | 스튜디오 | 2000 | 150 | |
- 기대값: 2층, 3층 모두 공실로 정상 인식. 총수익 합산 시 0으로 처리.

# §4. 공실률·렌트롤 컨플릭트 검수

사용자의 수기 입력값과 엑셀 데이터가 충돌할 때 시스템의 반응을 테스트합니다. 이 기능은 휴먼 에러를 방지하는 핵심 장치입니다.

1. 바텀시트에서 **공실률 0% (만실)** 입력 후 임시 저장.
2. 엑셀 렌트롤 업로드 시 **공실이 1개 이상 포함된 파일** 업로드 (위 5번 포맷 활용).
3. **기대값**: 
   - 시스템이 충돌을 감지하고 사용자에게 경고 알럿(Alert)을 띄우거나,
   - 엑셀 데이터 기준으로 공실률을 자동 덮어쓰고(Update) 화면에 반영.
4. **결과 확인**: [ ] 경고 표시됨 / [ ] 자동 업데이트됨
5. **추가 검증**: 알럿에서 '엑셀 기준 반영' 선택 시 바텀시트 입력값이 변경되는지 확인. [ ]

# §6. 결함 리포트 양식

테스트 중 문제가 발생하면 아래 양식을 복사하여 이슈 트래커나 슬랙에 리포트합니다. 상세히 적어주실수록 개발팀의 디버깅 속도가 빨라집니다.

```markdown

- **발생 일시**: [예: 2026-08-18 14:00]
- **테스트 케이스**: [예: Case 1 - 엑셀 업로드]
- **브라우저/OS**: [예: Chrome 115 / Windows 11]
- **발생 URL**: [예: http://localhost:3000/broker/deal-card/new]

#### 🚨 문제 설명
(무엇이 기대와 다르게 동작했는지 1-2줄로 요약 설명. 예: 다층 병합 포맷 업로드 시 층수 인식이 누락됨)

#### 📝 재현 단계 (Steps to Reproduce)
1. /broker/deal-card/new 로 이동

3. 다층 병합 포맷 엑셀 파일(Case 1-B) 업로드
4. 렌트롤 확인

#### ✅ 기대값 (Expected)
- 6-7F가 하나로 묶여서 표기되어야 함

#### ❌ 실제 결과 (Actual)
- 6층, 7층으로 분리되거나 '알 수 없음'으로 표기됨

#### 📸 스크린샷 첨부
(오류가 발생한 화면의 스크린샷 이미지를 캡처하여 붙여넣기. 개발자 도구 F12 탭의 콘솔 에러 메시지도 함께 첨부해주시면 좋습니다.)
```
