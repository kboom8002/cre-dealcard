## 1. 원칙 7가지

**7라운드에서 값을 치르고 배운 것입니다.** 각 항목 뒤에 근거 라운드를 적었습니다.

### 1.1 문구를 바꾼 것은 원인을 고친 것이 아닙니다

양평동 v2에서 「자산 하이라이트」의 틀린 자랑 3건이 결손 안내 문구로 교체됐습니다. **하지만 교체된 문구도 두 물건에 동일했습니다.**

| | v1 | v2 |
|---|---|---|
| 문구 | "우량 메디컬 테넌트 · 자주식 주차 · 잔여 용적률" | "…첨부 건축물대장을 기준으로 합니다" |
| 두 물건 동일 | **예** | **예** |
| 원인 A 해소 | ✗ | **✗** |

게다가 양평동의 첨부 공부는 **다른 자치구 필지**였습니다. **"오첨부 서류를 기준으로 삼겠다"는 선언이 됐습니다.**

> **개선 판정은 문자열이 아니라 계층에서 합니다.** 값이 데이터에서 파생되기 시작했는가를 봅니다. `(양평 v2)`

### 1.2 값이 없는 것보다 값이 여러 개인 것이 더 위험합니다

v3까지는 값이 비어 있었습니다(Hero 4칸 전부 `-`). v4는 **같은 지표에 값이 2~3개**입니다.

| 지표 | v4 값 | 개별 검산 |
|---|---|:-:|
| Cap Rate | 1.56% / 1.4~1.7% / 2.0% | 1개만 일치 |
| 실투자금 | 54.6억 / 118.4억 | **둘 다 정확** |
| 자기자본수익률 | −0.46% / +1.6% | 둘 다 정확 · **부호 반대** |

**실투자금 두 값은 무차입 기준과 LTV 50% 기준으로 각각 맞습니다.** 빈 칸은 매수인이 "없구나"로 읽지만, 두 값은 **어느 쪽이든 골라 읽습니다.** `(v4)`

### 1.3 산술 검산은 절반입니다 — 기준(basis)을 봐야 합니다

v4의 시세 벤치마킹은 **산술이 완벽했습니다.**

```
28,159,357 ÷ 6,028,226 = 4.671  →  +367.1%   ✓ 정확
```

**분자는 연면적 단가, 분모는 토지 실거래 단가였습니다.** 연면적 단가를 토지 단가와 비교하면 항상 몇 배가 나옵니다. 그 결과가 **"고평가 — 협상 여지 검토"** 라는, 매도인에게 직접 손해를 입히는 판정이었습니다.

> **모든 비율·단가·금액에 `basis`를 붙입니다.** 타입으로 강제하면 컴파일 단계에서 걸립니다. `(v4)`

### 1.4 신뢰 신호는 결손 목록에서 파생되어야 합니다

당산동 v2에서 "✓ 자료 확보" 뱃지 7개가 추가됐습니다. **결손 섹션에도 붙었습니다.**

| 섹션 | 뱃지 | 본문 |
|:-:|---|---|
| 3 임대 현황 | **✓ 자료 확보** | "🔒 임대차 상세 현황 자료가 아직 확보되지 않았습니다" |
| 5 수익 분석 | **✓ 자료 확보** | "🔒 임대 현황 데이터 확보 후 제공됩니다" |

v4에서 "✅ 공부확인"으로 개선됐지만 **대지면적 0㎡ · 용도지역 "확인 필요" · 주차 2,504대인 섹션에 그대로 붙어 있습니다.**

> **뱃지를 독립적으로 생성하지 않습니다.** `deficiencies`가 비어 있을 때만 파생시킵니다. `(당산 v2 · v3 · v4)`

### 1.5 두 물건을 나란히 놓으면 하드코딩이 즉시 드러납니다

당산동 보고서에서 저는 「자산 하이라이트」를 "퓨샷 폐순환의 실증"이라고 썼습니다. **틀렸습니다.**

양평동과 대조하니 **바이트 단위로 동일**했습니다. LLM 생성물이 아니라 **하드코딩된 상수**였습니다.

> **한 물건만 보면 원인을 오판합니다.** 최소 2건을 같은 회차에 생성해 대조합니다. `(양평 v1)`

### 1.6 이론 상한으로 단언합니다

산출물의 ROE 3.45%는 **수학적으로 불가능**했습니다.

```
총수익률 2.03%  <  대출금리 4.5%
→ 역레버리지. LTV가 오를수록 ROE는 단조 감소.
→ ROE의 이론 최대 = 무차입 ROE = 1.97%
→ 3.45% 는 어떤 LTV에서도 나올 수 없다
```

**값을 하나하나 대조하지 않아도 상한만으로 걸립니다.** 이런 단언은 물건이 바뀌어도 유지됩니다. `(당산 v1 · 양평 v1 · v4)`

### 1.7 정본을 통과시키지 못하는 점검기는 꺼집니다

`output_qa.py` 초판은 **골든 G01·G02를 스스로 차단**했습니다.

| 오탐 | 원인 |
|---|---|
| "Cap Rate 2개 (2.03 / 2.08)" | 기준이 명시된 정상 표기 |
| "순수익률 라벨 사용" | **"라벨을 붙이지 않습니다"** 라는 부정문 |
| "매매가 2개 (250 / 250.00)" | 같은 값의 다른 표기 |

**오탐이 몇 건만 나와도 팀은 검사를 끕니다.** 그래서 `calibrate.py`로 **골든 전량 무차단**을 매 커밋 확인합니다. `(§4.4)`

```python
# 기준이 적혀 있으면 값이 여럿이어도 정상이다
BASIS_MARK = re.compile(r'기준|매매가|보증금|총취득|취득원가|실투자금|무차입|LTV\s*\d'
                        r'|총임대료|투입비|소계|차감|NOI|GOP|연면적|토지|대지'
                        r'|자기자본|equity|price|basis')

def flatten(t):
    """PDF 셀 줄바꿈을 접는다. 부정문 줄은 먼저 제거한다."""
    keep = [ln for ln in t.split('\n') if not any(g in ln for g in NEGATION)]
    return re.sub(r'\s+', ' ', '\n'.join(keep))
```

## 6. 매체 교차 대조

**한 매체만 검사하면 조치 지점을 못 찾습니다.**

### 6.1 왜 필요한가

양평동에서 **자기자본수익률 2.85%는 PPTX에만 있었습니다.** 모바일과 섹션 md에는 없었습니다.

| 함의 | |
|---|---|
| 산식 위치 | 섹션 생성이 아니라 **PPTX 바인딩 단계** |
| 조치 지점 | `IMCore` 이전 · PPTX 어댑터 |
| 검증 | **모바일만 보면 못 잡습니다** |

### 6.2 대조표 서식

**같은 물건·같은 회차의 산출물을 한 표에 놓습니다.**

| 항목 | 섹션 md | 모바일 | PPTX | PDF | 판정 |
|---|:-:|:-:|:-:|:-:|---|
| Cap Rate | | | | | 값이 하나인가 |
| 실투자금 | | | | | 라벨·기준이 같은가 |
| 자기자본수익률 | | | | | **한 매체에만 있는가** |
| 연면적 | | | | | |
| 결손 표기 건수 | | | | | 0이면 차단 |

**한 매체에만 있는 값은 그 매체의 어댑터에서 생성된 것입니다.**

### 6.3 두 물건 대조 (원인 A 전용)

```bash
# 같은 회차에 생성한 두 물건의 25자 이상 공통 문장
python3 - <<'PY'
import re, sys
def sents(p):
    t = open(p, encoding='utf-8').read()
    return {s.strip() for s in re.split(r'[.!?\n]', t) if len(s.strip()) >= 25}
a, b = sents(sys.argv[1]), sents(sys.argv[2])
for s in sorted(a & b):
    print(len(s), s[:80])
PY
```

**바이트 동일 문장이 나오면 하드코딩입니다.** LLM 생성물은 물건이 바뀌면 문장이 바뀝니다.

## 7. 점검 보고서 서식

**7라운드에서 쓴 서식입니다. 그대로 쓰시면 됩니다.**

```markdown
# 산출물 점검 — <물건> <매체> (v<n>)

| | |
|---|---|
| 대상 | <파일명 · 크기> |
| 대조 | fixtures/<x>.json · golden/<G0n>.md |
| 판정 | 발행 차단 / 조건부 / 가능 |
| 점검일 | YYYY-MM-DD |

## 0. 요약           ← 개선 · 차단 · 중대 · 경미 건수
## 1. 개선 n건       ← **먼저 인정합니다**
## 2~ 차단 사유      ← 각 건에 산출물 값 vs 원장 값 vs 검산
## 중대 · 경미
## 오류 원인          ← A~H 중 어디인가
## 조치               ← 우선순위 · 난이도 · 효과
## 회귀 테스트        ← 실행 가능한 코드
## 라운드 누적 추적    ← 해소 ○ / 미해소 ✗ / 해당없음 —
```

### 7.1 개선을 먼저 씁니다

**차단만 나열하면 팀이 방향을 잃습니다.** v4에서 리스크 섹션이 정반대로 바뀐 것은 큰 성과였고, 그것을 먼저 적어야 다음 회차에 되돌아가지 않습니다.

### 7.2 값은 항상 세 개를 같이 씁니다

| | 예 |
|---|---|
| 산출물 값 | "자기자본수익률 **+1.6%**" |
| 원장·재현값 | 월 순현금 −210.3만 → 연 −0.2523억 ÷ 54.6억 = **−0.46%** |
| 판정 | **부호 반대 · 차단** |

**"틀렸습니다"만 쓰면 개발팀이 재현할 수 없습니다.**

# .github/workflows/output-qa.yml
name: output-qa

| 3 교차 | 경고 · 리뷰어 확인 |

## 9. 점검 자체의 안티패턴 7종

**제가 7라운드 동안 실제로 저지른 것들입니다.**

### 9.1 같은 이름의 파일이 여러 개인 것을 확인하지 않음

양평동 모바일 IM이 첨부되어 있었는데 **"미첨부"라고 보고했습니다.** 파일명 충돌로 `viewer_mobile-4788a9c1.html`로 저장돼 있었고, 저는 같은 이름의 당산동 파일만 열었습니다.

> **점검 착수 시 대상 파일 목록을 먼저 출력하고 크기·해시를 적습니다.**

### 9.2 부정문을 위반으로 셈

`output_qa.py` 초판이 골든 G01의 **"'순수익률' 라벨을 붙이지 않습니다"** 를 순수익률 라벨 사용으로 판정했습니다. **정본이 스스로 차단됐습니다.**

> **검사기를 만들면 반드시 정본에 먼저 돌립니다.** (§4.4)

### 9.3 산술만 검산하고 기준을 안 봄

`+367.1% 프리미엄`의 나눗셈은 정확했습니다. **분자·분모의 기준이 달랐습니다.**

> **검산이 맞는 것과 지표가 옳은 것은 다릅니다.**

### 9.4 한 매체만 보고 원인을 확정

당산동 보고서에서 「자산 하이라이트」를 "퓨샷 폐순환의 실증"이라고 단정했습니다. 양평동과 대조하니 **바이트 동일한 하드코딩**이었습니다.

> **원인 판정은 2건 이상 대조 후에 합니다.**

### 9.5 문구 변화를 개선으로 판정

양평동 v2에서 하이라이트가 바뀐 것을 개선으로 셌습니다. **바뀐 문구도 두 물건에 동일했고, 더 위험했습니다** (오첨부 서류를 기준으로 선언).

> **"바뀌었는가"가 아니라 "데이터에서 파생되는가"를 봅니다.**

### 9.6 제 계산을 검산하지 않음

당산동 LTV50 ROE를 **−4.14%** 로 썼습니다. 정답은 **−0.41%** — 10배 오류였습니다.

> **점검 보고서의 수치도 스크립트로 재현합니다.** 손으로 쓴 숫자를 믿지 않습니다.

### 9.7 라운드 간 추적표를 안 만듦

4라운드까지 개별 보고서만 쓰다가, 통합 추적표를 만들고서야 **"4라운드 동안 해소된 차단 사유가 1건뿐"** 이라는 사실이 드러났습니다.

> **매 라운드 누적 추적표를 갱신합니다.** (§10)
